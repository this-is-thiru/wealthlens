# 02 — Lessons from the placeholder

**This is not a fix-list.** The placeholder is being replaced, not repaired. Its value is that it
already made 36 recorded mistakes, and each one identifies a **design property** that the replacement
must have structurally, so that the same mistake becomes impossible rather than merely fixed.

**Provenance.** The `O-n` observations are from `docs/taxplanning-context/04-constants-tests-history.md`,
read this session. That pack is a **lead, not proof** — I read the observation titles and bodies for
O-1 to O-16 directly and the titles for O-17 to O-36. Where a design rule below depends on a legal
fact, the fact carries a rule ID from `01-rulebook.md` and the observation only supplies the symptom.

## L1 — Mistake → the design rule that makes it impossible

| O-ID | What went wrong | Class | Design rule that prevents it | Where enforced |
|---|---|---|---|---|
| **O-1** | Seeded `limitFormula` strings (`min(0.14 * (basic + da), actual_nps)`) use a syntax the SpEL evaluator does not accept; every call site catches the failure and substitutes `0` | **silent-zero** | **`D-NOSILENT`** — a rule that cannot be evaluated must **fail the computation**, never return zero. There is no `catch (Exception) { return 0; }` anywhere in the engine | `G1` step 0; `X5` property test "no rule yields 0 by exception" |
| **O-1** | A hand-rolled formula DSL was introduced to express a cap that the statute states as a percentage of a defined base | **over-generalisation** | **`D-NOFORMULA`** — caps are **typed value objects** (`Fixed`, `PercentOfBase`, `LeastOf`, `Aggregate`, `Slab`), not strings. A formula language is only reachable if a real rule needs one, and none of R1–R24 does | `M1`, `X2` |
| **O-2** | `MarginalReliefCalculator` has three public methods, seven passing tests and **no production caller**; the relief that runs is a different inline implementation | **two implementations** | **`D-ONEIMPL`** — one implementation per rule ID, reached only through the pipeline. A class with no inbound edge from a `ComputationNode` fails the architecture test | `G3`; `X5` ArchUnit rule |
| **O-3** | Surcharge seeded at ₹5,00,00,000; the Javadoc says ₹50 lakh; two tests assert `0` and comment that they know | **wrong value, tests pinned to it** | **`D-GOLDEN`** — expected values come from **rulebook arithmetic shown step by step**, never from running the code. A test whose expectation was produced by the implementation is not a test | `08-golden-tests.md` preamble; `RATE-SUR-*` |
| **O-4** | `TaxYearRegistryEntity` models `startDate`, `endDate`, `governingAct`, `governingRules`, `defaultRegime` — and is never read or written | **model without a consumer** | **`D-REGISTRY`** — the tax-year registry is the **entry point**: no computation can begin without resolving a `RulePack` through it. It cannot be dead because nothing works without it | `M1`, `G1` step 0 |
| **O-5** | HRA warnings are computed and dropped into an empty `if`; the replacement warning fires only when the user is **not** paying rent | **diagnostics as a side channel** | **`D-TRACE`** — there is no separate "warnings" concept. Every step emits a `TraceLine`, and a `TraceLine` may carry `Notice`s. Nothing can be computed and discarded, because the trace is the return value | `G7`, `M5` |
| **O-6** | `esopPresent`, `sourceText`, `parsedByAi` have no production writer, so an ESOP warning can never fire | **orphan fields** | **`D-NOORPHAN`** — every persisted field is either written by a named ingestion path or does not exist. Enforced by a test that walks the entity graph and asserts a writer exists | `M7`, `X5` |
| **O-7** | `allowance_limits` says `80C`, `80D`, `80CCD_1B`, `24B`; `allowance_catalogue` says `SECTION_80C`, `SECTION_80D`, `NPS_SELF`, `SECTION_24`. Intersecting the two sets silently yields the empty set for those four | **two vocabularies** | **`D-ONECODE`** — one `ComponentCode` registry, **loaded from the rule pack** and used by data, engine and API alike. A rule pack or request naming a code outside the registry **fails to load or 400s**. Sections are never identifiers; rule IDs are. (Amended by `10-extensibility.md` E4: the registry is data, not a closed Java enum, so a new allowance is a data change) | `M2`, `X4` |
| **O-8** | A `GET` endpoint recomputes and persists; the read-only accessor has no caller | **verb/effect mismatch** | **`D-PURE`** — computation is a **pure function** `(RulePack, Inputs) → Computation`. Persistence is a separate, explicit command. `GET` returns what is stored or 404 | `X3`, `G1` |
| **O-9, O-12** | `.mapToLong(getAnnualAmount)` and `Math.min(getStandardDeduction(), gross)` unbox nullable `Long`s; the sibling call site guards the same field | **nullable money** | **`D-MONEY`** — money is a non-null value type (`Money`), never `Long`/`long`/`Long?`. Absence is `Money.ZERO` or `Optional<Money>` at the boundary, resolved once on ingestion | `M6` |
| **O-10** | `annualLimitFixed / monthlyLimitFixed / 12` is an integer divide-by-zero whenever the monthly limit is null | **derived value recomputed from parts** | **`D-CAPTYPE`** — a per-child monthly cap is a `PerUnitPerPeriod(amount, unitCount, periods)` value object that computes its own annual equivalent. Callers never divide | `M1`, `SAL-ALW-CEA-2026` |
| **O-11** | Marginal relief runs for the old regime, keyed off a generic `rebate87aLimit` that is ₹5,00,000 there | **regime-blind shared template** | **`D-REGIMESTEP`** — the pipeline is assembled **per regime** from the rule pack. A step that s.156(2) confines to s.202(1) is simply **not in the old-regime pipeline**. There is no runtime `if (regime == NEW)` in a shared base class | `REBATE-NEW-MR-001`, `G1`, `X2` |
| **O-13** | `netTakeHome = gross − employeePf − professionalTax − totalTax` where `gross` includes annualised car and driver perquisite values | **cash and non-cash summed** | **`D-CASHFLAG`** — every `ComponentCode` declares `isCash()`. `takeHome` is defined over cash components only, and the type system stops a non-cash component reaching it | `M2`, `A4`, `H-15` |
| **O-14** | Bands seeded at `previous_to + 1`; width computed as `min(TI, to) − from`, losing a rupee per band; `Math.round` applied per band | **off-by-one plus early rounding** | **`D-BAND`** — a band is `(lowerExclusive, upperInclusive, rate)` and the arithmetic bound is `lowerExclusive`. Rounding happens in exactly **two** places: total income, and the final payable. Enforced by a property test that the slab walk is continuous and exact | `RATE-SLAB-BAND-002`, `RATE-ROUND-003`, `G1` |
| **O-15** | An integration fixture writes `EMPLOR_PF`; the engine looks up `EMPLOYER_PF`; the amount is still summed into gross because gross sums everything regardless of code | **string codes, and a sum that ignores them** | **`D-ONECODE`** (a typo cannot compile) **plus `D-CLOSEDSUM`** — gross salary is the sum over a **declared partition** of component codes, so an unmapped component is a **load error**, not a silent addend | `M2`, `T9` |
| **O-16** | An integration test POSTs an `ACTIVE` slab policy with **no slabs**, superseding the seeded one, in a collection the harness deliberately protects from cleanup | **mutable reference data, admin-writable** | **`D-IMMUTABLE`** — rule packs are **immutable, versioned, checksummed artefacts loaded from the classpath**. There is no admin endpoint that writes one. A test that needs a different pack **loads a different pack** | `M1`, `X4`, `X5` |
| **O-17** | `updateAllowance` silently discards most of the request body | **partial write, silent** | **`D-EXPLICIT`** — request DTOs are validated wholes; an unrecognised or unhandled field is a 400, not a shrug | `X3` |
| **O-18** | Seeding failures are logged and swallowed | **silent-zero, at startup** | **`D-FAILFAST`** — rule-pack load failure **fails application startup**. A tax engine with no rules is not degraded, it is wrong | `X4`, `T9` |
| **O-19** | Five classes and roughly twenty methods/fields have no production caller | **dead code** | **`D-ONEIMPL`** + the ArchUnit reachability rule | `X5` |
| **O-20** | The PDF's restructuring sections are unreachable | **renderer ahead of the model** | **`D-VIEWFROMTRACE`** — every output (JSON, PDF, ITR figures) is a **projection of the same `Computation` trace**. A section with no trace lines renders as nothing, visibly | `G7`, `X2` |
| **O-21** | `annualSavingVsCurrent` does not consider the current regime | **comparison without a baseline** | **`D-SCENARIO`** — a saving is always `Scenario(B).totalTax − Scenario(A).totalTax` with both scenarios materialised and traceable. There is no scalar "saving" field | `A1`, `A3`, `M5` |
| **O-22** | No coverage gate on the module though PIT targets it | **gate declared, not enforced** | **`D-GATE`** — JaCoCo `check` and PIT thresholds are scoped to the computation packages and **fail the build** | `X5` |
| **O-23** | Restructuring always prices at the new-regime marginal rate | **hard-coded marginal rate** | **`D-MARGINAL`** — marginal value is measured, not assumed: recompute the scenario with the component changed and diff. That also captures rebate and surcharge marginal-relief cliffs, which a rate cannot | `A2`, `A3`, `G6` |
| **O-24** | Two different formula vocabularies coexist | **over-generalisation** | **`D-NOFORMULA`** | `M1` |
| **O-25** | `computePerquisiteValue` switches on a code that does not exist | **string codes** | **`D-ONECODE`** | `M2` |
| **O-26** | `createProfile` and `updateProfile` treat a null rent differently | **two write paths** | **`D-ONEWRITE`** — one command handler per aggregate, one validation path; create and update differ only in whether a prior version exists | `X3` |
| **O-27** | `computeWarnings` can abort the whole computation | **diagnostics can kill the result** | **`D-TRACE`** — notices are data attached to trace lines and cannot throw | `G7` |
| **O-28** | Two Act citations coexist | **provenance as prose** | **`D-PROVENANCE`** — every rule row carries `{ruleId, instrument, provision, effectiveFrom, effectiveTo, sourceUrl, status}`, and the status is rendered to the user. Citations are structured data | `M1`, `A4` |
| **O-29** | No Bean Validation anywhere in the module | — | **`D-VALIDATE`** — request DTOs carry constraints; the module's `@Valid` coverage is asserted by a test | `X3`, `X5` |

### The five failure classes, and what each one costs

`INFERENCE (from the table above)`: the 36 observations collapse into five classes, and the two that
matter most are the two that produce **silently wrong tax**, not crashes.

| Class | O-IDs | Why it is the dangerous kind |
|---|---|---|
| **Silent-zero** | O-1, O-18, O-27 | The computation completes and looks right. A ₹3,36,000 employer-NPS deduction becomes ₹0 and nothing says so. The user files on it |
| **Year-blind or regime-blind** | O-3, O-11, O-31, O-33, O-34 | Produces a plausible number from the wrong rule. `H-2` and `H-3` are both instances. Caught only by a golden test for the *other* year or the *other* regime — which is why `08-golden-tests.md` is organised by (year × regime) |
| **Two implementations / two vocabularies** | O-2, O-7, O-19, O-24, O-25, O-35 | The tested one and the running one drift apart. O-2 is the pure case: seven passing tests over code that never executes |
| **Model without a consumer** | O-4, O-6, O-20, O-34 | Design intent recorded as schema and never wired. Reads as coverage; is absence |
| **Cash/non-cash and definitional confusion** | O-13, O-21, O-23 | Not a tax error at all — an error in what the number *means*. The most damaging for trust, because the tax may be right while the headline is nonsense |

## L2 — Ideas worth keeping

Each of these is a real idea from the placeholder. Verification status is about whether **the law
supports the idea**, not whether the old code implemented it correctly.

| # | Idea | Keep because | Change because | Rule IDs | Status |
|---|---|---|---|---|---|
| **K-1** | **Policy data lives in JSON outside the code** (`resources/data/tax-policies/*.json`, five files, seeded at `@PostConstruct`) | Correct instinct, and the only way D2 ("adding a year = new data only") can hold | Load from the **classpath as an immutable, checksummed artefact**, not through a seeder that writes to Mongo and can be overwritten by an admin endpoint (O-16, O-18). No `@PostConstruct` database write | `D2`, `M1`, `X4` | **VERIFIED as necessary** — the R1–R24 diff shows 24 rows changing between two adjacent years |
| **K-2** | **A `TaxYearRegistryEntity` carrying `governingAct`, `governingRules`, `defaultRegime`, `startDate`, `endDate`** | Exactly the right fields. `YR-ACT-002`/`-003`/`-004` show that a tax year needs **three** identifiers — Act, Finance Act and Rules — not one | Make it the mandatory entry point rather than an unused table (O-4). ### Two ideas deliberately not kept

| Idea | Why not |
|---|---|
| **A SpEL-based `FormulaEvaluator` for rule limits** (O-1, O-24) | `RECOMMENDATION`: none of R1–R24 needs an expression language. Every cap in the rulebook is one of five shapes — fixed amount, percentage of a named base, least-of-N, aggregate-with-ceiling, or slab ladder. A general evaluator buys nothing and costs a sandbox, a syntax, a failure mode that returns zero, and a second vocabulary. If a future rule genuinely needs arithmetic the statute does not express in those five shapes, add a sixth typed shape |
| **Admin HTTP endpoints that create slab and allowance policies** (O-16) | `RECOMMENDATION`: a runtime-mutable tax rulebook is a correctness hazard with no offsetting benefit for a single-tenant product with no users yet. Rule packs ship with the JAR, are checksummed, and change by deploy. It also removes the only path by which a test can corrupt another test's reference data |
