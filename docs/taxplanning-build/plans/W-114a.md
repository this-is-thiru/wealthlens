## Plan for W-114a — the calendar's year-end deduction entry, and the LTA block end

**What this item is for (one sentence, in my own words):** add the calendar entry "the last day to pay for a deduction
this year", priced as the tax the unused room would save, and settle what the leave-travel block's end should be.

**Design sections I read:** W-114a's row (`03-WORK-ITEMS.md`, placed by D-665); `20-product-gaps.md` F30 and its
W-114 erratum; `00-SUMMARY.md:360` (`D-MARGINAL`); `plans/W-114.md`.

**What the code has (read this session):**
- **The 80C cap.** `DED-SCHEDULE-XV` (2025 s.123; 1961 s.80C) is an `AggregateWithCeiling`: 26 contributors, a
  ceiling of ₹1,50,000 and sub-caps (e.g. `EMPLOYEE_NPS` 10 % of salary).
- **The 80D and NPS caps.** The four 80D limbs (`DED-HEALTH-FAMILY`, `-FAMILY-SENIOR`, `-PARENTS`, `-PARENTS-SENIOR`)
  and `DED-NPS-OWN` use the same cap type.
- **The headroom exists but is unpublished.** `AggregateOutcome` (`rules/cap/AggregateOutcome.java:32`) already
  computes `headroom` per run, and nothing reads it (`grep -rn 'headroom()' main` → none). `ComputedTax` carries no
  deduction figures.
- **The payment date.** A `QualifyingPayment` is "the amount paid or deposited in the tax year"
  (`QualifyingPayment.java`), so its deadline is the year's last day (`TemporalContext.taxYearEnd`). That is a fact
  of the year, not a law constant.
- **An 80D hypothetical needs more.** A `HealthPayment` names whom it covers (assessee, family members by position)
  and its kind, and each 80D limb turns on who is covered and their age (`FamilySnapshot`).
- **The LTA block.** `SAL-LEAVE-TRAVEL-JOURNEYS` holds `journeys` 2, `calendarYears` 4 and `blocksCommence` 2022
  (TY 2026-27), so the current block is 2026 – 2029, ending 31-12-2029, **outside** TY 2026-27. Its `_note` quotes
  r.278(3) – (4): an unused block's concession carries into the next block's first calendar year.
  `LedgerSnapshot.leaveTravelByBlock` holds the journeys already claimed.

**Choices for the owner:**
- **C1: which deductions get an entry.**
  - **C1a (recommended):** Schedule XV (80C) now. The hypothetical payment is one `QualifyingPayment` of the
    headroom, under a contributor the rule data leaves without a sub-cap, so the price comes from the same
    aggregate. The 80D limbs and `DED-NPS-OWN` go to a placed **W-114c**: each needs a hypothetical payment of its
    own shape (who it covers, at what age; NPS's own-contribution base), read per row.
  - C1b: all six aggregate rows now.
- **C2: where the pricing lives.** A hypothetical payment must use a contributor code without a sub-cap, and only
  the rule data knows which.
  - **C2a (recommended):** in the engine. A new `TaxCalculator.priceDeductionRoom(EngineInputs)` returns, for each
    aggregate row the run evaluated with headroom above nil, `DeductionRoom(rule, headroom, taxSaved)`. `taxSaved`
    is the draft's bill less the bill with the headroom paid in that contributor (`D-MARGINAL`). The contributor is
    the first in the row's `contributors` that is a live `QUALIFYING_PAYMENT` component with no `subCaps` entry. No
    code is named in Java, so a pack change moves it.
  - C2b: in `taxplanning`, with a code chosen in Java. That is law in code (CLAUDE.md §4), so I don't recommend it.
- **C3: the entry.** `DraftCalendar.Kind.DEDUCTION_PAID_BY`, on the tax year's last day:
  - `rule` = `DED-SCHEDULE-XV`;
  - `amountToPay` = the headroom;
  - `paidByThen` = what the aggregate counted;
  - `costOfMissing` = `taxSaved`.
  - **C3a (recommended):** shown only where `taxSaved` is above nil. In the default regime, which allows no s.123
    deduction, it never appears. The cost is **tax**, not interest. This is different from W-114's entries, so the
    `DraftCalendar` Javadoc and the api-collection note say so.
  - C3b: shown always, with a nil cost.
- **C4: the LTA block end.**
  - **C4a (recommended):** no calendar entry. Missing it has no measurable cost: pricing it needs a fare the person
    has not paid, and r.278(3) – (4) carries an unused journey into the next block (the rule's `_note`). In
    TY 2026-27 the block ends after the year anyway. An erratum on the W-114a row and on `DR 20` F30's
    `SAL-LTA-BLOCK-001` line would record this.
  - C4b: an entry with the journeys left and a nil cost. That breaks F30.2 ("each entry carries the measured cost").
