### Decisions (for approval with this plan)

- **C1 — the split and order.** **C1a (recommended):** two run-log passes under this item, **W-337h1** (prod) and **W-337h2**
  (staging), each its own D-row and sign-off, as W-362b / c and W-366b / c were. Prod first, since D-827's reading assumed the
  owner's existing tenancy; staging waits for its sign-off. **C1b:** one pass, one D-row, both accounts interleaved.
- **C2 — the Bastion's CIDR block allowlist.** **C2a (recommended):** the owner's current public IP address, `/32`, on each
  Bastion (sources note: "at most 20" entries, so there is room to add more later). A session from any other address is
  refused. If the owner's IP changes (a home ISP's dynamic address), a new allowlist entry is added before the next session —
  flagged as a risk below, not solved here. **C2b:** a wider block (e.g. the owner's ISP's `/24`) for convenience, weaker.
- **C3 — the app MySQL user's privileges.** **C3a (recommended):** one user, `wealthlens_app`, with `ALL PRIVILEGES` on
  `wealthlens.*` only (no `GRANT OPTION`, no global privilege) — covers both runtime queries and a later Flyway migration
  from the same user, matching the work-item row's singular "an app user". **C3b:** a DML-only runtime user plus a separate
  migration user, decided later (adds a second password to track now for no caller yet).

Names used below (not a decision, OCI's own defaults, sources note: "recommended to accept the default values" for the VCN):
compartment = the tenancy's root compartment; VCN `wealthlens-<env>-vcn`; DB system `wealthlens-<env>-mysql`; Bastion
`wealthlens-<env>-bastion`, where `<env>` is `prod` or `staging`.

### Build — the same thirteen rows for each account (Part A: prod; Part B: staging)

**Row 0 — you: an Oracle Cloud account for this environment.** If you do not yet have one for this environment, sign up at
Oracle's Cloud Free Tier (a new account for staging, per D-929 (1): "for staging … I will create in other account"); otherwise
sign in to the OCI Console for it. This plan's sourced steps begin once you can reach the Console — paste nothing from the
sign-up itself.

**Row 1 — you: the VCN** (sources: creating-virtual-cloud-network.html). Networking → Virtual cloud networks → **Start VCN
wizard** → **Create VCN with Internet Connectivity**. VCN name `wealthlens-<env>-vcn`; Compartment = root; accept the default
VCN IPv4 CIDR and the default public and private subnet CIDRs (the page's own examples, e.g. `10.0.0.0/24`, `10.0.1.0/24`) —
**Create**.
- Expect: the VCN is created with a public subnet, a private subnet, an internet gateway, a NAT gateway and a service gateway.
- Paste: the VCN's name and the private subnet's CIDR block.
- Stop if the wizard reports an error. Way back: delete the VCN (its own cleanup removes the subnets and gateways with it); no
  data exists yet.

**Row 2 — you: the private subnet's ingress rule** (sources:
adding-ingress-rules-compute-instance-bastion-session-or-vpn-connection.html). Open the **private** subnet's security list →
**Add ingress rules**: Stateless **not** selected; Source Type **CIDR**; Source CIDR = the **public** subnet's CIDR block (from
row 1); IP Protocol **TCP**; Source port range blank; Destination Port Range **3306** — **Add ingress rules**.
- Expect: one new ingress rule listed on the private subnet's security list.
- Stop if the subnet has no default security list to add to (re-read the VCN wizard's output first).

**Row 3 — you: the Always Free DB system** (sources: creating-always-free-db-system.html). DB systems → **Create DB system** →
**Always Free**. Create in compartment = root; Name `wealthlens-<env>-mysql`; Description "WealthLens <env>"; **Username**
`admin`, **Password** / **Confirm password** = a password you generate and keep off this repo (the console's own generator or
your password manager); Configuration **Standalone**; Networking: this VCN, the **private** subnet; shape MySQL.Free /
HeatWave.Free (fixed); storage 50 GiB (fixed); backups left at their fixed default (enabled, 1-day retention, PITR disabled) —
**Create**.
- Expect: the DB system's state moves to **ACTIVE** (the console shows progress; this can take several minutes).
- Paste: the DB system's name and its state once ACTIVE, and its **private IP address** shown on its details page.
- Stop if it fails to reach ACTIVE, or if "Always Free" is greyed out (the tenancy may already hold one Always Free DB system
  elsewhere — tell me before creating a paid one).

**Row 4 — you: the Bastion** (sources: create-bastion.htm). Identity & Security → Bastion → **Create bastion**. Bastion name
`wealthlens-<env>-bastion`; Target VCN = this VCN; Target subnet = the **private** subnet (where the DB system sits); leave
FQDN / SOCKS5 unset; **CIDR block allowlist**: your current public IP address, `/32` (C2a — find it with `curl -s
https://ifconfig.me` in a terminal, or any "what is my IP" page you trust); Advanced → Maximum session time-to-live, leave the
default inside 30 – 180 minutes — **Create Bastion**.
- Expect: the Bastion reaches **ACTIVE**.
- Stop if creation refuses for a missing service gateway (sources: "the VCN needs a service gateway with a route rule" — the
  VCN wizard in row 1 already added one; re-read it if this happens).

**Row 5 — you: an SSH key for the session.** Reuse an existing one (`cat ~/.ssh/id_ed25519.pub`) or make a dedicated one:
```bash
ssh-keygen -t ed25519 -f ~/.ssh/wealthlens_bastion_<env> -N ''
cat ~/.ssh/wealthlens_bastion_<env>.pub
```
- Paste: the public key's one line (never the private key).

**Row 6 — you: the port-forwarding session** (sources: create-session-port-forwarding.htm). On the Bastion → **Create
session** → **SSH Port Forwarding Session**. Session name `wealthlens-<env>-mysql-tunnel`; Target **IP Address** = the DB
system's private IP (row 3); Target **Port** = `3306`; **Add SSH key** = row 5's public key; Session time-to-live, the
default — **Create session**.
- Expect: the session reaches **ACTIVE**.
- Stop if the target IP is refused (re-check it against row 3's details page).

**Row 7 — you: open the tunnel** (sources: connect-port-forwarding.htm). On the session → **Actions** → **Copy SSH command**,
then run it with `<privateKey>` replaced by row 5's private key path and `<localPort>` by `3306` (free on your machine —
check first: `lsof -nP -iTCP:3306 -sTCP:LISTEN || echo "3306 free"`). Leave it running in that terminal for rows 8 – 11.
- Paste: the command as copied (the key path and port substituted) and that it connected with no error.
- This session's TTL (row 6) bounds how long the tunnel stays open; if it expires mid-row, repeat rows 6 – 7 (a fresh session)
  and continue — nothing already written is lost.

**Row 8 — you: connect and read the version** (sources: mysql-server-versions.html, "the latest version" — not stated which
one for Always Free; this row reads it). In a second terminal, or your IntelliJ Database tool pointed at `127.0.0.1:3306`,
sign in as `admin` with row 3's password:
```bash
mysql -h 127.0.0.1 -P 3306 -u admin -p -e "SELECT VERSION(); SHOW DATABASES;"
```
- Paste: the exact version string and the database list.
- This is the number W-337a's C1 needs; nothing else in this plan depends on which version it is.

**Row 9 — you: the schema and the app user** (C3a). Same connection:
```sql
CREATE SCHEMA IF NOT EXISTS wealthlens;
CREATE USER 'wealthlens_app'@'%' IDENTIFIED BY '<a password you generate and keep off this repo>';
GRANT ALL PRIVILEGES ON wealthlens.* TO 'wealthlens_app'@'%';
FLUSH PRIVILEGES;
```
- Paste: `SHOW GRANTS FOR 'wealthlens_app'@'%';` and `SELECT COUNT(*) FROM information_schema.tables WHERE table_schema =
  'wealthlens';`
- Expect: the grant line shows exactly `ALL PRIVILEGES ON `wealthlens`.*` (no `GRANT OPTION`, no global privilege); the
  table count is **0** (nothing is created here — W-337b lays out Flyway).
- Stop if the count is not 0 (something already exists in this schema; tell me before continuing).

**Row 10 — you: credentials, off this repo.** Confirm, by name only (never paste the values): the admin password (row 3) and
the app password (row 9) are both saved in your password manager or a local file **outside** this git working tree, and
nothing from rows 3 / 9 was pasted into this chat or committed. Note the private key's path (row 5) the same way.
- Paste: "saved off-repo" once true.

**Row 11 — you: close the tunnel.** `Ctrl-C` the row 7 terminal; `lsof -nP -iTCP:3306 -sTCP:LISTEN || echo "3306 free"`.
- Paste: "3306 free".

**Row 12 — you: sign-off for this account.** "<env> signed off" once rows 0 – 11 are done and pasted.
