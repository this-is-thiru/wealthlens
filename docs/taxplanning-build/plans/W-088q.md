## Plan for W-088q — one carried-loss mechanism (split proposal)

**What this item is for (one sentence):** the house-property and capital-loss carry-forwards become one mechanism. The
rule data states what each loss may be set off against, for how long, and on what return condition, so a third
carried loss is new data and a ledger entry, not a third copy (review S2; D-250). The set-off context that D-260 moved
here comes with it.

**This plan proposes a split (§7: mis-sized). Approving it places W-088q1 – q3 and writes W-088q1's plan. Nothing is
built.**

### What I read (session 23, 2026-10-19)

- **The two copies.** `SetOffNode.broughtForward` / `useAttributable` / `use` (`node/SetOffNode.java:213–281`) and
  `CarriedCapitalLossSetOff.apply` / `use` (`node/CarriedCapitalLossSetOff.java:44–103`) run the same skeleton:
  1. the ledger's years of origin, oldest first (`TreeMap` by `startYear`);
  2. a year not before this one refused;
  3. a nil remainder skipped;
  4. a year outside the row's `TaxYearSpan` gets an expiry MEASURE line;
  5. the loss's portions used in turn against what may absorb them;
  6. what is left gets a "still carried" MEASURE line.

  They differ in:

  | | House property | Capital loss |
  |---|---|---|
  | Portions, in order | the part attributable to a new-regime disallowance (row `SETOFF-CARRIED-DISALLOWED-PART`, gated by the regime: where forbidden, deemed given full effect to), then the rest | the long-term loss, then the short-term |
  | Absorbed by | the `HOUSE_PROPERTY` head's income left | the capital-gains parts in `SETOFF-WITHIN-CAPITAL-GAINS`'s order, a long-term loss only by long-term parts (`part.isLongTerm()`) |
  | Return condition | none in code | `determinedInReturnFiledInTime` false → a MEASURE line, not carried (`:63–67`) |
  | Line texts | cite S2 s.110 / 1961 s.71B | cite S2 s.111 / 1961 s.74, s.80 |

- **What is law in Java today.**
  - Which head a carried loss may be set off against: `HOUSE_PROPERTY` (`SetOffNode:269`), and capital gains by
    construction.
  - Whether a return filed in time is a condition: capital loss only (`CarriedCapitalLossSetOff:63`).
  - The span is already data (`TaxYearSpan(8)` on both rows). It is a definition shared with three other rules
    (`DED-EDUCATION-LOAN`, `HP-PRE-CONSTRUCTION`, `HP-OWN-RESIDENCE-PRE-CONSTRUCTION`).
- **The return condition, both Acts:**
  - S2 s.121 does not name s.110. This is already recorded in `SETOFF-CARRIED-HOUSE-PROPERTY`'s `_note`
    (Gazette 265620 p.158).
  - **Newly read:** Income-tax Act, 1961 s.80 (thc copy p.327, from an earlier session's cached PDF): *"no loss which
    has not been determined in pursuance of a return filed in accordance with the provisions of sub-section (3) of
    section 139, shall be carried forward and set off under sub-section (1) of section 72 or sub-section (2) of
    section 73 or sub-section (2) of section 73A or sub-section (1) or sub-section (3) of section 74 or sub-section (3)
    of section 74A"*. **s.71B is not named.**
  - So the condition is "required" for the capital-loss row and "not required" for the house-property row, in both
    years. The engine computes exactly that today, but in Java.
- **The 7 set-off methods (D-260)** fall into three groups:
  - **Across heads:** `SetOffNode.setOff:131` (7), `absorb:166` (7), `absorbCapitalGains:189` (7) carry the same
    `ctx, order, lossHead, …, into, lines, row`.
  - **The carried losses:** `useAttributable:247` (6), `use:268` (7), `CarriedCapitalLossSetOff.use:84` (7) carry
    `row, arose, amount, absorbers, lines`.
  - **Within capital gains:** `CapitalGainsNode.setOff:91` (6) carries `loss, longTerm, order, available, lines, row`.
- **The capital-gains parts absorb a loss in order, in three places.** `SetOffNode.absorbCapitalGains`,
  `CarriedCapitalLossSetOff.use` and `CapitalGainsNode.setOff` each loop over the parts in the declared order:
  1. skip a part that has no gain left, or that a long-term loss may not reach;
  2. take the lesser of the loss left and the gain;
  3. write a SET_OFF line.
- **Two 5-parameter `line(...)` helpers** remain: `CarriedCapitalLossSetOff.line:105` and `CapitalGainsNode.line:134`.
  They have W-088p1's shape and are under their own nodes.
- **Sequencing with W-088o.** D-259 C1a says s.108(2)(b)'s long-term restriction (`isLongTerm`) becomes a fact each
  part declares "in W-088o, for W-088q to reuse". But W-088o is placed after W-088k, which is after this row.
- **Size:** about 450 changed lines over 6 Java files, 2 rule files, the locks, coverage and tests. That is over §7's
  300.

### Proposed split (C0)

| Row | What | Why separate |
|---|---|---|
| **W-088q1** | **The carry-forward as rule data.** A new definition `LossCarryForward(HeadCode absorbedBy, int succeedingYears, boolean requiresReturnFiledInTime)` on `SETOFF-CARRIED-HOUSE-PROPERTY` (`HOUSE_PROPERTY`, 8, false) and `SETOFF-CARRIED-CAPITAL-GAINS` (`CAPITAL_GAINS`, 8, true), both versions, in place of their `TaxYearSpan`. `TaxYearSpan` stays for the three deductions. The two nodes read the head and the return condition from the row, not from Java. 1961 s.80 is recorded as a source, the rows' `_note`s are extended, coverage's `manager` for these sections is updated, and the locks are relocked. Behaviour unchanged. | Rule vocabulary and pack only. Provable by identical traces, plus a test pack that flips the return condition and changes the outcome |
| **W-088q2** | **One carried-loss mechanism.** One package-private `CarriedLossSetOff` replaces `broughtForward` / `useAttributable` / `use` and `CarriedCapitalLossSetOff`. Each ledger kind becomes a list of **portions** (facts: an amount, the row that governs it, what may absorb it). The mechanism does the skeleton once, reading span, head and return condition from the row's `LossCarryForward`. The capital-gains parts' in-order absorption becomes one shared type, used by this mechanism and by `SetOffNode.absorbCapitalGains`. The carried-loss methods' parameter lists go with the copies. `CarriedCapitalLossSetOff.line` goes too. | The mechanism itself, provable by identical traces |
| **W-088q3** | **The set-off context.** A private type holding what `setOff` / `absorb` / `absorbCapitalGains` carry together (`ctx, order, into, lines`). `CapitalGainsNode.setOff` uses q2's shared parts absorption. `CapitalGainsNode.line` gives way to `ctx.traceLine`. | Typing only, once q2 has settled the shapes |

### Choices (recommended first)

- **C0 — split:**
  - **(a) recommended:** q1, q2 and q3 as above, in that order, in W-088q's place.
  - **(b)** one item of about 450 lines.
- **C1 — the line texts that cite each loss's sections** (expiry, still carried, not determined in time):
  - **(a) recommended:** each ledger kind's portions come with their texts. They are built where the ledger entry is
    turned into portions, so every trace stays word for word.
  - **(b)** derive the citations from the governing version's `provision1961` / `provision2025` references. This
    changes trace text: "S2 s.110(2); 1961 s.71B" would become what the row cites ("s.110" / "s.71B"), and test
    expectations would be edited.
- **C2 — the long-term restriction (W-088o's sequencing):**
  - **(a) recommended:** q2's portion states which parts may absorb it through today's `CapitalGainsPart.isLongTerm`.
    W-088o later replaces that with the parts' declared fact, and D-259's "for W-088q to reuse" is corrected to "for
    W-088q's mechanism to take over". The board stays as it is.
  - **(b)** move W-088o (and W-088f2 / W-088k, which it follows) before W-088q2.
- **C3 — `LossCarryForward`'s head:**
  - **(a) recommended:** one `HeadCode`. Each Act's carry-forward sections name exactly one head (s.110(1)(a) "only
    against the income from house property"; s.111(1)(a) "only against the income under the head 'Capital gains'").
  - **(b)** a set of heads, for which no current row has a caller (§2, no speculative generality).

### How W-088q1 would be verified (detail in its own plan)

- Every node, golden and set-off test unchanged.
- **A new test:** a test pack with the capital-loss row's `requiresReturnFiledInTime` set to `false` carries a loss
  the ledger says was not determined in time. Today's Java check would refuse it, so the test fails without q1.
- **A second new test:** a house-property row stating `true` is refused as a pack defect. The house-property ledger
  states no return fact for it to test (S2 s.121 and 1961 s.80 do not reach s.110 / s.71B), so this fails fast
  rather than being silently ignored.
- A bite probe on each row's flag.
- The locks are relocked. Both tiers.
