## Plan for W-316 — a rights issue or buyback blocks trades but can never be performed

**What this item is for (one sentence, in my own words):** a rights issue or buyback must stop holding a user's trades
in `TEMPORARY` and stop halting the quarter's run, because the app records such actions but cannot apply them (W-264c
G-5, D-631). Owner's direction: **(a)**, information only (2026-11-13).

**Findings (read this session):**
- `FILTERABLE_CORPORATE_ACTIONS` (`CorporateActionType:16 – 20`) lists `BONUS`, `STOCK_SPLIT`, `RIGHTS_ISSUANCE`,
  `BUYBACK` and `DEMERGER`.
- It has exactly two readers:
  - The trade hold, `TemporaryTransactionService:87, 95`.
  - The quarter's run, `CorporateActionService:172`. Its switch applies only bonus, split and demerger, and throws
    for the rest.
- `CLAUDE.md:157` already names only the three that are applied, so it needs no change.

**The change:** the list becomes `BONUS, STOCK_SPLIT, DEMERGER`, with a comment saying why. A rights issue or buyback
can still be added and read (`/corporate-action/all`), but it holds no trade and the run skips it.

**Probe run (applied, then stashed as "W-316 probe"; the tree is unchanged):** 10 classes reaching the list:
corporate (both), `TemporaryTransaction*`, `Portfolio*`, `PortfolioGapAudit`, `AssetsRebuild`, `LotLedgerTest` and
`ArchitectureTest`. **258 tests, 0 failures: no existing test moves.**

**Red test:** report §4 scenario 11, reworded for (a): a buy of 5 SBIN after the rights issue's record date is recorded
at once (15), and the run answers 200 and applies the quarter's WIPRO bonus (20). Today the buy is held and the run
answers 400 "Invalid action typeRIGHTS_ISSUANCE". **Probe:** put `RIGHTS_ISSUANCE` back in the list, and the test
fails.

**Stored data:** trades already held by a rights issue or buyback sit `TEMPORARY`. After the change, nothing holds
them, so a redrive records them.
- **Runbook §3.24:** a read-only list, per database, of the users and stocks with `TEMPORARY` trades on a stock that
  has a rights issue or buyback.
- **Then:** for each user listed, `POST /temporary-transactions/user/{email}/redrive` with a `SUPER_USER` token (an
  admin may act on any user's path, `UserValidator:15 – 32`).
- **Safe to repeat:** redrive is the normal, idempotent route. A trade still held by a real bonus, split or demerger
  stays held. The query is tried on a throwaway Mongo first.

**Numbers:** the scenario's own (10 + 5 SBIN; 10 + 10 WIPRO).

**What I am NOT doing:** modelling rights entitlements or buyback tenders (choice (b)); no row is placed unless you
ask. Dividends and name changes are untouched.

**How I will verify:** red first (the list restored, the test run), then the fix, the 10 classes, the probe restored
byte-identical, the §3.24 query on a throwaway `mongo:8.0.4`, `validate`. WL-A-2 is republished. The tiers run on
the pipeline.

**Post-deployment actions (R15):** §3.24, then redrive per listed user.

**Five roles:**
- **Architect:** the list that holds trades is now the list the run can apply, so the two cannot drift. The other
  types pass through as facts.
- **Product manager:** a user who trades a stock with a rights issue or buyback is no longer blocked. Held trades
  come back with one redrive.
- **Senior engineer:** a one-line data change with its reason; no new code path.
- **Automation tester:** one red scenario, one probe, 258 tests re-run.
- **Manual tester:** add a rights issue for a stock, buy it after the record date, and see it in `stocks/all` at once.
