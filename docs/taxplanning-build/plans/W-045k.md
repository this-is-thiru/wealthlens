**What this item is for (one sentence):** a plain-language entry per section, kept in `content/`, whose

come only from placeholders, so the explanation cannot drift from the computation.

### Findings that change the item as written

1. **Only one of the three entries can link to anything real.** The timeline holds one rule
   (`RATE-SLAB-NEW-TAX-REGIME`) and two regimes. None of the rules behind 80C or HRA exists yet. They
   arrive with `W-076` (`ChapterEightNode`) and `W-067` (`ExemptionNode` — HRA). If SC-3 only checks
   the *shape* of a reference, the text would link to rule ids that don't exist, and the brief's point
   ("the explanation and the computation are the same fact") would be lost. **Proposal (B2):** a
   reference must resolve in the timeline. Until a rule exists, the route or disqualifier is
   `NOT_MODELLED` with a reason that names the backlog item. That makes 80C and HRA almost entirely
   `NOT_MODELLED` today, which is accurate.
2. **HRA is not a section in the 2025 Act.** `SAL-HRA-001` puts it at **Sch. III Table Sl. 11** (1961:
   s.10(13A)). s.10 of the 1961 Act holds dozens of exemptions, not only HRA. So an entry's
   `provisions` must be the existing `Provision` type (instrument + reference + presence), not
   `SectionRef`. The link to the coverage register is then "which register sections this entry's
   provisions cite", via the existing `SectionRef.citedBy`.
3. **The worked 80C entry's routes cannot be completed from sources I have.** Brief §6.3 says the
   routes are "each sourced from the Act's own list (Schedule XV)". The rulebook quotes Schedule XV
   only in part: `DED-80C-ITEMS-001` says "includes, **among others**", and gives paragraph letters
   for only 1(a), 1(f), 1(g), 1(q), 1(x), 1(y) and para 3. The Act's text isn't in the repo.
   **Proposal (B5):** author the routes the rulebook quotes, and mark the entry `routesComplete:
   false` with `whatToCheck: "Schedule XV para 1, every clause"`. No route gets invented.
4. **The brief's own example breaks SC-2.** `plainName "… (the ₹1.5 lakh bucket)"` types a rupee
   figure. I'll follow SC-2, not the example.
5. **Where SC-1 stands today.** The register lists two sections (2025 s.202 and 1961 s.115BAC, both
   `MODELLED`), and the default-regime entry cites both. So SC-1 would pass in full now. It breaks
   once `W-045o` adds hundreds of `PLANNED` sections. **Proposal (B3):** run SC-1 **in full for
   `MODELLED`**, since D-043 already makes every item that models a section write its entry. Run it
   **as a ratchet for `PLANNED`**, as the row says.

### B. Choices (all recommended)

- **B1 — the entry's fields.** Record the fields the checks need and the three entries use: `key`
  (a concept, `SEC-…`), `provisions` (1961 and 2025 `Provision`s), `plainName`, `summary`,
  `routes[]`, `disqualifiers[]`. **Deferred, each to the item that brings its type:**
  - `process`, to **`W-117`**, because it reuses `DR 22` `ClaimStep`, which doesn't exist yet;
  - `evidence`, `interactions`, `commonMistakes` and `whoCanUse`, to W-045k2 or F41;
  - `statuses`.

  No field without a reader or a check.
- **B2 — references resolve.** A `RuleId` must be in the timeline. A `Condition` is named by one of
  `Condition`'s permitted record names (e.g. `PaidOtherThanInCash`). `NOT_MODELLED` requires a
  non-blank reason. Placeholders `{{RuleId.field}}`: the RuleId must be in the timeline. The *field* is
  checked by the renderer (F41), because no renderer exists yet to define what a field is.
- **B3 — SC-1.** Every `MODELLED` register section is cited by some entry (full). For `PLANNED`, the
  set of catalogued sections recorded in `SectionCatalogueTest` may only grow.
- **B4 — SC-2 / SC-4 as checks.** SC-2 is a pattern scan of every text field, with the placeholders
  stripped first. It refuses `₹`, `Rs`, `%`, `lakh`/`crore`, any digit run, and dates. Section
  numbers belong in `provisions`, never in text (brief: "no section numbers"). SC-4 is enforced by
  the reader: an entry carrying `availability` or `history` is refused ("derived, never authored").
  SC-5 (layer isolation, T23-1) is not this item's.
- **B5 — the 80C routes** (applies to W-045k2 if you split): only routes the rulebook quotes, plus
  `routesComplete: false` and a `whatToCheck`.
- **B6 — timeline.** `TimelineReader` learns `content/sections/*.json`, one file per entry, named for
  its key and carried verbatim, like `coverage.json`. Year packs aren't compiled from it, so **no
  lock changes**. `SectionCatalogue.of(Timeline)` parses, and `verify(Timeline, CoverageRegister)`
  checks. Both live in `taxengine/rules/catalogue/` (the row's `taxrules/`, which is where W-045j put
  `coverage/`).
