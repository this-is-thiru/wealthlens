## Plan for W-088j2c2 — the engine decides STT chargeability

**What this item is for (one sentence):** for a side whose STT evidence is `UNKNOWN`, the engine asks rule set
`RS-STT-CHARGEABLE` (Chapter VII s.98 Sl. 1–3, recognised exchanges `NSE` / `BSE`) whether the transaction was
chargeable. `RS-CG-PART` then accepts `CHARGEABLE` where s.196, s.198 (the Q1 ruling) and S.O. 5054(E) allow. A side
whose venue is on record stops being refused.

**Design approved in D-296. This plan raises C1 and C2, which narrow D-296's C1(a) and C3(a)** so that no rule data
ships that cannot fire.

### The build

**1. Input:**
- `CapitalGainsInput.BucketFacts` gains `SideVenue acquisitionVenue` and `SideVenue transferVenue`, making 8
  components.
- New nested record `CapitalGainsInput.SideVenue(Optional<String> exchange, Optional<String> segment)`, with
  `SideVenue.UNRECORDED`.
- `CapitalGainsAdapter` maps `TradeVenue` into it (the segment as `name()`).

**2. Definition:**
- `rules/definition/SttChargeability(String code)`, with the code not blank, added to `RuleDefinition`'s permits.
- `DefinitionJson` reads `{"type": "SttChargeability", "code": "CHARGEABLE"}`.

**3. Rule set `RS-STT-CHARGEABLE`:**
- `AT_MOST_ONE`, ground `REGIME_AND_CONDITIONS`.
- Its `_note`: Chapter VII; "a side no row covers keeps its evidence"; s.113A not shipped (C2).
- Three rows, two versions each (TY 2025-26 and TY 2026-27; Chapter VII's Sl. 1–3 are unamended since 2013, sources
  rows 2–7):

  | Row | Conditions (an `AllOf`, certain limbs first) | Code | Law |
  |---|---|---|---|
  | `STT-PURCHASE-DELIVERY` | `stt.side` `ACQUISITION`, `capitalgains.asset` `EQUITY`, `trade.exchange` `NSE` or `BSE`, `trade.segment` `DELIVERY` | `CHARGEABLE` | s.98 Sl. 1 (Purchaser) |
  | `STT-SALE-DELIVERY` | `stt.side` `TRANSFER`, … `DELIVERY` | `CHARGEABLE` | s.98 Sl. 2 (Seller) |
  | `STT-SALE-NONDELIVERY` | `stt.side` `TRANSFER`, … `INTRADAY` | `CHARGEABLE` | s.98 Sl. 3 (Seller) |

- **Provenance:** the D-294 / D-297 record.
  - `introducedBy`: *"Finance (No. 2) Act, 2004 (23 of 2004), Chapter VII, s.98 Table Sl. 1/2/3, as amended by the
    Finance Act, 2013 s.135"*. Its `gazetteRef` says what the copies are: the Act's text REPORTED and accepted
    (D-294 rows 1a, 1b), and FA 2013 an itatonline print (row 1d).
  - `SOURCE_CHECKED`, as D-294's ruling accepted.
  - The exchange list cites SEBI's list (D-297 row 2).
  - **I flag this provenance shape for review** (Risk 1).

**4. The step:** a new package-private class `node/CapitalGainsStt`.
- `codes(ctx, bucket, lines)` returns the two STT codes for the part rows.
- **Evidence other than `UNKNOWN`** passes as is (D-296 C2a).
- **`UNKNOWN`:**
  - It builds that side's `ItemFacts`: `stt.side`, `capitalgains.asset`, `trade.exchange`, `trade.segment`, with an
    absent value given as the code `UNRECORDED`, so no lookup throws.
  - It asks `optionalRuleOf(RS_STT_CHARGEABLE, …)`.
  - A row → its code, and a `MEASURE` trace line (in = out = the bucket's gain) citing that row. The line reads
    *"STT on the sale: CHARGEABLE (NSE, DELIVERY)"*; for a long-term bucket it adds *"; counted as paid for S2 s.198 /
    1961 s.112A by the owner's ruling D-294"*.
  - No row → `UNKNOWN` stays.
- `CapitalGainsNode`:
  - declares the set;
  - calls the step in its bucket loop, creating the trace list before it;
  - `factsOf` takes the two codes.

  Both methods stay ≤ 60 lines.

**5. `RS-CG-PART`** (C1(a)):
- `-SHORT-LISTED`: transfer `PAID` or `CHARGEABLE` (s.196(1)(b), *"chargeable"*).
- `-LONG-LISTED`: acquisition and transfer each `PAID` or `CHARGEABLE`. The `_note` cites D-294's Q1 ruling.
- `-LONG-NOTIFIED`: transfer `PAID` or `CHARGEABLE`; acquisition `Not(AnyOf(PAID, CHARGEABLE))` (S.O. 5054(E)(II),
  *"not chargeable"*), which stays disjoint from `-LONG-LISTED`.
- `-SHORT-SLAB` and `-LONG-OTHER`: unchanged.

Both years; one relock.
