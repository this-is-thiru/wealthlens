## Plan for W-311 — remove the test routes: the sale replay, `/request`, `/request2`

**What this item is for (one sentence, in my own words):** stop serving three routes written for testing. One of
them, `POST /test/user/{email}/transact/sell`, writes a whole sale outside the trade flow. The other two,
`/portfolio/user/{email}/request` and `/request2`, are marked "for testing purpose only" (W-309 / D-626, W-264d G-6 /
D-641).

**Findings (read this session, 2026-11-13):**

1. **The replay.** `TestController` (`helper/controller/TestController.java:17 – 33`, `SUPER_USER` at `:23`) hands the
   caller's `transactionId` and lots to `PortfolioService.allocateSaleV2` (`:31`). It writes gains, trade outcomes
   and the charge summary, but never saves the lots it changes (trade-ledger B-9, `docs/trade-ledger/backlog.md:88`,
   now W-268's row). Its only body type is `ProfitLossDto` (`helper/dto/helper/ProfitLossDto.java:7`, the only file
   in `helper/dto`). **Callers:** `HelperSellIntegrationTest` (`:69`, `:87`, two tests) and the api-collection request
   `Test Req/Transact - New.yml:8`. Nothing in `src/main` calls it. `allocateSaleV2` keeps its own caller
   (`PortfolioService:485`) and the unit tests `PortfolioServiceTest:582`, `:609`.
2. **`/request`** (`PortfolioController:104 – 112`) sets a missing date to today and echoes the body back. It has no
   test and no collection request. `LocalDate` is used only there (`:15`, `:110`).
3. **`/request2` is the only JSON route that filters assets.** (`PortfolioController:115 – 118` →
   `PortfolioQueryService.searchAssets` `:161 – 163`.) **Callers:** api-collection `Complex Filters/Filter.yml:8`
   and `Complex Filters/Assets more than 1 year.yml:8`; `PortfolioGapAuditIntegrationTest:320 – 327`, which pins the
   field allow-list's 400 (W-264a scenario 32). Transactions have the same capability under a real path,
   `POST /transactions/user/{email}` (`TransactionController:17`, `:22 – 25`). So this route is a feature with a test
   name, not a test. Removing it loses asset filtering over JSON; the Excel export (`EntityExportService:54`) still
   filters.
4. **`/test/**` in `AuthConfig:43`** guards only this controller (`grep '"/test' src/main` finds nothing else).
5. **Three collection requests in `Test Req/` point at routes that do not exist:** `Req.yml:8` (`/request1`),
   `Req3.yml:8` (`/request3/hello1`) and `Req - Msg.yml:8` (`/request/test`).
6. **Unknown paths answer 404.** `ControllerAdviser:109 – 113` maps `NoResourceFoundException` to 404, so a removed
   route answers 404, not 500.
7. **Probe (run 2026-11-13):** I removed `TestController.java`, `ProfitLossDto.java` and
   `HelperSellIntegrationTest.java`, then ran `./mvnw -o test-compile -pl backend`: no errors. The three files were
   restored and `git status` was clean for them. No other main or test source depends on them.

**Choices for the owner:**
- **C1: the replay.**
  - **C1a (recommended):** remove it. That means `TestController`, `ProfitLossDto` (and the then-empty
    `helper/dto` package), `HelperSellIntegrationTest`, the collection request `Transact - New.yml`, and `"/test/**"`
    in `AuthConfig:43`. Close B-9's text with a pointer to this item. `allocateSaleV2` stays public, because
    `PortfolioServiceTest` calls it from another package.
  - C1b: confine it to a non-production profile with `@Profile`. B-9 still holds there: it still writes a sale and
    never saves the lots.
- **C2: `/request`.**
  - **C2a (recommended):** remove it, with the comment at `:104` and the `LocalDate` import.
  - C2b: keep it.
- **C3: `/request2`.**
  - **C3a (recommended):** keep the capability under a real path,
    `POST /portfolio/user/{email}/assets/search`, named after `searchAssets`. Behaviour and allow-list stay as
    they are; the old path answers 404. The two collection requests and `PortfolioGapAuditIntegrationTest:322` move
    to the new path. This is a breaking path change for any client of `/request2`; the only known ones are the
    two collection requests.
  - C3b: remove it with `searchAssets`. JSON asset filtering is gone; the collection's `Complex Filters` asset
    requests are deleted and the allow-list test moves to `/transactions/user/{email}`.
  - C3c: keep `/request2` as it is (the row's "go the same way" not taken for it).
- **C4: the dead `Test Req/` requests.**
  - **C4a (recommended):** delete `Req.yml`, `Req3.yml` and `Req - Msg.yml` in the same api-collection commit. They
    call routes that do not exist (finding 5). `Template Fields.yml` stays, since `/helper/template/fields` is real
    (`HelperController:33`).
  - C4b: leave them; a separate row.
