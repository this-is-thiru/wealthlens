### What counts as a finding (the audit's criteria, from CLAUDE.md §4)

| Kind | Finding | Not a finding |
|---|---|---|
| **L1 value** | a legal date, amount, rate, period, threshold or age as a Java literal or constant | arithmetic (`Rate.HUNDRED`), units, formatting, test code |
| **L2 list** | a qualifying list deciding legal treatment as an enum set, `switch`, map or `if` chain | a list of the code's own states (e.g. a status machine) |
| **L3 path** | a computation path chosen in Java by a legal category (D-253's kind) | dispatch by a shape type that only evaluates data |
| **L4 field** | a model or read-model field derived from today's law (a flag, label or class computed from a threshold) | a fact (a date, an amount, a mode, an event) |
| **L5 collapse** | an open category folded into a catch-all | — |
| **S (noted)** | a carried non-law note (N5, N7, N8) | — |

Each finding is recorded with `path:line`, the law it encodes (section cited only where a rule row or `sources/`
already names it — R2; otherwise "law not identified"), its kind, and a proposed direction. A category the Rules leave
undefined and the taxpayer states (review E8, `CommutingCity`) is recorded as accepted, as D-102 did.

**Method, so the audit can itself be checked:** for each module, (1) the pattern greps above plus `if`/`switch` on
enums and `static final` collections, run and kept; (2) every hit read in context and given a verdict (finding, or
not a finding with the reason); (3) every class under `node/`, `adapter/` or `service/` that names a legal category
read whole, since a path choice (L3) need not match a pattern. The audit file lists the greps, the hit count and the
verdicts, so "nothing found" is a checked claim. Limit, stated in the file: a grep-led read, not every line of 747
files.
