### Findings

1. **A rounding row can't load today.** It carries no cap, no relief and no condition, so
   `RuleJson` refuses it as meaningless. Something in the row has to state the rounding (A1).
2. **`RATE-ROUND-003` isn't law.** It's the rulebook's design recommendation, so it has no pack row. Its
   substance, rounding in exactly two places, is a test.
3. **The one-rule-or-two question.** s.516 covers both amounts in one sentence; the 1961 Act splits them
   into s.288A and s.288B. A `Provision` holds one reference, and each node rounds one of the two amounts.
4. **`interest.and.fees` doesn't exist yet.** It's in no `NodeIds` and belongs to `W-112`. A node
   can't require it now.
5. **The "full pipeline, exactly two `ROUNDING` lines" check can't run here.** Nothing produces
   `totalincome`, `tax.cess` or `tax.netpayable` until `W-051`/`W-052`, so no pipeline reaches
   `round.netpayable`.
6. **`RATE-ROUND-001` (TY 2025-26) can now be sourced.** STATE lists it as `UNVERIFIED` (D-065 Q3, the
   India Code copy was unreachable). The thc.nic.in copy and the amendment chain meet D-065's bar (a
   quoted primary source with URL and page), with the chain's stated residual.
7. **`W-049` missed standing rules 1 and 2 (D-043). This is my defect, in a committed item.**
   - `coverage.json` still has 2025 s.156 and 1961 s.87A as `PLANNED` with `backlogItem: W-049`, not
     `MODELLED` with the three `REBATE-*` rules.
   - There is no section catalogue entry for the rebate.
   - `W-049`'s plan had no standing-rules line (W-046b's had one), and nothing in the build caught it.
     No test checks that a `PLANNED` entry's item is still open.
8. **This item owes the same for rounding.** 2025 s.516 and 1961 ss.288A and 288B are `PLANNED` with
   `backlogItem: W-050`; each flips to `MODELLED` here. s.516 also needs a catalogue entry
   (`content/sections/`: user-facing text under SC-1 to SC-4). Neither changes the lock:
   `RulePackCompiler` compiles only `content/explanations.json` from `content/`. *(Corrected at step 1:
   the approved plan said "content lock goes to `content.3`".)*

### A. Choices (recommended first)

- **A1 — how a rounding row states its rounding (finding 1).**
  - **(a) recommended:** a `rounding` block, `{ "toNearest": "10" }`, read into
    `rules/rounding/RuleRounding(Money toNearest)`.
    - `RuleVersion` gains `Optional<RuleRounding> rounding` after `relief`; it may not sit beside a
      cap or a relief (constructor refusal, as D-075).
    - A rule must carry a cap, a relief, a rounding or conditions.
    - The node applies `roundToNearestTenPerSection516` and **refuses any other `toNearest`**: the
      Acts state one method, and only that one is implemented.
    - This touches the 13 `new RuleVersion(` sites again (mechanical, `Optional.empty()`).
  - **(b)** Allow a row with nothing in it but provenance, i.e. relax the refusal for rules a node
    names. That's cheaper, but it reopens the "loads, evaluates, means nothing" hole D-075 closed,
    and the ₹10 lives only in code.
- **A2 — the rows (findings 2–3).** Two rows, one per node, each citing its own 1961 section and both
  citing s.516:

  | New ID | Rounds | 1961 | 2025 |
  |---|---|---|---|
  | `RATE-ROUND-TOTAL-INCOME` | total income | s.288A | s.516 |
  | `RATE-ROUND-PAYABLE` | the amount payable or refundable | s.288B | s.516 |

  These are concept names in the `W-045d2` manner; neither numbered ID is kept. There is **no row
  for `RATE-ROUND-003`**. Both rows are `AllRegimes`, with no conditions, and `SOURCE_CHECKED`.
- **A3 — years.** Author **TY 2026-27** versions now, and the 2025-26 versions with `W-052c`, as for
  every other row (D-072 C4). Finding 6 is recorded, not authored:
  - STATE's unverified entry for `RATE-ROUND-001` → SOURCE_CHECKED (URL, p.822, chain, residual);
  - a rulebook erratum on `RATE-ROUND-001` (not opened → quoted).
- **A4 — what the nodes read (findings 4–5).**
  - `RoundTotalIncomeNode` requires `totalincome`.
  - `RoundNetPayableNode` requires **`tax.netpayable` only**, with an erratum on T6 and `W-112`: it
    adds `interest.and.fees` to this node's requires when it builds that node.
  - The pipeline-level "exactly two `ROUNDING` lines" check moves to **`W-053`**, the first run
    through the pipeline, as an erratum on its Verify. Here, each node is tested to emit exactly one.
- **A5 — refunds.** A negative `tax.netpayable` (a refund) is rounded on its magnitude with the sign
  restored, which is `Money`'s existing reading of `ROUND-NEG-001`, recorded as STATUS UNCLEAR. The
