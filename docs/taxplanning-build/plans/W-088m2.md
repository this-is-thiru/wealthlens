**What this item is for (one sentence):** the seven places where a node maps an item's category to a rule set in Java
become one set each, whose rows say in their conditions which item they are for. Then a new car column, provider,
retirement entry, asset kind, special rate or employer kind is a row, not a code edit (D-251; review E1).

### Design

1. **Item facts:**
   - `rules/id/ItemFactId`: lower-case dotted, like `NodeId`.
   - `rules/condition/ItemFacts`: an immutable `Map<ItemFactId, String>` of codes the node supplies for the one item it
     is computing, with `ItemFacts.NONE`.
   - `ConditionContext` gains `ItemFacts item`. The existing convenience constructors pass `NONE`.
   - `code(id)` **throws** on a fact the item does not carry, by the class's existing rule: answering false would
     silently choose another row.
2. **One predicate, `ItemFactIs(ItemFactId fact, String code)`** (the 14th permit, a new class). JSON:
   `{"type": "ItemFactIs", "fact": "vehicle.engine", "code": "UP_TO_1600_CC"}`. Two values are `AnyOf`, as for
   `RET-GRATUITY-GOVERNMENT` (Government or defence retiring gratuity).
3. **Selection with an item:**
   - `NodeContext.ruleOf(set, ItemFacts)` and `optionalRuleOf(set, ItemFacts)`. The item goes into the
     `ConditionContext` the selection tests.
   - A set chosen on conditions tests **every** row, even when it holds one. The "one row, no test" shortcut stays for
     `REGIME` sets only.
   - Otherwise one item-keyed row would apply to any item in a year that holds only that row.
4. **The seven sites become seven sets.** Each takes `REGIME_AND_CONDITIONS` and holds the old rows, each with its
   `ItemFactIs`:

   | New set | Selection | Rows | Item fact |
   |---|---|---|---|
   | `RS-PERQ-CAR-PARTLY` | `AT_MOST_ONE` | `PERQ-CAR-PARTLY-SMALL`, `-LARGE`, `-ELECTRIC` | `vehicle.engine` |
   | `RS-PERQ-CAR-OWNRUN` | `AT_MOST_ONE` | `PERQ-CAR-OWNRUN-SMALL`, `-LARGE`, `-ELECTRIC` | `vehicle.engine` |
   | `RS-PERQ-ACCOM` | `EXACTLY_ONE` | `PERQ-ACCOM-GOVERNMENT`, `-OWNED`, `-LEASED`, `-HOTEL` | `accommodation.provider` |
   | `RS-RET-ENTRY` | `EXACTLY_ONE` | the 11 `RET-*` entry rows | `retirement.entry` |
   | `RS-RET-AGGREGATE` | `AT_MOST_ONE` | `RET-GRATUITY-AGGREGATE`, `RET-LEAVE-ENCASHMENT-AGGREGATE` | `retirement.entry` |
   | `RS-PERQ-ASSET-TRANSFER` | `EXACTLY_ONE` | `PERQ-ASSET-TRANSFER-ELECTRONIC`, `-CAR`, `-OTHER` | `asset.kind` |
   | `RS-RATE-CG-SPECIAL` | `AT_MOST_ONE` | `RATE-CG-SHORT-LISTED-EQUITY`, `-LONG-OTHER`, `-LONG-LISTED-EQUITY` | `capitalgains.part` |
   | `RS-DED-NPS-EMPLOYER` (kept; absorbs `-GOVT`) | `EXACTLY_ONE` | `DED-NPS-EMPLOYER-GOVT` (`employer.kind` is `GOVERNMENT`), `-OTHER` and `-NEW-TAX-REGIME` (`Not` that, plus their regimes) | `employer.kind` |

   - The codes are the input enums' constant names, the facts the inputs already publish.
   - The car and capital-gains sets are `AT_MOST_ONE`:
     - a year without an electric column keeps today's refusal (`MotorCarPerquisite:162`);
     - a part with no special-rate row (`SHORT_TERM_SLAB`) is at slab rates.
   - `RuleSelection.AT_MOST_ONE`'s Javadoc widens from "a row the year may not hold" to "or an item no row is for".
5. **Java removed:**
   - the seven maps;
   - `NotifiedRetirementLimits.isNotified`'s key test, which becomes "the aggregate set has a row for this entry";
   - `TaxByBasisNode`'s special parts, which become "the parts the set has a row for", in `CapitalGainsPart` order, the
     same order the `EnumMap` gives today.

   Knock-on changes:
   - `atSpecialRates` takes the `NodeContext`, so `SurchargeNode` declares `RS-RATE-CG-SPECIAL`;
   - `ChapterEightNode`'s `SPECIAL_RATE_ROWS` becomes that one set;
   - `RetirementNode`'s "every retirement component entered" reads `pack.membersOf(RS-RET-ENTRY)`.
6. **Pack:**
   - `rule-sets.json`: 166 sets → 143 (31 removed, 8 declared, `RS-DED-NPS-EMPLOYER` kept).
   - 31 rows gain `ruleSet` and `conditions`, scripted with a count assert ([[state-board-edits-exact-match]]).
   - Generated `RuleSetIds` regenerated. Both locks relocked once ([[rulepack-lock-recompute]]).
