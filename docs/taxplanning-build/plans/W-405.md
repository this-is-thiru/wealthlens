## Plan for W-405 — Hibernate validates the schema at start

> Planned in session 122 (2026-11-25), placed by D-962. **Stop point:** the owner answers C1. The probe below is left in the
> working tree, uncommitted.

**What this item is for (one sentence, in my own words):** the app refuses to start when any entity and its table disagree, so a
wrong column or type is found by every test run instead of by one query in front of a user.

### Probe (`probe-before-plan.md`)

- Added `"hibernate.hbm2ddl.auto", "validate"` to `PostgresJpaConfig.postgresEntityManagerFactory`'s properties (no `ddl-auto` /
  `hbm2ddl` was set anywhere: `backend/src/main/resources`, `src/test/resources`, `PostgresJpaConfig` searched).
- `FlywaySchemaBaselineIntegrationTest` (the app started on Flyway's V1 – V10): **2/2 green** — every entity's tables, columns
  and column types agree with the DDL today.
- Proven able to fail: `JobLease`'s `@Column(name = "holder")` renamed to `holder_x` → the start refused with
  `missing column [holder_x] in table [tax_job_leases]`; reverted.
- **What it does not check:** nullability, defaults, unique indexes, foreign keys — Hibernate's `validate` compares tables, columns
  and types only. Those are W-407a – e's audit.

### Decision

- **C1a (recommended):** keep it — the property as probed, plus one assertion in `FlywaySchemaBaselineIntegrationTest` that the
  started factory carries `hibernate.hbm2ddl.auto=validate`, so removing it fails a test. Every integration class starts the app,
  so every run validates. **C1b:** a separate schema-comparison test instead — duplicates what Hibernate already does.

**Files:** `shared/config/PostgresJpaConfig.java`; `integration/FlywaySchemaBaselineIntegrationTest.java`. **Numbers:** none.
**Not doing:** nullability, indexes, constraints (W-407). **Verify:** the new assertion red without the property, green with it;
the planted rename shown failing (done); `./mvnw validate`; pipeline. **Post-deployment (R15):** none — a deployed app whose
database lacks a column now refuses to start (Flyway runs first, so a database it migrated always passes).

**Five roles:** architect — one source of truth checked at start; PM — no visible change; senior engineer — a mismatch can no
longer hide behind untested queries; automation tester — proven by a planted rename; manual tester — none.
