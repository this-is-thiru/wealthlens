**Findings that shape the build:**
1. Every nested type still carries its MongoDB `@Field` names (`ChargeRule` `display_name`, `ChargeSlab` `from_value`, `WorkbookImport`
   `rows_applied`, `DraftStaleness` `computed_under` …), which Jackson ignores — so the stored key is the field's `@Field` name and
   the JSON property is its Java name. The walk maps one to the other by reading the annotation, never by guessing a rename.
2. The converters all use a default Jackson 3 `JsonMapper` (`ChargeRuleListConverter`, `JsonColumnConverter`); none encrypts.
3. Times: `DraftStaleness.since` = `context.nowUtc()` (`StalenessSweep.java:90` at `m1.6.1`) — UTC-held. Top-level times are UTC-held
   too, so g1's rule holds: `acted_on_at` / `archived_at` from `FilingDraft`'s `atUtc` (`FilingDraft.java:76-78`), `computed_at` =
   `LocalDateTime.now(clock.withZone(ZoneOffset.UTC))` (`DraftComputationService.java:102`). Dates (`start_date`, `end_date`,
   `verified_on`) are flat and midnight UTC.
4. Encrypted: `inputs_json`, `full_state_json`, `change_set_json`, `result_json` (sealed) and `email`, `changed_by` (searchable) are flat
   text columns, carried as ciphertext; nothing inside these JSON columns is encrypted.

### Decisions (for approval)

- **C1 — where the walk gets the Java type.** **C1a (recommended):** from the target entity's field whose `@Column` names the
  column (the same entity `readBack` already finds by `@Table`), its generic type read by reflection — so the type is never
  restated in the copier. **C1b:** name the type on the specification — a second copy that can drift; not recommended.
- **C2 — the walk.** **C2a (recommended):** a new `JsonWalk` turns a stored value into a Jackson tree by the Java type: a class or
  record maps each stored key to the field whose `@Field` name (else Java name) equals it, writing the Java name; a key with no
  field refuses; `_class` is skipped, `null` left out. Leaves: text, enum (a constant of the type, else refused), whole and
  fractional numbers (an int widened, a fraction never narrowed), boolean, `LocalDate` (midnight UTC), `LocalDateTime` (per C4);
  `List`, `Set`, `Map<String, …>` element by element. The tree is then read into the type and written by a default `JsonMapper`
  — the converters' own form — so the column holds exactly what the application would write, and the copy never passes
  through an `AttributeConverter` (W-337g2 finding 2). **C2b:** write the tree without reading it into the type — skips the proof
  that it parses; not recommended.
- **C3 — a column kept in step with a JSON value.** **C3a (recommended):** the JSON specification names it:
  `JsonCopy("imported_from", "imported_from", Map.of("workbook_sha256", "imported_from_workbook_sha256"))` — a stored sub-key
  that also fills a parent column, as `setImportedFrom` does. **C3b:** leave it null — `DraftRevisionRepository.findFirstByDraftIdAndImportedFromWorkbookSha256`
  (line 20), which refuses the same workbook twice, would then miss every copied revision; not recommended.
- **C4 — the time table (W-337g2 C4a).** **C4a (recommended):** `EmbeddedTimes`, a table in code from (type, field) to how the time
  was held, each entry citing its `m1.6.1` setter; this item adds one: `DraftStaleness.since` UTC-held (read in the written
  zone, as g1's top-level times). A `LocalDateTime` field absent from the table refuses. W-337g2b2 / b3 add theirs.

Also: `ChildCopy.orderedValues(key, table, parentColumn, column, orderColumn)` for `law_and_exec` — W-337g2a2's position rule
on a list of plain values.
