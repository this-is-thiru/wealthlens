## Plan for W-122b1 — the coarse label on the report and on the regime comparison

> **Approved as recommended — C1a, C2a, draft content adopted** (owner, session 101, 2026-11-16). Every path below was read on 2026-11-16 at `6dc07a04`; grep each
> again before relying on it. Probe: code read; no code changed.

**What this item is for (one sentence, in my own words):** wherever a draft's figure is shown outside the computation
view, it says whether it is coarse. The PDF report of a stored computation prints the band the stored view carries.
The regime comparison says whether its figures are coarse (PRD F34.3; W-122b C5a, D-721).

**Probe (2026-11-16):**
- **The report.** `ComputationReportService.report` (`compute/ComputationReportService.java:51`) reads the stored view
  by receipt but keeps only `.tax()` (`:52`); `model(tax, pinned)` (`:61`) builds `ComputationReport`
  (`compute/ComputationReport.java`).
  - Every text in the report is a stored value or a content sentence (its Javadoc; O-20).
  - The template prints an optional note the same way as `packNote`
    (`templates/taxplanning/computation-report.html:27`).
  - `model` is called by `ComputationReportServiceTest` in six places (`:105`, `:125`, `:171`, `:186`, `:187`,
    `:204`).
- **Report sentences** allow only the placeholders `{act}`, `{financeAct}`, `{rules}`, `{taxYear}`, `{receipt}`,
  `{computedUnder}` and `{current}` (`taxengine/rules/pack/Sentences.java`, `REPORT_PLACEHOLDERS`). A band sentence
  needs `{lower}` and `{upper}`.
- **The comparison.** `DraftComputationService.compare` (`:129`) returns the engine's
  `RegimeComparison(chosen, mode, priced)`. The engine knows nothing of onboarding steps, so a label needs a
  `taxplanning` record. W-122c reads `compare` (`DraftFirstFigureService.java:45`).
- **An old receipt** reads `coarse` and `band` absent (W-122b). The report then prints no note, so it says neither.

**Choices for the owner:**
- **C1: how the report shows the band.**
  - **C1a (recommended):**
    - The report gains an optional `coarseNote`. It is filled from a new report sentence, `COARSE_BAND`, only where
      the stored view says `coarse: true`, with its band's ends in Indian notation.
    - `Sentences` permits `{lower}` and `{upper}` in report sentences.
    - `model(tax, pinned)` becomes `model(view, pinned)`, so the six test calls pass a view.
  - C1b: two labelled rows in the header table, needing two sentences and two template rows.
- **C2: what the comparison says.**
  - **C2a (recommended):** a `taxplanning` record `DraftRegimeComparison(chosen, mode, priced, coarse, says)`. It has
    the engine's three fields as they are, plus `coarse` (per draft, from the answered steps) and `says` (the
    `COARSE` sentence while coarse). It is additive for clients. No band per regime: the row asks for the label,
    and a band per regime costs one more room pricing per regime.
  - C2b: a band per regime as well.

**Draft content (Claude's, for your adoption; no digits, per SC-2):**
- `report.COARSE_BAND`: "This figure was coarse when it was computed: not every step of the setup had been answered.
  The bill lay between {lower} and {upper}; income not yet entered was outside that."
