## Plan for W-152 — the gratuity's averaging period as rule data

**What this item is for (one sentence, in my own words):** the ten months a gratuity's salary is averaged over (S2
s.19(1) Table Sl. 6; 1961 s.10(10)(iii)) become a tax-year-versioned row the engine reads, instead of `10` written in
`Separation` and in `NotifiedRetirementLimits` (audit P2, D-313).

**This plan raises C1 – C2.**

### What I read (session 28, 2026-10-21)

- The row (`03-WORK-ITEMS.md`, W-152), the audit file § W-088l1 P2, D-313.
- **The law, already in the pack** — `RET-GRATUITY-OTHER`'s `_note`, `SOURCE_CHECKED` both years:
  - TY 2026-27, Income-tax Act, 2025 s.19(1) Table Sl. 6 (pp.41–42): *"(c) half month's salary for each completed
    year of service, calculated as under:— Amount = (A x B) where,— A = average salary for ten months immediately
    preceding the month when any such event occurs; B = number of such completed years."*
  - TY 2025-26, Income-tax Act, 1961 s.10(10)(iii) (thc.nic.in pp.71–72): *"… calculated on the basis of the average
    salary for the ten months immediately preceding the month in which any such event occurs …"*
- **The code:**
  - `input/Separation.java:23` `MONTHS = 10`; its constructor (`:34–41`) refuses entered months other than exactly the
    ten calendar months before the event's month.
  - `node/NotifiedRetirementLimits.java:44` `MONTHS_AVERAGED = 10`; `tenMonthAverage` (`:130–140`) sums the months'
    gratuity-base lines and divides by 10; `context` (`:74–79`) forms `AVERAGE_SALARY_BY_COMPLETED_YEARS` as average ×
    completed years for `RET-GRATUITY-OTHER`'s least-of.
  - `RET-GRATUITY-OTHER` (rule set `RS-RET-ENTRY`) is a `LeastOf` **cap** — a version holds at most one of cap,
    relief, rounding, definition (`RuleVersion.requireAtMostOneOf`), so the period cannot be a definition on it.
- **Leave encashment** (`RET-LEAVE-ENCASHMENT-OTHER`, s.10(10AA) "average salary … ten months") takes the employer's
  `averageMonthlySalary` as entered — no ten in Java there, so it is not in this item.
- `new Separation(` appears 9 times in 4 test classes (`SeparationTest`, `RetirementPaymentTest`, `RetirementNodeTest`,
  `InputsFingerprintTest`).

### Choices (recommended first)

- **C1 — where the period lives:**
  - **(a) recommended:** a new definition `SalaryAveragingPeriod(int months)` ("the salary averaged over the `months`
    calendar months immediately preceding the month of the event"; positive), on a new row `RET-GRATUITY-AVERAGING` in
    a new rule set `RS-RET-GRATUITY-AVERAGING` (`EXACTLY_ONE`, `REGIME`), both years, 10 months. Provisions and
    provenance copied from `RET-GRATUITY-OTHER`'s versions (the same pages); `introducedBy` the Acts themselves (TY
    2025-26 the 1961 Act, its fields copied from `RATE-ROUND-TOTAL-INCOME` TY 2025-26, which names the 1961 Act;
    TY 2026-27 the 2025 Act, s.19(1), copied from `SETOFF-WITHIN-CAPITAL-GAINS` TY 2026-27's pattern) — not the
    notification, which sets only the limit. Like `ShortTermHoldingPeriod`, one law element, one row.
  - **(b)** an optional `averagedOverMonths` on `SalaryBase`, set only on `SAL-SALARY-FOR-GRATUITY`. One row fewer,
    but `SalaryBase` serves seven rows, and the period is not what "salary" includes.
- **C2 — the check on the entered months:** `Separation` is built before any rule is read, so it cannot know the
  period.
  - **(a) recommended:** `Separation` keeps the checks that are facts (service before the event; months distinct and
    all before the event's month), and `NotifiedRetirementLimits` refuses, naming `RET-GRATUITY-AVERAGING`, entered
    months that are not exactly the row's N months immediately preceding the event's month (today's message, with the
    row named). The average divides by N.
  - **(b)** keep `Separation`'s check with its 10 and only make the divisor data — the input would then still hold the
    law.

amended **s.288A** (Act 13 of 1966 s.34; Act 19 of 1968 s.30) — not the 1961 Act as enacted, and not s.10(10)(iii).

`sources/2026-10-16-introduced-by.md:78` settles only the s.10(10) **Explanation** (Act 4 of 1988 s.6, w.e.f. 1-4-1989,
thc p.72 footnote 3), which `SAL-SALARY-FOR-GRATUITY` cites. Nothing was coded.
