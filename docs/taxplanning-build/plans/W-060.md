## Plan for W-060 — the component partition, and the first entered income

**What this item is for (one sentence):** the salary components a taxpayer enters reach the engine and
are partitioned into heads by the year's registry. A code the registry doesn't hold stops the computation
instead of being added in (`D-CLOSEDSUM`, O-15).

### What I read

- **The `W-060` row:** *"`ComponentPartitionNode` — `DR 06` G1.1 step 1 — unknown code = error, never a
  silent addend"*. There's no erratum. The D-089 erratum says no component ships until the first rule that
  reads one (`W-063`, `W-064`).
- **`DR 06` G1.1** step 1: *"Partition components into heads — `D-CLOSEDSUM`, `M2` — unknown code ⇒
  error, never a silent addend (O-15)"*. Step 2, gross salary, is `W-061`.
- **`DR 05` M3.2**, the entered model: `Employment { employerName, …, periodFrom, periodTo, isPrevious,
  components: List<SalaryComponent>, salaryRevisions, payrollCalendar }`; `SalaryComponent { code,
  annualAmount (non-null), monthlyAmount?, daFormsPartOfRetirementBenefits }`.
- **Code:**
  - `EnteredFacts` is **empty by design** (D-026): *"each field arrives with the income item that needs
    it"*. `DR 11` F4's `Employment` is `taxplanning`'s, so the engine holds its own projection (D-024).
  - `InputsFingerprintTest.enteredFactsIsTheOneComponentThatCannotBePerturbedYet` asserts that it has no
    fields, as the tripwire for exactly this item.
  - `NodeValue` permits `MoneyValue` and `TaxByBasis` only; its Javadoc says `ComponentSet` (named by
    `DR 15` B4) *"arrives with the node that produces it"*.
  - The `inputs.components` node is in both regimes' pipelines, and `GoldenCaseRunner` leaves it out
    (`droppedFromShippedPipeline` = `inputs.components`, `salary.gross`).
  - `NodeContext.pack()` gives a node the year's registry (`RulePack.components()`, only the codes live
    that year, `W-059`).
  - The names `Employment`, `SalaryComponent` and `ComponentSet` are free repo-wide.

### Findings

1. **The partition has no input yet.** `EnteredFacts` holds nothing, so W-060 is also where the first
   entered income arrives. That's by D-026's own rule, since this is the item that needs it.
2. **Only two fields have a caller:** the component's code and its annual amount. Periods, employer type,
   previous-employer status, revisions and monthly amounts all belong to later items (HRA per period
   `W-067`, NPS `W-076`, the TDS projection).
3. **The shipped registry is empty** (D-089), so the node is proven on a test pack with fixture components.
   Nothing in the shipped golden runs changes: they enter at total income.
4. **The node applies no rule.** `D-CLOSEDSUM` is a design decision, not a provision, so it declares no
   rule and emits no trace line; W-061's gross salary is the first line.
5. **Standing rules (D-043):** no section is modelled, so there's no coverage, catalogue or concept-ID
   change. Both years: the node reads each year's registry.

### Choices (recommended first)

- **C1 — the entered shape (findings 1–2).**
  - **(a) recommended:** `DR 05`'s names and nesting, holding only fields with a caller:
    `EnteredFacts(List<Employment> employments)`, `Employment(List<SalaryComponent> components)`,
    `SalaryComponent(ComponentCode code, Money annualAmount)`. All are in `taxengine.input`, immutable,
    fail fast on null, with `EnteredFacts.none()` still meaning no employments. Each later item adds its
    field to the record it belongs on.
  - **(b)** A flat `Map<ComponentCode, Money>` on `EnteredFacts`. It's simpler now, but it has to be
    reshaped the moment a second employer or a period arrives.
- **C2 — the output.** `ComponentSet`, a new `NodeValue` permit: each entered line (code, amount,
  employment index) grouped by its registry `HeadCode`, in input order, **not summed**. Summing is
  `W-061`'s, and HRA and the standard deduction will need per-employer lines. `asMoney()` is the total of
  every line, which is the trace's summary column only, as `NodeValue` defines it.
- **C3 — unknown code.** A code not in the year's registry (never defined, or not live that year) throws
  `IllegalStateException` naming the code, the employment and the tax year. That's `D-CLOSEDSUM`.
  Request validation (`T9-8`, a 400) is `taxplanning`'s later; the engine refuses regardless.
- **C4 — the fingerprint tripwire.** `enteredFactsIsTheOneComponentThatCannotBePerturbedYet` is replaced by
  a perturbation: adding a component to an employment changes the fingerprint. `entered` then joins the
  "every component perturbed" check, so it's a stronger test, not a deleted one.
- **C5 — the golden runner.** `ComponentPartitionNode` is **not** registered in `GoldenCaseRunner` yet.
  Nothing downstream reads `inputs.components` until `salary.gross` (`W-061`), and registering it would
  only change the "dropped" list for no run's benefit.
