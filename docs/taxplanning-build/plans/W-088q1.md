## Plan for W-088q1 — the carry-forward as rule data

**What this item is for (one sentence):** the two carried-loss rows state everything their law says: which head the
loss may be set off against, for how many years, and whether a return filed in time is required. The nodes read those
facts from the row instead of deciding them in Java (D-263; review S2; CLAUDE.md §4 "facts, not rules").

**Behaviour unchanged:** every value, trace line, limit text and provenance is identical with the shipped packs.

### Design

1. **`rules/definition/LossCarryForward(HeadCode absorbedBy, TaxYearSpan span, boolean requiresReturnFiledInTime)`.**
   - A new permit on `RuleDefinition`.
   - Its Javadoc states the contract: one head, because each section names one (D-263 C3a). The span is the existing
     `TaxYearSpan`, and the return condition is whether a loss not determined in a return filed in time is refused.
   - It refuses a null head or span.
2. **`ShapeJson`:** a new tag, `"LossCarryForward"`, with fields `absorbedBy` (the `HeadCode` name),
   `succeedingYears` and `requiresReturnFiledInTime`.
3. **Both rows, both versions:**
   - house property: `{"type": "LossCarryForward", "absorbedBy": "HOUSE_PROPERTY", "succeedingYears": 8,
     "requiresReturnFiledInTime": false}`;
   - capital loss: `CAPITAL_GAINS`, 8, `true`.

   The `_note`s gain the reason for each figure (s.121; s.80 as read). Relocked: law 2025-26.76 → .77 and
   2026-27.80 → .81.
4. **`SetOffNode.broughtForward`** reads `LossCarryForward` and sets off against `absorbedBy`'s income.
   - It refuses `CAPITAL_GAINS`, as a pack defect, because this path lowers a head's income and not the capital-gains
     parts.
   - It refuses `requiresReturnFiledInTime = true`, also as a pack defect, because the house-property ledger states no
     such fact and neither Act asks for one. Silently ignoring the flag would be the kind of failure §2 forbids.
   - To keep the parameter count, `use` / `useAttributable` take the head in place of the `TemporalContext`, which
     they can read from the context.
5. **`CarriedCapitalLossSetOff.apply`** reads `LossCarryForward`. It tests the return condition only where the row
   requires it, and lowers `absorbedBy`'s income. It refuses any head but `CAPITAL_GAINS`, as a pack defect, because
   it sets off against the capital-gains parts.
6. **Docs:**
   - coverage `manager` → `LossCarryForward` for the four sections;
   - a sources row for 1961 s.80, READ, in a new `sources/2026-10-19-carry-forward-return-condition.md`;
   - TS T1 `definition/` and Changes; WI; STATE (D-264); CHECKPOINT.
