### Choices (recommended first)

- **C1 — how the row states its reach:**
  - **(a) recommended:** both versions gain `AnyOf(ItemFactIs accommodation.provider EMPLOYER_OWNED,
    ItemFactIs accommodation.provider EMPLOYER_LEASED)`. The set becomes `AT_MOST_ONE` / `REGIME_AND_CONDITIONS`,
    as `RS-PERQ-CAR-PARTLY` is. The node asks `optionalRuleOf(RS_PERQ_ACCOM_CONTINUED, facts)`, and only a row it
    gets back caps the value. This is W-153c1's way of choosing a row by an item's facts.
  - **(b)** keep the set `EXACTLY_ONE` / `REGIME` and test the row's item conditions in the node, as W-153b's
    `OtherSourcesNode.reaches` does for rows that always exist. That suits a row that must also write a nil line
    for an item it misses. This one writes no line for an item it misses, so (a) needs no new helper.
- **C2 — "first provided before this tax year":**
  - **(a) recommended: stays in Java.** It compares two facts, the year the accommodation was first provided and the
    year being computed. That is what "continued" means; the comparison holds no legal value that could change.
    `ItemDateBefore` takes a fixed date (`rules/condition/ItemDateBefore.java`), so making it a condition would need
    a new condition type, relative to the year, for no data a law could change.
  - **(b)** a new condition type, "item year before the tax year", on the row.
