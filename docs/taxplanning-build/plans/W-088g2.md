### Findings

1. **The portfolio change is one line, and the WI row overstates what it costs.** Nothing switches on `AssetType`, nothing
   enumerates it, nothing validates it on the way in, and no seed or template lists the values. The buy and sell paths,
   the FIFO match, the charge resolver and the exporter all read the constant generically. "The buy/sell paths and seeds
   it touches" turns out to be **none**; the honest entry is the enum constant alone.
2. **The first refusal a land bucket meets is the term, not the part.** The WI row names `CapitalGainsNode:158`, but a
   bucket is put to `CapitalGainsTerm` first, and with no row for the kind it is refused there — "so how long a holding is
   short-term is not known for them" (`CapitalGainsTerm.java:49-53`). So this item adds **three** rows, not one: a term
   row and two part rows.
3. **A land bucket can never meet `stt.transfer = NOT_PAID`, so the two existing STT-free rows cannot be copied.** A side
   with no charge breakdown reads `UNKNOWN` (`CapitalGainsSummaryService.java:157-163`), and no `RS-STT-CHARGEABLE` row
   can turn it into NOT_PAID for a non-equity asset — every one of the three requires EQUITY (`STT-SALE-*.json`,
   `STT-PURCHASE-DELIVERY.json`), so the side "stays UNKNOWN" (`CapitalGainsStt.java:28`). The land rows must carry **no**
   STT condition; a copied one refuses every land sale.
4. **The parts already exist and already charge 12.5 %.** `RATE-CG-LONG-OTHER` keys on `capitalgains.part =
   LONG_TERM_OTHER` alone; nothing in the rate or set-off data names an asset. A long-term land gain is s.197(1)(b) /
   s.112(1)(a)(ii)(B) — the very provision that row quotes — and a short-term one is charged with total income, which is
   what `SHORT_TERM_SLAB` is (`CG-PART-SHORT-SLAB`'s `_note`). No new part, no new rate row, no Java.
5. **A fifth part would prejudge W-088g.** It would need `CG-PARTS` and `SETOFF-WITHIN-CAPITAL-GAINS` re-cut in both
   years, and its only use is to let the cap find the land slice — which is OQ-36, still open, and W-088g's to answer
   (`STATE.md` OQ-36; `plans/W-088g.md` finding 2).
6. **The 24-month period is the one the term set already says it has not shipped** (`rule-sets.json:18`), and its law is
   already read in a hashed copy (`sources/2026-10-21-holding-period.md` rows 1, 2, 7). No new gazette read is needed.
7. **The register tolerates a definitional rule with no section row.** Fourteen of the pack's rules are named by no
   MODELLED row (measured: the `SAL-SALARY-FOR-*` definitions, the surcharge limb rows, the cess row), and the citation
   baseline "may only shrink", so a new term rule whose provision is the NOT_COMPUTATIONAL s.2 is not added to that
   exception list.
8. **Five hand-kept artefacts move with three rules:** the pack-size assertion (219 → 222, `RulePackLoadTest.java:83`),
   the two hand-written id lists (`GeneratedConstantsTest.java:36`, `TimelineReaderTest.java:40`), the regenerated
   `RuleIds`, and the two lock files.
9. **One note becomes a lie.** `RATE-CG-LONG-OTHER`'s "no input carries the asset kind; the adapter maps equity only" is
   true today and false the moment the constant exists, so it is corrected in the same change rather than left for the
   next reader.

### Choices (recommended first)

**C1 — what the portfolio's kind is called.**

- **(a) Recommended: one constant, `LAND_OR_BUILDING`.** The law names one class — "land or building, or both" (2025
  s.197(3), `sources/2026-10-31-land-building-cap.md` row 1; 1961 s.112(1)(a) second proviso, row 9) — and nothing below
  the record distinguishes a plot from a flat: no row, rate, set-off or charge test reads the difference. The bucket's key
  and the engine's asset fact both carry the constant's name (`CapitalGainsSummaryService.java:115`,
  `CapitalGainsAdapter.java:75`), so one constant is one code.
- (b) Two constants, `LAND` and `BUILDING`. Truer to what the user records, but no consumer reads the difference, and every
  new row would have to test an `AnyOf` over two codes to say what one fact says.
- (c) Reuse an existing constant. Rejected outright: it would state a fact the record does not have.

**C2 — which part a land bucket is charged under.**

- **(a) Recommended: the existing parts, reached by two new rows per tax year — no new part, no new rate row.** A
  long-term land gain goes to `LONG_TERM_OTHER`, which `RATE-CG-LONG-OTHER` already charges at 12.5 % under s.197(1)(b) /
  s.112(1)(a)(ii)(B); a short-term one goes to `SHORT_TERM_SLAB`, charged with total income. Both parts and both rate
  provisions are unchanged, so a land sale is charged the day the rows land.
- (b) A fifth part for long-term land. It would let W-088g locate the land slice without a new measure, but it re-cuts
  `CG-PARTS` and `SETOFF-WITHIN-CAPITAL-GAINS` in both years, invents a slice s.108(2)(b) does not draw, and answers
  OQ-36's structure before OQ-36 is answered.
- (c) Relax `CG-PART-LONG-OTHER`'s asset condition to any asset. Rejected: it would also start charging BOND, GOLD_BOND,
  MUTUAL_FUND and INSURANCE long-term buckets — each refused today for want of a sourced part — in one silent step.

**C3 — how the holding period is added.**

- **(a) Recommended: a new row, `CG-TERM-LAND-BUILDING`, 24 months, conditioned on the asset code.** The period is the
  law's: 1961 s.2(42A) after Finance (No. 2) Act, 2024 s.3(b) (base 36 → 24 months; the land-or-building third proviso
  omitted as redundant) for TY 2025-26, and 2025 s.2(101)(a) for TY 2026-27 (`sources/2026-10-21-holding-period.md` rows 2
  and 7). The existing row stays as it is: a listed security's period is 12 months and its rule says so.
- (b) Extend `CG-TERM-LISTED-SECURITY` to cover both periods. Rejected: one id would then state two periods, and the id
  names listed securities.
- (c) Leave the term to a default. Rejected: there is no default — a bucket with no term row is refused
  (`CapitalGainsTerm.java:49-53`), which is the refusal this item exists to remove.

**C4 — whether the new term rule is listed in a coverage row.**

- **(a) Recommended: not listed.** Its home provision is s.2(42A) / s.2(101), which the register holds as
  NOT_COMPUTATIONAL in both Acts (measured); fourteen rules in the pack are named by no MODELLED row on the same basis; and
  listing it under the six capital-gains sections would add six entries to `citation-baseline.json`, whose own note says
  it "may only shrink".
- (b) Listed under s.196, 197, 198, 111A, 112 and 112A, as its sibling is. It makes the rule visible from the rows a
  reader starts at — but only by growing the exception list by six, which is the one thing that file says it must not do.
  If the owner prefers (b), it is a decision about the baseline, taken here and recorded, not a silent edit.

### Risks or ambiguities

1. **Charging land at 12.5 % before the cap exists may overstate a pre-23-7-2024 land sale.** That is the correct
   *provisional* answer — s.197(1)(b) applies, and s.197(3) only caps it — but a user who sells land bought before
