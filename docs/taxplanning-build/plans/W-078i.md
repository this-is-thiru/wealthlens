which are known to be wrong, without the notice the JSON endpoint carries, so print the same notice on the PDF, above
the first figure.

### Findings

1. **One source for the text.** `KnownErrorsComputation.NOTICE` already exists and must not be copied; a second copy
   could drift from the JSON one.
2. **Placement matters more than presence.** A notice after the figures (where the disclaimer sits) is read after the
   numbers are. D-063's "visible" means before them.

### Choices (recommended first)

- **C1 — where the notice enters:**
  - **(a) Recommended.** `DocumentGenerationService.generateTaxComparisonReport` puts
    `knownErrors = KnownErrorsComputation.NOTICE` in the context. This is the only report the old calculator produces,
    so it goes when that does.
  - **(b)** The controller passes it through the generator. This adds a parameter to two signatures for a constant.
- **C2 — where it prints:** directly under the header, before the employee details and every figure. It gets a bordered
  red box, bold, using the template's own inline-style idiom, with `th:text="${knownErrors}"` so it is never typed in
  the template. The end-of-page disclaimer is unchanged.
- **C3 — tests:**
  - **Unit:** a new `DocumentGenerationServiceTest`. It renders through a real Thymeleaf engine (classpath `templates/`)
    and Flying Saucer with a populated fixture (the ~30 fields the template reads), extracts page 1's text with
    `PdfTextExtractor`, and asserts the notice's opening ("Known errors: this calculator is being replaced") appears
    **before** "Tax Comparison Report"'s first figure label ("Gross Salary"). The test names the constant, not a copy.
  - **Integration:** extend the l.352 test to assert the PDF's text contains the notice. I cannot run it here (no
    Docker); I will say so in the report and you or CI run it.
- **C4 — records:** D-168; STATE; D-064's follow-up marked done in the W-078i row's erratum.
