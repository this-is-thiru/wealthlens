## Plan for W-079a — startup wiring

**What this item is for (one sentence):** the running application loads the timeline from its own JAR, compiles
each shipped year against its lock **once, at boot**, and holds the packs. A timeline that does not match its lock
then stops the application starting, instead of surfacing on a request (`DR 07` X2; D-054, D-159).

**This plan raises choices (C1–C5); nothing is coded until you choose.**

### A probe I ran (scratch only, nothing in the repo)

I packaged the JAR (`./mvnw package -pl backend -am -DskipTests`) and ran a 20-line class inside it through
`PropertiesLauncher` (`-Dloader.path`):

```
url=jar:nested:/Users/…/backend/target/wealthlens.jar/!BOOT-INF/classes/!/rulepacks/timeline
Path.of worked: class jdk.nio.zipfs.ZipPath
files=288                      (288 files under src/main/resources/rulepacks/timeline — equal)
coverage bytes=163195 rel=content/coverage.json sep=/
```

So inside the Boot JAR, `Path.of(url.toURI())` already gives a walkable zip path, and the reader needs no change.
A plain (non-Boot) JAR has no filesystem open for its `jar:file:` URI, so there `Path.of` throws
`FileSystemNotFoundException` until `FileSystems.newFileSystem(uri, Map.of())` opens one.

### Findings

1. **JAR loading is a small change.** The refusal becomes a `jar:` branch: take `Path.of(uri)`, and open a zip
   filesystem for the load only where none is open. The timeline reader is unchanged.
2. **A multi-year provider can't be given the right instruments today.** The assembler holds one year's. The
   lock already holds each year's, so the lock is the place to read them in main code. `LockedInstruments` then
   becomes one line over it, and its 57 call sites stay as they are.
3. **"Serves the packs" has no caller yet.** No module consumes `taxengine`, and `RulePack` is not in a named
   interface. What startup wiring delivers now is the fail-fast guarantee: a bad timeline stops the boot. Exposing
   packs to `taxplanning` belongs to the item that first calls the engine (D-048: *"a package is exposed by the
   item that first needs it"*). So this item builds the bean and no consumer.
4. **The years must be declared, not scanned.** The provider's Javadoc says so: *"a year that silently fails to
   appear is worse than one that fails to load"*. A test then ties the declared years to the lock files shipped.

### Choices (recommended first)

- **C1 — loading from the JAR:**
  - **(a) recommended:** `ClasspathRulePackProvider` accepts a `jar:` URL. It uses `Path.of(uri)`, or for a plain
    JAR opens a zip filesystem for the load and closes it after. Every other protocol is still refused, by name.
  - **(b)** Copy the timeline to a temporary directory at boot. More I/O and more code, for nothing the probe
    shows is needed.
- **C2 — instruments in main code:**
  - **(a) recommended:** `RulePackLock` gains `GoverningInstruments instruments`, parsed from the block by
    `LockedInstruments`' logic, moved. A lock without the block is refused, naming the path. The test helper
    `LockedInstruments.of` becomes a one-line delegate, so no call site changes.
  - **(b)** `PackAssembler.assemble` takes the instruments, so one assembler serves every year. This is the
    cleaner seam, but it is a mechanical edit across about 50 test files, which would take the item over size
    (§7). Not recommended now; I'd write it as a proposal.
- **C3 — the startup component.**
  - **(a) recommended:** two parts.
    - `rules/timeline/ShippedRulePacks implements RulePackProvider`, a final class. Its static `compile(root,
      years)` builds, for each year, a `ClasspathRulePackProvider` whose assembler carries that year's lock
      instruments. It loads (compiles and verifies) every year once and holds the packs in an immutable map.
      `load` returns the held pack, and refuses an undeclared year as the provider does.
    - A Spring `@Configuration` `taxengine/config/TaxEngineConfig` with one `@Bean` returning
      `ShippedRulePacks.compile("rulepacks", SHIPPED_YEARS)`. This is the module's first bean; it is internal
      (no named interface).
  - **(b)** Same, but compile lazily on first `load`. This contradicts TS l.203 (*"never on a request path"*).
    Not recommended.
- **C4 — where the years are declared:**
  - **(a) recommended:** a constant `SHIPPED_YEARS = {2025, 2026}` in `TaxEngineConfig`, plus a test that it equals
    the set of `rulepacks/*.lock.json` files. Adding a lock without declaring it, or the reverse, fails the build.
  - **(b)** A property in the three profile yamls. Not recommended: which years exist is the law shipped in the
    JAR, not something that varies by environment.
- **C5 — records:**
  - D-210;
  - the TS l.77 row → `W-079a` ✅ and ll.202–203 reworded;
  - the D-054 Javadoc text in `ClasspathRulePackProvider` and `LockedInstruments` updated;
  - C2(b) written into STATE as a proposal, not placed, for you to place or drop.
