capital-gains head) is added as rule data, not as new enum values and Java in three places (review E3; D-250).

**This plan proposes moving the item, not building it (R4: the order is yours).** Approving it moves W-088o after
W-088k, narrows it to `CapitalGainsPart`, and records which row owns each of the other two sets. Nothing is built.

- Built now, that mapping is written against `Term` and `RateBasisHint`'s codes. W-088f2 then deletes the basis codes,
  and W-088k the term, so the mapping is written twice.
- W-088q (one carried-loss mechanism, "heads absorbable" as data) also overlaps the `isLongTerm` restriction.

    - `RateBasisHint` stays W-088f2's and `Term` W-088k's, as their rows already say. W-088o's row records that.
    - Next in order becomes **W-088p**.
  - **(b)** build W-088o now, narrowed to `CapitalGainsPart`, with the part mapping on today's codes, rewritten by

  - **(a) recommended:** in W-088o, as a fact each part declares, so W-088q can reuse it. *(D-263: W-088q comes first; W-088o takes the restriction over from W-088q2's mechanism.)*
