## Plan for W-119b1 — evidence held for the other Chapter VIII inputs

> **Approved as recommended — C1a, C2a, C3a, C4a; draft content adopted** (owner, session 100, 2026-11-15). Every path below was read on 2026-11-15
> at `45f08969`; grep each again before relying on it.

**What this item is for (one sentence, in my own words):** let a person record what they can show for their health
payments, donations, loan interest and the other Chapter VIII entries, as they already can for rent, travel and
Schedule XV payments. The integrity panel can then show, for each of those claims, what is allowed, what is evidenced
and the gap.

**Probe (2026-11-15; code read, nothing run):**
- **The shape W-119b and W-119c built:**
  - `EvidenceHeld(receiptedMonths, journeyExpenditure, qualifyingPayments)` (`taxplanning/workspace/EvidenceHeld.java`)
    is matched to the entries by position.
  - `requireFits` refuses evidence that does not fit, on every patch.
  - `EvidencedFacts` (`taxplanning/compute/EvidencedFacts.java`) cuts each figure to what is held with `EnteredFacts`'
    own `with…` methods, so the engine never learns what evidence is.
  - `EvidenceKind` has one value per family, each with a closing sentence in `explanations.json`'s `evidence` section.
- **The entries still without evidence**, each a list on `EnteredFacts` with one amount to cut:

  | Family | Input | Amount |
  |---|---|---|
  | Health | `healthPayments` (`HealthPayment`) | `amount` |
  | Donations | `donations` (`Donation`) | `amount` |
  | Education-loan interest | `educationLoanInterest` | `interestPaid` |
  | Purpose-loan interest (house, electric vehicle) | `purposeLoanInterest` | `interestPayable` |
  | Dependant with disability | `disabledDependantSupport` | `spentOrDeposited` |
  | Specified disease | `specifiedDiseaseTreatment` | `paid` (with `reimbursed`) |
  | Agniveer fund | `agniveerCorpusFund` (optional) | `ownSubscription` |

- **Rent paid under s.134** (`DED-RENT-PAID`) reads the tenancies' rent, which W-119b's receipted months already cut.
  Nothing new is needed for it.
- **Only `withHealthPayments` exists** on `EnteredFacts`. The other six families need a `with…` method each in
  `taxengine/input` (the `input` named interface), as `withQualifyingPayments` was added for W-114a
  (`cf950b23`).
- **`EvidenceHeld` would grow from 3 components to 10.** More than 7 means a missing type (CLAUDE.md §4).

**Choices for the owner:**
- **C1: which families.**
  - **C1a (recommended):** all seven above. The Agniveer fund's own subscription only, since the government's part is
    the employer's to show.
  - C1b: the six lists, the Agniveer fund placed as its own item.
- **C2: the record's shape.**
  - **C2a (recommended):** a new `ChapterViiiEvidence` record holding the seven, as one component of `EvidenceHeld`
    (four components). Stored as `/evidence/chapterViii/…`; a draft stored before reads as nothing held.
  - C2b: seven more flat components on `EvidenceHeld` (ten).
- **C3: how the facts are cut.**
  - **C3a (recommended):** six small `with…` methods on `EnteredFacts`, each replacing one list or the optional fund,
    with the engine's own copying. The engine learns nothing new.
  - C3b: rebuild `EnteredFacts` in `taxplanning` through its forty-argument constructor, which breaks on every new
    input.
- **C4: the panel.**
  - **C4a (recommended):** one `EvidenceKind` per family, each with its own closing sentence in content (no digits,
    `{amount}` filled). Each kind entered gets its own run, as W-119c's kinds do. A specified-disease cut never
    leaves `reimbursed` above `paid`.
  - C4b: one kind for all of Chapter VIII. The rows could not say which document closes the gap.
