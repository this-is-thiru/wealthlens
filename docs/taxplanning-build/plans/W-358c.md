## Plan for W-358c — zoned, module-scoped URLs and `/me` (proposed split: W-358c1 – c3)

> Planned in session 113 (2026-11-21), after W-358b (D-854). `plans/W-359.md` commit 3 (D-853 C2a, C4a) named the shape; this plan
> adds what that plan left open — the route-by-route table, who may act on another user's data, and the sizing (00-START-HERE §7).
> **Stop point: nothing is built until the owner answers C1 – C6.**

**What this item is for (one sentence, in my own words):** every URL says who may call it and which module answers, and a user's own
data is reached only through the token, never through an email in the path.

### Decisions (for approval with this plan)

- **C1 — sizing (§7).** One commit for all of it is far over the size rule: every controller, 64 test files and 117 requests, plus
  DTO and REST reshaping that each need their own table. **C1a (recommended):** split —
  - **W-358c1** — zones and `/me`: the zone annotations and prefix, `/me` from the token, the admin routes of C3, `UserValidator`
    removed, per-zone rules in `AuthConfig`, the guards, the tests' and the api-collection's paths, the runbook's commands. Path
    **tails unchanged** (the table below): only the prefix moves and `/user/{email}` goes.
  - **W-358c2** — DTO-only responses for the 17 routes above (no `@Document` returned), and its ArchUnit rule.
  - **W-358c3** — REST shapes (verbs out of paths: `/add`, `/delete/{id}`, `/update/priority/…`, `/all`, `/list`, `/clear/all`,
    `/perform/test`, `/transaction/v2` …) and pagination on list routes, each with its own table and plan.
  **C1b:** one commit, as `plans/W-359.md` said.
- **C2 — reference data any signed-in caller reads** (rate cards, the charge catalogue, corporate actions, `/charges/simulate`). None
  is a user's own data and none is an admin's. **C2a (recommended):** the `me` zone means "signed in"; such a route sits there with no
  user in it (`/api/v1/me/charges/charge-schedules`). **C2b:** move them to admin (a user then cannot see the rate card that prices them).
- **C3 — the owner acting on another user's data.** Today a `SUPER_USER` token passes `UserValidator` on any user's path; under
  `/me` it would read only its own. The runbook uses that for: a user's holdings after a rebuild (line 1579), a user's charge gaps,
  contract note and reconciliation (1945, 1947, 1948); a test uses it for a held user's erasure receipt, which that user can no longer
  read. **C3a (recommended):** an admin route for exactly these six, naming the user (`/api/v1/admin/{module}/users/{email}/…`, table
  below); anything else later is a new row. **C3b:** none — those runbook steps become database queries.
- **C4 — how a `/me` route gets its user.** **C4a (recommended):** a parameter annotation resolved from the signed-in name (Spring's
  `HandlerMethodArgumentResolver`), so each controller swaps `@PathVariable String email` for it and no service signature changes.
  **C4b:** `@AuthenticationPrincipal Jwt jwt` in every handler and `jwt.getSubject()` (Spring's own, but the JWT type then reaches 96
  handlers).
- **C5 — paths that stay outside `/api/v1`.** **C5a (recommended):** the notice page `/privacy` (a page, not the API), `/error` and
  `/actuator/**` (Spring's own) stay where they are; Swagger comes with W-359b. **C5b:** move `/actuator` under `/api/v1/admin` now.
- **C6 — a controller serving two zones.** Each zone annotation sits on a class (`plans/W-359.md`: "exactly one zone annotation"), so
  **C6a (recommended):** the 7 mixed controllers split into one class per zone, named for what they serve (e.g. `ChargeScheduleController`
  for the reads, `ChargeSchedulePublishingController` for the admin writes — names settled at the build against the one-word rule).
  **C6b:** zone annotations on methods.

### The module names (`plans/W-359.md` C4a, completed)

`auth` → `auth`, `brokercharges` → `charges`, `corporate` → `corporate-actions`, `finance` → `finances`, `helper` → `templates`,
`portfolio` → `portfolio`, `shared` (all its controllers are privacy) → `privacy`, `taxplanning` → `tax`. The segment comes from the
controller's **package**, so `BonusAllotmentDateCorrectionController` (portfolio) answers under `/admin/portfolio/corporate-actions/…`.

### W-358c1 in detail (if C1a)

**Files I will create:** `shared/web/PublicApi`, `MeApi`, `AdminApi` (the zone annotations; package settled against the one-word
rule) and the prefix configuration (`WebMvcConfigurer.configurePathMatch` → `PathMatchConfigurer.addPathPrefix` per annotation and
module); the C4a annotation and its resolver; the admin twins of C3; the split classes of C6; `ZoneArchitectureTest` rules (each
`@RestController` has exactly one zone; none writes `/api` itself; none in `me` takes an `{email}` path variable).

authenticated, `/api/v1/admin/**` `SUPER_USER`, the three C5a paths, `anyRequest().denyAll()`); `UserValidator` deleted;
`RouteAccessIntegrationTest` for zones (no token → 401 outside public; a user token → 403 on admin; `/me` reads only the caller's
data — a second user's rows are never returned); the 64 test files' paths; the 117 requests and the runbook's commands (and its two
stale `.data`); CLAUDE.md's paths; `AuthConfig.PUBLIC_PATHS` becomes the zone.
**Numbers I will use:** the counts above (this session); nothing legal.
**Design sections I read:** `plans/W-359.md`, D-850, D-853, D-854; `AuthConfig.java`, `UserValidator.java`, every controller's mappings
(the inventory); the runbook lines cited.
**What I am NOT doing:** W-358c2, W-358c3, W-359b, W-358d; MFA / passkeys; `httpBasic` (D-854's proposal).
**How I will verify:** red first — `RouteAccessIntegrationTest` asserting zones fails on today's routes; the ArchUnit rules proven by a
deliberate violation each; the classes each module touches, module by module, green before the next; `validate`; then the pipeline.
**Post-deployment actions (R15):** a runbook entry: every URL changes (old → new is this plan's table); callers' saved commands and the
api-collection move; no stored data changes, nothing to run.
**Five roles:** Architect — rules follow the structure, so a new route cannot miss its zone. PM — one predictable URL scheme. Senior
engineer — tails kept, so the change is the prefix and the user's source only, reviewable by the table. Automation tester — guards read
Spring's real route table. Manual tester — the api-collection run end to end on the new paths.
**Risks or ambiguities:** anything outside this repo that calls today's URLs breaks (none known; D-853 C2a); a `/me` route whose
service also reads `email` from a request body must take it from the token too — listed at the build, per route.
