### What I read (at `29e88f6e`)

  test, no suppression, and no doc names it.

  `portfolio/migration/TradeOutcomeFinancialYearMigration.rewriteFinancialYears()`.
  - The migration finds `^FY` rows, and refuses one with no sell date, naming its id.
  - It rewrites in one bulk update, from each row's sell date, and is idempotent.
  - `TradeOutcomeFinancialYearMigrationIntegrationTest` has 4 cases: rewrite, a re-run changes nothing, it follows
    the sell date, an undated row is refused.

### Design

1. **Delete `TempTransactionMigrationRunner`.** Both databases are checked; nothing is left.
2. **The FY rewrite as an operation:**
   - `TradeOutcomeFinancialYearMigration.rewriteFinancialYears(boolean dryRun)` returns `FinancialYearRewriteReport`
     (`dryRun`, `auditor`, `rows`: the `FY` rows found, rewritten or that would be).
   - The undated-row refusal applies in a dry run too, so it shows before any write.
   - **`POST /trade-outcomes/financial-years/rewrite?dryRun=true|false`** goes on a new controller
     (`TradeOutcomeFinancialYearController`, `SUPER_USER`, `dryRun` default true), apart from the others so it can be
     removed alone.
   - It is a raw bulk update, so the audit is set explicitly: `audit_metadata.updatedBy` = the caller,
     `updatedAt` = now.
   - `TradeOutcomeFinancialYearMigrationRunner` is deleted.
3. **Remove after use:** a new row, **W-088u9d**, removes this endpoint, its report and the migration once the prod
   run is logged. It is placed under W-088u9 and tied to YouTrack **WL-32**, whose text is updated: the runner is
   gone now, and the endpoint is what remains. **WL-33** (the temporary-transaction runner) is closed by this item.
