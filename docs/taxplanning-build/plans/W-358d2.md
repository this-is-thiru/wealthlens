## Plan for W-358d2 — sign-in hardening

> Planned in session 114 (2026-11-21), the second part of W-358d (D-872). Also carries the owner's "RetiredTestRoutesIntegrationTest remove
> in next item" (2026-11-21). **Stop point: nothing is built until the owner answers C1 – C3.**

**What this item is for (one sentence, in my own words):** nobody can try passwords or test addresses without limit, and registration
stops telling a stranger whether an address has an account.

### What the code does today (measured this session, a temporary test, removed)

| Request | Answer | Where |
|---|---|---|
| sign-in, unknown address | 401 `Bad credentials` | Spring's `DaoAuthenticationProvider` hides "not found" |
| sign-in, known address, wrong password | 401 `Bad credentials` — **the same**: sign-in reveals nothing | |
| register, taken address (no valid notice version even) | 400 "User with email known@example.com already exists" — **reveals the account, before the notice version is checked** | `AuthService:45-48` |
| register, address held for erasure | 400 "The account … is being erased" — reveals a pending erasure | `AuthService:50-52` |
| register, free address, wrong version | 400 "Read the privacy notice … register with its version" | `AuthService:53` |
| attempts | unlimited on every public auth route; no rate-limit or cache library on the classpath | `dependency:tree` |

### Decisions (for approval with this plan)

- **C1 — the attempt limit.** **C1a (recommended):** kept in memory (one local instance; a restart clears it) and counted two ways:
  failed sign-ins **per address and client** — after **5** in **15 minutes** that pair answers **429** with `Retry-After` until the window
  passes, and a successful sign-in clears it; and every call to `/api/v1/public/auth/**` **per client** — over **30** in **15 minutes**
  answers 429. Not per address alone: that would let anyone lock a person out by guessing wrong on purpose. The numbers are design values
  (no standard read for them); C1 names them. **C1b:** other numbers. **C1c:** counts stored in Mongo (survive a restart, shared between
  instances) — only needed once the app runs on more than one machine.
- **C2 — registration.** Without a way to email the address (the app sends no mail), registration cannot fully hide whether an account
  exists: a free address must succeed and a taken one must not. **C2a (recommended):** check the notice version first; answer a taken and
  a held address the same, without naming the address or an erasure ("This email cannot be registered"); registration under C1's
  per-client limit; and place a row, **W-363 — registration confirmed by email**, parked until the app can send mail (then both answers
  become identical). **C2b:** answer a taken address with success too — a real person who mistyped would think they registered.
- **C3 — client address.** **C3a (recommended):** `request.getRemoteAddr()`, the connection's own address: the app runs without a proxy.
  A proxy in front (hosting, D-781) would make every client one address, so W-363's row also notes reading a forwarded address then.
  **C3b:** trust `X-Forwarded-For` now (a client could set it to dodge the limit).
