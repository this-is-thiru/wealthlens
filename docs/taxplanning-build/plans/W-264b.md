## Plan for W-264b — gap audit: charge engine

**What this item is for (one sentence, in my own words):** find where the charge engine gives a wrong amount, a 500
or a silent loss when driven through its HTTP API — seeding and publishing rate cards, picking the card, simulating,
pricing and recording V2 trades under each flag, exit loads per FIFO lot, AMC billing and the read views — and place
each gap as its own fix row; this item fixes nothing (W-264, D-530).

**Numbers I will use, and where each comes from:** no legal figure. The rates are the shipped cards' own data, and the
expected amounts are arithmetic on them. The base case is computed by hand.

The buy is Zerodha delivery equity, 10 units at ₹1,000 on 10 Jun 2025, so turnover is ₹10,000. The cards are
`zerodha-equity-delivery-2025-04-01.json` (BROKERAGE flat 0, EXCHANGE_TXN 0.00297 %, IPFT 0.0001 %, DP ₹13.50 on a
sale only) and `statutory-equity-delivery-2025-04-01.json` (STT 0.1 % rounded to the rupee, SEBI_FEE 0.0001 %,
STAMP_DUTY 0.015 % on a buy only, rounded to the rupee, GST 18 % of BROKERAGE + EXCHANGE_TXN + SEBI_FEE + IPFT + DP).

**Post-deployment actions (R15):** none. A fix row that needs a data correction says so in its own plan.

**Five roles:**
- **Architect:** watches for a gap that is really a boundary problem: the trade path and `/simulate` disagreeing,
  V1 and V2 recording differently, a flag combination the code does not define.
- **Product manager:** each gap is written as what the holder sees (a wrong charge, a charge missing from the cost,
  a 500), so you can order fixes by harm.
- **Senior engineer:** reads each scenario's code path first, and separates a gap from a decision already made (the
  CE backlog, D-rows, CLAUDE.md).
- **Automation tester:** expected values by hand, first; real HTTP; each gap reproduced twice; `MoneyAssert` for
  every amount.
- **Manual tester:** for each gap, the smallest request sequence that shows it, to repeat on your local app.

**Risks or ambiguities:**
- **Size.** 34 scenarios and about 8 old entries. If it runs long I stop at a finished area, report, and ask about
  continuing as W-264b2.
- "Expected" is sometimes a judgement, for example which of two equally specific cards should win, or scenario 22.
  Where the code, the tests and the docs do not settle it, the report asks you and does not call it a gap.
- The flag classes each start their own Spring context, which adds pipeline time. Only those kept are committed.
