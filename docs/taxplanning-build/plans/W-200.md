## Plan for W-200 — a build-time check that a DONE item's plan has no open step

**What this item is for (one sentence, in my own words):** the unit tier fails when a plan in
`docs/taxplanning-build/plans/` belongs to an item the status board marks finished, yet still holds an open step
(`- [ ]`) that does not say *"not taken"*. The 15 steps W-188 found therefore cannot build up again unseen.

**Source:** `03-WORK-ITEMS.md` W-200; `plans/W-188.md` C2a; D-398; audit G5.

**Board (R4):** `… W-188 D  W-200 ·  W-189 · …`. W-200 is the first open item. The resume check matched: last item
commit `81039bbf` (W-188), tree clean.

### What I found while planning

- **The board is not one line.** W-200's row says "STATE line 60", but the board is every `Phase …` line of
  STATE's `## Status board` block: Phase 0 – 15 plus 4b, 475 entries. W-075a and W-078f, two of G5's eight, sit on
  the Phase 7 / 8 lines. The check must read the whole block. I take this to be what the row means; it is stated
  here so you can say otherwise.
- **A reader of that block already exists:** `CoverageBacklogTest.statusBoard(List<String>)` (private,
  `taxengine/rules/coverage/CoverageBacklogTest.java`).
  - It reads from `## Status board` to the `Counts` line, entries `(W-[0-9]{3}[a-z0-9]*) (\S)`.
  - It has its own test, `statusBoard_whenTheBoardBlockIsRead_mapsEachItemToItsStatus`.
  - It treats `D` and `—` (retired or split) as finished: `FINISHED = Set.of("D", "—")`.
  - Writing a second copy would break "one word per concept" and "before inventing one, confirm nothing equivalent
    exists". See C1.
- **Today's tree passes the rule** (a dry run in Python over the same files):
  - The only finished item with open steps is W-180, and all three of its open steps say *"not taken: closed,
    D-387"*.
  - One plan, `plans/W-071.md`, has no board entry: W-071 was split into W-071a … (D-110) and the board lists only the
    children. See C3.
- **The tiers:** `CoverageBacklogTest` is untagged, so it runs in the unit tier, and that tier is what the pre-commit
  hook runs. A test placed the same way fails a commit in a Claude session, and fails CI.

### Choices (recommended first)

- **C1 — the board reader:**
  - **(a) recommended:** move `statusBoard` out of `CoverageBacklogTest` into a test-support class,
    `com.thiru.wealthlens.testsupport.StatusBoard`.
    - It gets one static `read(List<String>)` returning `Map<String, String>`, and the finished set as a
      predicate, `isFinished(String status)`. The `BOARD_ENTRY` pattern and `FINISHED` move with it.
    - `CoverageBacklogTest` calls it, and its existing reader test moves with the code as `StatusBoardTest`.
    - No behaviour of `CoverageBacklogTest` changes. Its five tests stay, less the moved one.
  - **(b)** The new test keeps a private copy of the reader.
- **C2 — which statuses count as finished:**
  - **(a) recommended:** `D` and `—`, the same set `CoverageBacklogTest` uses. A retired or split parent's plan is
    also finished work.
  - **(b)** `D` only, as W-200's row words it.
- **C3 — a plan whose item is not on the board** (W-071 today):
  - **(a) recommended:** not this check's concern. It is skipped, because the rule is about finished items and a
    missing entry is no status. Named in the test's Javadoc.
  - **(b)** Fail on it as well. W-071 would then need a board entry or a note first, which is a change outside this
    row.
