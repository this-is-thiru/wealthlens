## Plan for W-050a — a rounding on a rule row (D-076, split from `W-050`)

**What this item is for (one sentence):** a rule version can state a rounding, read from the pack like
a relief. `W-050`'s two rows then state "to the nearest ₹10" as data, and the loader no longer refuses
them as rows that carry nothing.

### What I read

- **The `W-050a` row**, D-076 and `plans/W-050.md` A1.
- **The `W-049a` pattern (D-075):**
  - `RuleRelief`;
  - `RuleVersion`'s `Optional<RuleRelief> relief` after `cap`, and its constructor refusing a null
    relief and a cap beside a relief;
  - `ShapeJson.relief` (tagged, `limitedToSlabRateTax` required);
  - `RuleJson.relief(...)` and `capOrNull`'s "has no cap, relief or conditions" refusal;
  - `RuleJsonReliefTest`, which asserts that message.
- **The 13 `new RuleVersion(` sites:** `RuleJson` and 6 test files, unchanged since `W-049a`; the
  `TaxByBasisNodeTest` copy passes `v.relief()`.
- **`Money`:** scale 2; `isGreaterThan`, `ZERO`.

### Choices (recommended first)

- **C1 — the type.** `rules/rounding/RuleRounding(Money toNearest)`, placed beside `rules/relief/`.
  - The constructor refuses a null, a zero or negative amount, and one with paise: a rounding step is
    a positive whole number of rupees.
  - It does **not** refuse amounts other than 10. D-076 puts that refusal in `W-050`'s node, where
    the only implemented method is s.516's; the type states the data, not the Act.
- **C2 — on `RuleVersion`:** `Optional<RuleRounding> rounding` after `relief`, with
  `Optional.empty()` for none (a null is refused, as for `relief`). **At most one of cap, relief and
  rounding** is present; the constructor refuses two, naming both.
- **C3 — JSON:** a `rounding` block beside `cap` and `relief`, **untagged**:
  `"rounding": { "toNearest": "10" }`.
  - Unlike caps and reliefs it isn't a family, and a `type` field would be a tag with one value
    (standards: no speculative generality).
  - `toNearest` is required and a rupee string, like every amount in the pack. A bad value is refused
    naming `…rounding.toNearest`.
- **C4 — the must-carry rule:** a rule must carry a cap, a relief, a rounding or conditions. The
  refusal becomes *"has no cap, relief, rounding or conditions"*; `RuleJsonReliefTest`'s assertion
  moves to the new wording, which only changes the message.
- **C5 — the 13 sites:**
  - 12 pass `Optional.empty()`;
  - `TaxByBasisNodeTest`'s copy passes `v.rounding()`, as it passes `v.relief()`;
  - `RuleJson` passes the parsed block.
