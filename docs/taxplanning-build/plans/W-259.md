## Plan for W-259 — the synthetic pack's generator keeps every row kind

> **Approved — C1a, C2a, C3a, C4** (owner, session 106, 2026-11-18: "approved C1a, C2a, C3a and C4"). Every path:line below was read this session at `1eee5163`.

**What this item is for (one sentence, in my own words):** running `tools/w146_synthetic_pack.py` again must not silently drop the
synthetic pack's hand-written rows and locks, and some check must say when the committed pack and a regeneration differ.

### What the design, the code and the sources say

- **The generator:** `docs/taxplanning-build/tools/w146_synthetic_pack.py` writes `backend/src/test/resources/rulepacks-synthetic`. It
  starts with `shutil.rmtree(ROOT, ignore_errors=True)` (line 95), so everything under the pack goes first. Its own header says the
  three locks are then written by a spike test (`zz_synthetic_spike_test.java.txt`) run by hand. Its synthetic law (three regimes, rate
  tables, the standard deduction) is its own; every other row is **copied from the shipped TY 2026-27 timeline** with its regime
  references renamed.
- **The committed pack** (`find`): 51 components, 30 pipelines, 242 rules, 3 regimes, 2 disallowance sets, 1 condition set,
  `rule-sets.json`, `shipped-years.json`, and, written by hand or by the spike, **3 `exec/declarations`, 3 `exec/funds`, 2
  `forms/itr-forms`, and 3 locks** (`2099-00`, `2100-01`, `2101-02`). Six test classes read it, among them `SyntheticPackTest`,
  `DeclarationProjectionTest`, `ItrFormProjectionTest` and `ItrFormCoverageTest`.
- **Probe (run in a scratch copy of the repo, nothing in the tree touched):** the generator wrote 333 files. Against the committed pack:
  - **Lost:** the 3 locks, `exec/declarations`, `exec/funds`, `forms/`. That is the defect the row names.
  - **Drift, new:** `exec/components/UNCOMMUTED_PENSION.json` (W-242) and `law/rules/INT-REFUND.json` with its `RS-INT-REFUND` set
    (W-112b). These are shipped rows added after the pack was last generated (`6445f864`, W-146, 2026-11-07).
  - **Drift, changed:** `INT-DEFERMENT.json` (its copied `_note`, from W-112a) and `rule-sets.json`.
  - So a regeneration today changes the synthetic pack even once the lost directories are kept. The pack is stale against the
    timeline it copies.

### Choices for the owner (recommended first)

- **C1 — keeping the hand-written rows:**
  - **(a)** The generator deletes and rewrites only what it writes: `law/rules`, `law/regimes`, `law/disallowances`,
    `law/condition-sets`, `exec/components`, `exec/pipelines`, `rule-sets.json`, `shipped-years.json`. It leaves `exec/funds`,
    `exec/declarations`, `forms/` and the locks as they are, and its header names both lists.
  - (b) The generator also writes funds, declarations and forms, their rows moved into the script as data. One source for
    everything, but the hand-written rows (synthetic-specific, W-238e / W-090a1 / W-090c) move into Python.
- **C2 — the drift found by the probe:**
  - **(a)** Regenerate now, so the copies follow today's shipped rows (UNCOMMUTED_PENSION, INT-REFUND, INT-DEFERMENT's note,
    rule-sets). Then relock the three years through the spike test, as the tool's header describes, and run the synthetic test classes.
    A figure that moves is shown in the report with its cause, never silently re-baselined.
  - (b) Leave the drift. The fix then only stops the deletion.
- **C3 — what proves it from now on:**
  - **(a)** A test, `SyntheticPackGeneratorTest`, runs the generator (`python3 -I`) into a temporary copy. It fails if any committed
    file is missing afterwards, or if any file the generator writes from **its own synthetic law** differs. Rows it **copies from the
    shipped timeline** are compared and listed in the failure message only when the generator's own files also differ. A shipped data
    change then does not break the build, but every regeneration is shown to keep every row kind.
  - (b) Byte for byte over the whole timeline, as the row's wording says. Every future edit to a shipped TY 2026-27 row would then
    fail this test until the synthetic pack is regenerated and relocked: the drift detector, at the cost of an extra step on every
    shipped data change.
  - (c) No test; the header's instructions only.
- **C4 — where `python3` comes from:** the owner's Mac and CI's `ubuntu-latest` both have it (the probe ran `python3 -I` here). With
  no `python3` the test **fails**, naming it, rather than skipping: a check that can skip silently is no check.
