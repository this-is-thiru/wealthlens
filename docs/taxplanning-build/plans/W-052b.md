## Plan for W-052b — from the runner's result to a `TaxComputation` (STATE Q3)

**What this item is for (one sentence):** say, once and in code, which pipeline slot is `totalIncome`,
which is `taxByBasis` and which is `netPayableBeforeFilingEffects`, so a pipeline run becomes the
durable, date-independent `TaxComputation` that `W-053` and the API read.

### What I read

- **The `W-052b` row:**
  - Produces `result/ComputationProjector` + test;
  - Do: *"read the anchor slots (`NodeIds.TOTAL_INCOME`, `NodeIds.TAX_BY_BASIS`, `NodeIds.NET_PAYABLE`,
    …) into `TaxComputation`; a missing anchor fails with its name."*
- **STATE Q3** (answered by D-043 with this item): *"Something must say which slot is `totalIncome` and
  which is `taxByBasis`."*
- **`PipelineRunner.Result(order, values, trace, inputs, lawAndExec)`** and its `valueOf(NodeId)`,
  which already refuses a slot the run didn't produce, naming it and the order. It carries **no tax
  year and no regime**.
- **`TaxComputation`:**
  - `(id, taxYear, regime, lawAndExec, inputs, trace, totalIncome, taxByBasis,
    netPayableBeforeFilingEffects)`;
  - the javadoc: `totalIncome` is *"total income, after every deduction and set-off"*; `taxByBasis` is
    *"tax split by the basis it was charged on … because the rebate reads one and not the other"*;
    `netPayable…` is *"the bill the statute computes before anything that depends on when the return
    is furnished"*;
  - *"No component of this record is a date"*.
- **`ComputationId.fresh()`** is random: *"two computations of the same inputs differ in their id and
  in nothing else"*.
- **`DR 15` B3 graph:** `tax.netpayable → interest.and.fees → round.netpayable`.
- **`DR 23` A6:** interest and fees live in the date-dependent `FilingPosition`.
- **S2 s.516:** the rounded amount *"shall be deemed to be the total income"*.
- **`NodeIds`:** the constants are `ROUND_TOTALINCOME`, `TOTALINCOME`, `TAX_BYBASIS`,
  `TAX_AFTERREBATE`, `TAX_NETPAYABLE`, `ROUND_NETPAYABLE`. The row's `TOTAL_INCOME`, `TAX_BY_BASIS`
  and `NET_PAYABLE` don't exist.
- **Dependencies:** `result` already imports `pipeline` (`TaxByBasis`); `pipeline` imports nothing
  from `result`.

### Findings

1. **The row's constant names don't exist.** The generated ones are named for the timeline's slots
   (finding for the erratum).
2. **Each anchor has two candidate slots, and the choice is a legal reading** (C1).
3. **`Result` lacks the tax year and regime**, and the id is random by design, so the projector takes
   them from its caller.

### Choices (recommended first)

- **C1 — the anchors:**

  | Field | Slot | Why |
  |---|---|---|
  | `totalIncome` | **`round.totalincome`** | s.516: the rounded amount "shall be deemed to be the total income". It's also what every tax node reads. The unrounded `totalincome` is a working figure |
  | `taxByBasis` | **`tax.bybasis`** | the field's own javadoc: the split exists "because the rebate reads one and not the other", so it's the tax before rebate. The post-rebate tax is recoverable from the trace's `RELIEF` lines |
  | `netPayableBeforeFilingEffects` | **`tax.netpayable`** (unrounded) | `round.netpayable` comes after `interest.and.fees` in the design's graph, and interest depends on the filing date (A6), so it can't sit in a date-independent record. Rounding `tax.netpayable` here would add a third rounding point (`RATE-ROUND-003`) |

  **A consequence for `W-053`**, stated now: `DR 08`'s "Expected" figures are **rounded** (T1-N3:
  ₹52,000; T1-N2: ₹10). So `W-053` compares them against `round.netpayable` from the run, not against
  this unrounded field. That becomes an erratum on `W-053`'s row.
- **C2 — the signature:** `static TaxComputation project(PipelineRunner.Result run, EngineInputs inputs,
  ComputationId id)`.
  - `taxYear` and `regime` come from `inputs`.
  - `inputs` is checked against `run.inputs()` (`InputsFingerprint.of(inputs)` must equal it), so a
    result can't be projected under the wrong year or regime.
  - The id is passed in, so identical inputs project to equal computations bar the id (T23-4, `W-053`).
- **C3 — failures:**
  - A missing anchor fails through `valueOf`, which already names the slot and the order the run took.
  - An anchor of the wrong value type is refused, naming the slot and both types.
  - A fingerprint mismatch is refused.
  - All are `IllegalArgumentException`: the caller passed a run this projection can't read.

### Numbers

None from the law. The projection copies values; the test's figures are arbitrary markers (e.g.
₹12,00,000, ₹60,000, ₹52,000), asserted to land in the right fields.
