### Decisions (for approval with this plan)

- **C1 — what a response holds.** **C1a (recommended):** the same JSON names as today, so a client reading a field keeps reading it,
  less what is stored only for the app: `auditMetadata` on every one of them, and on transactions `idempotencyKey`,
  `tradeFingerprint`, `submittedAt`, `assetRequest`, `tradeFlow`. Ids stay (routes take them: corporate action `id`, a transaction's
  id). **C1b:** keep `auditMetadata` on a user's own rows (their own email) and drop it only on reference data.
- **C2 — one word per concept.** **C2a (recommended):** a transaction answers as the existing `TransactionResponse` and a holding as
  `AssetResponse` (as `GET /me/portfolio/transactions` and `/stocks/all` already do); a new response record for each of the other
  seven: `ChargeScheduleResponse`, `ChargeCatalogueResponse`, `ChargeAccountResponse`, `UserChargeResponse`,
  `CorporateActionResponse`, `GazetteLeadResponse`, `GazetteCursorResponse` — each in its module's `dto`, with a `from(entity)`
  that names its fields (no reflection copy, so a new stored field never reaches a caller by accident). Embedded value types that
  are not documents (`ChargeRule`, `ChargeLine`, the demerger detail) pass through. **C2b:** one generic copy (`TJsonMapper.copy`)
  into each record.
- **C3 — the two request bodies.** **C3a (recommended):** out of scope; W-206 stays parked as the owner placed it. **C3b:** take W-206 in
  here (request DTOs for publish and register).
- **C4 — `AssetResponse` / `TransactionResponse` already carry `auditMetadata`.** **C4a (recommended):** drop it there too, as C1a
  (one rule for every response). **C4b:** leave those two as they are.
