## Plan for W-206 — request types for the routes that bind a stored document

> Planned in session 114 (2026-11-21), placed by D-863 (before W-359b, so the generated spec documents request types). **Stop point:
> nothing is built until the owner answers C1 – C5.**

**What this item is for (one sentence, in my own words):** a request body binds to a type that names what a caller may send, never to a
stored document, so a field the server owns cannot be written from outside and a new route cannot drift back to an entity.

### Probes (run this session, all reverted; tree clean)

- **Billing state:** an account registered with `"lastBilledThrough": "2099-12-31"` is stored with it (expected null, was 2099-12-31).
- **Guard:** a request-side twin of `ResponseContractTest` (no `@RequestBody` parameter is a `@Document` type, generics included)
  fails on today's code naming exactly `ChargeSchedulePublishingController.publish` and `ChargeAccountController.register`.
- **`AssetEntity` without both annotations:** only W-205's empty-body test fails (`{}` → `price` null into `double`, which no route
  sends any more); CorporateAction 48, BonusAllotment 2, StockSplit 7, LotLedger 9, Portfolio 43 and CreationAudit 3 all pass.

### Decisions (for approval with this plan)

- **C1 — the shape.** **C1a (recommended):** two records in `brokercharges/dto/request/`, `ChargeAccountRequest` and
  `ChargeScheduleRequest`, each building its entity (`asAccount(email)`, `asSchedule()`); the services keep their signatures. A new
  guard, `RequestContractTest.handler_whenItReadsABody_neverBindsAStoredDocument`, beside `ResponseContractTest`.
  `RequestBoundEntityBindingIntegrationTest` is deleted: its two entity cases guard binding that no longer happens (the new guard holds
  that), and its rule case is already covered over HTTP by `CallerMistakeIntegrationTest`. **C1b:** a class DTO
  (`@Data @NoArgsConstructor`, the older convention).
- **C2 — what a user may send for an account.** **C2a (recommended):** `accountHolder`, `brokerName`, `dematAccountId`, `planCode`,
  `openedOn`, `amcFrequency`, `status`, which is what `register`'s update path copies today. `lastBilledThrough` and
  `billingEvents` are the AMC run's, so a body naming them is refused 400 as an unknown field. **C2b:** also drop `status` (a user could
  set `SUPERSEDED`, which has no meaning for an account); a user could then no longer mark an account inactive, a capability they have today.
- **C3 — a card that omits `requiresInstrumentProfile`.** **C3a (recommended):** as today, absent means `false` (a `Boolean` in the
  record, read as `Boolean.TRUE.equals`); a refactor does not change what a card means. **C3b:** refuse the omission, as a rule's
  primitives are; nearly every card body in the tests omits it, and so may a caller.
- **C4 — a card's rules.** **C4a (recommended):** the request carries `List<ChargeRule>` as it is: `ChargeRule` is an embedded value
  (no `@Document`, no server-owned field), and its 27 fields are the card's language. **C4b:** a rule request type mirroring them.
- **C5 — `AssetEntity`'s annotations.** No request binds it now. **C5a (recommended):** remove both, with all six annotations on the
  three entities going as the row says. A bonus lot's copy then carries the source lot's `auditMetadata` until it is saved. Its `id` is
  null, so the save treats it as new and auditing writes its own author and time. **Checked at the build, not assumed:** a test that the
  allotted lot's stored `created_at` is later than the source lot's. **C5b:** keep them on `AssetEntity`, with the comment corrected to
  name the copies.
