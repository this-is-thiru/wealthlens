## Plan for W-137 (with W-136) — background jobs, auto-archive and retention purge

**For:** stored drafts don't pile up or outlive their purpose. A draft nobody touched for 18 months is archived, and
archived or expired drafts are deleted on a schedule whose legal part is read from the rule pack (`DR 19` E8,
`DR 11` F6, `DR 14` O5; D-447 C6a).

### What I read (session 47)

- `DR 19` E8 names six jobs and a `TaxJob` interface (type, timeout, retry, singleton, run), a Mongo lease
  (`tax_job_leases`, TTL index, fencing token) and a dead-letter collection `tax_job_failures`.
- **Nothing schedules today:** grep for `@EnableScheduling`, `@Scheduled`, `TaskScheduler` over `backend/src/main` finds
  nothing. No Micrometer or actuator dependency is in either pom, so E8's `taxplanning.job.failed` metric has nowhere
  to go.
- **Which of the six have something to act on:**

  | Job | Acts on | Status |
  |---|---|---|
  | `AutoArchive` | drafts (`DraftStatus` has `ARCHIVED`; F6: `DRAFT` untouched 18 months, not primary) | **buildable** |
  | `RetentionPurge` | archived and expired drafts, their revisions and computations | **buildable** |
  | `StalenessSweep` | `ACTED_ON` / `READY` drafts on a pack upgrade | its own row, **W-138** (next) |
  | `ParseDocument` | uploads | none exist — W-131 (Phase 13) |
  | `GeneratePdf` | `ComputationCompleted` | not built — W-123 (Phase 12) |
  | `GazetteWatch` | the Gazette index, opening a ticket | no source or ticket target designed |

- **Retention's law is in the pack:** `LossCarryForward(…, TaxYearSpan(8), …)` in `SETOFF-CARRIED-HOUSE-PROPERTY` and
  `SETOFF-CARRIED-CAPITAL-GAINS`, read from the Gazette (Income-tax Act, 2025 ss.110(2), 111(2)). `taxplanning` reaches
  the engine through `taxengine.api.TaxCalculator`, which already reads a year's pack (`defaultRegime`).
- **Facts a draft lacks:** `FilingDraft` stores neither when it was acted on nor when it was archived; `DR 11`'s model
  lists both (`actedOnAt`, `archivedAt`, line 87). Without `actedOnAt`, an `ACTED_ON` draft the user then archives
  (the transition map allows it) would be deleted after 12 months, not 8 years.
- `DR 11` F6 (archive `DRAFT` only, never the primary) is narrower than `DR 14` O5 ("`DRAFT` / `READY`"). F6 is the
  more specific of the two, so I follow it.

### Choices (recommended first)

**C1 — which jobs.** (a) The framework (`TaxJob`, `JobLease`, `tax_job_failures`) plus `AutoArchive` and
`RetentionPurge`. `StalenessSweep` comes in W-138 on the same framework. `ParseDocument` joins W-131 and `GeneratePdf`
joins W-123, each built with its trigger. `GazetteWatch` is placed as **W-236**, to be designed (source, ticket
target). E8's retry policy is not built: both jobs are idempotent and simply run again next period. (b) All six now,
four of them with nothing to act on.

**C2 — what the purge deletes.** (a) Drafts with their revisions and computations, by these facts:
- an `ACTED_ON` draft, or any draft with `acted_on_at`, is kept to the end of its tax year plus the pack's longest
  carry-forward span;
- any other `ARCHIVED` draft is deleted 12 months after `archived_at`.

A year with no pack, or with no `LossCarryForward`, is refused: kept, with a `tax_job_failures` row naming the year.
Landlords and lenders (profile-level, "erased with the draft") and the 8-year pseudonymising of the audit log go to
**W-235**, since nothing reaches either for years. (b) Every row of the O5 table now.

**C3 — the non-legal periods** (F6's 18 months, O5's 12 months). (a) Config in all three profile yamls:
`app.tax.retention.archive-after: P18M`, `purge-archived-after: P12M`. They are product policy, not law; only the
8 years is law, and it comes from the pack. (b) Rule-pack data.

**C4 — running them.** (a) `@EnableScheduling` with cron in config (`AutoArchive` weekly, `RetentionPurge` monthly),
each run under a `tax_job_leases` lease: TTL-indexed `expires_at`, and a fencing token re-checked before each delete
batch. A master switch `app.tax.jobs.enabled` is on in the profile yamls and off in the integration test, where tests
call the jobs directly. A failure is logged at ERROR and written to `tax_job_failures`; no metric. (b) The same, plus
the actuator and Micrometer for E8's metric.

### Tests, by hand (as of a fixed `Clock`)
- **Archive:** at 2026-11-06, 18 months back is 2025-05-06.
  - A `DRAFT` last changed 2025-05-05 → archived; one changed 2025-05-07 → kept.
  - The primary, or a `READY` draft, both changed 2025-05-05 → kept.
- **Purge, archived:** at 2026-11-06, 12 months back is 2025-11-06. `archived_at` 2025-11-05 → deleted with its
  revisions and computations; 2025-11-07 → kept.
- **Purge, acted on, TY 2025-26:** the year ends 31-3-2026, and its 8 succeeding years end 31-3-2034.
  - At 2034-03-31 → kept; at 2034-04-01 → deleted.
  - The same, archived by the user 2026-05-01, at 2027-06-01 → kept (12 months passed, 8 years not).
- **No pack:** an `ACTED_ON` draft for TY 2019-20 → kept, one failure row naming 2019-20.
- **Lease:** a second runner while a lease is live → does nothing; after expiry → runs. A run on stale data
  (fencing token moved on) → stops before deleting.
- **Engine:** `longestCarryForward` for TY 2025-26 and 2026-27 → 8, read from the shipped packs; a fixture pack
  without the rows → empty.
- **Probes:** drop the `acted_on_at` check → the archived-after-acting case is deleted, so its test fails; bypass the
  lease → the second-runner test fails.

- **Automation tester:** the hand cases above with a fixed `Clock`; the engine figure from the shipped packs.
- **Manual tester:** on staging, set the archive cron to a minute ahead, create a draft, set its `audit_metadata`

proof.

### Build record (D-449)

**Departures from the plan, each found while building:**
1. **The engine read unwraps an `Optional`.** `RuleVersion.definition()` is optional; my first version filtered the
   `Optional`s and found nothing. The engine test caught it: 8 for both shipped years now.
2. **No "pack without carry-forward" engine test.** The fixture packs are refused when they hold no rules, and a
   `RulePack` cannot be built short of a full pack. The case shares its code path with "no pack" (`max()` of nothing),
   which is tested.
3. **The lease's `expires_at` is an `Instant`.** As a `LocalDateTime` in UTC, Spring Data would store it shifted by the
   server's zone, so on a server not in UTC the TTL index would expire a live lease early.
4. **The derived query is `findByStatusAndAuditMetadataUpdatedAtBefore`.** Checkstyle refuses the underscore form,
   and `AuditMetadata` has no `@Field` names, so the stored field is `audit_metadata.updatedAt`.
5. **An unexpected failure inside a job is not dead-lettered.** Catching it would need `catch (RuntimeException)`
   (CLAUDE.md §2). It reaches the scheduler, which logs it, and the lease lapses at its timeout. `tax_job_failures`
   holds the job's own refusals: a year with no pack.
6. **A deleted draft that was its workspace's primary leaves the workspace with none.** The access log and the regime
   election history stay (`DR 14` O4, O5).

**Probes, each reverted byte for byte (`cmp`):** purge ignoring `acted_on_at` → the filed-then-archived case fails;
the lease bypassed → the held-lease case fails. Two failures, those two tests.
