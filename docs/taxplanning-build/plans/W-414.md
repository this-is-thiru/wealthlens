### W-415 — two caller mistakes answered 400 (code)

**Files I will modify:**
- `shared/entity/query/QueryBuilder.java` — `sanitize` turns an unreadable date into
  `IllegalArgumentException("A date filter's value must be a date as yyyy-MM-dd; got '<value>' for <filterKey>")`,
  which `ControllerAdviser` already answers 400 (C2).
- `shared/exception/ControllerAdviser.java` — `@ExceptionHandler(MultipartException.class)` → 400
  `"The upload could not be read as multipart form data"`, logged as a refusal (`refused(ex)`). `MaxUploadSizeExceededException`
  is a subclass and keeps its own, more specific handler (`ControllerAdviser.java:92`; Spring picks the closest match).
- `integration/CallerMistakeIntegrationTest.java` — two tests (below).

**Facts:** `QueryBuilder.toSpecification` calls `sanitize` (`QueryBuilder.java:48`), which calls
`TLocalDate.convertToDate` → `LocalDate.parse(date, yyyy-MM-dd)` (`TLocalDate.java:25 – 28`); its
`DateTimeParseException` reaches `@ExceptionHandler(Exception.class)` (`ControllerAdviser.java:153`) → 500. No handler
names `MultipartException` (`rg`). The same code is in `m1.6.1`. No test today sends a bad date or a broken multipart body
(`rg` over `backend/src/test`: none), so no existing test moves.

**C2 — where the date is refused.** **C2a (recommended):** in `QueryBuilder.sanitize`, the one place a filter's date is
read, naming the key and the value. **C2b:** a global `DateTimeParseException` handler in `ControllerAdviser` — broader,
but it would also turn a server's own bad parse (a stored value, a rule pack) into a 400, hiding a defect.

**Tests (red first, each proven red by running it before the change):**
- `search_whenADateFilterIsNotADate_expected400NamingIt` — `POST /api/v1/me/portfolio/assets/search` with
  `transaction_date` `"2024-12-3"`, `isDateField: true` → 400, `detail` naming `2024-12-3` and `transaction_date`.
- `upload_whenTheMultipartBodyCannotBeParsed_expected400` — `POST /api/v1/me/portfolio/transactions/uploads` with
  `Content-Type: multipart/form-data; boundary=x` and a body without that boundary → 400, the message above. If Tomcat
  answers this before Spring (no `MultipartException`), the test's red run shows it and I stop and report (R13).
