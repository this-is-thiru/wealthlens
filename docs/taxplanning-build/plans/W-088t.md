## Plan for W-088t — one tax-year derivation

**What this item is for (one sentence):** the tax year a date falls in is answered by `TaxYearId` itself, from the
boundaries it already defines (`startsOn` / `endsOn` / `contains`), instead of an inline "month ≥ 4" rule wherever a
date is turned into a year (review E7; D-250; CLAUDE.md §4 "one source").

**Behaviour unchanged:** every value and trace line, because the same dates map to the same years.

### Design

1. **`TaxYearId.containing(LocalDate date)`**, public static: the tax year a date falls in.
   - Defined through the type's own boundary: `of(date.getYear())` if that year `contains(date)`, else
     `of(date.getYear() - 1)`.
   - The April rule therefore stays only in `startsOn` / `endsOn`.
   - It refuses a null date.
   - Javadoc: "the one place a date becomes a tax year (W-088t)".
2. **`HousePropertyInterest`:** `taxYearOf` is deleted, and its two calls become `TaxYearId.containing(…)`.
3. **`OtherSourcesNodeTest.years`:** its body becomes `TaxYearId.containing(issuedOn)`. The helper stays, because
   its name says what the fixture means.
4. **Docs:**
   - TS T3 `id/` (`TaxYearId.containing`) and a Changes row;
   - WI "Built";
   - W-088l's row notes `TLocalDate.financialYear` as a third copy outside the tax modules;
   - STATE D-269; CHECKPOINT.

### Choices (recommended first)

- **C1 — the name:**
  - **(a) recommended:** `containing(date)`, which pairs with the existing `contains(date)` and reads as

    different kinds of argument.
