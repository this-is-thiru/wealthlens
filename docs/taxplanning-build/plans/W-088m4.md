## Plan for W-088m4 — elections name rule sets

**What this item is for (one sentence):** `HouseElection` and `SetOffOrderElection` stop naming `RuleIds`. Each reads
its rule through the rule set its own node declares, with the node's selection. The W-088m3 guard then widens to
`taxengine.election` (D-254).

**Behaviour unchanged:** the same rows (`HP-OWN-RESIDENCE`, `SETOFF-ACROSS-HEADS`), the same candidates, the same
priced lines and trace row ids.

  priced line cites; `candidates(EngineInputs, RulePack)` lists the choices.

### Design

1. **The election reads its rule as its node does.**
   - `Election.basis(T choice, NodeContext rules)` and `Election.candidates(NodeContext rules)` take a context scoped to
     the election's `node()`, in place of the pack and inputs (both are on the context).
   - `ElectionResolver` builds it once per election: `NodeContext.forRun(pack, regime, inputs)` then
     `.forNode(registry.producing(election.node()))`, in the computing regime.
   - So an election can read only a set its node declares, chosen the same way (regime, conditions, item). I3 keeps
     counting it through the node.
2. **Each election names its set:**
   - `HouseElection`: `rules.ruleOf(RuleSetIds.RS_HP_OWN_RESIDENCE)`;
   - `SetOffOrderElection`: `rules.ruleOf(RuleSetIds.RS_SETOFF_ACROSS_HEADS)`;
   - `basis` returns that row's id.
   - `RegimeElection` adapts to the signature only (`rules.pack()`, `rules.inputs()`).
3. **The guard widens.** `nodes_reach_rules_through_rule_sets` becomes `nodes_and_elections_reach_rules_through_rule_sets`
   over `..taxengine.node..` and `..taxengine.election..`. TS T10 changes the same way.

### Choices (recommended first)

- **C1 — how an election reaches a row:**
  - **(a) recommended:** through its node's context, as above. One selection mechanism, and I3 and the
    undeclared-set refusal come with it.
  - **(b)** extract `NodeContext`'s selection into a type callable with (pack, regime, inputs). This refactors
    `NodeContext` for two callers.
  - **(c)** read the one-row set's only member straight from the pack, refusing more than one. This is a second, partial
    selection, and a regime's variant row would not be reachable.
- **C2 — the map scan:**
  - **(a) recommended:** leave `nodes_hold_no_map_to_a_rule_set` on the node package. No election holds such a map, and
    the WI row names the ArchUnit rule.
  - **(b)** widen it too.
