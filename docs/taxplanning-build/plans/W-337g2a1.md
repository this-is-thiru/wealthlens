## Plan for W-337g2a1 — the copier's first child tables: refresh_tokens, insurances, privacy_breach_notices

> Planned in session 123 (2026-11-26) under W-337g2's approved choices (D-970: C3a parent and children in one transaction).
> **Stop point (Stage 2 EXPLAIN):** nothing is built until the owner approves C1 – C3 below.

**What this item is for (one sentence, in my own words):** teach the copier to fill a child table from a list a
`m1.6.1` document holds, and specify the three collections whose only embedded data is such a list, so they copy and are
proven like the 22 flat ones.

### What the three hold at `m1.6.1` (read this session, `git show m1.6.1:…`) and where it goes

| Source key (as stored) | Element | Target (`V1__auth_and_insurance.sql`, `shared/V3__privacy.sql`) |
|---|---|---|
| `refresh_tokens.factors` (`RefreshToken.java` `@Field("factors")`) | a string (`FACTOR_PASSWORD` …) | `refresh_token_factors (refresh_token_id, factor)` — V1:29-32 |
| `insurances.policyDetails` — **no `@Field`, so the Java name** (`InsuranceEntity.java` m1.6.1) | a sub-document, keys by `PolicyDetails`' `@Field`s: `policy_id`, `premium`, `start_date`, `end_date`, `policy_name`, `broker_name`, `agent_name`, `agent_email`, `agent_contact`, `agent_address`, `insurance_status`, `notes`, `policy_description` | `insurance_policy_details (insurance_id_fk, …)` — V1:59-74, every key the column of its own name |
| `privacy_breach_notices.affected` (`BreachNotice.java` m1.6.1, `@ValueConverter(SearchableIdentifier.class)`) | searchable ciphertext, one per element (`SearchableIdentifier.write` maps a collection element by element) | `privacy_breach_notice_affected (notice_id, affected)` — V3:94-97 |

Every other key of the three is flat and already handled by `RowMapping` (top-level `Instant`s → `TIMESTAMPTZ`, the
breach notice's `LocalDateTime`s and `audit_metadata` per D-954). Encrypted values (`policy_id`, the agent fields, `notes`,
`policy_description`, `affected`) are carried as ciphertext; the read-back through `InsuranceEntity` / `BreachNotice`
(EAGER element collections) proves they decrypt. The only time in a child is `PolicyDetails`' two `LocalDate`s — midnight
UTC through `ColumnValue.date`, as in g1. No child table has an order column, and neither entity has `@OrderColumn`, so
the app never kept list order there either; children are compared as multisets.

### Decisions (for approval)

- **C1 — how a child is specified.** **C1a (recommended):** a record `ChildCopy(key, table, parentColumn, valueColumn)` with two
  factories — `ChildCopy.values(key, table, parentColumn, column)` (a list of plain values, one column) and
  `ChildCopy.documents(key, table, parentColumn)` (a list of sub-documents, each key to the column of its name, `_class`
  skipped, a key with no column refused, `null` left out — `RowMapping`'s rules); `CollectionCopy` gains `List<ChildCopy> children`
  (`sameName` keeps an empty list). A child table is read by a new `ChildTable` record (columns and types from
  `information_schema`, no primary key) beside `TargetTable`. **C1b:** one generic "embedded" mapping for children, embedded
  columns and JSON — speculative until g2a2 / g2b need it; not recommended.
- **C2 — the transaction (W-337g2 C3a).** **C2a (recommended):** each source document is written in one transaction from a
  `TransactionTemplate` over a `DataSourceTransactionManager` the copier builds on its `DataSource` (the context has two
  `PlatformTransactionManager`s — Mongo's and `postgresTransactionManager`, `PostgresJpaConfig.java:93`; the copier needs
  only JDBC); the parent `INSERT … ON CONFLICT (id) DO NOTHING` returns its row count, and the children are inserted only when
  it is 1. A parent without children stays one statement, as now. **C2b:** inject `postgresTransactionManager` with a qualifier;
  works, but couples the copier to the JPA manager for plain JDBC.
- **C3 — the check.** **C3a (recommended):** each parent's children enter its digest and its row comparison (sorted canonical
  child rows per child table), so a changed, missing or extra child is reported under the parent's key ("rows differ from the
  source: <id>"); and per child table, "N source child rows but M target child rows in <table>" when the summed list lengths
  and the table's count differ (W-337g2 C3a). **C3b:** counts only — would miss a child whose value changed; not recommended.
