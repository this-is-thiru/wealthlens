## Plan for W-045h — the publish diff, `PackDiff` (D-037)

**What this item is for (one sentence):** before a rule change is published, list exactly what it
changes — which rules and versions appear or disappear, and every value that moves — so the reviewer
signs off a list rather than a guess.

### What I read

- Brief §5.4: the gate is *author → validate → **diff** → golden suite → reviewer approves → compile
  and lock*. Files in the repository today, reviewed as a pull request; the golden re-run is the build.
- TS T2: `PackDiff` in `validate/`, which **`W-139` reuses** for the cross-year diff and extends with
  lint findings.
- `DR 15` C4 (the source of the shape, read so as not to invent a rival):
  `record PackDiff(TaxYearId from, TaxYearId to, List<Finding> findings)`, with `Finding` sealed:

### The change

`PackDiff.between(CompiledPack before, CompiledPack after)` → `PackDiff(from, to, findings)`. It works
on the compiled `law/rates.json` (canonical JSON), rule by rule, sorted by id:

| Finding | When |
|---|---|
| `RuleAdded(RuleId)` / `RuleRemoved(RuleId)` | a rule is in one pack only |
| `VersionAdded(RuleId, version)` / `VersionRemoved(RuleId, version)` | a version of a rule in both packs is in one only |
| `ValueChanged(RuleId, version, field, before, after)` | a leaf value differs within a version held by both, or in the rule's top level; `field` is a path such as `cap.bands[1].rate`, and an absent side reads `(absent)` |

A version is identified by **its start date**: `validity.from` (or `deemedEffectiveFrom`), or `pending`
for a pending-notification version. So closing a version (adding an end date) reads as a
`ValueChanged` on `validity.to`, not as a removal plus an addition. Identical packs give
`findings().isEmpty()`. Because the canonical form drops notes, an edited note is not a change.

`VersionAdded`/`VersionRemoved` are new to the DR shape. The row's Verify asks for "every changed
version", and C4 has no finding for one.

### Choices (all recommended)

- **C1 — package `timeline/`, not `validate/`.** `PackDiff` takes `CompiledPack` (in `timeline`), and
  `timeline` already imports `validate` (`PackValidationException`), so `validate/` would create a
  cycle. TS T2 gets corrected.
- **C2 — the diff reads compiled canonical JSON,** not the assembled records. One generic walk covers
  every field of every cap shape, condition and provision, today and later, with no diff code per type.
- **C3 — `Magnitude` is left out** of `ValueChanged` until `W-139`, whose 10× lint is its only caller.
  The three lint findings are likewise `W-139`'s.
- **C4 — rules only.** Every finding in C4 is keyed by `RuleId`. A change to a **regime** (rate table,
  disallowances, lifecycle) is not diffed yet. I'll record that on `W-139` as an erratum, so the gap
  has an owner instead of going unnoticed.
