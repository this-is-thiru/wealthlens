### Choices (recommended first)

**C1 — test shape.** 41 records, most missing one or two branches.
- **(a) Recommended:** one table, `RuleDefinitionRefusalsTest`, in the `rules.definition` test package. It is
  one `@ParameterizedTest` over `RuleRefusals.refusal` cases, one bad field per case, using `withComponent` for any
  record of more than seven parts. Separate tests cover the three predicates: `TaxYearSpan.holds`,
  `PremiumShareBands.bandHolding`'s overlap refusal and `RuleDefinitions.require`'s wrong kind. This is about 300
  lines in 2 files.
- (b) One `<Record>Test` per record, as W-240a – c did. That is about 32 new classes and 9 extended, roughly 900
  lines, mostly boilerplate around one or two cases each.

**C2 — the gate.** **(a) Recommended:** `check-taxengine-rules`' branch minimum moves 0.81 → **0.85**, X5.5's figure,
if the measure reaches it. If it falls short, I stop and report. I would not reach into `rules.json` without asking.
