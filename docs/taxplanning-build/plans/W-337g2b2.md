### C1 — a defect found while planning: `AssetRequest.orderExecutionDateTime` is lost in PostgreSQL

`AssetRequest.orderExecutionDateTime` is `@JsonIgnore` (`AssetRequest.java`, unchanged since `m1.6.1`). It is set only by the
Excel upload (`AssetRequestParser.java:210`, the cell's raw value) and read first by `orderExecutionDateTime()`, which
`asTransaction()` calls on redrive. MongoDB stored it (Spring Data ignores `@JsonIgnore`); `AssetRequestConverter` (W-337e)
writes JSON with Jackson, which drops it. So **on the PostgreSQL build today, an uploaded trade that is held as a temporary
transaction loses its execution time when redriven** — the redriven transaction and its lot get `null` order time. The
copier, building the same JSON, would drop it from every stored temporary transaction too.

- **C1a (recommended):** place **W-408 — keep an uploaded trade's execution time in `asset_request_json`**, built before this
  item: the stored form of `AssetRequest` includes `orderExecutionDateTime` (the API request still ignores it), with a red
  test — an uploaded trade held as temporary keeps its order time through redrive. W-337g2b2 then writes the same stored form,
  and `EmbeddedTimes` classifies the field as held (the cell's value, read in the written zone, as UTC-held times are).
- **C1b:** the copier drops the value and the report counts the documents that held it — loses data the owner entered; not
  recommended.
- **C1c:** the copier refuses a document holding it — would block the move on every such temporary transaction.
