## Plan for W-123b — the copy before erasure: find every report, and point to it

> **Approved as recommended — C1a, C2a** (owner, session 98, 2026-11-15). Written ahead by the planning session for
> a later build session; not yet built. Builds
> after W-123a, on its endpoint (`GET /tax/user/{email}/computations/{receipt}/report`, approved C4a) — confirm it as

**What this item is for (one sentence, in my own words):** before a person asks for a profile to be erased, let them
find every computation that profile holds and take its report — and say so where the erasure request is described
(D-477 C1a).

**Probe (2026-11-15; code and api-collection read, nothing run):**
- **Half of the row is already true once W-123a is built.** Its report reads through
  `DraftComputationService.byReceipt` (`compute/DraftComputationService.java:141-145`), which refuses a profile held
  for erasure. "Producible until held, refused once held" needs no new guard — W-123a's step 6 tests it.
- **What is missing: a way to find the receipts.** A computation is read only by a receipt already known
  (`DraftComputationController.java:85`); `DraftComputationRepository` has `findByReceiptAndEmail` and `findByDraftId`
  (`:9`, `:13`), and no endpoint lists a draft's or a profile's computations. A person who did not keep each receipt
  cannot take "every" report.
- **The two pointers.** `api-collection/Tax Profile/Request Erasure of a Profile.yml:25-26` says "the PDF report
  replaces them as the copy when W-123 is built". `ErasureController`'s Javadoc
  (`taxplanning/erasure/controller/ErasureController.java:12-15`) says nothing of a copy.
- **Account erasure** has its own entry (`api-collection/Privacy/Request Erasure of the Account.yml`); the *offer*
  before both erasures is W-247's row (D-477 C2a), and no client is in this repository.

**Choices for the owner:**
- **C1: how a person finds the reports.**
  - **C1a (recommended):** a read listing a profile's computations —
    `GET /tax/user/{email}/profiles/{profileId}/computations` — each with its receipt, tax year, draft label and
    revision, regime, and when it was computed, newest first. Each report is then taken by its receipt. Refused for
    another account and for a held profile, and recorded in the access log, as the single read is.
  - C1b: one combined PDF of every computation of the profile — a large document, a second renderer, and a long
    request for a profile with many computations.
- **C2: the account erasure's entry.**
  - **C2a (recommended):** its api-collection docs gain the same sentence, naming the listing per profile. No code.
  - C2b: leave it to W-247.
