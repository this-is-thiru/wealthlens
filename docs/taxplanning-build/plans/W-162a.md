## Plan for W-162a — the engine nets the gain

**What this item is for (one sentence, in my own words):** `portfolio` stops subtracting the charges the catalogue
flags. Each bucket instead publishes its consideration, its cost and its charges by side and code. The engine then
works out the gain, and rule data decides, year by year, which charges reduce it (2025 s.72; 1961 s.48;
`plans/W-162.md` C1a – C4a, D-375).

**Medium-large:** about 300 lines of main code; four rule files, two years each; one input shape changed across
about 40 test sites. **No stored data changes and no API change.** The two `deductible_*` fields stay on
`trade_outcomes`, still written; this item stops reading them, and W-162b removes them.

- **The set:** `AT_MOST_ONE`, `REGIME_AND_CONDITIONS`. Its `_note` lists what is not modelled: indexation (s.72(2);

**2. The engine:**

- **`CapitalGainsInput.Bucket(Money consideration, Money cost, List<Charge> charges, BucketFacts facts, Optional<String> portfolioRuleRef)`**
  - The old `gain` component goes.
  - `Charge(ChargeSide side, String code, Money amount)`, where `ChargeSide` is `ACQUISITION` or `TRANSFER`.
  - It refuses a null component, a blank code or a negative amount. The list is copied defensively.
- **`node/CapitalGainsCharges`**, new and package-private, beside `CapitalGainsStt`:
  - `gainOf(ctx, bucket, lines)` puts each charge to `RS-CG-CHARGE` and returns consideration − cost − Σ deducted
    charges.
  - It adds one `MEASURE` line per charge, naming its row: in the amount, out the amount deducted (0 if not
    deducted), then the side, code and limb.
  - A charge no row covers refuses the computation with an `IllegalArgumentException` naming the side, code, bucket
    facts, set and year (C3a).
- **`CapitalGainsNode`:**
  - It computes the gain first and passes it on. `CapitalGainsScope.takes`, `CapitalGainsTerm.of` and
    `CapitalGainsStt.of` each gain a `Money gain` parameter in place of `bucket.gain()`.
  - `ruleSets()` adds `CapitalGainsCharges.DEDUCTIONS`.
  - So charges are netted before the scope test. A speculative bucket with an uncovered code is therefore refused
    for the code. It would be refused anyway.

**3. `portfolio`:**

- **`CapitalGainsBucket`:** `gainRupees` is replaced by `CapitalGainsAmounts amounts`, so the record stays at ten
  components.
  - `CapitalGainsAmounts(double considerationRupees, double costRupees, SideCharges acquisition, SideCharges transfer)`
    has a `plus(other)` that merges two buckets' rows.
  - `SideCharges(Map<String, Double> rupeesByCode, double miscRupees)` is copied defensively and scaled to the paisa.
- **`CapitalGainsSummaryService`:**
  - Each row contributes `sale` = `scale(sellPrice × sellQuantity)`, `cost` =
    `scale(adjustedBuyPrice × buyQuantity)`, its two breakdowns and its two misc charges.
  - Buckets sum them. Neither `deductible_*` field is read.
  - `requireQuantifiable` stays: a charge with no breakdown still refuses the year.
  - The reference digest hashes each row's id with its amounts instead of its gain.
  - The Javadoc loses the deductibility paragraph.
- **`CapitalGainsAdapter`:**
  - It maps the amounts to `Bucket` and the breakdowns to `Charge`s. Every code in a breakdown is passed, including
    a zero one: a code is a fact.
  - Misc is passed as `MISC` when it is not zero.
  - A bucket is dropped only when its consideration, cost and every charge are all zero, where today it is dropped
    when its net is zero (C2 below).

### Choices (recommended first)

- **C1 — rounding:**
  - **(a) recommended:** scale the consideration and the cost to the paisa per row, as a contract note shows them,
    then sum. Today the row's net is scaled once. The two differ only when price × quantity has digits below the
    paisa, which happens with a fund's NAV and units, never with equity at a 5-paisa tick: a gain can then move by
    at most a paisa per row. No existing test value has such digits. A new case pins the rule: a fund row at NAV
    12.3456 × 10.123 units.
  - **(b)** keep today's figure exactly. That needs a combined "consideration less cost" fact per row, which gives up
    the separate cost that indexation, when built, needs.
- **C2 — a bucket with nothing in it:**
  - **(a) recommended:** drop it only when every amount is zero. A zero-gain bucket with charges is then put to the
    engine like any other. If it is an intraday or a derivative bucket, the scope rows now refuse it where it was
    silently dropped before.
  - **(b)** drop it when its consideration equals its cost and it has no charges. That is narrower than (a) and has
    no clear reason.
