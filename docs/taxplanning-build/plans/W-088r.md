### Design

1. **`RuleVersion`:**
   - `Optional<CapShape> cap`.
   - A null is refused like its siblings: "A rule version's cap is Optional.empty() when it states none".
   - `requireAtMostOneOf` takes the `Optional`.
   - The Javadoc `@param cap` says "empty where the rule states a condition, relief, rounding or definition and no
     limit".
2. **`RuleJson`:** `capOrNull` → `cap(node, path)`, returning `Optional<CapShape>` with the same refusal. The Javadoc
   loses "may legitimately be absent… null".
3. **Readers. Each keeps its behaviour and its message:**
   - `TemporallyApportionedCap.capOf`: `version.cap().orElseThrow(() -> new IllegalStateException(<today's
     message>))`.
   - `HousePropertyInterest:143`: `version.cap().map(cap -> …).orElse(amount)`, the same arithmetic.
   - `CessNode`, `SurchargeNode:270`, `TaxByBasisNode:81`: each takes the shape out once and tests it, with no
     `orElse(null)`:
     - `Optional<CapShape> shape = version.cap();`
     - `if (!(shape.isPresent() && shape.get() instanceof PercentOfBase rate))`, with today's message: "not a rate"
       where empty, else `"a " + shapeName()`.
   - `PackValidator:254`, `AssetPerquisite:99`, `SurchargeNode:192`: the same `isPresent() && get() instanceof`
     pattern, with no message change.
   - **Casts** (`ChapterEightNode` ×2, `TaxByBasisNode:102`, `HealthInsuranceDeduction:234`):
     `(Shape) version.cap().orElseThrow()`. Their rows always carry the cap; the pack tests pin it.
4. **Tests:** the mechanical updates above; no expectation value changes. **One new test** for the one new
   behaviour, the null refusal (see Cases).
5. **Docs:** TS T1 (`RuleVersion.cap` is `Optional`) and a Changes row; WI "Built"; STATE D-267; CHECKPOINT.
