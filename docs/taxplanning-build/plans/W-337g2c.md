**What this item is for (one sentence, in my own words):** make the copier a run the owner can do at the move — tested as a
whole, written down step by step in the deploy runbook, and ticketed for removal once its last run is logged.

**What is true now (read this session):**
- `CopierRun` (`copier` profile, `application-copier.yaml`: no web server) refuses unless every collection is specified
  (`requireSpecified`, D-978), reads `app.copier.written-zone` (required), checks the source holds no unknown collection, copies,
  logs one line per source, throws naming every unproven source (a non-zero exit), else exits.
- The PostgreSQL target is bound from `app.postgres.datasource.*` (`PostgresJpaConfig.java:46`) — no profile yaml sets it yet, so
  the command passes it as environment variables (`APP_POSTGRES_DATASOURCE_URL`, `…_USERNAME`, `…_PASSWORD`); where they come from
  is W-337h's. The source is each profile's `spring.mongodb.uri` (`application-prod.yaml:9`, `-staging.yaml:9`, `application.yaml:14`).
- Flyway builds the target's schema at start, so a fresh database needs nothing before the run.
- The only startup listener that writes is `TaxJobSchedule` (`@ConditionalOnProperty(app.tax.jobs.enabled)`, off in every profile,
  W-336); the command sets it off anyway.
- The copier refuses a target holding a row its source lacks (D-953 C3a) — so the charge catalogue must **not** be seeded (§1B)
  on the new database before the copy; the copy brings the catalogue from MongoDB.
- D-964: a `user_details` row without `email` would fail the copy loudly; this entry's precheck counts them.
- A second run is safe and finishes a part-way run: `MongoCopierIntegrationTest`'s "run again" and "fails part-way" cases.

### The runbook entry (§3), as it will read

- **When / who:** at W-337i, once per database; the owner.
- **0. Read-only precheck** — one `mongosh` aggregate (the owner's console shows one result, [[mongo-console-single-query]]): per
  database, each of the 40 collections' and `tax_document_bytes.files`' counts, any other collection holding a document (the copier
  would refuse it), and `user_details` rows without `email` → **0**, else stop (C3a). And `psql`: the target's `public` schema has no
  table but `flyway_schema_history` (fresh) — or, after a failed run, only the copier's own rows.
- **1. Backup:** MongoDB is only read. The target is fresh, so its way back is its empty state (step 5).
- **2. The run** — one complete block per environment (`dev`, `staging`, `prod`), secrets by `read -s` prompts, never placeholders:
  `java -jar backend/target/backend-<version>.jar --spring.profiles.active=<env>,copier --app.copier.written-zone=Asia/Kolkata
  --app.tax.jobs.enabled=false` with `MONGO_USER`, `MONGO_PASSWORD`, `APP_POSTGRES_DATASOURCE_URL/USERNAME/PASSWORD`, `TAX_DATA_KEY`,
  `TAX_DIGEST_KEY`, `JWT_SECURITY_KEY`, `PRIVACY_CONTACT` (D-958 for the zone).
- **3. Read the report:** 41 lines `<source> -> <table>: n source rows, n target rows, digest …, clean`, then "Every source copied and
  proven …"; exit code 0. Any `PROBLEMS` line or a non-zero exit: stop, keep the log, report it.
- **4. After-check (read-only):** `psql` row counts of six named tables equal step 0's counts; the run-log line records the 41 digests' file.
- **5. Second run / way back:** a second run is safe and finishes a part-way one. Way back: `DROP SCHEMA public CASCADE; CREATE SCHEMA
  public;` on the target (MongoDB untouched), then run again.
- **Then:** §1B (seed) only after this; the app is started normally.
- **Removal:** W-337j / the YouTrack issue (C4a).
