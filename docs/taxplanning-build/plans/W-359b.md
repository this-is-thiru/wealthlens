### Probes (run this session, all reverted; tree clean)

- **springdoc 3.2.1 on Boot 4.1 works**, with `springdoc.api-docs.path: /api/v1/admin/docs/openapi` and
  `springdoc.swagger-ui.path: /api/v1/admin/docs/swagger-ui.html`. The spec answers an admin 200, a user 403, no token 401. The UI
  redirects an admin to `…/swagger-ui/index.html` (200), and answers a user 403 and no token 401. RouteAccess 8, ApiZone 4,
  ArchitectureTest 26, WealthLensModulith 1 and Actuator 3 all pass.
- **The spec:** 136 paths and 149 operations, with all 25 request records as schemas (`ChargeAccountRequest` among them). It has two
  defects. **`@CallerEmail` shows as an `email` query parameter on 85 operations**, which a caller never sends because the token
  carries it. **A paged route shows one `pageable` object** rather than `page` and `size`.
- **The collection against the spec**, matching method, path template and top-level body fields after removing `//` lines and any host:
  **112 of 116 match**. These do not:
  - `ITS-22/` (3 requests) are for `/entity-test1/…`, a route that does not exist;
  - `Privacy/Read the Privacy Notice.yml` is `GET /privacy`, a page outside the zones and so not in the spec, as `RouteAccessIntegrationTest` exempts it;
  - two bodies send fields the app refuses as unknown, so both requests answer 400 today: `Transactions/Sell Stock.yml` (`actorName`, `timeZoneId`) and `Sell Stock - V2.yml` (`actorName`).

### Decisions (for approval with this plan)

- **C1 — Swagger UI (D-853 C5a cannot be used as placed).** A browser cannot send a bearer token when it opens a page, and the app has no
  session or cookie, so a UI page in the admin zone always answers 401 in a browser. A public UI page cannot load an admin-only spec
  either. **C1a (recommended):** the spec only (`springdoc-openapi-starter-webmvc-api`, no UI), at `GET /api/v1/admin/docs/openapi` for a
  `SUPER_USER` token in every profile. You read it with `curl` and a token, or import it into the collection's client. **C1b:** the spec
  and Swagger UI both public, in every profile. Anyone who reaches the app can then read the whole route list, admin routes included,
  though each route still refuses them.
- **C2 — the stale requests.** **C2a (recommended):** delete `ITS-22/` (a route that does not exist), drop `actorName` and
  `timeZoneId` from the two Sell bodies (the server's default zone is `Asia/Kolkata`, `TLocalDate:11`), and point the 7 hard-coded
  hosts at `{{INVESTMENT_TRACKER_SERVICE}}` like the rest. **C2b:** only the first two, leaving the hosts as they are.
- **C3 — CI reads the collection.** **C3a (recommended):** `submodules: true` on the pipeline's checkout. The check fails when the
  collection is missing or holds fewer than 100 requests, so an absent folder cannot pass it. **C3b:** the check only locally, skipped
  where the folder is absent. It would then never run on the pipeline, which is where every tier runs.

**Five roles:** Architect: the contract generated from the code, and the one client held to it by the build. PM: the API is documented

**Risks or ambiguities:**
- The submodule's URL is SSH. I expect `actions/checkout` to fetch a public submodule over its HTTPS token, but I have not verified
  that. The pipeline run shows it; if it fails, the fallback is an HTTPS URL in `.gitmodules`, and your clone then needs
  `git submodule sync` (asked before it is done).
- springdoc 3.2.1's compatibility is measured only by the probe above. The full tiers on the pipeline are the proof.
- A future request in the collection with `//` text inside a JSON string would be cut by the comment removal. None does today.
