**Findings that shape the build:**
1. **The JSON a column holds is Jackson's form of the Java class** (camelCase keys) while MongoDB holds the sub-document under
   its `@Field` names — so each sub-document key is mapped to its Java field: the snake→camel rule plus the renames found in
   W-337g (inside the P&L tree: `capital_gains`→`monthlyReport`, `first_half_report`/`second_half_report`→
   `first/secondFortnightReport`).
2. **Encrypted values inside JSON stay ciphertext** — `AssetRequest.email` / `accountHolder` (`AssetRequestConverter`) and the
   corporate-action copies' audit `createdBy` / `updatedBy` (W-401, D-957) are already in MongoDB's searchable form; they are
   carried as they are, which means the JSON is built directly, never passed through those converters (which would encrypt
   them a second time).
3. **Times inside embedded data follow D-954**, classified at `m1.6.1`: local-held (read in UTC) — the copies' audit
   `createdAt` / `updatedAt`, `RealisedProfits.lastUpdatedTime` (`LocalDateTime.now()` until W-402), top-level
   `transactions.submitted_at`; UTC-held (read in `app.copier.written-zone`) — `OrderTimeQuantity.orderExecutionTime`,
   `ChargeSummaryReport.lastUpdatedTime` (`TLocalDateTime.now()`), `transactions.order_execution_time` (D-961), `AssetRequest.orderExecutionDateTime` (the caller's raw input, kept as held); instant —
   `assets.order_execution_time` (D-961). **Still to classify at build** from their `m1.6.1` setters: `ReportModel.lastUpdatedTime`,
   `DraftStaleness.since`. An unclassified time makes the copier refuse, never guess. Dates (`LocalDate`) are midnight UTC as in g1.
4. **`tax_draft_revisions` has both `imported_from` (JSON) and `imported_from_workbook_sha256`** (`V10__taxplanning.sql:98-99`);
   which field fills the second is checked at build before mapping it.
5. **Size:** 18 collections, ~27 embedded fields, ~15 nested types — over §7 for one item (estimate 1,000+ lines with tests).

### Decisions (for approval with this plan)

- **C1 — the split.** *(Revised by D-962, owner: "pick multiple small tasks" — seven sub-items, W-337g2a1 – a3, b1 – b3, c, rows
  in `03-WORK-ITEMS.md`; the two-way cut below is superseded.)* **C1a (was recommended):** **W-337g2a** — the 9 collections whose embedded data become child tables or embedded
  columns only (`refresh_tokens`, `insurances`, `charge_accounts`, `user_charges`, `corporate_action`, `privacy_breach_notices`,
  `tax_regime_election_history`, `tax_document_confirmations`, `tax_gazette_leads`); **W-337g2b** — the 8 with JSON columns (`charge_schedules`, `charge_instruments`, `assets`, `transactions`,
  `trade_outcomes`, `profit_and_loss`, `tax_filing_drafts`, `tax_draft_revisions`) plus `tax_draft_computations` (both kinds,
  copied as one unit), the runbook entry and the removal ticket. A collection is never split across the two. **C1b:** one item.
- **C2 — how a JSON column is built.** **C2a (recommended):** a typed walk — the copier reads the column's Java type from the
  entity attribute, maps each sub-document key to that type's field (finding 1), converts each value by the field's type
  (dates and times per finding 3, enums and numbers exactly, nested types recursively), carries ciphertext unchanged (finding
  2), and writes the tree with Jackson; the read-back through the entity (D-953 C4a) proves the converter reads it. A key with no
  field refuses. **C2b:** decode with the old Mongo mapping and write through the app's converters — needs the `m1.6.1`
  classes back and decrypts in transit; not recommended.
- **C3 — child rows and a second run.** **C3a (recommended):** one transaction per source document: the parent row with `ON
  CONFLICT (id) DO NOTHING`, its child rows written only when the parent row was written by this run (one row affected), so a
  second run never duplicates children and a run that failed part-way leaves no parent without its children. The check (C4a)
  counts child rows against the summed list lengths. **C3b:** delete-and-rewrite the children on every run; not recommended.
- **C4 — times in embedded data.** **C4a (recommended):** a classification table in code (finding 3), each entry citing its
  `m1.6.1` setter in a comment; a time absent from the table refuses. Top-level local-held keys (`submitted_at`) are named on the
  `CollectionCopy`. **C4b:** treat every embedded time as UTC-held — wrong for the audit and P&L times; not recommended.
- **C5 — the runbook entry and the removal ticket (W-337g2b).** **C5a (recommended):** `post-deployment-runbook.md` gets one
  entry: precheck (the source's collections, the target fresh, a backup of the target), the exact command
  (`java -jar … --spring.profiles.active=<env>,copier --app.copier.written-zone=Asia/Kolkata`, D-958), the report to read, second
  run safe, way back (drop and re-create the target schema; nothing on MongoDB is written); the removal ticket is W-337j's row
  plus a YouTrack issue opened at W-337g2b's close-out. **C5b:** write the entry in W-337i instead — splits the operation from
  the code that defines it; not recommended (CLAUDE.md §6: same commit).
