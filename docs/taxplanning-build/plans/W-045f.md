### Types

- `taxengine/rules/timeline/Timeline.java`: a record of `Map<RuleId, RuleRow> rules`,
  `Map<RegimeCode, RegimeSpec> regimes`, `Map<NodeId, String> pipelineNodes` (each node's file content,
  verbatim; see Q2). Defensive copies.
- `taxengine/rules/timeline/TimelineReader.java`: `static Timeline read(Path root)`. It walks the
  tree, dispatches each file by its directory, and refuses the timeline naming the path when:
  - a file is not `.json` or lies outside a **known** directory (`law/rules`, `law/regimes`,
    `exec/pipelines`, and `exec/components` once it has a reader; see Q3);
  - a file does not parse (the existing `PackValidationException`, with the file's path as prefix);
  - a file's name is not its own identity (`RATE-SLAB-X.json` holding `RATE-SLAB-Y`);
  - an identity appears in two files (on a case-insensitive filesystem only the name check can catch
    this, so both checks are made);
  - two versions of one rule overlap in validity, **across all time**; unlike I13 a gap is allowed,
    because a rule may lapse and return.
- `Validity.window()` → `Optional<DateRange>`, moved from `RuleRow.windowOf` as its javadoc asks;
  `RuleRow` then calls it. This modifies two files not in the item's Produces.

### Choices for you

- **Q1 — how a runtime reads the timeline from a JAR.** A directory cannot be listed through the
  class loader, which is how `ClasspathRulePackProvider` reads today. This item's reader takes a
  filesystem `Path` (tests, and a build-time compiler, have one). **I recommend leaving runtime
  loading to `W-045g`**, whose row already says the provider compiles from the timeline. It can then
  choose between the JDK's zip filesystem over the JAR and a build-time compile. Nothing here is
  written for a caller that does not exist yet.
- **Q2 — the node catalogue.** No Java reads it and no type models it. I recommend **one file per
  node, carried verbatim**, checked only for well-formed JSON and for `nodeId` equal to the file
  name. `W-045i` (NodeIds generated from the timeline's pipelines) then decides its type. The
  alternative is to invent a `PipelineNode` record now, which would be speculative.
- **Q3 — directories with no content.** I recommend the reader knows only the directories it can
  read (above). A file under `forms/` or `content/` is refused until the item that authors that
  content adds its reader. That is stricter than the row's "outside the four layer directories".
  `disallowanceSets`/`conditionSets` (empty, and not in the brief's layout) likewise get a directory
  with their first set.
- **Q4 — drift while two copies exist.** Until `W-045g`, the 2026-27 pack and the timeline both hold
  the law. I recommend `TimelineReaderTest` asserts that the timeline's rules and regimes **equal**
  the 2026-27 pack's parsed ones (record equality), so any edit to one without the other fails the
  build.
