## Plan for W-329 — the audit's created-at, never filled for an entity saved with its id set

> **Approved as recommended — C1a, C2a** (owner, session 101, 2026-11-16); W-329 closed as split into W-329a (built here) and W-329b (C2a, to plan). Every path below was read on 2026-11-16 at `1fde1c09`; grep each
> again before relying on it. Probe: code read, and one throwaway integration test run twice (deleted).

**What this item is for (one sentence, in my own words):** decide whether tax-planning records should know when and by
whom they were created, which today they never do. First, fix the one place that already breaks because they don't.

**Probe (2026-11-16):**
- **Measured, not inferred.** A throwaway integration test made a profile, a landlord and a W-122c first figure, then
  read every collection's stored `audit_metadata`:

  | Collection | Docs | `createdAt` set | `updatedAt` set | Stored keys |
  |---|---|---|---|---|
  | `tax_profiles`, `tax_year_workspaces`, `tax_filing_drafts`, `tax_landlords` | 1 each | 0 | 1 | `updatedBy`, `updatedAt` |
  | `tax_draft_revisions`, `tax_draft_computations` | 2 each | 0 | 2 | `updatedBy`, `updatedAt` |
  | `tax_slab_policies`, `perquisite_policies`, `allowance_catalogue`, `allowance_limits` | 2, 1, 39, 14 | all | all | all four |

  The policies have their ids assigned by Mongo and get all four fields. Every record whose id is set before `save`
  gets neither `createdAt` nor `createdBy`. Spring Data treats an entity with an id as not new (session 62 found the
  same for `createdBy`).
- **The row's own wording is off.** The keys are stored camelCase, `audit_metadata.createdAt`, not `created_at`:
  `AuditMetadata` (`shared/entity/helper/AuditMetadata.java`) has no `@Field` names.
- **Which records:** 11 entities, set by 4 classes.
  - `DraftService`: `FilingDraft`, `DraftRevision`, `RegimeElectionHistory`, `TaxYearWorkspace`.
  - `TaxProfileService`: `TaxpayerProfile`.
  - `TaxProfileReferenceService.create` (`:138` – `:144`): `FamilyMember`, `Employer`, `Landlord`, `Lender`,
    `BankAccount`.
  - `DraftComputationService`: `DraftComputation`.

  `AccessRecord`, `JobFailure` and `ProcessingRecord` also set their ids but carry no audit block.
- **Who reads it:**
  - **`StalenessSweep.java:61` – `:62` breaks.** It picks a draft's latest computation by revision, then by
    `auditMetadata.getCreatedAt()`, which is always null. The probe ran the sweep over a W-122c draft, which holds
    two computations at revision 1, marked `READY`. It threw `NullPointerException: Cannot invoke
    "java.lang.Comparable.compareTo(Object)" because the return value of "java.util.function.Function.apply(Object)"
    is null`. Every first-figure draft marked ready, and every draft computed under both regimes at one revision,
    now stops the sweep that flags drafts whose law moved.
  - `ThirdPartyRetention.java:96` – `:97` reads `updatedAt` first and `createdAt` only as a fallback. It works today
    because `updatedAt` is always set.
  - `DraftComputation` already has its own `computed_at` (W-123b, `DraftComputation.java:61`). It is set on every
    computation stored since W-123b and null before.

**Choices for the owner:**
- **C1: split.**
  - **C1a (recommended):**
    - **W-329a, the sweep, now.** The latest computation is chosen by revision, then by `computedAt` with nulls
      first, then by receipt. The order is total and needs no audit field. Its red test is the probe's case: two
      computations at one revision on a ready draft.
    - **W-329b, the audit, planned after.** It covers C2.
  - C1b: one item.
- **C2 (for W-329b): what to do about the audit.**
  - **C2a (recommended):** make the 11 entities report themselves new on creation. Each gets a `@Transient` flag that
    is true only on the creation path (`Persistable.isNew`). Spring Data then fills `createdAt` and `createdBy`.
    Stored records are not backfilled: their creation was never recorded, and a guess would be invented data. They
    stay without the fields, and readers treat absent as unknown.
  - C2b: let Mongo assign the ids. Revisions and computations name their draft's id before it is saved, so every
    creation path would be reordered. This is larger, with the same result.
  - C2c: drop `createdAt` and `createdBy` for these entities and say so in `AuditMetadata`'s Javadoc. It is the
    smallest change but loses who created a record.
