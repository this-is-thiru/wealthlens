## Plan for W-263 — a caller's mistake answers 400, not 500

**What this item is for (one sentence, in my own words):** a request the caller got wrong — a value of the wrong
type, a missing upload, a tax year no pack ships for — answers 400 and says what is accepted, instead of 500.

**Findings (each read this session, 2026-11-11):**

1. `ControllerAdviser` handles `IllegalArgumentException` and `HttpMessageNotReadableException` as 400
   (`shared/exception/ControllerAdviser.java:22`), a missing request parameter as 400 (`:28`), and everything else as
   500 (`:59`). It is the only `@ExceptionHandler` class in `src/main` (grep: `ResponseWrapperAdvice` has none).
2. **Type mismatch.** `capitalGains` binds `@PathVariable int taxYear` and `@RequestParam Optional<LocalDate> asOf`
   (`taxplanning/compute/controller/DraftComputationController.java:49-50`). `2026-27` is not an `int`, so Spring
   raises a type mismatch, which falls to `:59` — the owner's first 500. The same mechanism is reachable wherever a
   bound parameter is not a `String` (grep of `@PathVariable` / `@RequestParam` / `@RequestHeader` in `src/main`):

   | Bound type | Count | Example |
   |---|---|---|
   | `boolean` | 11 | `ProfitAndLossV2BackfillController.java:35` `dryRun` |
   | `int` path variable | 7 | `DraftController.java:41, 46, 52, 58, 96`; `CorporateActionController.java:43`; `DraftComputationController.java:49` |
   | `LocalDate` | 5 + 1 `Optional` | `ChargeAccountController.java:71, 79`; `ChargeScheduleController.java:91`; `UserChargesController.java:43-44` |
   | enum | 6 | `AmcChargeFrequency` ×2, `RegimeType` ×2, `BrokerName`, `AssetType` |
   | `LocalDateTime` | 1 | `ProfitAndLossV2BackfillController.java:36` (`ISO.DATE_TIME`) |

3. **Unshipped year.** `ShippedRulePacks.load` throws `PackValidationException` "No pack for … ; the application
   ships […]" (`taxengine/rules/timeline/ShippedRulePacks.java:62`) — the owner's second 500. That exception's own
   Javadoc says it means *a malformed pack* (`rules/validate/PackValidationException.java:4-11`), which is the
   server's fault and must stay 500. So the exception type cannot be mapped to 400 wholesale.
4. `TaxCalculator` loads the pack with no year check in five caller-facing methods: `compute` (`:63`),
   `compareRegimes` (`:78`), `optimise` (`:91`), `termIfSold` (`:103`), `defaultRegime` (`:122`). Four others already
   check `availableYears()` first (`:133, :150, :176, :196`); `requireAsked` throws `IllegalArgumentException` there.
5. A draft can exist for a year no pack ships (`DraftService.java:62`, "empty for a year no pack ships"). So
   `POST …/drafts/{id}/compute`, `/compare-regimes` and `/optimise` on such a draft reach finding 4 as well
   (`DraftComputationService.java:63, 89-90, 104-105`). Not requested yet — the tests will show it.
6. `CapitalGainsViewService.heldLot` resolves the `asOf` year and its regime per lot, inside a `try` that turns an
   `IllegalArgumentException` into a per-lot note (`CapitalGainsViewService.java:56-69`). If finding 4 is fixed by
   throwing `IllegalArgumentException`, an unshipped `asOf` year would answer **200** with the refusal repeated on
   every lot, not the 400 the row asks for.
7. **Multipart.** One upload: `@RequestParam("file") MultipartFile` (`PortfolioController.java:49`). A request
   without the part is a caller's mistake; no handler names it. *Unverified which exception class arrives* (missing
   part vs. "not a multipart request") — the first test step finds out.
8. **Nothing to do for:** bean validation (no `@Valid` / `@Validated` in `src/main`), required headers (the one
   `@RequestHeader` is `required = false`, `DraftController.java:69`), `@RequestPart`, `@ModelAttribute`, cookies
   (none).
9. No test asserts today's 500s: `grep 'No pack for'` in `src/test` finds only `ShippedRulePacksTest.java:64`, which
   tests the provider itself and stays. No test outside `taxengine/rules` names `PackValidationException`.
10. Spring's classes exist in the jars on this machine (`spring-web` 7.0.8): `MethodArgumentTypeMismatchException`,
    `MissingServletRequestPartException`, `MultipartException`, `HttpRequestMethodNotSupportedException`,
    `HttpMediaTypeNotSupportedException`. *Unverified:* that 7.0.8 is the version Boot 4.1.0 resolves — the compile
    decides.
