## Plan for W-133 — import a salary structure from Excel (F28)

> **Approved — C1a – C6a** (owner, session 106, 2026-11-18: "yes, go with all (a)"). Split: W-133a (read and match), W-133b (apply). Every path:line below was read this session at `6dd18068`.

**What this item is for (one sentence, in my own words):** a user uploads the CTC spreadsheet their HR sent, and the draft gets an
employment with those pay lines. Every label must match a salary component exactly, or come back for the user to map; nothing is
guessed, nothing is dropped, and nothing is written before the user has reviewed it.

### What the design, the code and the sources say

- **F28** (`04-product-spec.md:103` – `:112`): F28.1 reuse `shared/util/parser/{ExcelParser,ExcelSheet,ExcelColumn}`, "no new parsing
  code"; F28.2 every label resolves to a `ComponentCode` or is returned for mapping; F28.3 never guessed, never dropped; F28.4 imported
  values land as `EntryProvenance.source = IMPORTED`, reviewable before use. Design: `19-engineering-foundations.md` E9.1 (`:531`): one
  sheet, columns "Component", "Annual Amount", optional "Monthly Amount".
- **What the code has, against that:**
  - **No reader in `shared`.** `shared/util/parser/` holds `ExcelSheet` and `ExcelColumn`, which are writers (`ExcelColumn.java:34`:
    `Function<T, Object> value`). The reader `ExcelParser` is portfolio's interface (`portfolio/service/parser/model/ExcelParser.java`). Its one
    implementation, `AssetRequestParserImpl`, reads a sheet chosen by **quarter** (`ALLOWED_QUARTERS`) and **logs every row at INFO**
    (`log.info("Parsed Record: {}", record)`). For salaries that would put money in the log, against O1.1. E9's "verified present"
    is out of date.
  - **No `EntryProvenance`.** `EnteredFacts.java:18` names it as designed and never built ("No item produces them"). A draft's history is
    `DraftRevision` (`change_set_json`, `changed_by`).
  - **The catalogue:** `exec/components/*.json` (52 files), each with `code`, `displayName` (e.g. "Special allowance"), `kind`, `head`,
    validity.
  - **Writing to a draft:** the draft is patched with JSON Patch (`DraftController.java:68`, `PATCH /drafts/{draftId}` with `If-Match`).
    `DraftFirstFigureService.java:78` already builds an `add /entered/employments/-` patch. An `Employment` needs four facts besides its
    pay lines (`termsIncludeDearnessAllowance`, `employerKind`, `dearnessAllowanceCountsForRetirement`, `companyEmployer`) that no CTC
    sheet carries.
  - **The bytes are untrusted:** an `.xlsx` is a zip of XML from an unknown generator, the same threat as O6's PDF. Apache POI
    (`poi-ooxml`, `backend/pom.xml:59`) would parse it inside the application.

### Choices for the owner (recommended first)

- **C1 — split:**
  - **(a)** **W-133a** read and match: upload → a preview, nothing stored. **W-133b** apply: the reviewed preview, the user's mappings and
    the four employment facts → one employment on the draft. Each part has its own plan, test and commit.
  - (b) One item.
- **C2 — reading the workbook:**
  - **(a)** A small reader of our own (`SalaryStructureWorkbook`): the first sheet, the header row by name ("Component", "Annual Amount",
    optional "Monthly Amount"), at most 200 rows, and **no values logged**. This departs from F28.1, by an erratum: the reader it names is
    portfolio's quarter reader, which logs every row.
  - (b) Generalise portfolio's reader into `shared` and stop it logging rows. That touches portfolio's upload, which is outside this item.
- **C3 — where it is parsed:**
  - **(a)** In W-131f's child process: a second child `main` and reply type, run with the same limits, empty environment and user.
    No new server.
  - (b) In-process, with POI's zip-bomb guard and a size cap (1 MiB). Simpler, but it leaves the gap O6 closed for PDFs.
- **C4 — matching a label:**
  - **(a)** Exact match after trimming and ignoring case, against a salary component live in the draft's tax year, by `displayName` or
    `code`. Anything else, including a near miss, is returned for mapping, with the year's components to choose from.
  - (b) Also a table of aliases (data), e.g. "HRA" → `HRA`. Placed as a later row if wanted, not built now.
- **C5 — the amount:**
  - **(a)** "Annual Amount" if present. Otherwise "Monthly Amount" × 12, shown in the preview as "from monthly × 12". Neither present → the
    row comes back. A negative or non-numeric amount is refused with its row number.
  - (b) Annual only.
- **C6 — F28.4's provenance (W-133b):**
  - **(a)** The draft revision that applies an import records it in its change set: the file's SHA-256 and the rows applied. There is no
    per-field provenance model, by an erratum on F28.4: `EntryProvenance` is unbuilt, and the review happens in the preview.
  - (b) Build `EntryProvenance` on entered facts. That is a design-level item of its own.

### W-133b, if C1a — outline (its own plan follows)

- `POST …/salary-import/apply`: the preview's lines, a mapping for every returned row (or an explicit "leave out", recorded), and the
  four employment facts. It writes one `add /entered/employments/-` through the draft's existing patch path with `If-Match`, and the
  revision records the import (C6a).

### Numbers I will use, and where each comes from

| Value | Source |
|---|---|
| 200 rows, 1 MiB | **mine, not sourced**: a CTC breakup is tens of rows; adopt or change |
| × 12 | the sheet's own "Monthly" column; a month is a twelfth of the tax year's pay |

### What I am NOT doing

- An Excel template download; aliases (C4b); OCR or CSV; changing portfolio's upload.

### Five roles

- **Architect:** the import produces a preview and then an ordinary draft patch. No new write path, and the untrusted bytes stay out
  of the application (C3a).
- **Product manager:** thirty components become one upload and one review. A label the system does not know is asked, never assumed.
- **Senior engineer:** a small reader with caps; no values in the log; the employment facts are asked for, never defaulted.
- **Automation tester:** every outcome of a row (matched, returned, refused) has a hand-built sheet. A near miss proves "never guessed".
- **Manual tester:** a real HR CTC sheet on staging → a preview that names what it could not match.

### Risks or ambiguities

- Real CTC sheets vary: merged cells, a header not on row 1, several sheets. Under C2a those are refused with a reason, not guessed. A
  real sheet's shape may need a follow-up.
- C3a reuses W-131f's child. Its reply type and limits for a workbook are new, but small.
