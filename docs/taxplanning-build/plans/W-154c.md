setting; this item makes it the rows' conditions on `meals.setting` (D-325 Q5; audit P4 `MealPerquisite:46–55`).

### Choices (recommended first)

- **C1 — where each setting's treatment is stated (Q5, risk 3, the voucher fallback):**
  - **(a) recommended: the law's own shape.** Sl. 3's general value is `PERQ-MEAL`, and its column D cuts it down two
    ways, each now a set chosen by `meals.setting`:
    - `RS-PERQ-MEAL-EXCLUDED` (`AT_MOST_ONE`, `REGIME_AND_CONDITIONS`): the wholly excluded settings, nil.
    - `RS-PERQ-MEAL-LIMIT` (`AT_MOST_ONE`, `REGIME_AND_CONDITIONS`): `PERQ-MEAL-AT-WORK` (`AT_WORK`) and
      `PERQ-MEAL-VOUCHER` (`PAID_VOUCHER`), the excess over the limit.

    The node tests the excluded set, then the limit set. An item neither reaches is valued in full on `PERQ-MEAL`.
    That is the general rule, not a branch by setting. A voucher in TY 2025-26's new regime is reached by no limit
    row, because the row's own `ExceptIn` drops it, so it falls to `PERQ-MEAL` in full, as today. `OTHERWISE` is
    reached by neither. `appliesInRegime` goes.
  - **(b)** one set holding every row, with `PERQ-MEAL` reaching `OTHERWISE` and `PAID_VOUCHER`. Then two rows apply
    to a voucher in the old regime and in TY 2026-27, and there is no regime condition type to separate them.
  - **(c)** a new selection, "first that applies". It would be new vocabulary for one use.
- **C2 — the two nil settings (risk 4; asks leave):**
  - **(a) recommended:** two rows in `RS-PERQ-MEAL-EXCLUDED`, `Fixed 0` as the club exclusions are:
    - `PERQ-MEAL-TEA-SNACKS` (`TEA_OR_SNACKS_AT_WORK`);
    - `PERQ-MEAL-REMOTE` (`AT_WORK_REMOTE_OR_OFFSHORE`).

    Each has two versions whose provisions, `introducedBy`, provenance and verification levels are **copied from
    `PERQ-MEAL`'s** versions. They are the same instrument and Table serial (2026: r.15(5) Table IV Sl. 3,
    Gazette 271092, pp.1545–1546; 2025-26: Rules 1962 r.3(7)(iii), the Department's consolidated rule 3, pp.3–4;
    both versions `SOURCE_CHECKED`). The rulebook
    names them (b) and (c) of `PERQ-MEAL-2026`.
    - **This moves the two nil lines' row id `PERQ-MEAL` → the new rows**, which C4a of D-325 forbids without
      leave, as D-321 gave W-153c. Their value stays nil.
    - `PERQ-MEAL`'s `_note` loses "nil lines citing this row".
  - **(b)** keep the nil lines on `PERQ-MEAL`, and state the excluded settings as a new definition on it (an
    "excluded settings" list, as `ExcludedAssets` is for assets). Row ids are kept, but that is a second way of
    stating an item's reach beside conditions, and a new definition type.
- **C3 — the words:**
  - **(a) recommended:**
    - a nil line reads "not a perquisite: excluded by <row> (n meals at x)", the club's words;
    - a limit line is unchanged (the cap's own words);
    - an in-full line reads "<SETTING>: in full, no row of RS-PERQ-MEAL-LIMIT reaching it in <regime> (n meals at
      x)".

    This replaces three strings in Java: "tea or snacks during working hours", "food during working hours in a
    remote area or an off-shore installation", and "food other than at work or by voucher" / "paid vouchers: … does
    not apply in …".
  - **(b)** keep the Java strings, which restate the settings' law a second time.
