## Plan for W-281 — `PortfolioService` hygiene

**What this item is for (one sentence, in my own words):** clear what the 2026-09-18 review found untidy in
`PortfolioService` (PS-9, PS-10, PS-12, PS-15) and the redrive's broad catch, changing behaviour only where named.

**Findings (each read this session, 2026-11-11; `PortfolioService.java`, 936 lines):**

1. **PS-10:** `addTransactionInternal` (`:544`) has no caller. The quoted log line went with `updateTransactions` in
   W-268. The other dead lines PS-10 listed are gone already.
2. **PS-12 names:** the V2 sale allocation is `updateQuantityBySavingReportAndProfitAndLoss1` (`:718`), its V1 twin
   `updateQuantityBySavingReportAndProfitAndLoss`. **Visibility:** `buyStock` (`:386`) and
   `updateBrokerChargesAndProfitAndLoss` (`:710`) are public with callers only in this class; `buyStockV2`,
   `sellStock` and the V2 allocation are called by tests (`PortfolioServiceTest`, `PortfolioServiceCostBasisTest`) and
   the V2 allocation by `TestController` (`:31`), so they stay public.
3. **PS-15:** `buildRedriveMessage` (`:362`) places commas with four nested checks; no blank line after `package`.
   The redrive checks the corporate-action filter twice per item (`:316`, then inside processing) — removing the first
   would change the outcome (an item still blocked would be stored again as a new temporary, "Re-filtered", instead of
   "Still filtered"), so it is **not** hygiene.
4. **Redrive's `catch (Exception e)`** (`:335`) breaks CLAUDE.md §2 and swallows everything as "this item failed" —
   including a Mongo `TransientTransactionError` after which the transaction is aborted and every later item fails
   too, and which `TradeCollisionRetry` (W-269) would otherwise retry. The failures an item is expected to have are
   the trade rules' refusals, all `IllegalArgumentException` (`validateAssetRequest`, `validateTransaction`).
5. **PS-9 (split into command and query services):** the query half — `getAllStocks`, `getMutualFunds`,
   `getStocksWithDateRange`, `getStockQuantity`, `searchAssets`, `getExportEntities`, `getProfitAndLoss`, with
   `groupedWithCharges`, `combineAllDetailsOfEntities` and `Holding` — has callers in three controllers,
   `EntityExportService` and tests. Moving it is the largest change here and touches nothing wrong.

**Choices for the owner:**

- **C1 — the split (PS-9).**
  - **C1a (recommended):** place it as its own row (W-286, next), so this diff stays readable as tidy-up only.
  - C1b: do it here.
- **C2 — redrive's catch.**
  - **C2a (recommended):** catch `IllegalArgumentException` only — a trade the rules refuse is that item's failure,
    as now; anything else (a database failure, a collision) aborts the whole redrive, which rolls back and, for a
    collision, is retried by `TradeCollisionRetry`. A behaviour change, named here.
  - C2b: leave it.
- **No choice, done as hygiene:** remove `addTransactionInternal`; rename the allocations `allocateSale` (V1) and
  `allocateSaleV2` (V2), matching `buyStock` / `buyStockV2`; make `buyStock` and `updateBrokerChargesAndProfitAndLoss`
  private; `buildRedriveMessage` as label/count pairs, filtered and joined; the blank line after `package`. The double
  check stays, with a comment saying why.

**Files I will modify:** `PortfolioService`, `TestController` (rename), `PortfolioServiceTest` (rename); a test for
C2a — a redrive whose item hits a non-rule failure aborts and leaves the temporaries as they were (a `PortfolioServiceTest`
unit test with the repository throwing, since a real database failure cannot be provoked over HTTP); `docs/portfolio-service/backlog.md`
is already pointed at the audit (W-264a).

**Five roles:**
- **Architect:** the catch now separates a refused trade from a broken system.
- **Product manager:** a redrive interrupted by a database fault is reported as such and retried, not as a list of
  mysterious item failures.
- **Senior engineer:** renames by meaning; dead code gone; the split kept separate for review.

**Risks or ambiguities:** C2a — a failure that is neither a rule nor transient (say a null in old data) now fails the
whole redrive instead of one item; that is the point of narrowing, and the message names it.
