**The pack.** `RATE-COST-INFLATION-INDEX` holds three years for TY 2025-26 and four for TY 2026-27
(`law/rules/RATE-COST-INFLATION-INDEX.json:28-42`, `:81-101`) — 2023-24 onwards. Its `_note` says it is "read here only
by the accommodation cap … capital gains are not built" and "A year the table does not hold is refused" (`:4`).

**The table's one reader.** `PerquisiteNode` names the set among its dependencies (`:85`) and reads the rule in exactly
one place, `costInflationIndex` (`:190-193`). The refusal is **the table's contents doing the work**, not a threshold in
code: `continuedCap` throws when `firstProvidedIn` is not a key of the table (`:180-184`), with the message "… is not
settled (OQ-11), so it cannot be valued yet (D-115)".

**The decision behind that refusal.** OQ-11 is **closed by D-163** with "refusals stay refusals" (`STATE.md:983`,
`:715`); as built, D-115 C2a refuses accommodation first provided before 2023-24 (`STATE.md:763`). So the refusal is a
decided answer, not an unbuilt corner.

**The definition type.** `IndexByYear` is generic — `Map<TaxYearId, Integer>` (`rules/definition/IndexByYear.java:18`) —
and `of()` throws for a year the table lacks rather than reading zero or a neighbour (`:36-43`). Nothing in it names the
perquisite cap except the javadoc's example (`:9-14`); a second rule of the same type needs no Java.

**The id grammars** (checked before naming, as `check-id-grammar-before-naming` requires): a rule id is two to eight
capitals then one to five hyphenated segments (`rules/id/RuleId.java:23`), a set id is `RS-` then one to seven
(`rules/id/RuleSetId.java:15`). `RATE-CG-COST-INFLATION-INDEX` and `RS-RATE-CG-COST-INFLATION-INDEX` both fit.

**What the build can see.** A rule must name a rule set, and a set must hold one row a year (`PackValidator.java:98-122`),
but reachability by a *node* is invariant **I3**, recorded as "not yet checkable" from the pack because the node-to-rule
mapping is engine-side (`PackValidator.java:50-52`). A rule no node reads would load, compile and ship in silence.

### Findings

1. **The sourcing is complete, and it is complete for good.** Every year from 2001-02 to 2026-27 now has a Gazette copy
   held and hashed; nothing before 2001-02 can ever be needed, because the divisor is floored at the year beginning
   1-4-2001 (`sources/2026-10-31-land-building-cap.md` row 3, 2025 s.72(8)(b)).
2. **The pack holds four of the twenty-six.** Adding the missing twenty-two is a data change, not a code change: the
   definition type already carries a table of years.
3. **Widening the shared table would silently lift a decided refusal.** The perquisite cap refuses a year it lacks
   *because* the table lacks it (`PerquisiteNode.java:180-184`); if 2001-02…2022-23 are added, an accommodation first
   provided in 2015-16 stops throwing and starts being valued — a change to a DONE item's decided behaviour (D-115 C2a,
   OQ-11 as closed by D-163) that no one asked for.
4. **The two could be kept apart at no cost in Java.** `IndexByYear` is a generic table (`:18`); a capital-gains rule is
   a second JSON rule with the same type, and its id fits the grammar (`RuleId.java:23`).
5. **Adding the rule now would be dead data the build cannot see.** No node reads a cost inflation index on the capital
   gains side — `CapitalGainsNode` does not, and `RATE-COST-INFLATION-INDEX` has exactly one reader (`PerquisiteNode:85`,
   `:191`). I3 says reachability by a node "is not yet checkable" (`PackValidator.java:50-52`), so a rule with no reader
   would pass every check silently — the worst kind of dead weight, because nothing would ever point at it.
6. **The 2019 copy carries a drafting slip, and it is not a second table.** S.O. 3266(E) says it amends "S.O. 2413(E),
   dated the 13th June, 2018", while A18's own text, and A20/A21/A22, all name **S.O. 1790(E)** as principal. Read
   together the chain is unbroken; the slip is recorded in the source file so a later reader does not go looking for a
   table that does not exist.
7. **The base year is recorded, not assumed.** P's table starts at 2001-02 and P takes effect 1-4-2018 — consistent with
   the substitution that the thc consolidation's footnote to 1961 s.48 Explanation (iii) attributes to Act 7 of 2017
   s.24. The 2017 Act itself was not read; the standing is what the repo already gives that footnote.

### Risks or ambiguities

   rather than add the second — cheaper to decide now than after a row exists, which is why C2 is asked here.
2. **Two rules means two copies of the same figures.** They can drift. The mitigation is in the pack: each `_note` names
   the same notification chain and the same gazette refs, and the source file records where every value came from, so a
   drift is detectable by reading rather than by trusting.
3. **The 2019 drafting slip will catch the next reader.** S.O. 3266(E) names S.O. 2413(E) as the notification it amends,
   which reads as though a second table exists. Recorded in the source file and here; not corrected in the pack, because
   `RATE-COST-INFLATION-INDEX`'s `_note` names S.O. 1790(E) and is right.
4. **Nothing here is proven by a failing test**, because nothing is built. The proof this item can offer is that every
   value is traced to a hashed Gazette copy and the backend is untouched — reported as what it is, not as a green build
   of new code.
5. **The base-year change rests on a footnote.** Act 7 of 2017 s.24 was not read; the thc consolidation's footnote is
   the record, the same as W-088g used. A reader who needs the Act itself should raise it rather than assume this item
   closed it.
