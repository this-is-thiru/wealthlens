### Decisions (owner)

- **C1 — whose token.** **C1a (recommended):** the tool mints a 15-minute token per user with `JWT_SECURITY_KEY`, read
  from a prompt, the same claims `AccessTokens` issues (`AuthService.java` read at build for the exact authorities).
  One token serves both builds, since both check the same key. **C1b:** the owner signs in as each account. Only the
  accounts whose password the owner holds would be compared.
- **C2 — which reads.** **C2a (recommended):** every `GET` in the `w-337` build's OpenAPI spec (57, one route set on
  both builds). A path id is taken from a list answer already read (`/me/tax/drafts/:draftId/…` per draft listed), and
  a page is walked at size 200 to its end. **C2b:** only api-collection's 39 GETs, W-406's original words; 18 routes go
  unread.
- **C3 — the allowed differences, fixed before the run.** **C3a (recommended):** (1) a date-time string where
  `m1.6.1`'s value is `w-337`'s read as UTC and shown in Asia/Kolkata (D-958; the tool converts with Python's
  `zoneinfo`, so no offset is written in code); (2) a field filled at request time, named one by one in the plan's
  appendix after the dev run, each with the line that fills it; (3) an Excel or PDF answer, compared on status, content
  type and, for Excel, every cell's value. A PDF's bytes carry its creation time. Anything else stops the move.
  **C3b:** also compare PDF text, extracted. That needs a PDF library the tools do not have yet.
- **C4 — where it lives.** **C4a (recommended):** `docs/taxplanning-build/tools/read_comparison.py` (Python standard
  library only, run with `python3 -I`) and `read_comparison_test.py` (unittest). It has two stages: `fetch` saves
  every answer per build to a folder, and `compare` diffs the two folders and exits non-zero on any difference not
  allowed. A new runbook entry, §0.10, is the one W-337i's rehearsal calls. Both are removed at W-337j: WL-50's scope
  grows, and W-337j's row names them. **C4b:** a Java tool under `shared/migration` beside the copier. That would need
  a Spring profile and a third running process.

### Trial run and R13 stop (session 124, D-982)

The tool is built and its 19 tests pass. A planted fault (accept any two date-times) failed 2 tests and was reverted. The
trial (build step 4) ran `m1.6.1` on a local `mongo:8.0.4` and `w-337` on a local `postgres:18`, filled by the
copier, with 2 users, 6 trades, a split, a profile, a draft and 2 computations: 130 answers each side, 222 differences.
Not reached on both sides: `admin/charges/charge-accounts/due` (needs `frequency`, `billedThrough`), the admin
contract note (no `transactionId` source in the admin pass), a breach notice report and a document parse (no data).

Fixed within C3a: an .xlsx served as `application/vnd.ms-excel` (`FileType.java:9`) is compared by cell; the P&L's
`yyyy-MM-dd HH:mm:ss` time is a date-time; `portfolio-summary` `$.lastUpdated` is the first request-time field
(`AnalyticsService.java:86`).

**What the approved plan got wrong, and needs your decision:**

- **C5 — times `m1.6.1` already held in UTC.** C3a (1) expects every date-time to be shown in Asia/Kolkata by `m1.6.1`.
  But `computedOn` (user charges), the charge tree's `lastUpdatedTime` and `computedAt` (computations) were written
  in UTC by `m1.6.1` already (`EmbeddedTimes.java:16 – 24` lists such fields for the copier). They come back equal on
  both sides, which is correct, yet the rule stops them. **C5a (recommended):** the tool names the fields `m1.6.1` held
  in UTC (route and path, each with the `m1.6.1` line that wrote it). Those must be **equal**; every other date-time
  must be **shifted**. A field the copier forgot to shift still stops. **C5b:** accept either equal or shifted for any
  field. That is simpler, but it hides a local time the copier left unshifted, which is the defect this exists to catch.
- **C6 — a GET that writes.** `GET /me/tax/profiles/{id}/workspaces/{taxYear}` creates the workspace when there is
  none (`DraftService.java:55 – 58`), so each build makes its own id. **C6a (recommended):** read only the tax years
  each profile already has (the `--value taxYear` the owner passes from the copy). Place an item to make that GET
  answer 404 instead of creating. **C6b:** allow `$.id` on that route as a request-time field.
- **C7 — ties in a list's order.** `GET /me/charges/charge-schedules` sorts by start date only
  (`ChargeScheduleRepository.java:42`), and cards that share a start date come back in a different order (200 of the
  222 differences). **C7a (recommended):** place an item giving that list a full order (start date, then schedule code),
  built before W-337i. The comparison stays order-sensitive. **C7b:** the tool compares that route's list keyed by
  `scheduleCode`, ignoring order.
- **C8 — `W-409`, placed.** The `copier` profile cannot start from the jar: `web-application-type: none` leaves
  `AuthConfig.java:55`'s `.cors(...)` without a `CorsConfigurationSource`. Runbook §0.9 step 3 fails as written.
  The trial copied clean only with the web server switched on, as a workaround. **C8a (recommended):** plan and build
  W-409 next, before W-406 resumes, with a test that starts the jar's context under `copier`.
