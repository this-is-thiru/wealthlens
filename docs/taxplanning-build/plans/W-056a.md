## Plan for W-056a — pipeline re-entry, so a node can price U (split from `W-056` by D-086)

**What this item is for (one sentence):** a node can ask for a slot as it would be had an earlier slot held
another value. `SurchargeNode` (`W-056`) gets U, the tax at exactly a threshold, by re-running the real
nodes rather than by duplicating them (`DR 06` G3.2).

The design is `plans/W-056.md` C1a, approved there. This file records how it's built.

### Design

- **`pipeline/Recomputation`** (functional interface; first drafted as `Reentry`, renamed because `PipelineRunnerTest.thereIsNoTryInTheRunner` rightly forbids the text `try {` in the runner, which `implements Reentry {` contains): `NodeValue recompute(NodeId target, NodeId pinned,
  NodeValue value)`.
- **`NodeContext.recomputed(target, pinned, value)`:** refuses a `target` or `pinned` the node didn't
  declare in `requires()`, with the same message as `get`. A node can then depend on nothing it hasn't
  declared, and the topological order is still derived from `requires()`.
  - `forRun(pack, regime, inputs)` keeps its meaning: a context that **cannot** re-enter and says so if
    asked.
  - `forRun(pack, regime, inputs, recomputation)` is the runner's.
- **`PipelineRunner`** supplies it for a run, as a nested record `RunRecomputation` (the run's nodes, pack, regime, inputs and values — five fields, so not eight parameters):
  - the nodes re-run are those that depend on `pinned` **and** that `target` depends on, in the run's
    order;
  - they run in a **fresh store** seeded with `pinned = value`, plus the outer run's values for anything
    else they read (none of those depends on `pinned`, so they're unchanged);
  - the sub-run's trace is discarded, and it cannot re-enter again;
  - a `target` that doesn't depend on `pinned` is refused: recomputing it would just return the outer
    value.
- **`NodeHarness.recomputation(Recomputation)`:** a node test states U's figures itself.

### How I will verify

`./mvnw test -pl backend -Dtest=PipelineRecomputationTest,PipelineRunnerTest,NodeHarnessTest`, then the unit
tier.
- **`PipelineRecomputationTest`** uses the real Phase 5 nodes and a probe node that re-enters:
  - **By hand:** new regime, TY 2026-27, the outer TI is ₹60,00,000 and the probe asks for
    `tax.afterrebate` at ₹12,10,000. Tax is 61,500, the rebate is 61,500 − 10,000 = 51,500, so the
    answer is **10,000** (rulebook, `REBATE-NEW-MR-001` worked example).
  - **Against a fresh run:** both regimes, and a resident aged 80 (the age ladder), at incomes of
    ₹5,00,000, ₹50,00,000 and ₹2,00,00,000. The re-entered value equals a fresh run's `tax.afterrebate`
    at that income.
  - The outer run's own `tax.afterrebate` and trace are unchanged by the re-entry.
  - Refused: an undeclared target; a target that doesn't depend on `pinned`; re-entry from a context
    built without one.
- **Bite probe:** seed the sub-run from the outer store, `pinned` included → the fresh-run comparison
  fails.
