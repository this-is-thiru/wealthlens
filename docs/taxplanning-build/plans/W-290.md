## Plan for W-290 — remove the uncalled `TransactionService.addTransaction`

**What this item is for (one sentence, in my own words):** a deprecated way to record a trade is still there, kept
"because the V1 flow is in live use", but V1 no longer calls it. It can return a replayed trade's id as if the trade
were new, so it should go before anything starts calling it again (D-581).

**Findings (read this session, 2026-11-13):**

1. **There is no caller in `src/main`.** The only `.addTransaction(` in main is `PortfolioController:40`, which calls
   `TradeCollisionRetry.addTransaction`, a different method. The method itself is `TransactionService:102 – 129`,
   `@Deprecated`, and its Javadoc gives the reason the row says no longer holds (`:105 – 106`).
2. **Every behaviour it has is already proven on its replacement.** `recordTransaction` (`:54`) does the same steps
   and more:

   | `addTransaction` step | Its test on `recordTransaction` |
   |---|---|
   | no date given → today | `TransactionServiceIdempotencyTest:217` |
   | a temporary trade already redriven → the existing id | `TransactionServiceIdempotencyTest:166` (as a replay) |
   | stores the caller's email | `TransactionServiceIdempotencyTest:235` |
   | a new trade is written | `TransactionServiceIdempotencyTest:88` |

3. **The row names one test class, but two call the method.**
   - `TransactionServiceTest` calls it in five tests (`:58`, `:71`, `:88`, `:104`, `:121`). Its other six tests cover
     other methods and stay, so the class is not deleted. The row's "(`TransactionServiceTest`)" means those five
     tests.
   - `TransactionIntegrationTest` also calls it, in three tests (`:48`, `:70`, `:95`). The row does not name these.
4. **Nothing else becomes unused in main.** `LocalDate`, `Optional` and `findByEmailAndSourceTempTransactionId` are
   still used by `recordTransaction` (`:56`, `:60`, `:69`).

**Rev 2 (2026-11-13, at build, owner's answer):** finding 2 missed one step. A given date is kept, which only `TransactionServiceTest:121` asserted. No `recordTransaction` test did: `:76` sets a date, but only the no-date case is asserted (`:227`). That one test is retargeted, not deleted, as `TransactionServiceIdempotencyTest.recordTransaction_whenDated_keepsTheDateAndStoresTheCallersEmail`. The other seven are deleted as planned.

**Choices for the owner:**

    steps on `recordTransaction`.

    proves, which is more than the row asks.
