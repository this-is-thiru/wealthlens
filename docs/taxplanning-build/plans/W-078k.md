## Plan for W-078k — the tax-report PDF's failure handling

**What this item is for (one sentence):** make `DocumentGenerationService.convertHtmlToPdf` catch only what the PDF
renderer actually throws, and report the failure in words that name the report and the cause, so that the
`catch (Exception)` and its Checkstyle baseline exemption both go.

### What I read (each fact checked, not recalled)

- **The row:** W-078k *(D-169)*: "catch only what Flying Saucer and iText throw, and say what failed (CLAUDE.md
  standard 2, 'Nothing silent')". Test: "a rendering failure is reported, not swallowed".
- **The code:** `taxplanning/document/DocumentGenerationService.java:41-51`. Inside a try-with-resources on a
  `ByteArrayOutputStream` it calls `new ITextRenderer()`, `setDocumentFromString(html)`, `layout()` and
  `createPDF(out)`, then has `catch (Exception e) { throw new RuntimeException("Failed to generate PDF", e); }`.
- **The library, from the jars on the build classpath** (`mvn dependency:build-classpath`, then `javap`):
  flying-saucer-pdf 10.0.6 and flying-saucer-core 10.0.6, **built on OpenPDF 3.0.0** (`com.github.librepdf:openpdf`).
  iText 5.5.13.4 is on the classpath but is used only by the test to read the PDF back.
  - `createPDF(java.io.OutputStream) throws org.openpdf.text.DocumentException`, and
    `DocumentException extends java.lang.RuntimeException`.
  - `setDocumentFromString(String)` and `layout()` declare nothing.
- **What actually throws, probed** (a scratch `Probe.java` run on that classpath):
  - malformed XHTML (`<p>` unclosed) → `org.xhtmlrenderer.util.XRRuntimeException: Can't load the XML resource (using
    TrAX transformer). … The element type "p" must be terminated …`;
  - non-XML text → `XRRuntimeException: … Content is not allowed in prolog.`;
  - a missing image → no exception (849-byte PDF).
  - `XRRuntimeException extends java.lang.RuntimeException` (flying-saucer-core).
- **The guards:** `checkstyle.xml` enables `IllegalCatch`. This file is exempt by `checkstyle-suppressions.xml:57`,
  inside the BASELINE, which "may only shrink". `CheckstyleBaselineTest` caps the baseline at
  `MAXIMUM_BASELINE_ENTRIES = 99`, and the baseline holds exactly 99 today.
- **Errors at the boundary:** `shared/exception/ControllerAdviser` maps `IllegalArgumentException` to 400 and
  everything else to 500. A rendering failure is the server's fault, so 500 is right.
- **The test:** `DocumentGenerationServiceTest` builds the service on a real `SpringTemplateEngine` with a
  `ClassLoaderTemplateResolver`. `TemplateEngine.process(String, IContext)` is `final`.

### Choices (recommended first)

- **C1, what to throw:** **(a)** `IllegalStateException("The tax-comparison report could not be rendered as a PDF: "
  + cause message, cause)`. No new type, and it reaches the 500 handler. **(b)** a new
  `TaxReportRenderingException`: a type with one thrower and no handler of its own, which is speculative (standard 2).
- **C2, what to catch:** **(a)** exactly `XRRuntimeException | DocumentException`, the two the jars and the probe show,

  `IOException` needs catching. **(b)** also catch `org.openpdf.text.ExceptionConverter`. Nothing declares it, so
  that would be guessing.
- **C3, the baseline:** **(a)** delete `checkstyle-suppressions.xml:57`, and lower `MAXIMUM_BASELINE_ENTRIES` 99 → 98
  so the ratchet stays tight. **(b)** delete the line and leave the cap at 99.
