## Plan for W-163b — the statutory rules move

**What this item is for (one sentence, in my own words):** STT, stamp duty, the SEBI fee and GST leave the 10 broker
cards for statutory cards that name no broker, with exactly the same figures. A trade whose scope has no statutory
card is then reported as a gap instead of being silently under-charged.

**Source:** `plans/W-163.md` (D-380: C1a, C2a), and W-163a (D-381; D3a put the gap here).

### What I read (session 37, 2026-10-28)

- **The rules are identical across brokers in each scope.** A script compared each scope's statutory rules across
  cards, every field except `notes`: all four scopes are identical.

  | Scope (assetType, segment) | Cards | Moves |
  |---|---|---|
  | `EQUITY`, `DELIVERY` | Zerodha ×3, Upstox ×2, Fyers ×2 | `STT` 0.1 % both; `STAMP_DUTY` 0.015 % buy; `SEBI_FEE` 0.0001 % both; `GST` 18 % of `BROKERAGE, EXCHANGE_TXN, SEBI_FEE, IPFT, DP` |

  | none, none | `ZERODHA_MAINTENANCE_2025_04` | `GST` 18 % of `AMC`, event `AMC_CYCLE` |

- **The seeder** reads `classpath*:data/charges/*.json` except the catalogue (`ChargeSeederService:69`), so a new card
  file is picked up with no code change.
- **`ChargeGoldenFileTest`** prices 21 fixtures (`test/resources/charges/golden/`) with the real resolver, engine and
  calculators over the shipped cards. They cover every scope: Zerodha, Upstox and Fyers delivery, Zerodha intraday,

  21 figures are the proof that nothing changes.** They stay as they are, and the test gains a stub for
  `findStatutoryCandidates`.
- **The AMC cycle's context** declares no asset type or segment (`AmcChargeService:127–146`). A statutory card that
  declares one disagrees with it, so GST on `AMC` can only sit on a statutory card with no scope.
  `AmcChargeService:94` holds the billing watermark unless the resolution is `RESOLVED`.
- **The mutual fund card keeps nothing.** `ZERODHA_MF_2025_04` has only `STAMP_DUTY` and `STT`. With both moved it has
  no rules, and the validator refuses an empty card ("it declares no rules", `ChargeScheduleValidator`), because an
  empty card looks like a broker that charges nothing.
- **Tests that count the cards:** `ChargeSeederServiceTest:264`, `:288` (`hasSize(11)`) and a comment in
  `ChargeExtensibilityTest:80`. **Documents:** runbook §1B ("11 rate cards"), `staging-runbook.md` §2a / §3,
  `docs/charges-engine/README.md`.

### Choices (recommended first)

  - **(a) recommended:** `STATUTORY_ACCOUNT_2025_04`, a statutory card with no scope, holding only that rule. Only the
    AMC cycle resolves it: every trade declares an asset type, so a trade gets its own scoped card, which is more
    specific. The cost is that a future asset type with a broker card and no statutory card would resolve this card
    and show no gap. That case needs a new broker card anyway, and its plan would add the statutory card.
  - **(b)** GST on `AMC` stays on the maintenance card. This keeps one piece of law on a broker card, against C2a.

    mutual funds carry no brokerage. If the page doesn't say so, I stop and ask you.
  - **(b)** the validator accepts an empty broker card. That removes a guard that exists for a reason.
  - **(c)** the mutual fund's two rules stay on its broker card, as an exception to C2a.
- **C3 — `sourceUrl` / `verifiedOn` on the statutory cards until W-163c:**
  - **(a) recommended: none.** `GET /charge-schedules/unverified` lists the four cards until W-163c cites the law,

  - **(b)** carry the brokers' AC-2 check (2026-09-08, the broker page).
