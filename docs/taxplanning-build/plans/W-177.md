## Amendment (R13, session 38) — a side effect the plan missed

**Found at step 4:** a card's null `assetType` / `segment` matches anything (`ChargeScheduleResolver.java:161`), so
the two new **unscoped maintenance cards** become the fallback card for every Upstox or Fyers trade no other card
covers: bonds, gold bonds through a broker, futures, options. Those trades now resolve `NO_MATCHING_RULES` instead
of `NO_SCHEDULE`. Both are ₹0, and both are in `ChargeResolution`'s gap list (`:73`). Zerodha already behaves this
way, because its maintenance card is the same shape. Verified by two golden cases:
- `upstox-bond-sell-no-card`, 2025-06-02: `NO_MATCHING_RULES`.
- `upstox-bond-sell-before-any-card`, 2025-03-01: `NO_SCHEDULE`.

The plan's staging-guide example (an Upstox `BOND` as "a broker with no card") would have been false, so it uses
the pre-window date instead.

**Owner (AskUserQuestion):** "Keep it, pin it (Recommended)". The label change is kept, the two cases stay as pins,
and the guide example uses the date before any card.
