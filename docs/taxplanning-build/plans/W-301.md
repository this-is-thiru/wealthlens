## Plan for W-301 — the upload reads a trade's segment and account type

**What this item is for (one sentence, in my own words):** a JSON trade can say it was intraday, or for an
outsourced account, but an uploaded one cannot. The upload always gives delivery on the user's own account, so it
should read both, the way JSON does (D-606).

**Findings (read this session, 2026-11-12):**

1. **Neither is read.** `AssetRequestParser` maps no segment or account-type header (`:29 – 48`). The request
   keeps its defaults, `accountType = SELF` (`AssetRequest:55`) and `segment = DELIVERY` (`:65`).
   `ExcelHeaders` has no constant for either. I searched for `SEGMENT`, `ACCOUNT TYPE` and `ACCOUNT_TYPE` and found
   no header.
2. **The values JSON accepts:** `TradeSegment` is `DELIVERY`, `INTRADAY`, `FUTURES`, `OPTIONS` or `NA`
   (`TradeSegment:22 – 34`), and `AccountType` is `SELF` or `OUTSOURCED` (`AccountType:4 – 5`). Nothing on the trade
   path refuses any of these constants.
3. **A segment matters downstream.** Since W-292 – W-296 it is stored on the transaction and the lot, it splits a V1
   same-day merge, the charge engine prices by it, and P&L files by it. An uploaded intraday trade is therefore
   priced and filed as delivery today.
4. **How the parser answers a bad value today:** the existing enum columns use `valueOf` (`:100`, `:117`, `:160`).
   A wrong word then answers 400 with Java's `No enum constant …`, which names neither the row nor the accepted
   words.

**Choices for the owner:**

- **C1 — what an absent or blank cell means.**
  - **C1a (recommended):** the same defaults a JSON trade gets, `DELIVERY` and `SELF`. Existing workbooks keep their
    meaning unchanged.
- **C2 — the values accepted.**
  - **C2a (recommended):** every constant JSON accepts, and nothing more.
  - C2b: `DELIVERY` and `INTRADAY` only. That would make the upload narrower than JSON.
- **C3 — a value that is not a constant.**
  - **C3a (recommended):** refuse it, naming the row, the column and the accepted words, for example
    `Row 3, SEGMENT: "intra" is not one of [DELIVERY, INTRADAY, FUTURES, OPTIONS, NA]`. This applies to these two
    new columns only. The existing enum columns are a separate change, and the same wording could be placed as a row.
  - C3b: `valueOf`, as the existing columns do.
- **C4 — the template.**
  - **C4a (recommended):** `SEGMENT` after `EXCHANGE NAME`, and `ACCOUNT TYPE` before `ACCOUNT HOLDER`. The sample
    row gets `DELIVERY` and `SELF`.

**Files I will modify (all recommended):**
- `ExcelHeaders`: `SEGMENT` and `ACCOUNT_TYPE`.
- `AssetRequestParser`: two map entries, two setters, and one enum reader shared by both.
- `PortfolioExportColumns.TRANSACTION_TEMPLATE` and `EntityExportService.templateRow`.
- Tests:
  - `AssetRequestParserTest`: `INTRADAY` / `OUTSOURCED` read; absent gives `DELIVERY` / `SELF`; `intra` refused
    with the message (red before).
  - `PortfolioExcelExporterTest`: the headings.
  - `PortfolioGapAuditIntegrationTest`: a workbook row with `SEGMENT` `INTRADAY` stores an intraday transaction and
    lot (red before: `DELIVERY`).
- `STATE.md`; a row for the existing columns' wording if C3a.

**Numbers I will use:** none.

**Design sections I read:** D-606 (the row), D-605 (W-285, absent means as JSON), D-591 – D-598 (where segment is
used).

**What I am NOT doing:** the existing enum columns' error wording; correcting trades already uploaded (stored data
does not record what the workbook said).

**How I will verify:**
- The red tests run first.
- Probe: drop the segment map entry. The upload case must fail.
- Locally: the touched classes and `validate`. The tiers run on the PR's pipeline.

**Post-deployment actions (R15):** none.

**Five roles:**
- **Architect:** the upload records the same facts as JSON, with the same defaults.
- **Product manager:** intraday and outsourced trades can be uploaded.
- **Senior engineer:** two columns and one enum reader that names its row.
- **Automation tester:** read, absent, refused and the upload round trip, red first, plus a probe.
- **Manual tester:** fill `SEGMENT` `INTRADAY` in the template and upload it. The holding shows intraday.

**Risks or ambiguities:** none beyond C2. `FUTURES` and `OPTIONS` are accepted as JSON accepts them, and the charge
engine already handles whatever they resolve to.
