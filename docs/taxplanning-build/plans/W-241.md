## Plan for W-241 — Persona demo fixtures

**What this item is for (one sentence, in my own words):** a person demonstrating the running app can create Ravi,
Priya, Anand or Meera from `api-collection` requests and compute them, instead of typing every component by hand.

**Findings that shape the plan (each read this session):**
- F1 — A draft has no field for capital gains. `DraftInputs` is `(entered, filing, brought, thirdParties)`
  (`taxplanning/workspace/DraftInputs.java:20`); gains enter only from the portfolio's trade ledger, and only for the
  profile that holds the portfolio (`taxplanning/assemble/EngineInputsAssembler.java:62`). Ravi's and Meera's gains
  (`sources/2026-11-07-persona-figures.md` PR-1, PR-4) therefore cannot come from a draft patch. Through the API they
  would come from V2 buy and sell trades, which the charge engine prices (CLAUDE.md "Charge engine flags": shipped
  `true`), and `CapitalGainsSummaryService` carries each side's charges into the bucket
  (`portfolio/service/CapitalGainsSummaryService.java:99` – `108`). So the gain is no longer 1,50,000 / 40,000 /
  5,50,000, and the persona figures would not be reproduced. → **C1**.
- F2 — Compute prices on today's date (`taxplanning/compute/DraftComputationService.java:62`, `LocalDate.now(clock)`).
  The persona figures assume 2026-04-01 with no interest. The demo will add interest for a late year; the figure to
  compare is `/tax/bill` (before credits and interest), as `DraftComputationIntegrationTest.java:236` and `:250` read it.
- F3 — Compute refuses a draft without `/filing/dueDate` (`DraftComputationIntegrationTest.java:313` – `327`). The demo
  patch sets `2027-07-31`, the value that test uses (`:74`); it is an input, not a legal claim. That it leaves the bill alone is unverified; the replay checks it.
- F4 — Patch shapes exist: `/entered/employments/-` (`DraftComputationIntegrationTest.java:70` – `73`); the other
  members are `EnteredFacts` components (`taxengine/input/EnteredFacts.java:106`, `:107`, `:124`, `:129`, `:138`);
  record fields `Tenancy.java:18`, `EmployerFundContribution.java:13`, `HealthPayment.java:18` – `24`,
  `OtherSourceItem.java:22`; codes `ComponentCodes.java:20`, `:30`, `:41`, `:63`. Ages: Ravi 1995-09-30, Anand
  1964-09-30 (`Fixtures.java:77`, `:105`); Priya and Meera take the harness's 1985-06-15 (`NodeHarness.java:200`).
- F5 — The collection has no "create a draft" or "patch a draft" request today (`api-collection/Tax Profile/`: Create a
  Profile, Compute a Draft, Optimise a Draft, Request Erasure).

## Revision 2 (R13) — the figure to compare is the bill before rounding

board back to E).

**What I found:** `ComputedTax.bill` is "the tax, surcharge and cess before anything already paid"
(`taxengine/api/ComputedTax.java:16`), and it is **not rounded**; only `finalAmount` is rounded, and it includes the
day's interest and fees (`:20`). The replay of the built requests returned Ravi new 371467.2 and Anand old 23712.0
against my rounded 3,71,470 and 23,710. Both equal my own hand working one step before its rounding. Priya (2,14,500),
Anand new (0) and Meera new and old (9,67,200; 12,16,800) passed as built. Ravi old was not reached; the case stops at its
first failure.

(same files, patches, verification, choices).
