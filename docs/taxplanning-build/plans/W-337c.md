### Core findings from probing the code before planning (`probe-before-plan.md`)

1. **`AbstractIntegrationTest` must own the shared `PostgreSQLContainer` (`AbstractIntegrationTest.java:71-133`).** Once `auth` and `insurance` run on Postgres, every integration test that registers, logs in or calls `storedLogin(email)` (`AbstractIntegrationTest.java:141-143`) needs Postgres running and wiped between tests. Moving `PostgreSQLContainer("postgres:18")` from `AbstractPostgresIntegrationTest.java:16-28` into `AbstractIntegrationTest` (and truncating all public tables except `flyway_schema_history` and `charge_catalogue` in `@AfterEach cleanDatabase()`) retires `AbstractPostgresIntegrationTest` and serves W-337c through W-337f.
2. **`V1__auth_and_insurance.sql:35-56` omitted audit columns on `insurances`,** whereas `InsuranceEntity.java:26,80-82` implements `AuditableEntity`. Adding `db/migration/insurance/V6__insurances_audit.sql` (adding `created_by`, `updated_by`, `created_at`, `updated_at`) keeps `V1` immutable and matches `V2`–`V5`.
3. **`RefreshTokenJpa.java:41-44` left `@ElementCollection` lazy,** whereas `AuthService.java:126` calls `spent.getFactors().stream()` outside `RefreshTokens.spend()`. `RefreshToken.factors` needs `fetch = FetchType.EAGER` (matching `InsuranceJpa.java:102`).
4. **`RefreshTokens.java:48-52` needs D-937 C3a's expiry sweep** (`DELETE FROM refresh_tokens WHERE expires_at <= :now` on `start()`) because Postgres has no TTL index, and `spend()` / `endFamily()` / `endAll()` (`RefreshTokens.java:58-93`) plus `RegisteredUserDirectory.recordSignIn()` / `storePassword()` / `startCounting()` (`RegisteredUserDirectory.java:37-57`) need `@Transactional("postgresTransactionManager")` around `@Modifying @Query` calls (per `docs/adr/W-337a.md:38-41`).
5. **`AccountErasureIntegrationTest.java:167-216` scans `@Document` classes dynamically** to seed and count a row in every per-person collection. Once `UserDetail`, `RefreshToken` and `InsuranceEntity` move to `@Entity`, `AccountErasureIntegrationTest` must also scan `@Entity` tables (via JDBC) so erasure coverage still proves every per-person store across both Mongo and Postgres during the split.
6. **`PasswordUpgradeIntegrationTest.java:101-147`** tests W-369's in-place update by email (originally against a Mongo `ObjectId` `_id`). On Postgres (`id VARCHAR(255)`), `ObjectId` no longer exists, so the test keeps the in-place update + 1-row assertion + 0-row refusal (`IllegalStateException`) using a pre-existing string-id row.
7. **For W-337c2 (noted now so nothing surprises us):** `PrivacyConsents.java:65` catches Mongo's `DuplicateKeyException`, which must widen to Spring's `DataIntegrityViolationException` on JPA/Postgres; `GrievanceService.java:21` and `BreachNoticeService.java:25` switch `@Transactional` → `@Transactional("postgresTransactionManager")`; `AccountErasureService.java:22` spans both stores until W-337f (D-937 C2a).

### Decisions (for approval with this plan)

- **C1 — split.** **C1a (recommended):** split W-337c into **W-337c1** (JPA foundation + `auth` + `insurance`) and **W-337c2** (`shared` `privacy_*`), each its own plan approval/commit on branch `w-337`. **C1b:** keep all 9 collections and 14 integration tests in a single W-337c commit.
- **C2 — entity class names and W-337a's parallel `*Jpa` classes.** **C2a (recommended):** convert the live classes (`UserDetail`, `RefreshToken`, `InsuranceEntity`, `PolicyDetails`) in place to `@Entity` / `@Embeddable` and replace `UserDetailsRepository` / `RefreshTokenRepository` with `JpaRepository`, deleting W-337a's temporary `*Jpa` duplicates (`UserDetailJpa`, `RefreshTokenJpa`, `InsuranceJpa`, `PolicyDetailsJpa`, `UserDetailJpaRepository`, `RefreshTokenJpaRepository`, `InsuranceJpaRepository` → `InsuranceRepository`) and re-pointing `PostgresMappingProbeIntegrationTest` to the real entities. Keeps every service and caller import unchanged. **C2b:** keep `*Jpa` class names and rewrite every caller to import them.
- **C3 — `app.postgres.enabled` default on branch `w-337`.** **C3a (recommended):** make `PostgresJpaConfig` active by default (`matchIfMissing = true`, still switchable off via `app.postgres.enabled=false` if ever needed) on branch `w-337`, since `auth` and `insurance` now require Postgres whenever the app boots; `AbstractIntegrationTest` supplies the Testcontainers Postgres URL/credentials. **C3b:** keep `app.postgres.enabled=false` by default and require every profile/test to opt in — risks a silent startup failure with missing `UserDetailsRepository` beans whenever a profile forgets the flag.

**Risks or ambiguities:**
1. **`AccountErasureIntegrationTest` dual-store scan:** during W-337c1 – W-337e, per-person tables live in both Mongo and Postgres; extending the test's dynamic scanner to cover `@Entity` tables ensures no regression in DPDP erasure guarantees while both stores coexist.
