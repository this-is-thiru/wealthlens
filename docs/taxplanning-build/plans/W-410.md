## Plan for W-410 — reading a workspace never creates one

> Planned in session 124 (2026-11-27) with W-411 / W-410 as one batch (owner: "plan W-410 and W-411"; one approval, each
> item its own red test, D-row and commit). Placed by D-983 from W-406's trial (D-982 (2), (3)); both before W-337i.

**What this item is for (one sentence, in my own words):** a `GET` of a profile's year must not write, so asking for a year
no draft was ever made in leaves the database as it was, on both builds and for every caller.

### Decisions (owner)

- **C1 — what reading an absent year answers.** **C1a (recommended):** 400, "This profile has no workspace for that year".
  That matches every other missing record here (`BadRequestException`, CLAUDE.md "IllegalArgumentException → 400"). It
  needs no new exception type or handler. The row's "404" is corrected in `03-WORK-ITEMS.md`. **C1b:** 404, as W-410's row
  first said. That needs a new not-found exception and a `ControllerAdviser` handler, and it makes this the one missing
  record that answers 404.
- **C2 — the drafts of an absent year.** **C2a (recommended, probed):** `[]`. A list of nothing is an empty list, as
  every other list route here answers, and the read records nothing. **C2b:** the same refusal as C1.

### Build (after approval)

   `drafts_whenYearNeverStarted_listsNoneAndWritesNothing` expects `[]` and no row. Both fail today, because the row is
   made.
