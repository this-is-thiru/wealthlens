## Plan for W-131c — the parse job: each stored document read once per parser version, within a time budget

> **Approved as recommended — C1a – C5a** (owner, session 104, 2026-11-17; PT30S adopted with C3a). Built; review: "commit and push" (D-764). Every path:line below was read this session at `cdaa474c`.
> **Probe: none run.** Nothing shared changes shape; the build's first integration case runs the real parser on a stored
> document end to end.

**What this item is for (one sentence, in my own words):** read every stored document with the parser for its form, in the
background:
- record each run as an attempt;
- never twice for one parser version, never for a profile held for erasure, and never longer than a set time;
- so that W-131d's upload is followed by something the person can confirm.

### What the design and the code say

- **DR 19 E8** (`19-engineering-foundations.md:495` – `:497`): "| `ParseDocument` | on upload | no | idempotent on
  `(documentId, parserVersion)`; a new attempt row per run (`M4`) |". The columns are Job, Trigger, Singleton, Notes.
- **D-449 C1a:** the job runs on W-137's `TaxJob` / `TaxJobRunner`.
  - `TaxJobRunner.run` takes a lease named by `TaxJob.name()` (`jobs/TaxJobRunner.java`).
  - Jobs are scheduled in `TaxJobSchedule` behind `app.tax.jobs.enabled`.
  - Nothing in the application uses `@Async` or an executor (grep: none).
- **O6:** the parser runs "with no network egress and a hard CPU and wall-clock budget". The process and CPU parts are W-131f
  (D-761 C4a); the wall-clock budget is this item's.
- **O9:** "Parser crashes or times out | `ParseAttempt.outcome = FAILED` with a reason. **The document is retained**, so a
  later parser version can retry".
- **The entry point:** `DocumentParsers.parse(IngestedDocument, DocumentContent)`
  (`documents/parser/DocumentParsers.java`). It refuses content whose SHA-256 is not the document's, and a form no parser
  reads. Each parser declares `version()`, which "Changes when what the parser reads changes, so an attempt can be repeated
  by a later version" (`DocumentParser.java:21`).
- **Held profiles:** W-235's hold says "nothing reads or processes it". An account's hold marks each of its profiles
  (`TaxAccountErasure.hold`), so `TaxpayerProfile.erasureRequestedAt` covers both.
- **The stored pieces:** `StoredDocument`, `StoredParseAttempt`, `DocumentBytes.read` (W-131a, W-131b).

### Findings

1. **E8 says "Singleton: no"**, but the runner is built for singletons (one lease per job name). The volume is one upload at
   a time.
2. **A parse that overruns cannot be stopped in-process.** A Java thread can be interrupted but not killed, so a parse that
   ignores the interrupt keeps its thread. The O6 caps (20 MB, 50 pages) bound it, and W-131f isolates it.
3. **A parser that throws on hostile input** is what O9 calls a crash. It is caught as the `ExecutionException` of the
   parse's own thread, not with a broad `catch`.
4. **Content that is not the document's** (a SHA-256 mismatch) can only mean the wrong bytes. Recording it as a failed
   attempt means the next run does not meet it again; a refusal would be recorded every run.

### Choices for the owner (recommended first)

- **C1 — the job's shape** (finding 1):
  - **(a)** One job, `ParseDocuments` (lease `parse-documents`), that parses every due document.
    - It runs every minute (`app.tax.jobs.parse-documents-cron: "0 * * * * *"`, the three yamls).
    - W-131d also starts a run in the background right after an upload. If another run holds the lease, the next minute's
      run takes the document.
    - This departs from E8's "Singleton: no", with an erratum to E8.
  - (b) A job per document, with its own lease, in parallel.
- **C2 — which documents are due:**
  - **(a)** A document whose form has a parser, whose profile is not held, and which has no attempt, or only failed
    attempts, all by an older version of that parser.
    - A document parsed by the current version is never parsed again, whatever the outcome (E8's idempotence).
    - A document read successfully by an older version is not re-read by a new one; its confirmation stands.
  - (b) Every document with no attempt by the current version, which re-reads confirmed documents on every parser upgrade.
- **C3 — the time budget** (findings 2, 3):
  - **(a)** Each parse runs in its own daemon thread, and the job waits `app.tax.documents.parse-budget`.
    - **PT30S** is my number; O6 gives none, so it needs your adoption.
    - Past the budget: interrupt, abandon, and record a FAILED attempt, "The parser took longer than PT30S".
    - A parser that throws: a FAILED attempt, "The parser stopped: <exception class>", logged at ERROR with its stack.
  - (b) The parse runs in the job's own thread with no budget.
- **C4 — a held profile:**
  - **(a)** Its documents are skipped: not parsed, no failure row, since the hold is expected and the profile is erased
    when it ends.
  - (b) Refused, which records a failure row every minute.
- **C5 — content that is not the document's** (finding 4):
  - **(a)** A FAILED attempt by the current parser, "The stored bytes are not this document's", logged at ERROR. Missing
    bytes are refused (`context.refuse`), since there is no content to attempt.
  - (b) Refused every run.

### Files (C1a – C5a)

- **`taxplanning/jobs`:** `ParseDocuments` (`TaxJob`), its schedule in `TaxJobSchedule`.
- **`documents/store`:** repository queries for the due documents; `DocumentSettings.parseBudget`.
- **Yamls:** `parse-documents-cron`, `parse-budget`.
- **Tests** in `ParseDocumentsIntegrationTest` (real Mongo; a test parser bean for the slow and throwing cases):
  - a stored document is parsed once with the current version, and a second run adds nothing;
  - a held profile's document is not parsed;
  - a parse past a budget of PT0.2S is a FAILED attempt with the budget reason;
  - a throwing parser is a FAILED attempt;
  - bytes that are not the document's are a FAILED attempt;
  - a document whose only attempt failed under an older version is parsed again;
  - one read successfully by an older version is not.
- **Docs:** the E8 erratum; runbook §1.n (the cron and the budget to confirm).
