## Plan for W-333 — group `ComputedTax`'s 18 components into four small records

> **Approved — C1a, C2a, C3a**; closed D-774 (owner, session 106, 2026-11-18: "yes, go with C1a, C2a, C3a"). Every path:line below was read this session at `56a4592d`.

**What this item is for (one sentence, in my own words):** `ComputedTax` (`taxengine/api/ComputedTax.java:35`) holds 18 components
where `CLAUDE.md` §4 says more than 7 means a missing type. Splitting it into named groups makes it easier to change, **without
changing one byte of the JSON** the API returns or the database stores.

### What the design, the code and the sources say

- **Why the build does not catch it:** Checkstyle's `ParameterNumber` looks at methods and constructors, not a record's header, so
  `validate` passes today. `CLAUDE.md` §4 still applies (D-760 proposed this item; D-772 placed it).
- **It is stored and served as JSON.** `DraftComputationView(ComputedTax tax, …)` (`compute/DraftComputationView.java:19`) is what the
  draft computation endpoints return. `DraftComputationService` stores it as `resultJson` on `DraftComputation` and reads it back
  with `MAPPER.readValue(stored.getResultJson(), DraftComputationView.class).tax()` (`DraftComputationService.java:204`,
  `MAPPER = JsonMapper.builder().build()` at `:69`). **So the JSON shape is a stored format.** Changing it would make every stored
  computation unreadable, or need a data migration.
- **Probe (run, then deleted):** under this project's Jackson 3, `record Grouped(@JsonUnwrapped A a, @JsonUnwrapped B b)` wrote
  **byte-identical** JSON to a flat record of the same fields, and read the flat JSON back to an equal value (1/0, `UnwrappedProbeTest`).
- **Who builds it:** one main site, `TaxCalculator.java:106`, and five test sites (`DraftForecastServiceTest:32`,
  `ComputationReportServiceTest:189`, `ReconciliationTest:58, :158, :313`). **Who reads it:** 13 main files (`compute/*`,
  `documents/reconcile/Reconciliation`, `taxengine/api/ClaimPlaybook`).
- **Names checked free:** `Provenance`, `Figures`, `Dues`, `Workings` — `rg` finds no type of those names in main or test.

### Choices for the owner (recommended first)

- **C1 — the groups:**
  - **(a)** Four nested records:
    - `Provenance(computationId, receipt, taxYear, regime, inputsFingerprint, lawAndExec)` — 6, what the run was;
    - `Figures(totalIncome, bill, credits, finalAmount, chapterEight, otherHeads)` — 6, the money; `total(name)` moves here;
    - `Dues(advanceTax, interestAndFees, interestOnRefund)` — 3, what is owed beyond the bill;
    - `Workings(trace, capitalGainsBuckets, notices)` — 3, how it was reached; `notices`' "none when read back from before" stays.
    - `ComputedTax(provenance, figures, dues, workings)` — 4.
  - (b) Another split you prefer.
- **C2 — the JSON:**
  - **(a)** `@JsonUnwrapped` on each group: the API's and the stored JSON stay exactly as today (the probe). A golden test proves it:
    today's JSON of T8-1's computation is captured **before** the change as a test resource. After the change it must serialize to the
    same bytes and read back equal. A computation stored before W-130b (no `chapterEight`) must still read.
  - (b) Nested JSON, a data migration of every stored computation (runbook, backup, idempotent), and an API change. Not recommended.
- **C3 — callers:**
  - **(a)** Callers read through the groups (`tax.figures().bill()`). No duplicate accessors.
  - (b) Keep 18 shortcut accessors on `ComputedTax` that delegate to the groups. No caller changes, but the record keeps a second,
    18-wide surface, which is the thing this item removes.

### Five roles

- **Architect:** a wide result becomes four named concepts. The wire and stored format is frozen by a test, not by care.
- **Product manager:** nothing visible changes.
- **Senior engineer:** one builder site; readers change mechanically, guided by the compiler. No duplicate accessors.
- **Automation tester:** the golden JSON fails on any shape drift. Existing figure tests are unchanged in value.
- **Manual tester:** on staging, a computation stored before the deploy still opens, and a new one returns the same fields.

### Risks or ambiguities

- **`@JsonUnwrapped` with a nested `Optional`/`null` group:** a group whose every field is missing could come back `null`. The golden test
  includes a computation stored before W-130b to catch that. If it bites, the group keeps a default.
- **Churn:** many reader lines change. The compile lists every one, and no figure changes.
