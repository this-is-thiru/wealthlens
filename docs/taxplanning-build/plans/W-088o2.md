### Choices (recommended first)

- **C1 — the type:**
  - **(a) recommended:** `record CapitalGainsPart(String value)`, the `BaseId` idiom (pattern
    `^[A-Z][A-Z0-9_]{1,63}$`, `toString()` the value), staying in `rules.definition` (moving it to `rules.id` would
    touch every import for no behaviour). No named constants: the four codes appear only in data and tests.
  - **(b)** the same, moved to `rules.id`.
- **C2 — order of the special-rate tax lines:**
  - **(a) recommended:** `TaxByBasisNode` declares `RS-CG-PARTS` and walks the parts in `CG-PARTS`' declared order
    (through `DeclaredCapitalGainsParts`, which gains `parts()`), so the order is the row's and today's lines are
    unchanged. `CapitalGainsHead` / `HeadsAfterSetOff` keep only the parts given, unordered (`Map.copyOf`), and a
    lookup of a part not held is nil (`getOrDefault`) instead of the `values()` fill.
  - **(b)** the heads keep insertion order (a `LinkedHashMap` copy) and `TaxByBasisNode` walks the head. No new set
    declared, but the line order then follows the absorption order (OQ-32's declared default) by accident.
- **C3 — where "every part named is declared" is checked:**
  - **(a) recommended:** at pack load, a new `rules/validate/CapitalGainsPartReferences` called from `PackValidator`
    (one line there, so it does not grow past 423). For each version covering the year it checks against **each**
    `CapitalGainsParts` version covering the year:
    1. some row declares the parts (if any reference exists);
    2. every part a `BucketPart` names is declared;
    3. a `CapitalGainsAbsorptionOrder` names each declared part exactly once;
    4. a `SpecialRateShortfallOrder` names each part some row's `capitalgains.part` condition names (walking
       `AllOf` / `AnyOf` / `Not`), each once, and no other;
    5. every `capitalgains.part` condition code is a declared part (closes the silent slab fallback above).

    The two orders' constructors keep only "not null, no part twice". The fact id moves to
    `CapitalGainsPart.FACT` so the validator and `TaxByBasisNode` share one definition.
  - **(b)** checks 2 – 4 only; the condition codes (5) left as since W-088m2.
- **C4 — the tests' 72 constant references:**
  - **(a) recommended:** each test class gets private constants (`SLAB = new CapitalGainsPart("SHORT_TERM_SLAB")`,
    …), the references replaced mechanically by a script asserting each count; expected values untouched.
    `NodeContextRuleSetTest:357`'s `values()` becomes the four codes listed.
  - **(b)** a shared test fixture class. Not the repo's idiom: each node test holds its own helpers.

## Stopped at step 4 (R13) — C3's premise is wrong

**Found while writing case 8:** `PackValidator` is **not run when a pack is loaded**. No class in `main` calls it
(`ClasspathRulePackProvider`, `JsonPackAssembler`, `ShippedRulePacks` only throw `PackValidationException` from the
readers). It runs only in tests over the shipped packs: `RulePackLoadTest:82`, `TaxYear2025RulePackTest:127`. The plan
(C3a, and the Javadoc I wrote on `CapitalGainsPart`) says "refused at pack load"; it would be refused **by the build**,
which runs those tests, not at runtime.

What that changes: today an unknown part is refused at runtime parse (`DefinitionJson`'s enum read). After this item a
well-shaped unknown code parses, and the guard is the build's validation of the shipped packs. Packs ship only inside
the jar, so every pack a deploy can load has passed it — the same footing as I2, I13 – I15 and D-252 today.

**State on disk:** steps 1 – 3 written and compiling; step 4 part-done (the 72 references replaced, one parse test
replaced, `PackValidatorTest` cases 3 – 7 written, not yet run; case 8 not written). Nothing committed.
