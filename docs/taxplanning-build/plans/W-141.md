## Plan for W-141 — independent oracle and `expected.csv`

**For:** golden expectations at a scale hand working cannot reach (hundreds of incomes, both regimes, every age class,
both years), each checked against a second, deliberately naive implementation of the same law, so a disagreement means
one of the two is wrong and a person decides which (`DR 19` E4.2; `D-GOLDEN`).

### What I read (session 48)

- **`DR 19` E4.2** (`taxplanning-design/19-engineering-foundations.md:344`): "a deliberately naive, deliberately
  separate reference implementation — a few hundred lines of Python, written from the rulebook by a different person,
  with no shared code, no packs, and hard-coded numbers"; `test-oracle/oracle.py`, `cases.csv` (inputs),
  `expected.csv` (its output, checked in and reviewed); the Java test reads `expected.csv`. Release gate 1
  (`:582`): "the independent oracle agrees on every case".
- **What the oracle can be checked against today:** the hand-worked T1/T2 cases (44, W-140a) cover total income → tax:
  slabs, rebate and its marginal relief, surcharge and its relief, cess, rounding. Every rate it needs was read from the
  Gazette this session (`sources/2026-11-07-boundary-figures.md`), rows 1 – 10.
- **The build has no Python:** `cicd.yaml` runs Maven only. So the build reads `expected.csv`; it cannot rerun the
  oracle.
- **No law is introduced:** the oracle hard-codes the rates already read, each constant citing its row in that source
  document.

### Choices (recommended first)

**C1 — who writes the oracle.** E4.2 asks for "a different person". (a) **I write it, and say plainly what is and is
not independent:** no shared code, no pack, no Java, written from the Gazette text in the source document rather than
from the engine; but the same author as most of the engine, so a misreading of the statute common to both would pass.
The 44 hand cases, which the oracle must reproduce first, are the check on that. (b) You, or someone you name, write
`oracle.py`; I write the cases, the Java test and the fingerprint. (The labour worker is ruled out: its brief excludes
law and figures.)

**C2 — scope.** (a) **Total income → payable**, as T1/T2: regime, age class (under 60, 60 – 79, 80+), tax year, total
income; slabs, rebate with its marginal relief, surcharge with its relief, cess, rounding. Salary, house property,
capital gains and Chapter VIII are out, each a larger oracle of its own. (b) Also the salary head: several times the
size, and most of its law is rule data the oracle would have to restate.

**C3 — the cases.** (a) A deterministic grid in `cases.csv`, about 1,200 rows: every ₹25,000 to ₹60 lakh, every ₹5 lakh
to ₹6 crore, and ±₹10 / ±₹100 around each boundary W-140's generator finds — for both regimes, the three old-regime age
classes, both years. About 2 ms an engine run (measured in W-140), so about 3 seconds in the unit tier. (b) Random
incomes: not reproducible as a reviewed file.

**C4 — keeping `expected.csv` honest without Python in the build.** (a) `expected.csv`'s first line records the sha256
of `oracle.py` and `cases.csv`; the Java test recomputes both and fails if either file changed without
`expected.csv` being regenerated. A disagreement between the engine and a row fails the test listing every differing row
with both figures; nothing is adjusted until a person decides (as W-140a C3a). (b) Trust the regeneration: an edited
oracle could sit beside a stale `expected.csv`.

### Build (C1a – C4a)
1. `test-oracle/oracle.py` (standard library only, `Fraction` arithmetic, no imports from the repo), its constants
   each citing a row of the source document; `test-oracle/cases.py` writes `cases.csv`; `oracle.py` writes
   `expected.csv` with the fingerprint line. `test-oracle/README.md`: how to regenerate, and what independence it has.
2. First, the oracle reproduces all 44 T1/T2 figures (a check inside `oracle.py`, run when it generates); any miss stops
   it before `expected.csv` is written.
3. `backend` test `taxengine/golden/OracleAgreementTest`: the fingerprint check, then every row through
   `GoldenCaseRunner`.
4. W-141 row; release gate 1's "oracle agrees" now has a test to point to.

### Tests, by hand
- The 44 hand cases are the oracle's own acceptance (step 2): they are worked by hand, not by either implementation.
- **Probes:** edit one `expected.csv` figure → the Java test fails naming that row; edit `oracle.py` without
  regenerating → the fingerprint check fails; change the oracle's 2-crore surcharge to 20 % and regenerate → step 2
  stops it (the hand cases T2-10 – T2-13 and T2-22 – T2-25 disagree).
