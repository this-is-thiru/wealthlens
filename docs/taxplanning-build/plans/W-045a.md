## Plan for W-045a — the engineering standards, enforced by the build

**What this item is for (one sentence):** make the `CLAUDE.md` "Engineering standards" fail the
build and block a commit when broken, so they hold in every module without anyone remembering them,
while leaving today's legacy code buildable through a baseline that can only shrink.

**Files I will create:**
- `checkstyle-suppressions.xml` (repo root) — the legacy baseline: one `<suppress files=… checks=…/>`
  per (file, check) from the 2026-09-23 measurement, **generated** from the report, not hand-typed;
  no line numbers, so an edit to a legacy file does not shift it
- `backend/src/test/java/com/thiru/wealthlens/architecture/CheckstyleBaselineTest.java` — fails if
  the baseline gains an entry (shrink-only ratchet: the recorded maximum is a constant that may only
  be lowered)
- `.claude/settings.json` — a `PreToolUse` hook on `Bash` commands running `git commit`
- `.claude/hooks/pre-commit-gate.sh` — runs `./mvnw -q test -pl backend -Punit` (Checkstyle runs in
  `validate`, so the same call covers it); non-zero → exit 2, blocking the commit with the failing
  output

**Files I will modify:**
- `pom.xml` — `maven-checkstyle-plugin` 3.4.0 → 3.6.0 with `com.puppycrawl.tools:checkstyle:10.26.1`
  (9.3 predates Java 25); `failOnViolation=true`, `violationSeverity=warning`,
  `includeTestSourceDirectory=true`, `suppressionsLocation=checkstyle-suppressions.xml`; add a
  `spotless` execution: goal `check`, phase `validate`
- `checkstyle.xml` — the strict rule set measured in session 4 (below); test method names allow
  `methodName_whenCondition_expectedResult`
- `backend/src/test/java/com/thiru/wealthlens/architecture/ArchitectureTest.java` — two rules:
  `classes_have_no_generic_suffix` and `simple_class_names_are_unique`, each with the existing cases
  as a named exception list

**Rule set** (all Checkstyle built-ins): the naming checks (`TypeName`, `MethodName`, `ConstantName`,
`MemberName`, `ParameterName`, `LocalVariableName`, `StaticVariableName`, `PackageName`,
`AbbreviationAsWordInName` ≤ 3); `AvoidStarImport`, `UnusedImports`, `RedundantImport`,
`IllegalImport`; `EmptyCatchBlock`, `IllegalCatch`, `EmptyBlock`, `NeedBraces`; `EqualsHashCode`,
`StringLiteralEquality`, `SimplifyBooleanExpression`; `OneStatementPerLine`,
`MultipleVariableDeclarations`, `HideUtilityClassConstructor`; `MethodLength`, `ParameterNumber`,
`CyclomaticComplexity`, `FileLength`; `TodoComment` (a `TODO(W-0nn)` with an id is allowed).

**ArchUnit exceptions, listed by name in the rules:**
- generic suffixes: `AuthHelper`, `FileHelper`, `ParserUtil`, `DoubleUtil`,
  `ChargeRecordingGatewayImpl`, `UserDetailsServiceImpl`, `UserDetailsImpl`,
  `AssetRequestParserImpl`; the `T`-prefixed classes in `shared/util` are allowed by convention
- duplicate names: `DateRange` (`taxrules.temporal` and `shared.dto`), recorded as owed in Appendix F;
  `TaxEngine` is resolved by **deleting the placeholder** `taxengine/TaxEngine.java`, which its own
  javadoc says to delete once the module has real types (it has 30 files)

**Design sections I read:** `CLAUDE.md` Build gotchas and Conventions; `pom.xml:285-326`;
`checkstyle.xml`; `ArchitectureTest.java`; `.github/workflows/cicd.yaml:34` (CI already runs
`spotless:check`, and the code passes it today — exit 0).

**What I am NOT doing:** fixing the 89 legacy violations outside the tax modules (they go into the
baseline); renaming the 8 grandfathered classes or `DateRange`; compiler `-Werror`; PMD or any new
tool; a git (non-Claude) pre-commit hook — proposed below as an option, not done.

**How I will verify:**
```
./mvnw test -pl backend -Punit            # green, with Checkstyle failing on violation
./mvnw -q validate -pl backend            # Checkstyle + spotless:check pass
```
and prove each gate bites, then revert each probe and show `git diff` empty for it:
1. add a `catch (Exception e)` to a tax-module class → Checkstyle fails;
2. add a class named `…Helper` → `ArchitectureTest` fails;
3. add a second class with an existing simple name → `ArchitectureTest` fails;
4. add a suppression entry → `CheckstyleBaselineTest` fails;
5. mis-indent / leave a trailing space → `spotless:check` fails;
6. break one assertion and attempt `git commit` → the hook blocks it.

**Risks or ambiguities:**
- **Size:** ~300 hand-written lines, plus the generated baseline (~110 entries of XML, data). At the
  top of §7's limit. If you prefer, split: **W-045a** = Checkstyle + baseline + Spotless + the 7
  fixes; **W-045a2** = ArchUnit naming + the hook.
- **Build time:** Checkstyle over main + test adds a few seconds to every build; the hook adds the
  unit tier (~9 s) to every commit. NFR N12's 20 s budget covers the tests, not Checkstyle — I will
  report the measured total.
- **The hook binds Claude Code sessions only.** A human running `git commit` in a terminal is not
  gated. Option (not in this item): a versioned `.githooks/pre-commit` plus a one-time
  `git config core.hooksPath .githooks` per clone.
- **`TraceLine.limited` → `.limitedBy(...)`** changes a public method of a `W-036` type; it is inside
  this item's `Produces` by the approval of this plan, not by `W-036`'s.
