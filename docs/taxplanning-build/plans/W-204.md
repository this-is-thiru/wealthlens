## Plan for W-204 — a JSON `null` for a primitive field

**What this item is for (one sentence, in my own words):** two `api-collection` requests cannot be read by the
application — Jackson 3 binds the Lombok all-args constructor of the types they carry and passes `null` for every
field the body omits, which `FAIL_ON_NULL_FOR_PRIMITIVES` refuses — so this item checks the failure by a request (it
was unchecked) and repairs the two requests, or the binding they depend on.

**Source:** `03-WORK-ITEMS.md` W-204; `plans/W-202.md` RV2 and RV2a; D-406.

**Board (R4):** `… W-201 D  W-202 D  W-203 D  W-204 ·  W-194 · …`. W-204 is the first open item. The resume check
matched: last item commit `e5c7e305` (W-203), tree clean.

### What I found (2026-10-31)

**The application refuses both requests today — measured by a request, which is what the row asked to check.** A
scratch integration test (deleted after the runs; copies in `/tmp/w204/kept/`, never committed) posted each YAML body
to its endpoint against the app on the integration profile, with a real `SUPER_USER` / user JWT:

- `POST /charge-schedules` (`ChargeScheduleController:60-62`, binds `ChargeScheduleEntity`) → **400**,
  *"JSON parse error: Cannot map `null` into type `boolean` (set `DeserializationFeature.FAIL_ON_NULL_FOR_PRIMITIVES`
  to 'false' to allow)"*.
- `POST /test/user/{email}/transact/sell` (`TestController:22-29`, binds `ProfitLossDto`, which holds
  `List<AssetEntity>`) → **400**, the same message with `double`.

The auto-configured MVC mapper is `tools.jackson.databind.json.JsonMapper` (Boot 4.1.0, Jackson 3.1.4) with
`FAIL_ON_NULL_FOR_PRIMITIVES` **on**, and `FAIL_ON_UNKNOWN_PROPERTIES` on (W-202).

**No body carries a `null` for those fields — the fields are absent, and the constructor supplies the `null`.** The
server stack names the mechanism: `PropertyBasedCreator.build` → `ValueInstantiator.createFromObjectWith` →
`getAbsentValue` → `handleNullForPrimitives`. Jackson 3 uses the **public all-args constructor** that Lombok generates
for `@Data @AllArgsConstructor` classes as a properties-based creator, so every omitted field reaches the constructor
as `null`; `ChargeRule`'s `perLot` (`ChargeRule.java:124`) and `AssetEntity`'s `brokerCharges`
(`AssetEntity.java:73`) are primitives, and null into a primitive is refused.

- `Publish a rate card` is missing `perLot` and `appliesToCorporateActions` on all four rules (`ChargeRule.java:124`,
  `:133`); every other boolean it declares (`taxable`, `active`, `order`) is present.
- `Test Req/Transact - New` is missing `brokerCharges`, `miscCharges`, `allocatedBuyCharges`,
  `allocatedBuyMiscCharges` (`AssetEntity.java:73`, `:76`, `:90`, `:94`) on both holdings; `price`, the fifth
  primitive (`:57`), is present.

**The same binding also nulls omitted collections and `auditMetadata`, which the primitive check hides.** Once the
four doubles are sent, the transact request no longer fails at the boundary but 500s at
`PortfolioService.java:641` — *"Cannot invoke java.util.List.add(Object) because the return value of
AssetEntity.getSellTransactionIds() is null"*: the initialisers at `AssetEntity.java:134`, `:137`, `:140`, `:112` are
bypassed. And a card published through the API stores **no author**: the re-read document answers
`"auditMetadata":{"createdAt":null,"createdBy":null,…}`, while the same body with `"auditMetadata": {}` answers
`"createdBy":"probe@example.com"` — the `new AuditMetadata()` initialiser (`ChargeScheduleEntity.java:110`) was
nulled by the constructor. This is the root cause, not the two bodies; it is W-205 below.

**The two requests have two further defects that keep them broken after the binding is satisfied (both measured).**

- **The rate card can never publish after the seed.** With the two booleans added, the service refuses it:
  *"Charge schedule ZERODHA_EQ_DELIVERY_2026_04 starts on 2026-04-01, which is not after the open schedule
  ZERODHA_EQ_DELIVERY_2026_06 starting on 2026-06-19"* (`ChargeScheduleService.java:120-145`; the shipped card at
  `backend/src/main/resources/data/charges/zerodha-equity-delivery-2026-06-01.json`). The runbook seeds before the
  app is used, so this state is the normal one.
- **The transact request sells 40 against lots totalling 30.** `assetRequest.quantity` is `40.00`, the two
  `stockEntities` hold `10.00 + 20.00`, and the service iterates the list until the quantity is met → the repaired
  request 500s at `PortfolioService.java:641` with `NoSuchElementException`.

**Repaired bodies work — measured.** Rate card with the two booleans per rule and `"planCode": "PROBE_PLAN"` →
**200**, the card returned with `perLot:false`, `appliesToCorporateActions:false`; a plan-scoped card finds no open
incumbent because every shipped card has `planCode: null`. Transact with the four doubles, four empty lists
(`buyTransactionIds`, `sellTransactionIds`, `corporateActions`, `orderTimeQuantities`) and `quantity: 30.0` → **200**.

**The affected surface is these two types, not request bodies in general.** `AssetRequest` — the V2 trade body — is
`@Getter @Setter @NoArgsConstructor` (`AssetRequest.java:26-29`) and binds through its no-arg constructor; every
`@RequestBody` type with primitives was checked: `CorporateActionDto` (`priority`, `@Data` only), `ChargeSimulationRequest`
(`@Data @NoArgsConstructor`), `ChargeAccountEntity` (primitives only in the nested `BillingEvent`, not sent), the tax
policy entities (no primitives), `BonusAllotmentDate` (a record with none).

**Levers measured on a minimal public class and on the real types (scratch probe, Jackson 3.1.4).**

| Lever | Result |
|---|---|
| a public class with a public no-arg and a public all-args constructor | binds the **all-args** one — the rule reproduces without Lombok |
| `ConstructorDetector.EXPLICIT_ONLY` | no change; both bodies still refused |
| `ConstructorDetector.DEFAULT.withAllowImplicitWithDefaultConstructor(false)` | both bodies **bind**; `new ArrayList<>()` initialisers survive |
| `@JsonCreator(mode = DISABLED)` on the all-args constructor | binds through the no-arg constructor |
| records | still bind under every setting (canonical constructor); a record with a primitive component still refuses a missing one |

Boot 4.1.0 exposes `spring.jackson.constructor-detector` (`spring-boot-jackson-4.1.0.jar`, default `default`), but its
strategies do not include the flag that fixes this; the working lever needs a `JsonMapperBuilderCustomizer` bean.

### Choices (recommended first)

- **C1 — where the refusal is removed:**
  - **(a) recommended: fix the two requests.** Send the fields the bound types declare — `perLot` and
    `appliesToCorporateActions` on each rule, the four doubles and four empty lists on each holding. No code changes;
    the loud refusal stays as the guard for the next body that omits a primitive (always send what the type has). Its
    limit is honest: it does not repair the initialiser loss (`auditMetadata`, omitted collections), which is W-205.
  - **(b) fix the binding globally.** A `JsonMapperBuilderCustomizer` setting
    `ConstructorDetector.DEFAULT.withAllowImplicitWithDefaultConstructor(false)` — measured to make both bodies bind
    as written, restore the initialisers and the audit author. It changes every request body's binding and makes an
    omitted primitive default silently across the API, against "Nothing silent" and W-202's direction; it needs a
    test proving records still bind and a sweep of every endpoint, and the two data defects (C2, C3) still need
    repairs.
  - **(c) fix the two types.** `@JsonCreator(mode = DISABLED)` on the Lombok all-args constructor via
    `onConstructor_`. Targeted, and the same silent-default consequence for these two types only; the next
    entity-bodied request is broken again.
- **C2 — the rate card example's scope:**
  - **(a) recommended: a plan-scoped card.** Add `"planCode": "TEST_PLAN"` (or another clearly test-only code). No
    shipped card is open for that scope, so the request publishes at any time and prices nobody — measured 200. The
    docs call a plan "reserved for per-user negotiated rates", so a test plan is a truthful scope.
  - **(b) supersede the open card.** Move `scheduleCode`/`startDate` past `ZERODHA_EQ_DELIVERY_2026_06` (2026-06-19).
    It demonstrates supersession, but a real publish closes the default card and reprices everyone from the new start
    date, and the example ages again with the next shipped card.
  - **(c) leave it broken; place a row.**
- **C3 — the transact example sells 40 of 30 units:** set `assetRequest.quantity` to `30.0` (a full sale of the two
  lots). Adding a third lot only to reach 40 invents a holding. Measured 200.
