## Plan for W-125 — the `DocumentParser` SPI

> **Approved C1a, C2a, C3a** (owner, session 102, 2026-11-16). Built; review: "commit and push". Every path below was read on 2026-11-16 at `67349dbe`; grep each again before

**What this item is for (one sentence, in my own words):** the seam every form parser plugs into, and the one place a
parse runs — it picks the parser for the document's form, checks the bytes are the document's, times the run and
records it as a `ParseAttempt` (W-124), so W-126 – W-129 write only the reading of a form.

### What the design says

- `DR 07` X2.5 (`07-architecture.md:234` – `:246`): `supports(DocumentType type, TaxYearId year)` and
  `ParseAttempt parse(IngestedDocument doc)`, "never throws on bad input; records outcome". The year is there "because
  Form 16 (TY 2025-26) and Form No. 130 (TY 2026-27) are different documents" — written when one type covered both.
- `02-TECH-SPEC.md:109`: package `taxplanning.documents.parser` — `DocumentParser`, `Form130Parser`, `Form16Parser`.
- `DR 14` O6 (`14-operational-design.md:161` – `:175`): the parser takes untrusted bytes; it runs with no network and a
  CPU and wall-clock budget; a password is never kept. O9 (`:233`): a crash or timeout is `FAILED` with a reason, the
  document kept.
- `DR 13` rows 71 – 72 (`13-edge-cases.md:492` – `:493`): a password-protected PDF and a scan with no text layer are
  clean `FAILED` outcomes, not exceptions.
- D-727 C2a: `DocumentType` names the form itself (`FORM_16`, `FORM_130`, `FORM_122`, `FORM_123`), no year.

### Findings

1. **The year in `supports(type, year)` is no longer needed, and would be law in code.** Since D-727 C2a, Form 16 and
   Form No. 130 are two `DocumentType`s, so the type alone picks the parser. Which form a tax year prescribes is law
   (the Income-tax Rules, 2026 prescribe Form No. 130); a parser declaring the years it reads would write that into
   Java (CLAUDE.md §4). A Form 16 uploaded for TY 2026-27 is a question for the upload (`DR 13` row 74, W-131).
2. **`parse(IngestedDocument)` has no bytes.** `IngestedDocument` holds no content and no storage reference (D-727
   C1a), so the parser must be handed the bytes.
3. **A parser that times itself and makes its own ids reads a clock** — every parser would. The repo injects a
   `Clock` into services (`DraftService:44`, `TaxAccessLog:17`) and makes ids with `UUID.randomUUID()`
   (`DraftService:56`).
4. **No caller yet**, as with W-124: the first parser is W-126, the first production call W-131.

### Choices for the owner (recommended first)

- **C1 — how a parser says what it reads:**
  - **(a) `DocumentType reads()` — one form per parser, no year** (finding 1). A departure from `DR 07` X2.5,
    recorded as an erratum in the D-row.
  - (b) `supports(DocumentType, TaxYearId)` as written: each parser lists the years it reads, in Java.
- **C2 — what a parser returns:**
  - **(a) a `DocumentReading` — outcome, fields, unread text, notes — and `DocumentParsers` makes the
    `ParseAttempt`** (attempt id, parser id and version, start and finish from an injected `Clock`). A parser is then a
    pure function of the bytes (finding 3), easy to test on a fixture.
  - (b) the parser builds the `ParseAttempt` itself, as `DR 07` writes it: each parser takes a `Clock` and makes ids.
- **C3 — the budget and isolation of O6:**
  - **(a) not here: W-131's `ParseDocument` job** runs the parse and holds the wall-clock budget, where a timeout
    becomes a stored `FAILED` attempt (O9). W-125 adds nothing that runs a thread. W-131's row gains it.
  - (b) here: `DocumentParsers` runs each parse on a bounded executor with a timeout.

### Files I will create (C1a, C2a, C3a)

In `backend/src/main/java/com/thiru/wealthlens/taxplanning/documents/parser/`:
- `DocumentParser.java` — the SPI: `DocumentType reads()`, `String id()`, `String version()`,
  `DocumentReading read(DocumentContent content)`. Contract in its Javadoc: a bad document (password, no text layer,
  unreadable) is a `FAILED` reading with its reason, never an exception; the bytes are untrusted.
- `DocumentContent.java` — record holding the bytes (copied in and out). Refuses empty content.
- `DocumentReading.java` — record: `outcome`, `extractedFields`, `unmappedText`, `parserNotes`. The outcome rules
  stay in `ParseAttempt` (D-727), checked once, when the attempt is made.
- `DocumentParsers.java` — a record of the parsers by `DocumentType` and the `Clock`, made by `DocumentParsers.of(List<DocumentParser>, Clock)`.
  - **At start:** two parsers reading one `DocumentType` are refused by `of`, naming both, so the boot stops — never a
    silent pick. This follows `HrSupportTable` (`compute/HrSupportTable.java:15` – `:41`), a record refused at start
    and made by a `@Bean` in `HrSupportConfig`.
- `DocumentParsersConfig.java` — `@Configuration`: the `@Bean` `DocumentParsers` from the context's parsers (none until
  W-126) and its `Clock`.
  - `ParseAttempt parse(IngestedDocument document, DocumentContent content)`: refuses content whose SHA-256 is not the
    document's (`IllegalArgumentException`, "The content is not this document's"); refuses a type no parser reads
    ("No parser reads FORM_122 yet"); otherwise times `read` with the clock and returns the attempt with a fresh UUID.

`documents/ingest/`'s `Checks` is package-private; the parser package needs its two refusals once each and states
them inline.

Tests in `backend/src/test/java/com/thiru/wealthlens/taxplanning/documents/parser/`:
- `DocumentParsersTest` (Mockito-free; two small test parsers as nested classes, a fixed `Clock`):
  - a document parsed by its type's parser → the attempt carries the parser's id and version, the reading's outcome
    and fields, the document's id, start and finish from the clock;
  - content whose SHA-256 differs → refused;
  - a type no parser reads → refused, naming it;
  - two parsers for one type → refused at start, naming both.
- `DocumentContentTest`: empty refused; the bytes are copied in and out.
