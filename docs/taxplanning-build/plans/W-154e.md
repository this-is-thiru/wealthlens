V4 is why W-154c / d's shape does not fit as it stands. If the Sl. 1(c)(i) rows gained owner and use conditions to
choose the path, the employee's own car could no longer find "its" Sl. 1(c)(i) amount by its engine. The column (by
engine, already data) and the path (by owner / use / running / position) are two different choices, and the design
has to keep them apart.

### Choices (recommended first)

- **C1 — how the path is stated:**
  - **(a) recommended: a classification set, `RS-CG-PART`'s pattern.**
    - A new set `RS-PERQ-CAR-PATH` (`AT_MOST_ONE`, `REGIME_AND_CONDITIONS`), whose rows carry no cap but a
      definition `VehiclePath`. It names which Table II computation applies: `NONE` (wholly official),
      `MONTHLY_EMPLOYER_RUNS` (Sl. 1(c)(i)), `MONTHLY_EMPLOYEE_RUNS` (Sl. 1(c)(ii)), `RUNNING_AND_WEAR`
      (Sl. 1(b)), `EXPENDITURE_LESS_OFFICIAL_USE` (Sl. 2(b) / 3(b)).
    - Each row is chosen by `vehicle.owner`, `vehicle.use`, `vehicle.employee.meets.private.running`,
      `vehicle.journeys.and.certificate.kept`, and the V5 facts (C3).
    - The engine-column sets (`RS-PERQ-CAR-PARTLY`, `-OWNRUN`) and the valuing rows stay as they are, so V4
      reads `RS-PERQ-CAR-PARTLY` by engine as today.
    - A vehicle no path row reaches is refused generically. That covers wholly official without records, and so
      ends the G9 `:187` test.
    - The node maps each path to its computation. That mapping is Java, as `CapitalGainsNode` maps
      `CapitalGainsPart`: it names a shape of arithmetic, not a legal category, and which vehicles take it is
      data.
    - New pieces: one definition type (record and enum, JSON parsing, `RuleJsonDefinitionTest` cases) and about
      six path rows × two versions. Their provisions and provenance are copied from the valuing row each path
      leads to.
  - **(b) one set per path (W-154c / d's shape).** The Sl. 1(c)(i) / (ii) / 1(b) / 2(b) / 3(b) valuing rows each
    gain owner and use conditions, and the path is whichever set answers. V4 then needs the employee's car to look
    up Sl. 1(c)(i) as if it were an employer's car partly used, which means invented facts. Alternatively the engine
    columns are duplicated, with each column's figure held twice per year. I do not recommend it.
- **C2 — the split (each builds and verifies alone):**
  - **(a) recommended:**

    | Row | Scope | Elements | Size (est.) |
    |---|---|---|---|
    | **W-154e1** | The employer's car's gate on `perquisite.arrangement` (W-154b's mechanism; the car publishes `EMPLOYER_PROVIDED` for its own or hired car, `EMPLOYEE_OBLIGATION_MET` for the employee's own vehicle — see C4) | V2 | ~25 main, ~60 test, no rows |
    | **W-154e2** | `VehiclePath` and `RS-PERQ-CAR-PATH`: V1, V3 as path rows; the owner `switch`, the use tests and `requireOfficialRecords` go | V1, V3 | ~130 main, ~180 test, ~6 rows, 1 definition type |
    | **W-154e3** | The several-cars proviso as path-row conditions on the V5 facts; `carsNotWhollyOfficial`'s legal test goes | V5 | ~40 main, ~80 test, conditions on 2 – 3 path rows |

    The order is e1 → e2 → e3. e3 needs e2's path rows to put its conditions on.
  - **(b)** W-154e whole: about 200 main and 320 test lines, ~6 rows, a definition type. That is over §7.
- **C3 — the V5 facts (dot-separated, D-327 R1a):**
  - **(a) recommended:** two quantities a car publishes: `vehicle.employer.cars.shared` (how many of this
    employment's employer cars are not wholly official) and `vehicle.employer.cars.position` (this car's place among
    them, from 1). Both are counts of the entered facts. The rule "one at Sl. 1(c)(i), the rest at Sl. 1(b)" becomes
    path conditions (`ItemFactAtMost` on the count, a position test). Which one is "the one" stays "the first
    entered" (D-113), and e3's plan shows that reading.
  - **(b)** one boolean, "another of this employment's cars precedes this one". Simpler, but it folds the count and
    the position into one Java-derived flag, close to a derived label (CLAUDE.md §4).
- **C4 — the car's `perquisite.arrangement` (e1):**
  - **(a) recommended:** read from `VehicleOwner` in the input. `EMPLOYER_CAR` is defined as "a motor car the
    employer owns or hires", the employer's own provision; the employee's vehicles are their own. It is stated once,
    on `VehicleOwner` (an `arrangement()` accessor), as the input's fact, the same standing as a child's education
    publishing `EMPLOYER_PROVIDED` (D-327).
  - **(b)** a new `arrangement` field on `EmployerVehicle`, entered by the taxpayer. It would be redundant with the
    owner, and the two could contradict each other.
- **C5 — the wholly-official vehicle's trace (e2; asks leave, D-325 C4a):**
  - **(a) recommended:** a `NONE` path writes a nil line on its path row ("not a perquisite: wholly official, with
    records — <row>"), as every other exclusion now does. `:296–309`'s "no line" assertion **changes** to that line
    (R3: shown here for approval). Its value stays 0.
  - **(b)** a `NONE` path writes no line, as today. Then it is the only exclusion with no trace of the row that
    excluded it.
