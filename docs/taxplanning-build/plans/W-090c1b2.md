## Plan for W-090c1b2 — The losses across years

**What this item is for (one sentence, in my own words):** every computation publishes, for each head, the loss
brought forward into the year and the loss left to carry forward out of it. r.164(2)(b) and (d) bar ITR-1 on either
(Gazette 271092 p.1662, read in `plans/W-090c.md` F1), and today both exist only as trace text.

**Findings (each read this session):**
- F1: `SetOffNode` publishes `new HeadsAfterSetOff(total, parts, indexedGains)` (`node/SetOffNode.java:132`). The
  losses appear only as MEASURE lines:
  - this year's house-property loss not set off, "carried forward" (`:163`), or in the new regime "deemed to have been
    given full effect to" and not carried (`:148`);
  - a carried-in loss that is refused because it was not determined in time (`node/CarriedLossSetOff.java:138`),
    expired (`:144`), deemed given full effect to (`:176`), or "still carried forward" (`:162`).
  - `CarriedLossSetOff.apply` returns nothing (`SetOffNode.java:128` – `129`).
- F2: the year's own capital loss is already a value. `CapitalGainsHead` carries `shortTermLossLeft` and
  `longTermLossLeft` (`pipeline/CapitalGainsHead.java:28`), carried forward by `CapitalGainsNode.java:187`.
- F3, **a defect in W-090c1b1:** `HasLossUnderHead(CAPITAL_GAINS)` can never hold.
  - `ReturnFactsProjection.java:39` reads the head as `CapitalGainsHead.total()`. That is the sum of parts, each nil or
    more (`CapitalGainsHead.java:75`, with the constructor refusing a negative part).
  - The year's capital loss sits in the two "loss left" fields (F2), which no fact reads.
  - No test or form uses `HasLossUnderHead(CAPITAL_GAINS)` today. Its only test uses `HOUSE_PROPERTY`
    (`ConditionTest.java:721`). r.164(2)(c) applies it only to other sources.
- F4: `HeadsAfterSetOff` readers. Each one reads by accessor, and none reads a new component:
  - `GrossTotalIncomeNode.java:39` reads `total()`.
  - `TaxByBasisNode.java:84`, `:157` read the parts and indexed gains. `SurchargeNode.java:125` and
    `ChapterEightNode.java:252` read them through `TaxByBasisNode.atSpecialRates`.
  - `new HeadsAfterSetOff(` is called once in main and 19 times in 18 test files, through the 2- and 3-argument
    constructors.
  - Nothing serialises a `NodeValue`. `PipelineRunner` keys its cache on the inputs' fingerprint, not on values
    (`PipelineRunner.java:59`).

**Choices for the owner:**
- **C1a (recommended): "brought forward" is what the law still carries into this year.** That is each ledger year's
  remaining loss that is within its span and, for a capital loss, was determined in time, counted before set-off. It
  includes a portion the new regime then deems given full effect to, because that loss was brought forward and then
  went.
  - C1b: every remaining ledger loss, including an expired one. An expired loss is no longer carried (S2 s.110(2),
    s.111(2)), so it is not "brought forward".
- **C2a (recommended): "to be carried forward" is what the year leaves, by head.**
  - House property: this year's loss not set off, in the old regime (F1 `:163`), plus the carried-in house-property
    loss "still carried forward".
  - Capital gains: the year's short-term and long-term losses left (F2), plus the carried-in capital loss still carried
    forward.
  - Not included: a deemed, expired or refused loss, or a loss under other sources (no provision carries it).
  - The year's own capital loss is carried only if this year's return is filed in time (S2 s.121). The engine cannot
    know that, so the fact counts it and its Javadoc says so.
- **C3a (recommended): fix F3 by refusing it.** `HasLossUnderHead` refuses `CAPITAL_GAINS` when it is built, and the
  message points to `HasLossCarriedForward`. The `ReturnFacts` Javadoc then says the capital-gains figure is the
  surviving income, never below nil. An erratum goes on the W-090c1b1 plan.
  - C3b: report the capital-gains figure as the parts minus the losses left. But a long-term loss left can sit beside
    short-term gains, and the netted figure would then hide the loss.
