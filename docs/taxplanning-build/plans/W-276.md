## Plan for W-276 — an upload row with an empty cell is misread; the hollow upload tests

**What this item is for (one sentence, in my own words):** each uploaded cell is read under its own column's header,
so an empty cell stays empty instead of shifting every later value, a misfit names its row and column, and the upload
tests check rows that are actually parsed (G-10).

**Findings (each read this session, 2026-11-11):**

1. **Cells are mapped by iteration order.** `AssetRequestParserImpl.extractRows` walks `row.cellIterator()` and gives
   the n-th cell met the n-th header; POI's iterator skips cells never written, so an untouched maturity date or
   comment moves every later value one header left. Proven: W-264a scenario 16 — an equity row with its maturity-date
   and comment cells untouched answered 400 "Cannot get a NUMERIC value from a STRING cell" (QUANTITY read under
   PRICE's neighbour). A spreadsheet program does not write an empty cell.
2. **The misfit message names a cell type only** (`getCellDetail` rethrows POI's message as a 400).
3. **A blank cell read as a number gives 0.0** (POI's `getNumericCellValue` on a blank) — so mapping by index must
   read a blank as absent, not as 0.
4. **Four upload tests are hollow.** `PortfolioIntegrationTest.buildValidExcelContent` (`:1388`) writes its row to the
   sheet of today's quarter (`:1399`, `quarterFromDate(LocalDate.now())`) while every caller uploads `quarter=Q1`
   (`:415, 485, 519, 1169`); since October the parsed sheet is empty, so `uploadTransactions_allSucceed…`,
   `…someBlockedByCA…` and the two others pass without reading a row.
5. **Required cells** (an empty price or quantity) are validation — W-277 (PS-1) — not this item.

**Choices for the owner:**

- **C1 — reading a row.**
  - **C1a (recommended):** read cell *i* under header *i* (`row.getCell(i, RETURN_BLANK_AS_NULL)`); a missing or
    blank cell is absent (`null`), never 0; a cell that does not fit its column answers 400 "Row 2, PRICE: expected a
    number" (row as the sheet numbers it); a value in a column with no header is refused naming the row and column.
- **C2 — a row with nothing in it** (a formatted but empty row a spreadsheet keeps after the data).
  - **C2a (recommended):** skipped — it is not a trade. Today it is refused as "Invalid number of columns".
  - C2b: refused, naming the row.
- **C3 — the hollow tests.**
  - **C3a (recommended):** the helper writes to the `Q1` sheet the callers upload, with a date inside Q1 of this year
    so it is never in the future, and each of the four tests asserts what was stored, not only the status.

**Files I will modify:** `AssetRequestParserImpl` (C1a, C2a); `PortfolioIntegrationTest` (C3a); tests — W-264a
