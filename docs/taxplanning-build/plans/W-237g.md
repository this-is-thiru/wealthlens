## Plan for W-237g — a copy before erasure

**For:** the user can take a copy of their tax computations before an erasure request makes a profile unreadable.
This is a product decision, not a legal duty (W-237 C2a). The row says to decide it with W-123.

### What I read (session 55)

- **The row** (`03-WORK-ITEMS.md:1524`): *"the client offers the user their computations (the PDF report, W-123) before
  an erasure request is confirmed"*.
- **W-235's decision** (`plans/W-235.md:30-32`, C1a): everything under a profile is erased. Before that, the response
  points the user to their own copy. Risk 4 (`:114-115`): the receipt cannot point to the copy, because a held profile
  reads as absent. The offer has to come *before* the request.
- **No client is in this repository** (`README.md:707` lists a web UI as future work). W-247 already holds "whichever
  client users see". So "the client offers" cannot be built here. What the server can do is make a copy exist and say,
  in the API, where it is.
- **What a user can read today, before a request**, for a `TaxpayerProfile`:
  - `GET …/drafts/{draftId}` and its revisions (`workspace/controller/DraftController.java:44-88`).
  - `GET …/computations/{receipt}` (`compute/controller/DraftComputationController.java:46`).
  - These are JSON only. **No PDF exists for the new profile.** The only PDF,
    `GET /tax-planning/user/{email}/profile/{profileId}/document/tax-report` (`controller/TaxPlanningController.java:96`),
    reads the legacy `SalaryProfileEntity`. That path is W-159's to retire after W-123.
- **W-123** (`03-WORK-ITEMS.md:1485`, Phase 12, `·`) is the PDF report (`DR 04` F10), not started. It is far behind
  W-237g on the board.
- **Account-wide erasure (W-237d)** made everything unreadable once requested. Its plan put "a copy before erasure"
  here (`plans/W-237d.md:93`). For the portfolio, a copy already exists: `POST /portfolio/user/{email}/stocks/download`
  (`portfolio/controller/EntityExportController.java:24`, Excel).
- **`DR 14` O5** (`taxplanning-design/14-operational-design.md:126-140`) was amended by W-235 C1a. It says nothing about the order of
  copy then erasure.

- **(a) Recommended: decide, and build nothing now.**
  - The PDF part moves into W-123's row: the report must be producible for any profile until it is held. W-123 also
    says, in the erasure request's api-collection entry and in the `ErasureController` Javadoc, that the report comes
    first.
  - The client part goes to W-247's row: the screen offers the report, and the portfolio download, before the user
    confirms either erasure.
  - W-237g closes as decided.

    product, not law, so missing it breaches nothing.

  revisions and computations in one body. It would be inside W-135's guard (`ArchitectureTest.exports_carry_no_third_party_data`).
  This meets the date without W-123, but it is a second copy format that W-123 later makes redundant. The JSON reads
  above already give the same data, in several calls.
- (c) Close as not taken. The JSON reads exist, and a copy is not a duty.
