## Plan for W-327e3 — the five missed sites, then the coverage pin

**What this item is for (one sentence, in my own words):** give the last five engine lines a reason, then add a check
that fails any test whose node writes `limitedBy` text the content cannot word, so a line without a reason cannot come
back.

**Probe (the W-327e probe log, re-checked per rule; a read of each site and of both test harnesses; 2026-11-14):**
- **What reads in words** (`ExplanationRenderer.explain`): a line whose `limitedBy` is a limit name its rule's content
  words (`Explanation.byLimit`), or else a line with a reason. Anything else shows the engine's text.
- **Checked per rule** against `content/explanations.json`, the W-327e log has six producers left after W-327e1 and
  e2. Five are this item's sites. The sixth is `SYN-STANDARD-DEDUCTION`, a rule a test builds itself, with no shipped
  explanation, so the pin skips it.
- **The five sites:**

| Site | Today's text | Why it does not read in words |
|---|---|---|
| `AgniveerDeduction:58` | "the whole amount" | engine text, no reason |
| `DepositInterestDeduction:111` (where interest is netted) | "the interest; interest net of the expenditure deducted against it (S2 s.93(1)(e); …; D-228)" | a limit name with engine text after it |
| `RentPaidDeduction:77` | "5000 per month, on total income before this deduction 450000.00" | the same |
| `RetirementNode:225` | "amount under the gratuity statute; separation on 2025-12-15" | the same |
| `RetirementNode:251` (an earlier payment shares the limit) | "limit, less the 300000.00 allowed on this year's earlier voluntary retirement payments, …" | the same |

- **Where the pin can sit:** node tests run through `NodeHarness.run` (80 test files) or `GoldenCaseRunner.run` (21).
  A grep finds no test that calls `evaluate` any other way. Seven classes drive `PipelineRunner.run` directly
  (`PipelineRunnerTest` and `PipelineRecomputationTest` with stub nodes; `SalaryHeadPipelineTest`,
  `ReturnFactsProjectionTest`, the two optimiser room-pricing tests and `EngineBenchmarkTest`). The pin does not see
  those runs, but the nodes they run are also run through the harnesses. A check in the two harness methods therefore
  covers the node outputs the unit tests produce, with nothing added to production code.

**Each site's reason:**
- `AgniveerDeduction:58`: `ALL_DEDUCTED`, the existing code ("All of it is deducted."). No new code.
- `DepositInterestDeduction:111`: `DEPOSIT_INTEREST_NET {received, net}`.
- `RentPaidDeduction:77`: `RENT_PAID_ON_INCOME_BEFORE {income}`.
- `RetirementNode:225`: `RETIREMENT_AT_SEPARATION {date}`.
- `RetirementNode:251`: `VOLUNTARY_RETIREMENT_EARLIER_PAYMENTS {earlier}`.

That is **4 new codes** (168 in all). Where the suffix is absent, each line keeps its limit name alone and reads as it
does today.

**Choices for the owner:**
- **C1: the four suffixed lines.**
  - **C1a (recommended):** each gets a reason for its suffix's fact, as above. The sentence replaces the limit's own
    sentence on those lines. Which limit bound is still in `limitedBy`, and the figure is on the line.
  - C1b: the renderer joins the two, writing the limit sentence for the name at the start of `limitedBy` and then the
    reason's sentence. That reads both, but the renderer would parse audit text and change how every line with both a
    name and a reason reads today.
- **C2: the pin.**
  - **C2a (recommended):** a check in `NodeHarness.run` and `GoldenCaseRunner.run`, in a new test-support class. It
    fails the running test when a line's rule has a shipped explanation, the line has `limitedBy`, the text is not one
    of that rule's `byLimit` names for either shipped year, and the line has no reason. Rules with no shipped
    explanation (fixtures such as `SYN-…`) are skipped.
  - C2b: one test that runs the golden corpus and checks every line. That is simpler, but sees only what the goldens
    reach.
  - C2c: a source scan for `withLimitedBy` calls with no reason in the same statement. It sees every site, but a cap's
    name or a caller-supplied reason makes it guess (the W-327e grep was wrong this way).

**Draft wording (Claude's, for your adoption; no digits):**

- `RENT_PAID_ON_INCOME_BEFORE`: "It is the least of the limits the law sets, measured on your total income before this deduction, {income}."
- `RETIREMENT_AT_SEPARATION`: "It is the least of the limits the law sets for this payment, measured at your separation on {date}."
- `VOLUNTARY_RETIREMENT_EARLIER_PAYMENTS`: "The limit is one for the year: {earlier} of it went to this year's earlier voluntary retirement payments."

**Risks:**

**Departed from the plan (mid-build; owner ruled (a), D-693):** the renderer matches a limit by prefix
(`ExplanationRenderer.limitSentence`, `startsWith`), so four of the five sites already read in words through their limit
sentence, which takes precedence over a reason. Their four reasons would never show, so they were dropped. The build
keeps `ALL_DEDUCTED` at `AgniveerDeduction:58` and the pin, which matches by prefix as the renderer does. The red
checks became Agniveer's reason removed (13 failures) and the credits reason removed (323 failures).
