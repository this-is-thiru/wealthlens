## Plan for W-264a — gap audit: portfolio

**What this item is for (one sentence, in my own words):** find where `portfolio` gives a wrong answer, a 500 or a
silent loss when driven through its HTTP API — buys and sells on both flows, FIFO lots, the holdings views, temporary
transactions and redrive, Excel in and out, and retries — and place each gap as its own fix row; this item fixes
nothing.

**Five roles:**
- **Architect:** watches for a gap that is really a boundary problem — a view computing something another module
  owns, the two flows disagreeing about one lot — and words the fix row at that level, not as a patch.
- **Product manager:** every gap is written as what the holder sees (a wrong quantity, a lost row, a 500), with which
  flow and which client path meets it, so you can order the fixes by harm.
- **Senior engineer:** reads the code path of each scenario before running it, so "expected" is the intended
  behaviour, and a gap is separated from a decision already made (the 2026-09-18 backlog, CLAUDE.md's domain rules).
- **Automation tester:** expected values by hand, first; real HTTP and the real filter chain; each gap reproduced
  twice; kept scenarios named `method_whenCondition_expectedResult`.
- **Manual tester:** the report gives, for each gap, the smallest request sequence that shows it, so you can repeat
  it against your local app.

**Risks or ambiguities:**
- **Size.** Thirty-five scenarios and fifteen-plus old entries is large for one item. If it runs long I will stop at a
  clean boundary (an area finished), report what is covered, and ask whether to continue as W-264a2 — not silently
  thin the rest.
- "Expected" is sometimes a judgement (what should a duplicate trade answer? should a sold-out lot show?). Where the
  code, the tests and CLAUDE.md do not settle it, the report records the behaviour and asks you, and does not call it
  a gap.
- A scenario kept as a test freezes today's behaviour; I keep only those whose expected value is settled.
- Fix rows could be many. Each still gets its own row and D-row, as the W-264 row requires; I will group only what is
  one cause.
