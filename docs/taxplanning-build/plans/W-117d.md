## Plan for W-117d — the claim catalogue's coverage check (I23)

> **Approved as recommended — C1a, C2a, C3a** (owner, session 100, 2026-11-15). Every path and count below was read on
> 2026-11-15 at `b3670cbe`.

**What this item is for (one sentence, in my own words):** make sure the product never computes a deduction or
exemption it cannot say how to claim. Every such rule either has a catalogue entry or is named on a list that only
shrinks, and a test fails on a rule that is neither (W-117 C3a, `DR 22` C8 I23, T22-12).

**Probe (2026-11-15; code and data read, nothing run):**
- **No data says which rules are deductions or exemptions.**
  - A trace line's kind (`StepKind.DEDUCTION` / `EXEMPTION`) is set in code: 67 call sites in 26 node classes
    (`grep -rhoE 'StepKind\.(EXEMPTION|DEDUCTION)' taxengine`).
  - Each site names its rule through a variable, a row read from a rule set, so a static scan cannot list the rules.
  - None of these holds a kind: the pipeline node files (`exec/pipelines/*.json`, node id and product only), the
    section catalogue's routes, the coverage register, the rule files (`ruleId`, `axis`, `versions`, …).
- **Today:**
  - 244 rules; 35 are catalogued (13 entries plus their `covers`).
  - By id prefix, uncatalogued: DED 16, SAL 18, RET 19, HP 6, PERQ 58, OS 26, CG 22, RATE 21, INT 5, SETOFF 6, other 12.
    A prefix is not a classification: some RET-, OS- and CG- rules exempt (gratuity, a gift from a relative, a
    reinvested gain), and many SAL- rules are measures.
- **Some deductions are not claims.**
  - The standard deductions (`SAL-STANDARD-DEDUCTION-*`, `HP-STANDARD-DEDUCTION`) apply with nothing for the person
    to do, so "not yet catalogued" would never shrink for them.
  - The same holds for rules that only bar or cap a claim: `RET-BAR-*`, `DED-WITHIN-GROSS-TOTAL`,
    `SAL-HOUSE-RENT-LANDLORD-PAN`.
- **The precedent:** W-325d made "every rule explained or listed" (F37.2) — `explanations.json` has `explanations` for
  the rules that write lines and `notALine` with a reason for the rest, and a test fails on a rule in neither.

**Choices for the owner:**
- **C1: how the test knows a rule is a deduction or exemption.**
  - **C1a (recommended): classify every rule by hand, and check the hand against the engine.**
    - `claim-catalogue.json` gains two lists, each rule with a reason in words:
      - `notYetCatalogued`: a deduction or exemption a person claims, with no entry yet. This list only shrinks.
      - `notAClaim`: a rule that is not a deduction or exemption, or one that applies with nothing to claim, such as a
        standard deduction, a bar, a cap or a measure.
    - **Test 1:** every one of the 244 rules is catalogued, on `notYetCatalogued` or on `notAClaim`, and on one of
      them only. A new rule fails the build until it is placed.
    - **Test 2:** running the engine's existing personas and goldens, a rule that writes a `DEDUCTION` or
      `EXEMPTION` line must not be on `notAClaim` unless its reason says it applies with nothing to claim. This
      catches a hand that put a claim among the measures.
  - C1b: the engine's runs only — whatever the personas exercise. Rules no persona reaches are never checked.
  - C1c: a `stepKind` fact on every rule, checked against the line each node writes. Sound, but it touches all 244
    rule files and the trace path, and it is an engine change for a content check.
- **C2: the "nothing to claim" deductions** (standard deductions, bars, caps).
  - **C2a (recommended):** on `notAClaim` with the reason "applies without a claim". I23's "a number it cannot
    explain how to claim" does not arise; the computation's sentence (W-116) already explains them.
  - C2b: catalogue them too, with an entry saying there is nothing to do.
- **C3: where the lists live.**
  - **C3a (recommended):** in `content/claim-catalogue.json`, beside the entries. Content: no pack reads them. Whether the
    compiler copies unknown keys into the pack file is **not checked**; if it does, `RulePackCompiler` leaves them out. The lock moves once.
  - C3b: a separate content file.
