## Plan for W-242 — Uncommuted pension as a salary component

**What this item is for (one sentence, in my own words):** a periodical pension is entered as itself, not as basic pay.
It is salary under S2 s.16(b), but it does not enter the salary bases that only basic pay should reach.

**Findings (each read this session):**
- F1 — Today's vocabulary has `COMMUTED_PENSION` (`exec/components/COMMUTED_PENSION.json`: `SALARIES`, `SALARY`, `CASH`,
  `TAXABLE`, `feedsInto SAL-SALARY-INCLUDES` plus the three RET rows, `salaryBaseFor []`). It has no periodical
  pension. `BASIC` is in all seven bases (`BASIC.json`: HRA, GRATUITY, EMPLOYER-PENSION, EMPLOYEE-PENSION, ENTMT, ACCOM,
  RPF), so Anand's pension entered as `BASIC` (`Fixtures.java:98`) reaches every one of them.
- F2 — Salary includes "(b) any annuity or pension" (`SAL-SALARY-INCLUDES` note, 2025 Act s.16, pp.37 – 38; Gazette
  265620). TY 2025-26: 1961 s.17(1)(ii), as `COMMUTED_PENSION` cites.
- F3 — The bases' words:
  - HRA, gratuity, and both pension-scheme bases: "includes dearness allowance, if the terms … provide, but excludes
    all other allowances and perquisites". Sources: `SAL-SALARY-FOR-HRA` (Rules 2026 r.279(2)(b), p.1776);
    `-GRATUITY` (s.19(2)(b), p.45); `-EMPLOYER-PENSION` (s.124(13)(b), p.161); `-EMPLOYEE-PENSION` (Sch. XV para 1(y)(i), p.563).
  - RPF has the same words (TY 2025-26 only); entertainment is "exclusive of any allowance, benefit or other
    perquisite" (TY 2025-26 only).
  - Accommodation: "the pay, allowances, bonus or commission … or any monetary payment, by whatever name called, from one
    or more employers". It excludes "(vi) lump-sum payments … like … commutation of pension" (`SAL-SALARY-FOR-ACCOM`,
    Rules 2026 r.15(8)(k), p.1548).
  - None of these words names a periodical pension. Bonus stands in the same place: in `SAL-SALARY-FOR-ACCOM` only, and
    out of the others pending OQ-5 (`BONUS.json`; D-094 C2a).
- F4 — Touchpoints of a new code: `ComponentCodes.java` (regenerated via `GeneratedConstantsTest`, whose list at `:409`
  names every code); `data/tax-planning/hr-support.json` (`HrSupportTable` must name every component;
  `COMMUTED_PENSION` is `NOT_APPLICABLE` at `:25`); the rule-pack locks (exec layer; `run_relock.sh`). No Form 16
  mapping exists in main code yet (grep `form ?16` finds none), so that half of the row is W-123's.

**Choices for the owner:**

  of the six others: they name no pension, and the reading recorded for bonus (D-094) applies. This is an owner ruling
  on a reading, not a quoted exclusion, so the component's note says so.
- C1b — in no base at all.
- C1c — in the same bases as `BASIC`, which is today's effect.
- **C2a** — the HR support value is `NOT_APPLICABLE`, as for `COMMUTED_PENSION`: no employer restructures a pension.
