## Plan for W-124 — the document model: `IngestedDocument`, `ParseAttempt`, `ExtractedField`, `DocumentConfirmation`

> **Approved C1a, C2a, C3a** (owner, session 102, 2026-11-16). Built; review: "commit and push". Every path below was read on 2026-11-16 at `ac14d02c`; grep each again before
> relying on it. No probe: the item adds new types and changes no shared logic.

**What this item is for (one sentence, in my own words):** give Phase 13 its vocabulary — what was uploaded, each try
at reading it, each value read with where it came from and how sure the reader is, and the person's own confirmation —
as immutable values that refuse an impossible state, so the parser SPI (W-125) and the parsers (W-126 – W-129) have
something to produce.

### What the design says

- `DR 05` M4 (`05-domain-model.md:488` – `:519`) — the four types and their fields. M4.1 (`:521` – `:532`):
  confidence bands and `D-NOSILENT` — a low-confidence field is never defaulted to zero.
- `02-TECH-SPEC.md:107` – `:110` — package `taxplanning.documents`, sub-package `ingest/` for these four (the
  `taxdocs` module was removed by D-048).
- `DR 07` X2.5 (`07-architecture.md:234` – `:246`) — `DocumentParser.supports(DocumentType, TaxYearId)` and
  `parse(IngestedDocument) → ParseAttempt`, "never throws on bad input; records outcome": W-125's, and the reason
  `ParseAttempt` must hold a failure as a value.
- `DR 06` G5.1 (`06-algorithms.md:472` – `:489`) — L3 infers a cell from the form's own arithmetic, so a field can have
  **no raw text and no page position**; L4 leaves text unmapped.
- `DR 14` O6 (`14-operational-design.md:163` – `:175`): storage outside Mongo, encryption, malware scan, password,
  size — all upload concerns (W-131). O5 (`:141`): uploaded documents kept 8 years, erased on request.
- `DR 13` rows 70 – 75 (`13-edge-cases.md:491` – `:496`): same bytes twice idempotent on SHA-256; a revised Form 16
  is a new document, superseding by `certificateNo` + `lastUpdatedOn` — values read from the form, so extracted
  fields, not upload metadata.

### The finding that drives C1

None of these four types has a caller until W-125 (the SPI's signature), W-126 (the first parser creates them) and W-131
(the upload, parse and confirm endpoints and the async `ParseDocument` job store them). CLAUDE.md §2 says "no field …
without a current caller". The persistence half — collections `tax_documents`, `tax_parse_attempts`,
`tax_document_confirmations` (`02-TECH-SPEC.md:331` – `:333`), indexes, field encryption, erasure, the 8-year
retention, the runbook — has nothing to store until W-131, and would be built untested against a real write path.

### Choices for the owner (recommended first)

- **C1 — what W-124 builds:**
  - **(a) the four types as immutable values only, in `taxplanning.documents.ingest`; their stored form moves to
    W-131**, which writes them first (W-131's row gains: collections, indexes, encryption of the read text and values,
    erasure with the profile and the account, the 8-year retention, the runbook entry). The values' callers arrive in
    W-125 and W-126, next in board order.
  - (b) values **and** persistence now (entities, repositories, an index initializer, encryption, erasure): the
    design's full M4 + M7 rows, unwritten until W-131.
  - (c) merge W-124 into W-126, so the values arrive with the first parser that makes them.
- **C2 — the document's type** (`DR 05` lists `FORM_16 (TY 2025-26) | FORM_130 (TY 2026-27) | FORM_123 | FORM_122`):
  - **(a) `DocumentType` — an enum naming what the paper is: `FORM_16`, `FORM_130`, `FORM_122`, `FORM_123`, with no
    year.** Each needs its own parser class anyway, so a new form is new code whichever way it is named. Which year's
    employer issues which form is not written here; `DocumentParser.supports(type, year)` (W-125) decides what reads
    it. A form for the wrong year is W-131's to refuse or re-file (DR 13 row 74: "Reject, or offer to file it under the right workspace").
  - (b) an open code checked against the registered parsers (as `ComponentCode` is against the pack) — nothing to
    check it against until W-125.
- **C3 — what a value read from a form is** (`DR 05`: "`Optional<Money>` or `Optional<Boolean>` or `Optional<String>`"):
  - **(a) a sealed `ExtractedValue` with three records, `MoneyRead(Money)`, `FlagRead(boolean)`, `TextRead(String)`**;
    `ExtractedField.interpretedValue` is `Optional<ExtractedValue>`, empty when the reader could not interpret the text
    (never zero, `D-NOSILENT`). `Money` is `taxengine.rules.money.Money`, already used across `taxplanning` (22
    imports).
  - (b) three `Optional` fields, at most one present — a state the type allows and a check must forbid.

### Files I will create (C1a, C2a, C3a)

All in `backend/src/main/java/com/thiru/wealthlens/taxplanning/documents/ingest/`:
- `DocumentType.java` — enum, the four forms (C2a).
- `IngestedDocument.java` — record: `documentId`, `profileId`, `taxYear` (`TaxYearId`), `documentType`, `sha256`
  (64 lowercase hex, refused otherwise), `uploadedAt` (`LocalDateTime`, UTC), `pageCount` (≥ 1). **No
  `storageRef`** (C1a: where the bytes live is W-131's choice between GridFS and an object store, O6).
- `ParseOutcome.java` — enum `SUCCESS`, `PARTIAL`, `FAILED` (DR 05).
- `ParseAttempt.java` — record: `attemptId`, `documentId`, `parserId`, `parserVersion`, `startedAt`, `finishedAt` (not
  before `startedAt`), `outcome`, `extractedFields` (copied, unmodifiable), `unmappedText` (copied list, verbatim),
  `parserNotes` (copied list). A `FAILED` attempt must carry at least one note — its reason (O9, `14-operational-design.md:233`: "FAILED with a
  reason") — and no extracted field; a `SUCCESS` must leave nothing unmapped (else it is `PARTIAL`).
- `ExtractedField.java` — record: `fieldPath` (non-blank), `rawText` (`Optional<String>`: empty for an L3 inference),
  `interpretedValue` (`Optional<ExtractedValue>`), `confidence` (0.0 – 1.0, refused outside), `location`
  (`Optional<FieldLocation>`: empty for an L3 inference), `mappedTo` (`Optional<ComponentCode>`). Field paths are unique
  within one attempt (checked by `ParseAttempt`).
- `FieldLocation.java` — record: `pageNumber` (≥ 1) and the box `left`, `top`, `width`, `height` (non-negative) —
  "show me where this came from".
- `ExtractedValue.java` — sealed interface with `MoneyRead`, `FlagRead`, `TextRead` (C3a).
- `DocumentConfirmation.java` — record: `attemptId`, `confirmedBy`, `confirmedAt`, `acceptedFields`
  (`Map<String, ExtractedValue>` — the value the person accepted, which may differ from the read one), `rejectedFields`
  (`Set<String>`); a path both accepted and rejected is refused; both copied.
- `package-info.java` — the package's contract (Javadoc only).

Tests, `backend/src/test/java/com/thiru/wealthlens/taxplanning/documents/ingest/`: `IngestedDocumentTest`,
`ParseAttemptTest`, `ExtractedFieldTest`, `DocumentConfirmationTest` — each refusal above, one test each, plus one
valid value of each type and the defensive copies.

**`mappedTo` departs from DR 05**, which allows "`Optional<ComponentCode>` or `Optional<RuleId>`": no row of any form is
known yet to map to a rule rather than a component, and the rulebook's `DOC-F130-*` rows are not in any pack
(`grep -rl DOC-F130 rulepacks` finds none). The rule target is added by the parser that first needs one.
