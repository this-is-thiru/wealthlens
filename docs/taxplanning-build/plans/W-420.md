### Choices

- **C1 — one pass.** **C1a (recommended):** `./mvnw clean verify -Dmaven.test.failure.ignore=true` — every check runs once,
  nothing dropped (format and Checkstyle at `validate`, tests, the JaCoCo gates and the consolidated report at `verify`).
  About 40 s.
- **C2 — the tiers side by side.** **C2a (recommended):** three jobs: `unit` and `integration` in parallel (each compiles,
  runs its tier with the agent, uploads its `jacoco.exec` and surefire XML); then `gate` downloads both, merges the data
  (`jacoco:merge`), runs the four `check`s and the report on the merged file, applies the report count and failure
  annotations to both sets, writes the consolidated report, and builds the image. Wall time ≈ the longer tier + the gate:
  about 5 – 5½ min. **C2b:** keep one job (C1 and C3 only, about 7 min).
- **C3 — the image on a pull request.** **C3a (recommended):** still built on every run (proves the `Dockerfile`), pushed only
  from `master`. **C3b:** unchanged.

**Files I will modify:** `.github/workflows/cicd.yaml`; root `pom.xml` only if the merge needs an execution (a `merge` goal
and the `check`s pointed at its file, in a profile the gate job alone uses); `CLAUDE.md` "Build gotchas" (the CI command
and the jobs); `STATE.md`, `03-WORK-ITEMS.md`, `DECISIONS.md`, `CHECKPOINT.md`, this plan.

**What I am NOT doing:** removing or weakening any test, gate or report; changing a coverage minimum; a paid larger runner;
path filters (docs feed tests: `FinishedPlanTest`, `ApiCollectionContractIntegrationTest`); the benchmark job.

**How I will verify:** the PR's own run, read against PR #77's: the same number of test classes and tests (6888 + 26, one
skipped), the four `check`s reporting the same covered ratios from the merged data, the report artifact present, wall time
logged. **A test that the gate can still fail:** one throwaway commit on the PR with a failing assertion in a unit test and
one in an integration test (each tier's failure must turn the run red with its annotation), then reverted in the next commit.

**Post-deployment actions (R15):** none.

**Five roles:**
- **Architect:** the build's contract (what gates a merge) is unchanged; only where each piece runs.
- **PM:** a green tick about 2½ minutes sooner on every PR and master push.
- **Senior engineer:** one source of truth for the command; the merge step is the only new build logic.
- **Automation tester:** the deliberate red commit per tier; counts compared with PR #77's run.
- **Manual tester:** the run page shows the three jobs, the annotations on failure, and the report artifact.

**Risks:** (1) a gate that only the two tiers together reach passes only after the merge — the reason for C2a's `gate` job;
(2) two jobs use twice the runner minutes (free on a public repository); (3) the `concurrency` group must cancel all three.
