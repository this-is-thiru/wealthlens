## Plan for W-358a — deny by default, and a guard that lists every route

> Planned in session 112 (2026-11-21), the first of the auth and API revamp (W-358, D-850). **Probe run before this plan:**
> `AuthConfig`'s fallback switched to `anyRequest().authenticated()` on the working copy; the six integration classes that touch
> security or public routes — Auth 17, PropertySale 8, Finances 5, PrivacyNotice 5, ConsentNotice 8, ProcessingLog 10 — **53 / 53
> pass, nothing moves**; reverted. So no existing test proves the open route below: this item adds the tests that do.

**What this item is for (one sentence, in my own words):** make every route need a login unless it is named public, and make the
build fail if any route — today's or a future one — is reachable without a login when it should not be, or reaches another user's data.

### What the code does today (read this session)

- `AuthConfig` lists public paths, then authenticated ones, then **`.anyRequest().permitAll()`** (`AuthConfig.java:53`): an unlisted
  path is public. `POST /properties/user/{email}/sales` (`PropertySaleController.java:15-24`, no `@PreAuthorize`) is unlisted — **open
  without a login**.
- The cross-user check: `AuthFilter.java:53` → `UserValidator.isRestrictedUser` (`UserValidator.java:24-31`) compares the segment after
  `/user/` with the token's subject; a mismatch throws, `AuthFilter.java:68-70` catches **every** exception and continues without a login,
  so the refusal reaches the caller only where the route is `.authenticated()`.
- `AuthService.extractAllClaims` (`AuthService.java:73-92`) also ends in `catch (Exception e)` and returns `null`.
- Four tax-planning controllers' comments say "`AuthFilter` refuses a caller whose token is not the path's email"
  (`DocumentController.java:20`, `ErasureController.java:14`, `TaxProfileController.java:16`, `TaxProfileReferenceController.java:24`);
  the check is `UserValidator`'s, called by `AuthFilter`.

### Decisions (for approval with this plan)

- **C1 — the public list.** **C1a (recommended):** exactly today's public list (`/auth/login`, `/auth/register`, `/helper/**`,
  `/finances/**`, `/template/**`, `/privacy/rights`, `/privacy`) plus Spring Boot's `/error` (where a refused or failed request is
  rendered — read at the build; added only if a test shows it is needed), and **`anyRequest().authenticated()`**. **C1b:** also review
  whether `/helper/**`, `/finances/**`, `/template/**` should stay public (a product question; today's behaviour kept meanwhile).
- **C2 — the swallowed exceptions.** **C2a (recommended):** `AuthFilter` and `extractAllClaims` catch only what they mean — the token
  library's `JwtException` family and the refusal's `BadCredentialsException` — with the same outcome as today (the request continues
  without a login, so a protected route answers 401); anything else is no longer swallowed. **C2b:** answer 401 at once on a bad token,
  even on a public route — changes behaviour for a client that sends a stale token to `/auth/login`; left to W-358b's rewrite.
- **C3 — the route guard's shape.** **C3a (recommended):** one integration test, `RouteAccessIntegrationTest`, that reads every route from
  Spring's `RequestMappingHandlerMapping` (so a new route is in it automatically) and, over real HTTP: every route not on the public
  list answers **401 without a token**; every route with `{email}` answers **401 / 403 to another user's token** and not to its own
  user's (the latter only checked as "not 401/403"); a route on the public list answers without a token. Path variables are filled
  with dummy values (security runs before binding). **C3b:** an ArchUnit-only check of annotations — cannot see the real filter chain.

**Five roles:** Architect — one rule (deny unless named) instead of a list that must be remembered. PM — no route opens by accident.

**Risks or ambiguities I noticed:** a public endpoint no test calls without a token (C1a keeps today's list exactly); `/error` handling
(checked at the build, C1a); a route whose dummy path values break routing before security (the guard reports it by name).
