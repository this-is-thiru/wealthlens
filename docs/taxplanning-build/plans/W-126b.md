**What this item is for (one sentence, in my own words):** the first real `DocumentParser` — read a Form No. 130 PDF's
text with positions, find Part A and Part C (Annexure-I) by their headings and every line by its printed label from
W-126a's layout, and return each line's value text, page and box as an `ExtractedField` with no value yet, so W-127 can
read the numbers.

### What the design and the code say

- `DR 06` G5.1 (`06-algorithms.md:482`): L1 finds parts by heading text and rows by statutory label, 0.95+ on an exact
  match; positional parsing never. L4: text that cannot be placed goes to `unmappedText`, never a default.
- W-126a (D-730): `TaxCalculator.certificate(TaxYearId, CertificateCode)` gives the year's `CertificateLayout`: parts
  with headings, lines with path, row, label, kind, columns, repeating, page. The labels are the words alone; the page
  images showed row numbers in their own column and "(refer Note 1)", "(Yes/No)", "(dd/mm/yyyy)" in the value column.
- W-125 (D-728): `DocumentParser.read(DocumentContent)` — **no tax year reaches the parser**, but the layout is the
  year's. `DocumentParsers.parse(IngestedDocument, DocumentContent)` knows the document's `taxYear`.
- iText 5 is already the PDF reader (`taxplanning/gazette/GazetteMatcher.java:3` – `:4`); its `parser` package has
  `PdfReaderContentParser`, `RenderListener` and `TextRenderInfo` (each chunk with its baseline) — checked in the
  5.5.13.4 jar — and `exceptions.BadPasswordException`.
- `DR 13` rows 71 – 72: a password and a scan without text are `FAILED` with a reason (W-125's contract).
- `DOC-F130-ANNEX-001` (Form No. 130 Part C Note 1, p.2278): Part C may be issued by the last employer only.

### Choices for the owner (recommended first)

- **C1 — how the parser learns the year:**
  - **(a) `read(DocumentContent content, TaxYearId year)`** — `DocumentParsers` passes the document's year; the two
    W-125 test parsers gain the parameter. The year's layout is then the law the document was issued under.
  - (b) read Part A's printed "Tax year" first and pick the layout from it — the label to find it by is itself the
    year's, so it needs a guess first.
- **C2 — a part the certificate does not carry:**
  - **(a) Part C absent is not a defect** (Note 1: the last employer may issue it alone); the reading lists no Part C
    line and says so in `parserNotes`. Part A absent → `FAILED` ("not a Form No. 130: no PART A"). A part present
    with a line missing → `PARTIAL`, the missing paths in `parserNotes`.
  - (b) any missing part or line → `PARTIAL`.
- **C3 — what L1 records as a line's text:**
  - **(a) the text printed to the right of the label on the label's own lines** (the value cells), verbatim, as
    `rawText`; empty `interpretedValue` (L2 is W-127); confidence 0.95 on an exact match after normalising
    (whitespace collapsed, a line-end hyphen joined, curly and straight quotes alike); the box spans the label's lines.
    A heading line (`NONE`) is recorded with no text. Text on a part's pages that no label claims goes to
    `unmappedText`.
  - (b) record only that the label was found, no text.

### Files I will create (C1a, C2a, C3a)

`taxplanning/documents/parser/`:
- `Form130Parser.java` — `@Component`, `DocumentParser` for `FORM_130`, id `form-130-l1`, version `1`; asks
  `TaxCalculator` for the year's layout (`taxengine :: api` already allowed); refuses nothing — every failure is a reading.
- `PrintedText.java` — the page text as positioned lines, from iText's render listener: each line's words with x and
  baseline y; `BadPasswordException` and an empty text layer become `FAILED` readings upstream.
- `LabelMatch.java` — the normalising matcher (the three rules in C3a), finding a label across consecutive lines.

Tests: `Form130ParserTest` over fixtures rendered in the test (D-729 C4a) from HTML in
`src/test/resources/taxplanning/documents/form-130-*.html` with flying-saucer, as `ComputationReportService` renders:
1. a whole certificate (Part A + Annexure-I, sample values) → `SUCCESS`, every line found, values verbatim, pages and
   boxes set, confidence 0.95;
2. Part A only (Note 1) → `SUCCESS`, a note that Part C is absent;
3. a label wrapped differently from the Gazette, and row 7(a) with straight quotes → still found;
4. a row deleted → `PARTIAL`, its path in the notes;
5. a password-protected PDF (iText `PdfStamper.setEncryption`) → `FAILED`, "password";
6. an image-only page → `FAILED`, "no text layer";
7. not a PDF → `FAILED`, "not a PDF".
Expected values are the fixture's own printed text (the HTML the test wrote), never the parser's output.
