**What this item is for (one sentence, in my own words):** bring `CertificateSpec` and `CertificateLayout` back within
the 7-component limit by holding their three check lists as one value each, with no change in what is read, checked or
reconciled.

### What the row and the standards say

- **Row** (`03-WORK-ITEMS.md:1690`): "one `CertificateChecks` type for the rules side and one for the layout, no
  behaviour change" (D-756).
- **CLAUDE.md §4:** "more than 7 parameters means a missing type". Two classes with the same simple name in different
  modules are a defect (§3).

### Findings

1. **`CertificateSpec`** (`taxengine/rules/filing/CertificateSpec.java:20`) has 9 components: code, title, parts,
   fields, identities, tables, agreements, comparisons, provenance.
2. **`CertificateLayout`** (`taxengine/api/CertificateLayout.java:31`) has 9: code, title, parts, lines, sums, tables,
   agreements, comparisons, source. It is built only by `CertificateLayout.of(spec)` (`:44`), which maps each list.
3. **Constructor sites:** `CertificateJson` (1, main), `CertificateLayout.of` (1, main); tests `CertificateSpecTest`
   (7), `ReconciliationTest` (4), `ContradictionsTest` (1), `EmployerAssemblyTest` (1).
4. **Accessor uses** (`.identities()`, `.sums()`, `.agreements()`, `.comparisons()`):
   - main: `Reconciliation:53`, `Contradictions:43` and `:47`, `CertificateReading:105`;
   - tests: `CertificateJsonTest:160`, `:397`; `CertificateSpecTest:308`, `:389`; `Form130LayoutTest:249`, `:333`,
     `:361`, `:371`; `ReconciliationTest:143`, `:215`, `:301`.
5. **Names:** neither `CertificateChecks` nor `PrintedChecks` exists in `backend/src` or the design docs. The layout's
   nested records are all `Printed*` (`PrintedLine`, `PrintedSum`, `PrintedTable`, `PrintedAgreement`,
   `PrintedComparison`), so its group follows that word.
6. **Tables stay outside the group:** they say where the reading finds cells, not what the reading must agree with.

### Choices for the owner (recommended first)

- **C1 — the two types:**
  - **(a)**
    - `taxengine.rules.filing.CertificateChecks(identities, agreements, comparisons)`, with defensive copies;
    - `CertificateLayout.PrintedChecks(sums, agreements, comparisons)`, nested like the other `Printed*` records.

    Each record drops to 7 components. Validation that relates checks to fields stays in `CertificateSpec`'s constructor,
    since it needs the fields.
  - (b) One type shared by both sides. This would make the API's layout carry rules-side records.
- **C2 — callers:**
  - **(a)** Callers read through the group: `layout.checks().comparisons()`.
  - (b) Keep delegating accessors on both records, which adds surface with no caller that needs it.
- **C3 — the pack's JSON:**
  - **(a)** Unchanged: `identities`, `agreements` and `comparisons` stay at the version's top level; `CertificateJson`
    builds the group. No relock and no locked checksum moves.
  - (b) Nested under `checks`, which is a data change and a relock for a shape nobody reads.

### Files (C1a – C3a)
