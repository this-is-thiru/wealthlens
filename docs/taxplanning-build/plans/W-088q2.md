## Plan for W-088q2 — one carried-loss mechanism

**What this item is for (one sentence):** the carried house-property loss and the carried capital loss are set off
by one mechanism, which reads each loss's span, head and return condition from its row (W-088q1's
`LossCarryForward`). Each ledger kind only states its losses as facts: portions, their rows and their texts. A third
carried loss then becomes a ledger kind and a row, not a third copy (D-263; review S2; D-250).

**Behaviour unchanged:** every value and every trace line stays word for word identical (D-263 C1a). This is proven
by a full-trace comparison, before and after, over the whole unit tier (see Verify).

### Design

1. **`node/CapitalGainsAbsorption`** (package-private, final): the capital-gains parts absorbing a loss in the
   declared order.
   - Built from the `CapitalGainsAbsorptionOrder` and the parts map, which it lowers in place, as the three loops do
     today.
   - One method: `Money absorb(Money loss, Predicate<CapitalGainsPart> reaches, List<TraceLine> lines, PartLine line)`.
     It returns what the parts took.
   - `PartLine` is a nested functional interface `(sequence, part, available, taken) → TraceLine`, so each caller
     keeps its own text.
   - Used by `SetOffNode.absorbCapitalGains` (reaching every part) and by the mechanism.
2. **`node/CarriedLossSetOff`** (package-private, final): the mechanism, written once.
   - `static void apply(NodeContext ctx, List<CarriedLoss> losses, Map<HeadCode, Money> income,
     CapitalGainsAbsorption parts, List<TraceLine> lines)`.
   - Nested records state the facts:
     - `CarriedLoss(TaxYearId arose, RuleId row, Optional<Boolean> determinedInReturnFiledInTime, List<Portion>
       portions, CarriedLossTexts texts)`. Empty means the ledger kind states no return fact (house property:
       neither Act asks, D-263).
     - `Portion(Money amount, RuleId row, Predicate<CapitalGainsPart> reaches, Function<String, String> setOffText)`.
       `setOffText` is given the absorber's name (a head or a part).
     - `CarriedLossTexts(String noun, String expiredCitation, String stillCarriedCitation, Optional<String>
       notDeterminedInTime)`.
   - For each loss, oldest first, it reads the row's `LossCarryForward`, then:
     1. refuses a year not before this one;
     2. skips a nil sum of the portions;
     3. **the return condition:** if the row requires it and the year states `false` → the not-in-time line. If the
        row requires it and the year states nothing → refused as a pack defect, with q1's message;
     4. the expiry line;
     5. each portion: the regime of its row asked (C1). Where it is forbidden, the two s.202(3) lines. Otherwise it
        is set off against the row's `absorbedBy`: through `CapitalGainsAbsorption` where that is `CAPITAL_GAINS`
        (lowering the head's income by what was taken), else the lesser of the portion and the head's income left;
     6. the still-carried line.

     Every line is written by `ctx.traceLine`.
   - A portion that reaches only some parts, meeting a head other than `CAPITAL_GAINS`, is refused: the restriction
     would otherwise be silently ignored (§2).
3. **`SetOffNode`.**
   - `broughtForward` / `useAttributable` / `use` / `requireAgainstAHead` are replaced by two short private
     builders:
     - `carriedHousePropertyLosses(ctx)`: the ledger → `CarriedLoss`es. Two portions, the house-property texts, no
       return fact. It refuses a row naming `CAPITAL_GAINS`, with q1's message (C3).
     - `carriedCapitalLosses(ctx)`: the ledger → `CarriedLoss`es. The long-term portion reaching
       `CapitalGainsPart::isLongTerm` (C2a of D-263), then the short-term portion reaching every part; the return
       fact; the capital texts. It refuses a row naming another head, with q1's message.
   - `evaluate` calls `CarriedLossSetOff.apply` once for each, house property first, as today. It holds one
     `CapitalGainsAbsorption` over `parts` and `order.capitalGainsOrder()`.
   - `absorbCapitalGains` keeps its text and calls `CapitalGainsAbsorption.absorb`.
   - The class Javadoc's last two paragraphs are rewritten to name the mechanism. The citations are kept.
4. **`CarriedCapitalLossSetOff` is deleted**, its `line` helper with it. The import of `TaxYearSpan` and
   `TreeMap` / `Comparator` move as needed.
5. **Docs.** TS T6 `setoff` row and a Changes row; WI W-088q2 "Built"; STATE D-265; CHECKPOINT.

### Choices (recommended first)

- **C1 — which portions are asked of the regime:**
  - **(a) recommended:** every portion's row, by `ctx.inRegime`. This is the one place a node asks (D-165), and the
    data decides which are forbidden. A forbidden portion writes today's two lines: the SET_OFF line with the
    verdict's reason, and the MEASURE line "deemed to have been given full effect to … (S2 s.202(3); 1961
    s.115BAC(3))". This is the regime's consequence for a set-off its disallowance set forbids, the same text
    `SetOffNode.setOff:142` writes for this year's loss. No result changes today: the carried rows are
    `AllRegimes` and undisallowed.
  - **(b)** a per-portion flag, "asked of the regime", true only for the attributable part. This mirrors today's
    Java, but it is a flag that encodes law.
- **C2 — the not-in-time text where a row requires the condition:**
  - **(a) recommended:** it is the ledger kind's (`notDeterminedInTime`). A year whose kind states the fact but no
    text is refused as a pack defect. Only the capital kind states it today.
  - **(b)** one generic text in the mechanism citing S2 s.121 / 1961 s.80. This is true only for the capital loss's
    sections, so a future kind would inherit a wrong citation.
- **C3 — the house-property builder's refusal of `CAPITAL_GAINS`:**
  - **(a) recommended:** keep it, with q1's message and test. The mechanism could now follow it, but no row asks
    for it. Lifting it is a law question, not a refactor.
  - **(b)** lift it and delete q1's test `evaluate_whenTheHousePropertyRowNamesCapitalGains_isRefused`. That is a
    deleted assertion, which §5 forbids without a decision.
