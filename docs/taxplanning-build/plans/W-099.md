### Choices (recommended first)

**C1 — what a draft stores (row 3).**
- **(a) `inputs` as a JSON document, checked by binding it to `EnteredFacts` on every save.** One model, the engine's; a patch that does not bind is refused (400) with the field named. **Departs from `DR 11` F4's list.** Depends on `EnteredFacts` binding from JSON (`Money`, `Optional`, nested records), which I prove first with a round-trip test; if it cannot, I stop (R13).
- (b) `DraftInputs` as its own typed model, per F4, mapped by W-103: about 60 more types' worth of fields, and drift.

**C2 — JSON Patch (row 4).**
- **(a) A small `add` / `remove` / `replace` applier over the document**, about 70 lines, RFC 6902 paths, tested. Those are the operations a form sends.
- (b) A library, which may pull in Jackson 2 beside Jackson 3.

**C3 — scope (row 5).**
- **(a) Build what the compute family needs:** workspace, create and read a draft, `PATCH` with `If-Match` and a 409, revisions and replay, status with `ACTED_ON` frozen, primary draft, and `RegimeElectionHistory` appended on `ACTED_ON`. **Noted, not built:** snapshots (a replay is short until a draft has hundreds of revisions), fork, diff, eviction, rollover, provenance (no reader until document import), I8 (no ledger entry is consumed yet). Each goes on a line in `PARKED-ROWS.md` "Noted"; I8 gets a row, since three `ACTED_ON` drafts could claim one lifetime deduction silently once ledgers feed in.
- (b) All of `DR 11` now: a much larger family before any figure exists.

- **Architect:** one input model; facts stay in the engine's types; `/tax/**` already authenticated; `taxengine.input` is a named interface, so no new dependency.
