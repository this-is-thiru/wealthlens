### Choices (recommended first)

**C1 — test shape.** **(a) Recommended:** W-240a's shape, one parameterised refusal method per record over
`InputRefusals`-style cases. `InputRefusals` lives in `taxengine.input` and is package-private, so a twin
`RuleRefusals` goes in the test package `taxengine.rules`. It is the same three lines, and has a different name
because ArchitectureTest refuses duplicate simple names. On top of that:
- in `ConditionTest`, one test that calls `isAboutItem()` and `itemFactsRead()` on one instance of each of the 15
  types, with the expected values worked by hand;
- the `describe()` wording cases.

That makes about 18 test classes (new or extended), roughly 350 lines. (b) Fewer classes, grouping the one- and
two-branch records into one test per package. That breaks the `<Record>Test` convention.

**C2 — the gate.** **(a) Recommended:** `check-taxengine-rules`' branch minimum moves from 0.76 to the measured
figure floored to two decimals. W-240d then takes it to 0.85.
