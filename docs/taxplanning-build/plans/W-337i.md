### Risks or ambiguities

1. **`mongodump` from the container to Atlas:** the owner's network needed `GODEBUG=netdns=cgo` for the macOS tools
   (W-334 lessons); inside a Linux container that setting does not apply, and the SRV lookup may fail. W-337i3's first row
   tries it read-only; if it fails, `--network host` or a standard (non-SRV) connection string is the next try.
2. **The w-337 start still connects to MongoDB** (fact above): after a move it reaches the old cluster but reads and
   writes nothing there. Each start row greps the log for the auditor's line, and W-337j removes the client.
3. **Dev's MongoDB content is unknown** (empty on 2026-11-19, W-334c used and wiped it): W-337i2's precheck counts it;
   an empty source is a valid copy (41 clean lines, counts 0).
4. **§1.h falls due 2026-11-29**, likely mid-move: on a database still on MongoDB it is the console count; on one moved,
   the same count in SQL. Each sub-item plan carries whichever applies.
