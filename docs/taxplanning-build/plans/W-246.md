## Plan for W-246 — Eligibility that reads a computed income

**What this item is for (one sentence, in my own words):** to decide whether to build income-based regime eligibility now,
when no regime needs it, or to park it until one does.

**Findings (each read this session):**
- F1 — The row's own trigger is "before a regime with income-based eligibility ships" (`03-WORK-ITEMS.md:1580`).
- F2 — No shipped regime needs it. `IncomeAtMost` appears in the shipped packs only in
  `law/rules/PERQ-MEDABROAD-TRAVEL.json`. That is a rule's condition, evaluated inside the pipeline, not a regime's
  eligibility set. W-244 moved E8's synthetic `SYN_FLAT` to "no business income" for this reason (D-466 C3a).
- F3 — If one were shipped, it fails loudly, not wrongly. `RegimeOffers` builds its `ConditionContext` before computing
  (`election/RegimeOffers.java:62`), and `ConditionContext.valueOf` throws `IllegalArgumentException("No value for node …")`
  (`rules/condition/ConditionContext.java:119` – `125`). `ControllerAdviser` maps that to a 400 (CLAUDE.md). It gives no
  wrong figure.
- F4 — Building it now means choosing whose income an offer reads (each regime's own computed total, or a regime-neutral
  one) with no law that asks the question. That is generality for a case that does not exist (CLAUDE.md §2, "No
  speculative code").
- F5 — A parked row stays visible: `ParkedRowsTest` fails the build if a `K` row is missing from `PARKED-ROWS.md`, and the
  deploy gate makes the owner build or waive each one by name (`PARKED-ROWS.md:5` – `8`). W-251 was parked the same way
  (D-483).

**Choices for the owner:**
- **C1a (recommended)** — park W-246 (board `K`). Row in `PARKED-ROWS.md`:
  - **Comes back:** when a regime whose eligibility reads an income is placed; otherwise waived at the deploy gate.
  - **Meanwhile:** no shipped regime's eligibility reads an income (F2); one that did would be refused with a 400 naming
    the missing node (F3), never priced wrongly.
- C1b — build it now. It needs a ruling on whose income an offer reads, and offers would be computed after every regime is
  priced. Nothing reads it today.
- C1c — build only a build-time check refusing `IncomeAtMost` in an eligibility set. F3 already fails loudly, so this adds a
  guard for data nobody has written.
