corporate-action `date` that the API accepts and never keeps. The other is an unused `MARCH` constant in the P&L
service.

  - **(b)** The DTO only, as the audit row says. The entity keeps an always-null field.
- **C2 — `DAY_31`:**
  - **(a) recommended: remove it with `MARCH`.** It is the same defect, two lines apart.
  - **(b)** `MARCH` only, and report `DAY_31` for you to place.
- **C3 — a client that still sends `"date"`:**

    ignored, as it always was. A test proves it. If Boot's mapper refuses unknown properties, I stop and re-plan
    (R13) rather than change the global mapper.
