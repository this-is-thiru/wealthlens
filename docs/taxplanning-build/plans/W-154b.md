## Revision 1 (R13) — the carrier fact's name breaks the id grammar

**What I found while coding (Step 1, the relock):** the pack refused to load:

```
PackValidation law/rules/PERQ-CARRIER-TRAVEL.json (PERQ-CARRIER-TRAVEL).versions[0].conditions[1].condition:
ItemFactId must be lower-case, dot-separated, 3-64 characters, e.g. vehicle.engine, but was
"household.carrier.airline_or_railways"
```

`ItemFactId`'s pattern is `^[a-z][a-z0-9.]{2,63}$` (`rules/id/ItemFactId.java:13`), so an underscore is not allowed.
The name was written in this plan and in `plans/W-154.md` C2, and I did not check it against the grammar. That was
my error. `perquisite.arrangement` and `household.kind` are valid. The umbrella's other example names
(`expense.wholly_for_work`, `expense.records_kept`, `expense.health_club_uniform`,
`vehicle.employee_meets_running`) are invalid in the same way. Those belong to W-154d and W-154e, whose plans will
name their facts.

**What I did:** stopped. The work so far (pack, `RuleSetIds`, `HouseholdBenefitPerquisite`, `SpecifiedEmployee`,
pins; no tests yet) is saved as a patch outside the repo and reverted, so the tree holds only docs. The item is back
to EXPLAINED.

**Choice R1 — the fact's name** (every other part of the plan is unchanged):
- **(a) recommended: `household.carrier.airline.or.railways`**, the words separated by dots. Existing facts already
  use dots as word separators (`capitalgains.acquired.on`, `trade.transfer.exchange`), and this one reads as the
  input field does. For later items, a multi-word fact name uses dots between words: W-154d / e then use
  `expense.wholly.for.work` and the like.
- **(b) `household.carrier.airlineorrailways`**, the words run together as `capitalgains` is. It is shorter but
  harder to read.
- **(c) widen `ItemFactId`'s grammar to allow `_`.** That is a change to the rules vocabulary, outside this item.

On approval I re-apply the saved patch with the chosen name, then continue at Step 1 (relock) with nothing else
changed.

**Revision 1 approval:** "W-154b Revision 1 approved — proceed as recommended" (session 30, 2026-10-23) — R1(a), `household.carrier.airline.or.railways`; multi-word fact names use dots between words.
