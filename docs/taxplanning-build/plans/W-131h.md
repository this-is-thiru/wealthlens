**What this item is for (one sentence, in my own words):** let the documents switch be turned on with no ClamAV server, by a second
switch that turns the scan off, so the scan can be turned back on later without new code.

### What the design, the code and the sources say

- **O6** (`14-operational-design.md:161` –): "**Scan before storage**". **D-761 C3a / C4a**: the documents switch turns on only after
  W-131e (scan) **and** W-131f (isolation). This item departs from O6 and from D-761 C3a by the owner's decision; the new D-row records it.
- **Today the scan fails closed:** `MalwareScan.requireClean` answers 503 when clamd cannot be reached, and `DocumentBytes.store`
  calls it on every upload. So with uploads on and no server, **every upload is a 503**.
- **Settings:** `DocumentSettings.Scan(host, port, timeout)`; one more component makes 4.
- **Runbook:** §1.n says "Turning it on … only after W-131e (scan) and W-131f (isolation) are done and §1.m's scanner is `healthy`".

### Choices for the owner (recommended first)

- **C1 — the switch:**
  - **(a)** `app.tax.documents.scan.enabled`. `true` in `application.yaml` and for integration tests; **`false`** in the staging and
    prod yamls, as you asked. Off, `MalwareScan` does not connect and lets the bytes through; the other checks (size, PDF, password,
    pages) still run. The start logs one warning: "The malware scan is off: uploads are stored unscanned (W-131h)".
  - (b) Remove the scan. **Not recommended:** turning it on later would be new code, not a yaml change.
- **C2 — isolation (W-131f):** D-761 C4a also holds the switch until the parser runs in its own process.
  - **(a)** W-131f stays required before uploads go on: the parse runs in-process with only a wall-clock budget today.
  - (b) Deferred as well: uploads may go on with in-process parsing. A hostile PDF is then parsed inside the app.
- **C3 — files stored while the scan is off:**
  - **(a)** Record, per stored document, whether it was scanned (`scanned: true|false`), a fact, so a later rescan item knows what to
    scan. Placed now as a backlog row for when the scan goes on.
  - (b) Record nothing. When the scan goes on, every document stored before is unknown.

- **Architect:** the scan stays at the one write path; off is a setting, so turning it on is a yaml change and a server.
- **Product manager:** uploads can go live without the ClamAV host cost; the risk (unscanned tax documents) is the owner's, recorded.
