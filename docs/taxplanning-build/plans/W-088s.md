## Plan for W-088s — shipped years as a manifest

**What this item is for (one sentence):** the tax years the application ships are declared in a resource file beside
the locks, `rulepacks/shipped-years.json`, instead of a Java constant. Shipping a new year then becomes data: a lock
plus a line in the manifest, not a code change. The years stay **declared, not scanned** (review E6; D-250;
CLAUDE.md §4).

**Behaviour unchanged:** the same two years compile at startup, refused together on any failure, as today.

### Design

1. **The manifest**, `src/main/resources/rulepacks/shipped-years.json`:
   ```json
   {
     "_note": "The tax years the application ships, each with a lock beside this file. Declared, not scanned (D-210, D-268): a year that silently fails to appear is worse than one that fails to load. Shipping a year is a lock and a line here.",
     "taxYears": ["2025-26", "2026-27"]
   }
   ```
   The years are written as labels, the way the lock files and each lock's `"taxYear"` name them.
2. **`ClasspathRulePackProvider.shippedYears(String root)`**, public static, beside `lock(root, year)` and using the
   same `read`. It refuses:
   - a missing file (`read`'s message);
   - a missing or non-array `taxYears` (`PackJson.array`);
   - a label that is not a tax year: a label is accepted only if `TaxYearId.of(<its first four digits>).label()`
     gives it back exactly, so "2025-27" and "2025" are refused;
   - a label listed twice.

   It returns an immutable set. An empty list is left to `ShippedRulePacks.compile`'s existing refusal (one place).
   No `TaxYearId.parse` is added: the reader is the one caller (§2).
3. **`TaxEngineConfig`:** `SHIPPED_YEARS` is removed. The bean calls `ShippedRulePacks.compile(ROOT,
   ClasspathRulePackProvider.shippedYears(ROOT))` with `ROOT = "rulepacks"`. The Javadoc keeps the "declared, not
   scanned" reason and points to the manifest.
4. **`TaxEngineConfigTest`:** `shippedYears_whenComparedWithTheLocksShipped_areTheSame` compares the manifest
   (through `shippedYears("rulepacks")`) with the lock files, as before.
5. **`GoldenCaseRunner`** (C1a): its copy reads the manifest too.
6. **Docs:** TS T4 (the manifest beside the locks) and a Changes row; WI "Built"; STATE D-268; CHECKPOINT.

### Choices (recommended first)

- **C1 — `GoldenCaseRunner`'s own copy of the years:**
  - **(a) recommended:** read the manifest. Otherwise the fact is declared twice, and a third year would be added
    in one place and forgotten in the other. Two lines.
  - **(b)** leave it, because the WI row names only `TaxEngineConfig`. The duplicate then stays, recorded for W-088l.
- **C2 — how a year is written in the manifest:**
  - **(a) recommended:** its label, "2026-27", as the lock files and `"taxYear"` write it. The reader checks the
    label round-trips through `TaxYearId`.
  - **(b)** the start year as an integer (`2026`). That is simpler to read, but it is a second spelling of a tax year
    in the pack's files.
