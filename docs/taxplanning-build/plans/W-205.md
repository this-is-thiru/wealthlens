## Plan for W-205 — request bodies bound to entities lose their field initialisers

**What this item is for (one sentence, in my own words):** a request body that omits a field arrives at the entity with
`null` instead of the value its initialiser gives it, because Jackson 3 builds the entity through the Lombok all-args
constructor — so a holding loses its empty `sellTransactionIds` (500), a published card loses its `auditMetadata` (no
author) — and this item settles which constructor those six request-bound types bind through, and who owns audit
metadata.

**Source:** `03-WORK-ITEMS.md` W-205; `plans/W-204.md` ("What I found", the root-cause paragraph); D-408.

**Board (R4):** `… W-203 D  W-204 D  W-205 ·  W-194 · …`. W-205 is the first open item. The resume check matched:

### What I found (2026-10-31, session 41)

**The affected surface is six entity types that arrive as request bodies, and one field on each is load-bearing.**

| Type | Bound by | Initialiser lost when omitted |
|---|---|---|
| `AssetEntity` | `POST /test/user/{email}/transact/sell` (inside `ProfitLossDto`) | `buyTransactionIds` `:134`, `sellTransactionIds` `:137`, `corporateActions` `:140`, `auditMetadata` `:144` |
| `ChargeScheduleEntity` | `POST /charge-schedules` | `rules` `:98`, `auditMetadata` `:110` |
| `ChargeAccountEntity` | `POST /charge-accounts/user/{email}` | `billingEvents` `:84`, `auditMetadata` `:91` |
| `TaxSlabPolicyEntity` | `POST /tax-planning/admin/policies/slab` | `auditMetadata` `:62` |
| `PerquisitePolicyEntity` | `POST /tax-planning/admin/policies/perquisite` | `auditMetadata` `:81` |
| `AllowanceCatalogueEntity` | `PUT /tax-planning/admin/allowances/{code}` | `auditMetadata` `:110` |

Each `auditMetadata` field is `@Setter(AccessLevel.NONE)` — the entity already says a caller may not write it, yet the
all-args creator is the one door left open. Its nested `@Data @AllArgsConstructor @NoArgsConstructor` types
(`ChargeRule`, `ChargeSlab`, `TaxSlab`, `SurchargeSlab`, `BillingEvent`) declare no initialisers and are **not** part of
this defect.

**The mechanism, measured today with a scratch probe (Lombok classes, `JsonMapper`, Jackson 3.1.4; probe deleted, tree
clean).**

| Probe | Result |
|---|---|
| `@Data @AllArgsConstructor @NoArgsConstructor`, body `{"name":"x"}` | `items=null audit=null` — the all-args constructor is the creator, initialisers never run |
| same class with `@AllArgsConstructor(onConstructor_ = @JsonCreator(mode = DISABLED))` | `items=[] audit=Auditish(createdBy=null)` — the no-arg constructor is used, initialisers run |
| an un-annotated nested rule with a primitive, primitive omitted | still refused: `MismatchedInputException: Cannot map null into type boolean` (`FAIL_ON_NULL_FOR_PRIMITIVES`) |
| `@JsonProperty(access = READ_ONLY)` on the audit field, body sends `{"audit":{"createdBy":"spoof"}}` | ignored — initialiser intact (`createdBy=null`) |
| the same, body sends `"audit": null` | ignored — initialiser intact |
| the same, serialising the object | `"audit":{"createdBy":null}` still in the response — responses unchanged |

**The cause is Jackson 3's constructor detector, not `@ConstructorProperties`.** `javap -v` on the compiled
`ChargeScheduleEntity` shows **no** `RuntimeVisibleAnnotations` on either constructor, and the repository has no
`lombok.config`: Lombok adds no `@ConstructorProperties` here. What selects the all-args constructor is
`ConstructorDetector.DEFAULT` allowing an implicit properties-based creator even when a public no-arg constructor
exists — `DEFAULT.withAllowImplicitWithDefaultConstructor(false)` is the lever that switches it off (measured in W-204).
`ChargeSeederService.read` (`:322-340`) documents the opposite cause ("Lombok puts `@ConstructorProperties` on
`@AllArgsConstructor`, Jackson honours it as a creator"); the workaround it describes — `readerForUpdating(factory.get())`
— is still the right workaround and is unaffected. The sentence is wrong and this item's subject, so it is corrected
below.

**Today, per field kind.** An omitted primitive is a loud 400 (W-204 kept that). An omitted collection arrives `null`
and fails later — `PortfolioService:641` NPEs on `sellTransactionIds`; `ChargeScheduleValidator` turns a null `rules`
into "it declares no rules". An omitted `auditMetadata` is silent: Spring Data's auditing fills an object, it does not
create one, so the stored card has `createdAt:null`/`createdBy:null` (W-204, re-read).

**The validator does not cover the silence a global lever would create.** `ChargeScheduleValidator` checks the start
date, the rule codes, basis parameters, slabs, derived order and expressions; it never reads `active`, `taxable` or
`order`. Under a mapper-wide no-arg binding an omitted `active` would publish `active:false` — a rule silently priced
at nothing, indistinguishable from a free trade. `perLot` and `appliesToCorporateActions` are different: they document
"defaults to false", and none of the 109 rules in the 39 shipped cards carries `perLot` (counted), so their omission is
the normal authored state on the seed path.

**The seam for a global setting exists.** Boot 4.1.0's `JacksonAutoConfiguration` registers a
`tools.jackson.databind.json.JsonMapper` bean and takes `JsonMapperBuilderCustomizer` beans (`javap` on
`spring-boot-jackson-4.1.0.jar`), so option (b) below would be one bean in `shared/config`. 41 classes carry both
`@AllArgsConstructor` and `@NoArgsConstructor` (grep count) — that is the blast radius a global setting changes.

### Choices (recommended first)

- **C1 — how the six types bind:**
  - **(a) recommended: per class, `@JsonCreator(mode = DISABLED)` on the all-args constructor** via
    `@AllArgsConstructor(onConstructor_ = @JsonCreator(mode = JsonCreator.Mode.DISABLED))`. Measured: the no-arg
    constructor is used, collections and audit survive. It touches exactly the six types that have something to lose,
    and leaves every other request body as it is — most importantly `ChargeRule`, whose omitted `perLot` stays a 400
    rather than becoming a silent `false`. Cost: an annotation per entity, and a new entity-bound request type must
    remember it (guarded by the test below).
  - **(b) one `JsonMapperBuilderCustomizer` bean** setting
    `ConstructorDetector.DEFAULT.withAllowImplicitWithDefaultConstructor(false)`. One line, fixes every type and every
    future one. It also switches off the loud refusal for `ChargeRule`'s five primitives — the validator does not check
    `active`/`taxable`/`order`, so a card published with a rule omitting `active` would be stored silently inert — and it
    changes the binding of all 41 double-constructor classes globally. Rejected: silence on the pricing booleans for
    the sake of one setting.
  - **(c) request DTOs at the five entity-bound endpoints** (plus `ProfitLossDto`'s holding list): entities stop being
    the wire contract, required fields can be refused with a domain message, audit is never a client field. It is the
    right boundary design, but it needs a ~30-field `ChargeRule` mirror and its `ChargeSlab` mirror, and rewrites five
    admin endpoints — a redesign, not this defect. Proposed as its own row if the owner wants it.
- **C2 — who owns `auditMetadata`:**
  - **(a) recommended: the server.** `@JsonProperty(access = JsonProperty.Access.READ_ONLY)` on each of the six fields.
    Measured: a client sending `{"auditMetadata": {...}}` or `null` is ignored, the initialiser survives, and the
    response still carries the object. This closes the other door the all-args creator leaves open — today a body can
    set (or blank) the author through the private field even with `@Setter(NONE)`.
  - **(b) rely on C1 alone.** The field survives when omitted, but a body that sends it or sends `null` still writes it;
    the `@Setter(NONE)` intent stays half-enforced.

### What I will build (C1a, C2a)

### Risks or ambiguities

- **The six-type list is the guard's weak point.** A seventh entity-bound request type will lose its initialisers
  exactly as these did until it is annotated and added to the test list. Named in the test so the next author sees it.
- **Absent primitives on the six types now default silently** (`requiresInstrumentProfile` → false; `AssetEntity`'s five
  doubles → 0.0 in the helper hook). Both defaults are the documented/neutral value; `ChargeRule`'s pricing booleans
  keep their 400.
- **`@JsonProperty(READ_ONLY)` changes what a client may send.** A body carrying `auditMetadata` is ignored rather than
  refused (measured: no 400). No collection body sends it (grep of `api-collection` finds none).
- **The seeders bind these entities too.** Measured effect: none — they already construct through the no-arg constructor
  (`readerForUpdating(factory.get())`), and the seed files carry no `auditMetadata`; `ChargeSeederServiceTest`'s shipped
  files and the policy seeder are re-run to prove it.
- **`ProfitLossDto` is a record; its canonical constructor is unaffected** by the annotation on `AssetEntity` — the
  holding value inside it is deserialised by `AssetEntity`'s own (now no-arg) binding.
