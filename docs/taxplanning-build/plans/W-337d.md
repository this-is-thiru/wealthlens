### Core findings from probing `corporate` before planning (`probe-before-plan.md`)

1. **`lastly_performed_corporate_action`** already has its Flyway table in `db/migration/corporate/V2__corporate.sql:4-17` (`id`, `email`, `stock_code`, `asset_type`, `action_type`, `action_date`, `broker_name`, `created_by`, `updated_by`, `created_at`, `updated_at`, and `lastly_performed_corporate_action_email_idx`).
2. **`corporate_action`** (`CorporateActionEntity.java:19-56`) was deferred from W-337b because `demergerDetail` (`DemergerDetail.java:10-35`) embeds `List<DemergerStock> demergerStocks`. In `db/migration/corporate/V7__corporate_action.sql`:
   - `corporate_action` holds the 14 scalar columns + 4 embedded `DemergerDetail` scalar columns (`demerger_ratio`, `demerger_price_ratio`, `main_stock_code`, `main_stock_name`) + 4 `AuditColumns`, with indexes on `(stock_code, record_date)` and `(type, record_date)`.
   - `corporate_action_demerger_stocks` holds `(corporate_action_id VARCHAR(255) NOT NULL REFERENCES corporate_action (id), stock_code TEXT, stock_name TEXT)` indexed on `corporate_action_id`.
3. **Mongo `@Query` replacements:**
   - `CorporateActionRepository.java:24-33`: 3 Mongo JSON `@Query` methods (`findByStockCodeAndTypeInAndRecordDateBetween`, `findByTypeInAndRecordDateBetween` ordered by `recordDate ASC, priority ASC`, `findByStockCodeAndRecordDateAndOrderByPriorityAsc`) become clean JPQL `@Query` methods.
   - `LastlyPerformedCorporateActionRepo.java:11-12`: `findLastPerformedCA` becomes a clean JPQL `@Query` matching all 5 fields (`SearchableColumn` handles `email` automatically).
4. **Transactions while `portfolio` stays on MongoDB until W-337e (`CorporateActionService.java:43,109,129,230`):**
   - Pure-corporate mutations (`addCorporateAction`, `updateCorporateActionPriority`, `deleteCorporateActions`) use `@Transactional("postgresTransactionManager")`.
   - `performPendingCorporateActions` / `performCorporateAction` span `portfolio` (Mongo) and `lastly_performed_corporate_action` (Postgres), so they stay on `@Primary` Mongo `@Transactional` until W-337e moves `portfolio` to Postgres, while `LastlyPerformedCorporateActionRepo` writes in its own JPA transaction.
   - `TemporaryTransactionService.deleteTemporaryTransactions` calls `lastlyPerformedCorporateActionRepo.deleteByEmail(email)` — `deleteByEmail` needs a Postgres transaction (either `@Transactional("postgresTransactionManager")` on a small helper or `@Modifying @Query` / derived delete inside a Postgres transaction).
5. **Every moving test for W-337d1:** `FlywaySchemaBaselineIntegrationTest` (assert `V1`–`V7`), `CorporateActionIntegrationTest`, `TemporaryTransactionIntegrationTest`, `StockSplitIntegrationTest`, `BonusAllotmentIntegrationTest`, `PaginationIntegrationTest`, `AssetsRebuildIntegrationTest`, `EarlierQuarterHoldIntegrationTest`, `PortfolioGapAuditIntegrationTest`, `PortfolioIntegrationTest`, `StoredStringIdIntegrationTest` (any that save/query `CorporateActionEntity` or `LastlyPerformedCorporateAction` via `mongoTemplate`).

### Decisions (for approval with this plan)

- **C1 — split.** **C1a (recommended):** split W-337d into **W-337d1** (`corporate`) and **W-337d2** (`brokercharges`), each its own commit and D-row on branch `w-337`. **C1b:** port both modules together in one W-337d commit.
- **C2 — `DemergerDetail` mapping in `corporate_action`.** **C2a (recommended):** flatten `DemergerDetail`'s 4 scalar fields into `@Embedded` columns on `corporate_action` and store `demergerStocks` in child table `corporate_action_demerger_stocks` (`@ElementCollection(fetch = FetchType.EAGER)`), matching the relational pattern used across W-337a–c. **C2b:** store `demerger_detail` as a single `TEXT` JSON column via a custom converter.
- **C3 — `CorporateActionService` transaction boundary during W-337d1.** **C3a (recommended):** `@Transactional("postgresTransactionManager")` on pure-corporate mutations (`addCorporateAction`, `updateCorporateActionPriority`, `deleteCorporateActions`), while `performPendingCorporateActions` / `performCorporateAction` keep `@Primary` Mongo `@Transactional` for `portfolio` until W-337e moves `portfolio` to Postgres. **C3b:** switch the entire `CorporateActionService` class to `postgresTransactionManager` now (would drop Mongo multi-document transaction wrapping on `portfolio` writes during W-337d).
