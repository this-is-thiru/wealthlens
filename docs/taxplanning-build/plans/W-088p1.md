## Plan for W-088p1 — trace lines from the node's context

**What this item is for (one sentence):** the 13 node-local `line(...)` helpers (6–7 parameters each) are replaced by
one `NodeContext.traceLine(sequence, rule, kind, in, out)`. It knows the node and finds the rule's provenance itself,
so the parameter list the review flagged (S1) has its missing type: the node's context (D-260).

**Behaviour unchanged:** every trace line's sequence, node, rule, kind, in, out, limit text and provenance are
identical.

### Design

1. **`NodeContext` keeps what the node declared as one value,** a private record
   `Declared(Optional<NodeId> node, Set<NodeId> requires, Set<RuleSetId> ruleSets)`:
   - `forRun` uses `Declared.NOTHING`;
   - `forNode` uses the node's own;
   - the private constructor goes from 7 parameters to 5. *(Wrong: `Declared` replaces two, so 6. Corrected by D-262.)*
2. **`NodeContext.traceLine(int sequence, RuleId rule, StepKind kind, Money in, Money out)`:**
   - writes under the context's node;
   - takes provenance from `TemporallyApportionedCap.governingVersion(rule(rule), inputs.temporal())`, through the
     existing `rule(id)` so an undeclared row is still refused;
   - a run-level context, which has no node, refuses.
   - Limit text stays `.withLimitedBy(...)` on the returned line.
3. **The 13 helpers are deleted.** Each call becomes `ctx.traceLine(...)`, with any helper-specific text built at the
   call: `MealPerquisite`'s meals suffix, and `LoanPerquisite` / `ExpenseBenefitPerquisite` reading `in` from their
   item.
4. **`TraceLine.of` stays** the record's factory for lines that are not a rule's money step. It is W-088v's baseline
   entry (D-260 C0).
