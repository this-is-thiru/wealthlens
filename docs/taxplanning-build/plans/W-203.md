## Plan for W-203 — the seeders drop unknown keys silently

**What this item is for (one sentence, in my own words):** both seeders build their own JSON mapper, which ignores a
key the entity does not have, so a misspelt field in a shipped rate card or policy file disappears and the seed
succeeds with a silently incomplete document. This item makes both refuse such a file, and settles the one unknown
key the shipped files carry today: `"currency": "INR"` in all 39 rate cards.

**Source:** `03-WORK-ITEMS.md` W-203; `plans/W-202.md` C3, RV2; D-406.

**Board (R4):** `… W-201 D  W-202 D  W-203 ·  W-204 · …`. W-203 is the first open item. The resume check matched:
last item commit `2c61b96a` (W-202), tree clean but for the owner's untracked `.env`.

### What I found (2026-10-31)

- **The behaviour, measured on this version.** Jackson 3.1.4 is lenient about unknown properties by default. A
  scratch probe (a throwaway class, not committed) against `jackson-databind 3.1.4`:
  `new ObjectMapper()`, `JsonMapper.builder().build()` and both through `readerForUpdating` all accepted
  `{"code":…, "currency":"INR"}` into a two-field class; only
  `JsonMapper.builder().enable(DeserializationFeature.FAIL_ON_UNKNOWN_PROPERTIES).build()` refused it with
  `UnrecognizedPropertyException: Unrecognized property "currency" (class …), not marked as ignorable`.
  The constant exists in `tools.jackson.databind.DeserializationFeature` (`javap` on the jar).
- **The charge seeder.** `ChargeSeederService:101-103` builds its mapper with one setting —
  `disable(FAIL_ON_NULL_FOR_PRIMITIVES)` — so `currency` is dropped on every card. `ChargeSeederServiceTest:101`
  (`seed_parsesAndAcceptsEveryShippedCard`) seeds all 39 real files and passes today, which is the measurement.
- **The policy seeder.** `PolicySeederService:56` is a plain `new ObjectMapper()`, the same default.
- **The shipped inventory.** A scratch survey compared every JSON key against the entity property names:
  - **39 of 39** card files carry exactly one unknown key, the identical line `  "currency": "INR",`
    (`grep -c` : one occurrence per file; e.g. `fyers-equity-futures-2025-04-01.json:11`);
  - no unknown key in `charge-catalogue.json`, in the 2 instrument profiles, in the 4 tax-policy files (`items[]`
    and `slabs[]`/surchargeSlabs[]/limits[] included), and none inside `rules[]` or `rules[].slabs[]`;
  - `grep -rn currency src/main/java`: no field anywhere. The only mention is `TMoney:27` — Indian currency
    resolves to paise. `ChargeScheduleEntity:46-110` has no `currency`; the design docs do not mention one.
- **Beside it:** `api-collection`'s `Publish a rate card` already lost `currency` in W-202 (`756ab44`, D-406), so the
  collection and the shipped files currently disagree about what a card carries.

### Choices (recommended first)

- **C1 — `currency` in the 39 card files:**
  - **(a) recommended: drop it.** It has no field, no reader and no design mention, and the collection's one card
    body already lost it. Removing a key nothing models is the smallest truthful state; if multi-currency ever
    arrives, the field is added then with a reader and an enum of its own.
  - **(b) model it.** Add `currency` to `ChargeScheduleEntity` and fill it in the 39 files — a field with no current
    caller, which CLAUDE.md §2 forbids, and it would need a type and a meaning the design has not given.

The strictness itself is not a choice: W-203's row says make both seeders refuse.

### What I will build (C1a)

1. **`ChargeSeederService`** (`brokercharges/service/ChargeSeederService.java:101-103`): add
   `.enable(DeserializationFeature.FAIL_ON_UNKNOWN_PROPERTIES)` to the mapper builder and extend the field's
   Javadoc by one sentence saying an unknown key is now refused rather than ignored. Its failure path needs no
   new code: `read` (`:333-340`) already wraps every read error in `IllegalStateException("Could not read the
   charge seed file <name>: <cause>")`, so the message names the file and the property. `FAIL_ON_NULL_FOR_PRIMITIVES`
   stays disabled — that is W-204's subject and this item does not touch it.
2. **`PolicySeederService`** (`taxplanning/policy/service/PolicySeederService.java:56`): replace `new ObjectMapper()`
   with `JsonMapper.builder().enable(DeserializationFeature.FAIL_ON_UNKNOWN_PROPERTIES).build()`; its `failed`
   (`:172-175`) already names the file and the cause. Make `read(String, T)` (`:139-145`) package-private so a test
   can hand it a fixture, as `ChargeSeederService.read` already is.
3. **Drop `currency`** from the 39 card files: one exact-match line deletion per file
   (`  "currency": "INR",`), verified by `grep -rl '"currency"' data/charges | wc -l` → 0.
4. **Tests:**
   - `ChargeSeederServiceTest`: `read_whenAFileCarriesAPropertyTheCardDoesNot_failsNamingTheFileAndTheProperty` —
     a `ByteArrayResource` named `misspelt-card.json` carrying `"requiresInstrumentProfiles"` (the real field is
     `requiresInstrumentProfile`); asserts `IllegalStateException` naming both the file and the key.
   - `PolicySeederServiceTest`: the same shape, through the package-private `read` and a new test-classpath fixture
     `backend/src/test/resources/tax-policies-fixture/misspelt-slab.json` with `"standardDeducton"`.
   - The **failing-first order** is the proof for the files: enable the strictness first, run the two classes — the
     new tests pass and `seed_parsesAndAcceptsEveryShippedCard` fails, naming `currency`; then drop `currency` and
     both are green.
5. **Bite probes** (each guard proven by a deliberate violation, then reverted):
   - remove `.enable(FAIL_ON_UNKNOWN_PROPERTIES)` from the charge seeder → its new test fails; restore + `touch`;
   - the same for the policy seeder;
   - restore one card's `currency` line → `seed_parsesAndAcceptsEveryShippedCard` fails naming `currency`; remove.

**None.** `POST /charges/seed` and `POST /tax-planning/admin/policies/seed` are already the runbook's §1B seed step,

### The five roles

- **Architect:** the guard sits where the data enters — one builder setting per seeder, no new type, no shared
  helper across two modules that may not depend on each other.
- **Product manager:** a rate-card typo stops the seed loudly instead of pricing trades from a partly-read card, and
  the shipped inventory stops carrying a key nothing models.
- **Senior engineer:** the two mappers stay independent (Jackson 3 lenient default is the cause, measured); the
  existing wrap already names file and key; disabling unknown keys must not disturb the deliberate omission of
  booleans.
- **Automation tester:** the new tests fail first with the flag off; `seed_parsesAndAcceptsEveryShippedCard` is the
  build-time gate that every shipped card is unknown-key free; both tiers run.
- **Manual tester:** rename one field in a local card copy and run `POST /charges/seed` — it answers 500 naming the
  file and the key, and writes nothing; restore the file and it seeds.

### Risks or ambiguities

- **`ChargeSeederService:46`** says `PolicySeederService` "logs and continues when a file will not load". That has
  been stale since W-088u8a made the policy seeder throw. Not this item's line to change; reported, not touched.
- **The unknown-property flag is per mapper, not global.** A future seeder that builds a bare mapper reintroduces
  the fault; the test convention (one test per seeder proving refusal) is the guard. Putting the mapper in `shared`
  would be one more abstraction for two callers, and `taxplanning` may not read `brokercharges` anyway.
- **The 39-line drop changes shipped data files.** Every card's contents are the same after parsing; the drift
  report and the seeded documents are unchanged, so no database action follows.
