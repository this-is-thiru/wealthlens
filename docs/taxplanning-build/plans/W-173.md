### Decisions (for approval with this plan)

- **C1 — the two caller-mistake cases on the backfill route.** **C1a (recommended):** the `dryRun=maybe` case moves to the P&L rebuild route
  (`POST /api/v1/admin/portfolio/users/{email}/profit-and-loss/rebuild?dryRun=maybe`, the same `boolean dryRun` binding). The
  `recordedBefore` case is deleted: no other route binds a `LocalDateTime` parameter (grep), and `ControllerAdviserTest:142` keeps that wording
  on its own stub route. **C1b:** delete both.
- **C2 — clearing the stored list (R15).** **C2a (recommended):** a new runbook step **§2.18**. The owner runs it in the IntelliJ console on
  each database, after the deploy that carries W-173 (from then on nothing writes the field). The steps:
  1. A read-only count.
  2. A backup copied into a collection (`$out`), since the MongoDB tools were removed (D-849).
  3. `updateMany` with `$unset`.
  4. The count again, expected 0.
  5. The backup collection dropped after the owner checks the P&L reads as before.

  Before the build, it is tried twice on a throwaway `mongo:8.0.4`; the second run matches nothing. Until §2.18 runs, a stored document still
  carries the field, and the app ignores it. A build-time test proves this: a document written with the field loads and saves. **C2b:** leave the
  field in the data. It is then unread junk, and the row's "unset" is not done.
- **C3 — §2.18 is itself one-time.** **C3a (recommended):** place **W-368** "retire runbook §2.18 once logged for every database", with a

  §2.18 in W-366's sign-off without a row.
