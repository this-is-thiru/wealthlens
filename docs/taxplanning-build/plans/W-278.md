## Plan for W-278 — caller mistakes on portfolio routes answer 500

**What this item is for (one sentence, in my own words):** three requests a caller got wrong answer 400 naming what
is missing, instead of 500 with a null-pointer message (G-1, G-14; W-263's reach).

**Findings (each read this session, 2026-11-11):**

1. **A trade with no price** — `validateAssetRequest` unboxes `getPrice()` (`PortfolioService.java:204`) → NPE → 500.
   Every trade passes the check since W-277, so this is the one place. Zero stays valid (bonus and split allotments
   are free — the check's own Javadoc). Proven: W-264a scenario 5.
2. **`POST /portfolio/user/{email}/stocks` without `dateRange`** — `PortfolioController.getStocks` (`:88-93`)
   dereferences `bulkGetRequest.getDateRange()` → 500; with a range but no start or end date the query runs on
   `null`. `getStocksWithDateRange` (`PortfolioService.java:589`) is its only caller. Proven: scenario 29.
3. **`POST …/stocks/download` without `entityName`** — `EntityExportService.export` switches on `null` (`:44-47`)
   → 500; an unknown name already answers 400 naming the three. Proven: scenario 24.
4. `ControllerAdviser` maps `IllegalArgumentException` (and `BadRequestException`) to 400 (CLAUDE.md).

**Choices for the owner:**

- **C1 (recommended, C1a):** each refused as `BadRequestException`, naming the field:
  "Price is required; it may be 0 for a free allotment"; "A date range is required: dateRange with startDate and
  endDate" (the service takes the `DateRangeFilter` and checks it, so the controller keeps no logic); "Name the
  entity to export: one of assets, transactions, transactions-template" (the existing unknown-name message's list).

**Files I will modify:** `PortfolioService` (price check; `getStocksWithDateRange` takes `DateRangeFilter`),
`PortfolioController` (passes the range), `EntityExportService`; tests — scenarios 5, 24, 29 as the first tests,
plus a range missing its end date.

**Numbers I will use:** none.

**What I am NOT doing:** a start date after the end date (it answers an empty list — a question, not a crash);
other modules' 500s (W-264b – d).

**How I will verify:** first tests red then green; probe: the price null-check removed → scenario 5 fails; the
affected classes; `./mvnw validate`.

**Post-deployment actions (R15):** none.

**Five roles:**
- **Architect:** checks at the boundary, once, in the service the route calls.
- **Product manager:** a mistake says what to send.
- **Senior engineer:** keep zero price valid; reuse the unknown-entity list.
- **Automation tester:** one test per field; a probe.
- **Manual tester:** each request from W-264a scenarios 5, 24, 29 answers 400 with the field named.

**Risks or ambiguities:** none known.
