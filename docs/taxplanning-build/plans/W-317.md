### W-317 — any signed-in user can add, reprioritise and globally perform corporate actions (G-6)
- **Change:** `@PreAuthorize("hasRole('SUPER_USER')")` on `add`, `update/priority`, `perform` and `perform/test`
  (`CorporateActionController:30, 42, 67, 74`), as `delete` already has (`:61`). The reads (`/{id}`, `/list`, `/all`)
  stay open to any signed-in user, since every user's holdings depend on them.
- **api-collection** (a submodule; committed inside it first): `Add - CA.yml`, `Stock Split.yml`, `Update
  priority.yml`, `Rename Symbol.yml` and `Test.yml` each gain `docs:` with "**Authorisation:** `SUPER_USER`.", as
  `Charges Engine/Close a rate card.yml:35` does.
- **Red test:** report §4 `adminRoutes_whenTheCallerIsNotASuperUser_answer403`, now covering all four routes (200
  today). **Probe:** remove the guard from `add`, and the test fails.

### W-315 — a wrong perform month is answered in Java's words (G-4)
- **Change:** `Month.valueOf` (`CorporateActionService:138`) is replaced by a lookup among the four quarter-start
  months. Anything else is refused: "A quarter starts in one of [JANUARY, APRIL, JULY, OCTOBER], but the month was
  'april'". Strict names, as the API documents them; "april" is refused, not accepted.
- **Red test:** report §4 `perform_whenTheMonthIsNotAQuarterStart_answers400NamingTheMonths`, with the exact message
  for "april" and "FEBRUARY". **Probe:** `Month.valueOf` put back, and the test fails.

  caller (`CorporateActionService:164`).
