## Plan for W-116 — plain-language explanations (F37)

**What this item is for (one sentence, in my own words):** give each trace line a plain sentence. It says what the
figure is, which limit set it, and what would or would not change it. The sentences are built from templates held in
the rule pack's content layer, never written in code. Where a line has no template, the rule's ID is shown instead.

**Design sections I read:**
- `01-PRD.md:233` (F37.1 – F37.3);
- `20-product-gaps.md` F37 (the HRA example);
- `03-advisory.md:369` A4.4 (the three sentences: what, why, what changes it);
- `05-domain-model.md:220` (a `LeastOf` names the limit that won);
- `23-architecture-consolidation.md:53, 351, 492` (`content/explanations.json`, which "never changes a number").

**Choices for the owner:**
- **C1: which rows get a template now.**
  - **C1a (recommended):** the 28 `LeastOf` rows. Every other line shows its rule ID plus `limitedBy` verbatim, which is F37.2's own fallback. A coverage test lists the rows still without a template, so the gap is visible. **W-325** is placed to write the rest, grouped by section.
  - C1b: all 244 now. That is roughly five times the content, mostly for rows with no limit to explain (rates, a fixed amount).
- **C2: where and how templates live.**
  - **C2a (recommended):** one file, `timeline/content/explanations.json`, as W-116's Produces names it. It holds one entry per rule, each with three parts:
    - `what`: a sentence with `{in}` and `{out}` placeholders;
    - `byLimit`: one "why" sentence per limit name of the rule's `LeastOf`;
    - `otherwise`: a "why" for a `limitedBy` that names no limit, such as a regime bar.

    Loading it fails the build where an entry names an unknown rule, a limit the rule's cap does not have, or a placeholder that does not exist. Under SC-2, no figure may appear in the text.
  - C2b: put a `displayName` on each rule row (the design doc's wording). PRD F37.1 says `content/`, so I recommend following the PRD.
- **C3: the figures.**
  - **C3a (recommended):** `ComputedTax.Step` gains `Optional<Money> in`, `Optional<Money> out` (present where the value is money) and `String explanation`. `TaxCalculator` renders the explanation when it builds the steps (one place). The explanation then reaches every reader: the computation view, the PDF, and the optimiser and calendar via `compute`.
  - C3b: render inside `taxplanning`. That would need the trace values exported anyway.
- **C4: "what changes it" (F37.3).**
  - **C4a (recommended):** for a `LeastOf` row, the "why" sentence names the limit that bound. A generated clause then names the other limits from the pack, saying that raising them alone would not change the figure. That holds for any least-of and needs no figures.
  - The rupee version ("₹19,000 a month more in rent would raise it to …") needs every limit's value in the trace, and `CapResult` holds only the winner. **W-326** is placed for it: the limit values in `CapResult` and `TraceLine`, then the quantified sentence.
  - C4b: build W-326's limit values now. That changes every cap shape, which is too large for this item.
- **C5: the wording.** The 28 templates are prose I will draft from each row's section entry (`summary`, `routes`) and its limit names. Plain-language content I draft needs the owner's adoption (as in session 69). The review is where you adopt or edit them, and nothing is legal text.
