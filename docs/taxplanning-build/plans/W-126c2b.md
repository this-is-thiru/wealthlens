**What this item is for (one sentence, in my own words):** read Part B's three tables from a Form No. 130 using the
layout W-126c2a shipped:
- each quarter's amount paid, tax deducted and tax deposited;
- each book-adjustment or challan deposit;
- each table's totals.

W-128 can then check Part B against Part C, and W-129 can assemble several employers.

### What the design and D-737 say

- `DR 06` G5.1 (`06-algorithms.md:482`): structural, never positional; 0.95 for a heading found, 0.90 for a cell read
  (D-732 C3a).
- D-737 C3a: a value goes under the heading whose printed span holds its centre. Each span is found from the heading's
  own words: the next word on the same line, or a word on a lower line that overlaps the words found so far. A value
  under no heading is left unread, named in the notes, and makes the reading `PARTIAL`.
- W-126c2a's layout (`CertificateLayout.tables`): titles, columns (heading, key, kind, group), and the Total row's
  cells with merged spans.

### Probe — the reader itself

Two new classes: `HeadingMatch` (89 lines) and `TableReading` (169 lines).

- **Isolated run.** I rendered Part B laid out as the Gazette lays it out: two quarters, one with its Rate cell blank;
  the merged Total cell; the BIN and CIN group headings; two challans. All three tables read completely: 13, 7 and 13
  cells, each value in its column. The merged Total amount came out as `partB.summary.total.amountPaid`, and nothing
  was left unread. The only unclaimed words were "PART B" (the part heading, which the parser claims when it enters the
  part) and "DECLARATION", which follows the tables.
- **Wired into `Form130Parser`**, with the test fixture rendering Part B from the layout: 51 run, 2 failures.
  - `read_whenOnlyPartAIsIssued_findsPartAAndSaysPartCIsAbsent` failed only because the probe triggered the tables
    from the first Part C line. That certificate has no Part C, so Part B was never read. The build reads each top part
    in the layout's part order instead.
  - `read_whenThePdfIsProtectedOnlyAgainstEditing_readsIt` failed because the stored `owner-only.pdf` still prints
    the old placeholder Part B. It needs re-rendering, as in W-126c1 (D-736).
  - Every other case still read `SUCCESS`, so the fixture's Part B, with empty cells, left nothing unread.

### Choices for the owner (recommended first)

- **C1 — size:** the probe has 258 lines of main code. Splitting the methods to the 60-line limit, plus the parser
  wiring, comes to about 330.
  - **(a) one item.** The reader has no caller without the wiring, so a split leaves a class nothing uses for an item's
    length.
  - (b) split: W-126c2b1 as `HeadingMatch` and `TableReading` with their own tests; W-126c2b2 as the wiring, fixture
    and parser cases.
- **C2 — a certificate without Part B:**
  - **(a) a note, "PART B is not in this certificate", with the outcome unchanged**, as for an absent annexure (D-735
    C2a).
  - (b) `PARTIAL`. Note 7 has each employer issue Parts A and B, but a Part C issued alone (Part C Note 1) prints no
    Part B.
- **C3 — Part B printed but one of its tables missing:**
  - **(a) a note for the missing table, outcome unchanged.** Notes 3 – 4 have a deductor fill item I *or* item II, so an
    issuer may leave the other out. A table whose title is found but one of its column headings is not makes the
    reading `PARTIAL`, and so does a missing Total row.
  - (b) `PARTIAL` for any table not found.
- **C4 — an empty cell:**
  - **(a) no field.** A table cell has no label of its own, so an empty cell says nothing. Lines differ: a line's
    label is found, so it is reported even when empty.
  - (b) a field with no text for every column of every row read.

### Risks or ambiguities

- **TRACES layouts may differ.** An issuer's own layout (for example, quarters printed as "Q1 (Apr-Jun)", or no group
  header row) may not match; W-126d will show it. The probe proves the Gazette's layout only.
- **Two "Total" rows on one line.** A table whose Total label prints on the same line as another table's would confuse
  the row bound. The Gazette prints the tables one under another.
