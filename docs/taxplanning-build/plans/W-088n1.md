## Plan for W-088n1 — the car's facts: engine capacity and whether electric

**What this item is for (one sentence):** the taxpayer states a car's engine capacity in cc, or that it is electric.
The Table II rows say in data which column that is: "does not exceed 1.6 litres", or electric where the year's Table
names it. The 1.6-litre line then lives in the pack, not in a Java enum (review E2; D-256).

**Behaviour unchanged:** every value, trace row id and refusal is as today. A test that entered `UP_TO_1600_CC` enters
1,500 cc; `ABOVE_1600_CC` becomes 2,000 cc; `ELECTRIC` becomes electric.

### What I read (session 23, 2026-10-19)

- **`CarEngine`** (`input/CarEngine.java`) is an enum of `UP_TO_1600_CC`, `ABOVE_1600_CC` and `ELECTRIC`.
- **`EmployerVehicle.engine`** is an `Optional<CarEngine>`, empty exactly for an other automotive conveyance
  (`EmployerVehicle.java:60–66`).
- **`MotorCarPerquisite.rowFor`** (`:155–164`) supplies `ItemFacts.of(vehicle.engine, name)`, and the six car rows test
  it with `ItemFactIs` (W-088m2).
- **`ItemFacts`** holds codes only. `ConditionJson` reads `ItemFactIs` (`rules/json/ConditionJson.java`).
- **`InputsFingerprint`** walks records and `Optional`s structurally (`input/InputsFingerprint.java:106–127`), so a
  record-valued `CarEngine` is fingerprinted with no change there.
- **Source:** `DR 01` `PERQ-CAR-2026` (`01-rulebook.md:782–784`), "≤ 1.6 litres **or electric vehicle** | > 1.6 litres".
  TY 2025-26's Table has no electric words, and the electric rows exist for TY 2026-27 only (their `_note`, D-113
  C5a). 1.6 litres = 1600 cc.
- **Call sites building a car:** `MotorCarPerquisiteTest` 16, `NodeContextRuleSetTest` 5, `EmployerVehicleTest` 4.

### Design

1. **The algebra:**
   - `ItemFacts` gains `quantities` (`Map<ItemFactId, Long>`) beside `codes`, and `quantity(id)` throws on an absent
     fact, as `code(id)` does.
   - One new predicate, the 15th: `ItemFactAtMost(fact, limit)`, inclusive, for the Rules' "does not exceed". JSON:
     `{"type": "ItemFactAtMost", "fact": "vehicle.engine.cc", "limit": 1600}`.
   - "Exceeds" is `Not(ItemFactAtMost)`.
2. **The input:** `CarEngine` becomes `record CarEngine(boolean electric, Optional<Integer> cubicCapacityCc)`.
   - The capacity is present exactly when the car is not electric, and positive.
   - Factories: `CarEngine.ofCapacity(int cc)` and `CarEngine.electric()`.
   - `EmployerVehicle` is unchanged.
3. **The node:** `MotorCarPerquisite.rowFor` supplies `vehicle.engine.electric` (`"true"` / `"false"`) and, for a car
   that is not electric, `vehicle.engine.cc`.
4. **The pack:** the six rows' conditions, per version.

   | Rows | Condition |
   |---|---|
   | `PERQ-CAR-PARTLY-SMALL`, `PERQ-CAR-OWNRUN-SMALL` | `AllOf(ItemFactIs(electric, "false"), ItemFactAtMost(cc, 1600))` |
   | `PERQ-CAR-PARTLY-LARGE`, `PERQ-CAR-OWNRUN-LARGE` | `AllOf(ItemFactIs(electric, "false"), Not(ItemFactAtMost(cc, 1600)))` |
   | `PERQ-CAR-PARTLY-ELECTRIC`, `PERQ-CAR-OWNRUN-ELECTRIC` (TY 2026-27 only) | `ItemFactIs(electric, "true")` |

   - The electric limb comes first. `AllOf` stops at it (`AllOf.java:9–12`), so an electric car's absent capacity is
     never read.
   - The two car sets' notes in `rule-sets.json` name the new facts.
   - Relocked once.
