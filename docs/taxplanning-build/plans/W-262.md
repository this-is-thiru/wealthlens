## Plan for W-262 — held assets by term, with Excel

**What this item is for (one sentence, in my own words):** give back what the removed
`/assets/holding/{LONG_TERM|SHORT_TERM}` was for — which held lots are long-term and which short-term, per lot and per
stock, as JSON and as Excel — with the term read from the year's `RS-CG-TERM` rows on the tax side, plus the date each
short-term lot turns long-term.

**Findings (each read this session, 2026-11-11):**

1. **What was removed.** W-160e removed `GET …/assets/holding/{holdingType}` and `/excel` from `PortfolioController`,
   with `HoldingType` and a one-year date split in `PortfolioService` (commit `4f63e5b4`; D-370). It answered one row
   per stock and broker: the quantity in the asked term and the total quantity.
2. **What exists.** `GET /tax/user/{email}/profiles/{profileId}/capital-gains/{taxYear}?asOf=` returns the year's
   realised buckets and, with `asOf`, each held lot's term (`DraftComputationController.java:48-52`;
   `CapitalGainsView.java:15, 28`). A held lot there has stock, quantity, acquired on, term, row, months, refusal — no
   broker, no account holder, no totals, no filter, no turning date, and it always runs the realised computation
   (`CapitalGainsViewService.java:47-48`).
3. **How a term is decided.** `CapitalGainsTerm.of` takes the one `RS-CG-TERM` row the lot's asset and transfer
   exchange meet and calls the lot long-term when `acquiredOn.plusMonths(months).isBefore(transferredOn)`
   (`taxengine/node/CapitalGainsTerm.java:48-57`). So the first day a sale is long-term is
   `acquiredOn.plusMonths(months).plusDays(1)`. `TaxCalculator.termIfSold` wraps it for a held lot and returns
   `HeldTerm(term, row, months)` (`TaxCalculator.java:102-118`).
4. **The rows.** `CG-TERM-LISTED-SECURITY` holds 12 months for an `EQUITY` whose transfer exchange is `NSE` or `BSE`,
   in both shipped years (`rules/CG-TERM-LISTED-SECURITY.json:11-12, 29` and `:79, 96`). `CG-TERM-LAND-BUILDING` is the
   only other row. A lot no row covers is refused with a sentence, which the view carries per lot
   (`CapitalGainsViewService.java:63-77`).
5. **The lot's facts.** `AssetEntity` holds `brokerName` (`:60`), `accountHolder` (`:128`), `quantity` (`:66`),
   `transactionDate` (`:108`), `exchangeName` (`:57`), `assetType` (`:69`). `taxplanning` already reads lots through
   `PortfolioRepository.findByEmail` (`CapitalGainsViewService.java:60`); `portfolio` is an allowed dependency.
6. **Excel.** `shared` has the workbook pieces: `ExcelColumn` (`shared/util/parser/ExcelColumn.java:34`, with `text`,
   `quantity`, `date`), `ExcelSheet` (`ExcelSheet.java:18`), `ExcelWorkbooks.toStream` (`ExcelWorkbooks.java:33`).
   `taxplanning` may depend on `shared`. (CLAUDE.md's `ExcelBuilder` does not exist under that name.)
7. **The term as a request value.** `CapitalGainsInput.Term` (`taxengine/input/CapitalGainsInput.java:55`) is in the
   `input` named interface, so a controller in `taxplanning` can bind it; a wrong value then answers 400 listing the
   constants (W-263).
8. **`api-collection`** is a git submodule (at `8a22284`). Its `Tax Profile` folder has no request for the
   capital-gains view.
9. **Today's date.** `DraftComputationService` takes the day from an injected `Clock` (`DraftComputationService.java:52`).

**Choices for the owner:**

- **C1 — the date a lot turns long-term, when that date is in a later tax year.** The turning date is computed from
  the row governing the `asOf` date. If it falls in a later year, that year's row is the one that will decide it.
  - **C1a (recommended):** publish the date when the later year ships a pack and its row agrees. Where the later year
    ships no pack, publish no date and say so on the lot: "TY 2027-28 decides this and no rule pack ships for it" —
    the row's own wording ("or that the year deciding it ships no pack"). Where the later year's row disagrees (the
    law changed), publish that year's date.
  - C1b: always publish the date from the `asOf` year's row, with a note when a later year decides. Simpler, but it
    states a date under law that may not apply.
- **C2 — `asOf` when not given.**
  - **C2a (recommended):** today, from the `Clock` — the old endpoint was "as of today".
  - C2b: required.
- **C3 — lots the rows give no term for** (a share with no exchange recorded, an asset type with no row).
  - **C3a (recommended):** listed with the refusal sentence when no `term` filter is given; left out under a filter;
    and each stock's totals carry a third figure, the quantity with no term, so no quantity silently disappears.
  - C3b: two totals only, as the row words it.
- **C4 — the held part of the capital-gains view (`?asOf=`).**
  - **C4a (recommended):** keep it, unchanged in shape, but read through the same code as the new view so the term
    logic exists once.
  - C4b: remove it now that the held view exists (a breaking change for a view added on 2026-11-01).
- **C5 — the route.** `GET /tax/user/{email}/profiles/{profileId}/held-assets?asOf=&term=` and
  `…/held-assets/excel` with the same parameters (recommended). Say if you prefer the old words (`/assets/holding/…`).
