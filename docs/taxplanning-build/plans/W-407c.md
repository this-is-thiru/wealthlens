**G-1 — a unique index over a column that can be NULL no longer refuses duplicates.** MongoDB's (non-sparse) unique index treats a
missing field as `null` and refuses a second `null`; PostgreSQL treats NULLs as distinct unless the index is `NULLS NOT
DISTINCT`, and no migration says so (searched V1 – V10). Nullable here (`V8`): `charge_instruments.start_date` (`:37`),
`charge_accounts.broker_name`, `demat_account_id` (`:56-57`), `user_charges.transaction_id` (`:90`). So, for example, two
accounts for one email and broker with no demat id are now both accepted. Whether each NULL case is real, and whether the old
refusal was wanted, is per index — a decision, not this audit's. *`charge_catalogue.code` and `charge_schedules.schedule_code`
are single-column; their nullability is checked in G-1's item. Proposed row **W-408**: every unique index with a nullable column,
in every module (W-407d, e add theirs), each made `NULLS NOT DISTINCT` (PostgreSQL 15+; the target is 18) or ruled to stay.
