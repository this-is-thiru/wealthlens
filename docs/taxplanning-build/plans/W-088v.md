  `EnteredFacts`'s is 53. Checkstyle's own count, which this item makes the gate, does not have the gap.
- **What a widely used signature costs:** `TraceLine.of` has 7 parameters and **68** call sites (main and test,
  `grep -c "TraceLine.of("`). Fixing it is a type refactor, not a baseline line.

### Design

1. **`checkstyle.xml`:** `MethodLength` max **40**; `ParameterNumber` max **5** (`ignoreOverriddenMethods` kept).
2. **The baseline, per method (C1a):**
   - Add `SuppressWarningsHolder` (in `TreeWalker`) and `SuppressWarningsFilter` (in `Checker`).
   - Each of the 56 violations gets `@SuppressWarnings("checkstyle:methodlength")` or
     `@SuppressWarnings("checkstyle:parameternumber")` on its own method or constructor.
   - Exact spelling: checked at build against Checkstyle's documented alias, then proven by removing one and watching
     the build fail.
   - **Why per method rather than per file:** a per-file entry would also hide the *next* long method added to that
     file. Per method, any new violation anywhere fails the build, and the marker sits where the debt is.
3. **The guard, `CheckstyleBaselineTest` (may only shrink):**
   - `MAXIMUM_BASELINE_ENTRIES` 98 → **96**, the real count (C0).
   - A new count of `checkstyle:` suppressions across `src/main` and `src/test`, at most **56**, the recorded size.
     Fixing a method lowers it in the same change, as the class Javadoc already asks for the XML baseline.
   - Only `methodlength` and `parameternumber` may be suppressed this way, so the annotation cannot become a way round
     any other check. Any other `checkstyle:` id fails the test.
4. **`tools/method_lengths.py`:** its header notes that compact constructors are not measured and that Checkstyle is
   the gate now. The tool stays for quick reports only.
5. **Docs:** CLAUDE.md "Build gotchas" says the limits are 40 / 5, enforced, with the per-method baseline. WI, STATE
   D-288, CHECKPOINT.
