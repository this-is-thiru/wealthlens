**What this item is for (one sentence, in my own words):** give W-124's document, attempt and confirmation records a stored
form:
- encrypted where it holds what the person's certificate says;
- erased with the profile and the account;
- deleted when the rule pack's carry-forward span runs out;
- so W-131b – d have somewhere to keep what they upload, read and confirm.

### What the design and the code say

- **Collections** (`02-TECH-SPEC.md:331` – `:333`):
  - `tax_documents`: key `document_id`, unique `{sha256}`, index `{profile_id, tax_year}`;
  - `tax_parse_attempts`: key `attempt_id`, index `{document_id, started_at desc}`;
  - `tax_document_confirmations`: key `attempt_id`, unique.
- **The records** (`taxplanning/documents/ingest`):
  - `IngestedDocument(documentId, profileId, taxYear, documentType, sha256, uploadedAt, pageCount)`: "Where the bytes are
    kept is the upload's (W-131), so no storage reference is held here";
  - `ParseAttempt(attemptId, documentId, run, outcome, extractedFields, unmappedText, parserNotes)`;
  - `DocumentConfirmation(attemptId, confirmedBy, confirmedAt, acceptedFields, rejectedFields)`.
- **Encryption:** `EncryptedField` (`shared/protection/EncryptedField.java`) takes text, a date or an enum. A structured
  value is stored as encrypted JSON text, as `DraftRevision.fullStateJson` is (`workspace/DraftRevision.java:37` –
  `:43`). An actor is a `SearchableIdentifier` (`DraftRevision.changedBy`).
- **Erasure:** `ProfileRemoval.remove` (`jobs/ProfileRemoval.java`) erases everything under a profile in one
  transaction. Profile and account erasure both go through it (`TaxAccountErasure.erase` calls it per profile).
- **Retention** (O5): "Uploaded documents | 8 years, same reason", and the figure is "computed from the rule pack".
  `RetentionPurge` already does this for filed drafts: `taxCalculator.longestCarryForward(taxYear)`; a year with no pack
  is refused and kept; third parties go through a collaborator (`ThirdPartyRetention`).
- **Indexes:** `auto-index-creation` is off. Each family has an initializer that runs `@PostConstruct`, e.g.
  `DraftComputationIndexInitializer`, whose runbook entry asks the owner to confirm "Ensured the indexes of" in the log.

### Findings

1. **The read values need their own stored shape** (probe): a discriminator for the value's kind, and money as exact text.
2. **TS T7's unique `{sha256}` is global.** A second account uploading the same file would be refused for a file it never
   stored, and the refusal would tell it that someone else has. M7's idempotence ("same bytes, same `sha256`") is about
   one person's re-upload.
3. **Bytes are W-131b's, the job W-131c's, the notice W-131d's.** Nothing can store a document until W-131d's endpoint,
   and then only with the flag on (D-761 C3a).
4. **Names are free:** none of `StoredDocument`, `StoredParseAttempt`, `StoredConfirmation`, `DocumentRemoval`,
   `DocumentRetention`, `ReadingJson` or `DocumentIndexInitializer` occurs in `backend/src` or the design docs. The
   `Stored` prefix is in use for stored forms (`StoredFieldEncryption`, `StoredTermRemovalReport`).

### Choices for the owner (recommended first)

- **C1 — the stored classes:**
  - **(a)** In `taxplanning.documents.store`:
    - `StoredDocument`, `StoredParseAttempt` and `StoredConfirmation` (entities, conventions' `@Data`, snake_case,
      `AuditableEntity`), each with `of(record)` and `toRecord()`, so W-124's records stay the domain's;
    - their repositories, `DocumentIndexInitializer`, `DocumentRemoval` and `DocumentRetention`.
  - (b) Annotate W-124's records as documents, which puts storage concerns on the domain records.
- **C2 — the unique key** (finding 2):
  - **(a)** Unique `{profile_id, sha256}`, with an erratum to TS T7 line 331.
  - (b) Global `{sha256}` as written.
- **C3 — the read values' stored form** (finding 1):
  - **(a)** `ReadingJson`, a codec with its own shape. Each value carries a `kind` (`MONEY`, `FLAG`, `PERIOD`, `TEXT`);
    money is exact text; an unknown kind refuses to read.
  - (b) Jackson type annotations on `ExtractedValue`, keeping `Money`'s accessor shape.
- **C4 — what is encrypted:**
  - **(a)** Encrypted (`EncryptedField` over the JSON text): an attempt's fields, unmapped text and parser notes, and a
    confirmation's accepted and rejected fields. `confirmed_by` is a `SearchableIdentifier`.
  - In clear, because indexes, idempotence on `(documentId, parserVersion)` and retention need them: ids, `profile_id`,
    `tax_year`, `document_type`, `sha256`, `uploaded_at`, `page_count`, parser id and version, start and finish
    times, outcome.
  - (b) Also encrypt `sha256`, which would cost the unique index.
- **C5 — retention:**
  - **(a)** `DocumentRetention`, run by `RetentionPurge` after the drafts. It deletes a tax year's documents, with their
    attempts and confirmations, once the end of the tax year `year + longestCarryForward(year)` has passed; a year with no
    pack is refused and kept, as drafts are.
  - (b) Counted from the upload date.
- **C6 — the notice before consent:**
  - **(a)** Unchanged here. W-131d adds uploaded documents to the `tax-planning` part when its endpoint can store one
    (finding 3).
  - (b) Changed now.
