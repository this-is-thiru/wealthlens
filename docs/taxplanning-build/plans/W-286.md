## Plan for W-286 — split `PortfolioService` into command and query services

**What this item is for (one sentence, in my own words):** the reads of a portfolio move out of the 927-line
`PortfolioService` into a service of their own, so each class has one reason to change (PS-9; CLAUDE.md §4); no
behaviour changes.

**Findings (each read this session, 2026-11-11):**

1. **The query half** — `getAllStocks`, `getMutualFunds`, `getStocksWithDateRange`, `getStockQuantity`, `searchAssets`,
   `getExportEntities`, `getProfitAndLoss`, with `groupedWithCharges`, `combineAllDetailsOfEntities` and the
   `Holding` record. It needs `PortfolioRepository`, `ChargeViewAssembler`, `MongoTemplateService` and
   `ProfitAndLossService` (for `getProfitAndLoss`).
2. **Its callers:** `PortfolioController` (`:57, 79, 84, 90, 96, 118`), `EntityExportService` (`:52`), and one unit test
   (`PortfolioServiceTest:879`). No other module.
3. **Shared:** `hasNothingLeft` (the W-274 tolerance) is used by both the sell path (`:495, 518`) and the views
   (`:574`).
4. **The name `PortfolioQueryService`** is free again (W-272 deleted the dead class of that name); CLAUDE.md bans
   none of its words, and `ArchitectureTest` checks for duplicate simple names.
5. After the move `PortfolioService` no longer needs `ChargeViewAssembler` or `MongoTemplateService`.

**Choices for the owner:**

- **C1a (recommended):** a new `PortfolioQueryService` (`@Service @Transactional(readOnly = true)`) holding the seven
  reads and their helpers, moved unchanged; `PortfolioController` and `EntityExportService` call it;
  `hasNothingLeft` becomes package-private static on `PortfolioService`, shared by both; `PortfolioService` drops the
  two dependencies it no longer uses; `PortfolioServiceTest`'s holdings test moves to `PortfolioQueryServiceTest`.

**Files I will create:** `portfolio/service/PortfolioQueryService.java`, its unit test.

**Files I will modify:** `PortfolioService`, `PortfolioController`, `EntityExportService`, `PortfolioServiceTest`.

**Numbers I will use:** none.

**What I am NOT doing:** changing any read's behaviour; moving the corporate-action helpers
(`stocksForCorporateActions`, `saveCorporateActionProcessedStocks`), which are writes' helpers.

**How I will verify:** no test's expected value changes; the full portfolio integration set and the unit tests pass;
`ArchitectureTest` and the module test; `./mvnw validate`. A move has no probe of its own — the existing tests are its
check.

**Post-deployment actions (R15):** none.

**Five roles:**
- **Architect:** reads and writes on separate services, along the seam that was already there.
- **Product manager:** nothing visible changes.
- **Senior engineer:** methods moved verbatim; constructor shrinks.
- **Automation tester:** every existing test green; the moved unit test unchanged but for its class.
- **Manual tester:** the holdings views answer as before.

**Risks or ambiguities:** `readOnly = true` on the query service is a transaction hint only; the reads did not write
before either.
