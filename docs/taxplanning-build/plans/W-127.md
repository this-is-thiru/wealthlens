## Plan for W-127 — Form No. 130 layers L2 (anchored numeric) and L3 (checksum-driven)

> **Approved C1a, C2a, C3a, C4a** (owner, session 102, 2026-11-16). Split recorded (D-732); building W-127a. Every path below was read on 2026-11-16 at `5952aced`; grep each again before
> relying on it.

**What this item is for (one sentence, in my own words):** turn the text W-126b found in each line's value cells into
values — amounts, Yes/No, words — and, where the form's own printed arithmetic leaves exactly one cell unknown, infer
that cell, never defaulting a missing one to zero.

### What the design and the Gazette say

- `DR 06` G5.1 (`06-algorithms.md:482` – `:485`): **L2** "within an identified row, take the rightmost numeric token on
  the line, normalising Indian digit grouping", confidence **0.85 – 0.95**; **L3** "use the form's own arithmetic to infer
  a missing cell … 0.70 – 0.85, and only where the derivation is uniquely determined"; L4 keeps the raw text, no value
  (`D-NOSILENT`).
- **The arithmetic is printed on the form** (Gazette 271092, `sources/2026-11-16-form-130.md`): 2(f) [2(a)+2(b)+2(c)+2(e)],
  3 [1(d)-2(f)], 5 [4(a)+…+4(g)], 6 [3+1(e)-5], 8 [7(a)-7(b)], 9 (6+8), 11 [10(a)+…+10(i)+10(k)], 12 (9-11), 17
  (13+15+16-14), 21 (17-18-19-20). Row 1(d) is printed only as "Total"; it is still determined by row 3
  (1(d) = 3 + 2(f)). Rows 2(e) and 10(k) total the repeating "section …" lines, which W-126b does not read.
- `DR 06` G5.2 lists the same identities for W-128's checks, but loosely: it writes row 11 as "Σ 10(a..k)", while the
  form prints **10(a) … 10(i) + 10(k)** — 10(j) is the heading of the lines 10(k) totals. The printed form governs.
- **The identities are law**: the form prescribes them, and an amended form could change them (CLAUDE.md §4). They
  belong with W-126a's layout in the pack, not in Java. W-128 will check them too.
- Money: `taxengine.rules.money.Money.of(String)` takes a plain decimal (`Money.java:45` – `:47`).

### Choices for the owner (recommended first)

- **C1 — the split** (L2 needs nothing new in the pack; L3 needs the identities as pack data, a schema change and a
  relock, about 300 lines together with L2):
  - **(a) W-127a — L2:** amounts, Yes/No and words from each line's value text; **W-127b — L3:** the printed identities
    as pack data on W-126a's layer (each with its Gazette page), read through `CertificateLayout`, and the inference.
  - (b) one item.
- **C2 — what L2 reads:**
  - **(a)** an `AMOUNT` line: its value text must be **numbers only** — Indian or Western grouping, an optional
    leading minus, at most two decimals (`12,00,000.00`, `1200000`) — one per printed column; anything else (a word, a
    bracketed negative, more or fewer numbers than columns) is **not read**: no value, the text kept, a note naming
    the line. A multi-column line (10(a) – 11) gives **one field per column**, path `<line>.<column>` with the column's
    heading in camel case (`partC.annexureI.row10a.grossAmount`). An empty cell is no value, not zero.
    `YES_NO`: "Yes" or "No", any case. `TEXT`: the text as it is.
  - (b) "the rightmost numeric token on the line" as `DR 06` writes it — on a two- or three-column line that takes the
    deductible amount and silently drops the gross.
- **C3 — the confidences** (`DR 06` gives ranges, not points):
  - **(a) L2 0.90** (the middle of 0.85 – 0.95; the label matched exactly and the cell held numbers only) and
    **L3 0.80** (the middle of 0.70 – 0.85).
  - (b) the top of each range, 0.95 and 0.85.
- **C4 — the parser's name:** W-126b called it `form-130-l1`, version 1.
  - **(a) id `form-130`, version 2** — the id names the form, the version what it reads; nothing is stored yet (W-131).
  - (b) keep `form-130-l1` and bump the version.
