## Plan for W-358c3 — REST shapes and pagination (proposed split: W-358c3a, W-358c3b)

> Planned in session 113 (2026-11-21), placed by D-855. **Stop point: nothing is built until the owner answers C1 – C5.**

**What this item is for (one sentence, in my own words):** a route's path names a thing and its method says what is done to it, so
a caller can guess a URL, and no list grows without bound in one answer.

### Decisions (for approval with this plan)

- **C1 — sizing.** **C1a (recommended):** split — **W-358c3a** the paths (below), **W-358c3b** pagination with its own plan (the page
  shape, the size limits and which lists, decided there). **C1b:** one item.
- **C2 — what counts as "REST shape".** **C2a (recommended):** fix create / read / update / delete written as verbs, plural collection
  names, abbreviations (`mfs`), and reads that take a body; **domain actions stay** as `POST /…/{action}` on the thing they act on
  (`/drafts/{id}/compute`, `/temporary-transactions/redrive`) — the usual form for an operation that is not a record's create,
  update or delete. **C2b:** turn actions into resources too (`POST /computations` with the draft in the body …).
- **C3 — the three routes to remove.** **C3a (recommended):** remove `GET /me/portfolio/all/transactions` (the duplicate),
  `PUT /admin/corporate-actions/perform/test` (the leftover — the dry run it seems to want is not what it does) and
  `GET /public/auth/login` (answers a word). **C3b:** keep them.
- **C4 — trade entry.** `POST /me/portfolio/transaction` (V1) and `…/transaction/v2` are singular and versioned in the path.
  **C4a (recommended):** leave both as they are here — both are live, and renaming the trade paths belongs with V1's future, not
  with a path tidy-up. **C4b:** `POST /me/portfolio/transactions` for V2 and `…/transactions/v1` for V1.
- **C5 — reads that take a body.** **C5a (recommended):** they become `POST …/search` (a body of filters is a search):
  `POST /me/portfolio/stocks/search`, `POST /me/portfolio/transactions/search`; `/assets/search` already is. **C5b:** `GET` with
  query parameters (the filter body has nested operators, which query strings carry badly).
