**For:** a split recorded as performed changes no holding, and a malformed one is marked performed too. Make a split actually apply, once, on one path. **Queue:** after W-223 (`PARKED-ROWS.md`, D-435).

### Choices (recommended first)

**C1 — which path applies a split.**
- **(a) The per-user path gets the arithmetic; the deprecated one goes.** `PUT /corporate-action/perform` then refuses `STOCK_SPLIT` (400), and keeps `NAME_OR_SYMBOL_CHANGE`. It is per user and per broker, and already has the duplicate guard. Dead helpers it leaves behind go too. The test at row 3 that performs a split through it changes to expect the refusal.
- (b) Keep both: the double-apply stays possible.

**C2 — what a split changes.**
- **(a) Lots only:** quantity × new ÷ old, price × old ÷ new; date, charges and transactions untouched. Cost is preserved, so a later gain and holding period are unchanged, and transactions stay the record of what was traded (row 4). **Limit:** a trade-outcome rebuild from transactions would not see the split; the row cap puts that in "Noted", with a check of whether it can give a wrong figure, and a row if so.
- (b) Lots and transactions: `originalBuyPrice` would become the adjusted price, losing what was paid.

**C3 — what stored data gets (row 6).**
- **(a) A read-only count now (runbook §3.9)**, with a correction row placed only if a database shows any. No write without seeing the count.
- (b) Build a correction now, blind.

### Build (C1a, C2a, C3a)

1. **`SplitRatio`** (`corporate/dto`): a record, one `parse`, two positive whole numbers `n:d`; one sentence for every refused shape. Used at entry and when applied, so a malformed row already stored also refuses before it is marked performed (W-216).
2. **`addCorporateAction`:** `STOCK_SPLIT` validated once on the way in.
3. **`processStockSplit`:** for each lot of this broker on or before the record date, the arithmetic and the action added to the lot; saved; then the performed row.
4. **Removed:** the deprecated method, its `case`, its `TODO`, helpers left with no caller (grepped in `src/main` and `src/test`). `Stock Split.yml` corrected, in the submodule.

Ratio meaning stays as the deprecated path read it: `2:1` doubles the shares.

### Roles

- **Architect:** one path, the ledger's duplicate guard, facts unchanged on transactions; no module boundary moves. The tax side reads adjusted price and date as it does today.
- **Product:** holdings show the split; the admin endpoint stops double-applying. **An admin who used it must use the per-user path.** Malformed ratios are refused when entered.
- **Engineer:** removes the deprecated method and a `TODO`; one parser; no new field.
- **Automation:** table above, by hand; three bite checks; the changed test named in the report.
- **Manual:** add a split, `PUT /corporate-action/user/{email}/perform`, `GET /portfolio/user/{email}/stocks/all` shows the doubled quantity and halved price. Edge: buying on the record date is included, as the existing query reads it (confirmed at build).

**Risks:** a ratio like 3:2 leaves fractional shares where a real allotment pays cash in lieu; not modelled, the quantity stays exact. Row 6's count may force a correction item. Removing an endpoint's split support is a behaviour change for any admin script.
