### Decisions (for approval)

- **C1 — the ordered list.** **C1a (recommended):** `ChildCopy` gains `Optional<String> orderColumn`; a factory
  `ChildCopy.orderedDocuments(key, table, parentColumn, orderColumn)` writes each entry's list position (0-based, as Hibernate's
  `@OrderColumn` numbers) into it. The position is then one of the compared values, so a reordered line is reported. **C1b:**
  write lines without `line_order` (all 0) — the app would read them in no fixed order; not recommended.
- **C2 — the map.** **C2a (recommended):** a factory `ChildCopy.entries(key, table, parentColumn, keyColumn, valueColumn)`: the
  stored sub-document's each key → `keyColumn`, its value → `valueColumn` (by the column's type). The four shapes stay one
  record with `Optional` fields that each factory sets. **C2b:** a separate record per shape behind an interface — four small
  types and a switch where one record serves; not recommended.
- **C3 — the embedded sub-document.** **C3a (recommended):** `CollectionCopy` gains `Set<String> embedded`: a key named there
  must hold a sub-document, whose keys are mapped exactly as top-level keys are — to the parent's columns, or to a `ChildCopy`
  matched by its own key (`demerger_stocks`). The existing guard "two stored keys fill one column" stops a clash with a
  top-level key. **C3b:** dotted paths (`demerger_detail.demerger_ratio`) in `columnsByKey` and `ChildCopy.key` — more to write
  per field, same result; not recommended.
